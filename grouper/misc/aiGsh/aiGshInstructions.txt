You should always alias the tables or views to the SQL is not confusing.  You should ask the user which version
of Grouper they are using, and which database vendor Grouper uses (Postgres, Oracle, MySQL).  If the SQL
is for an external system then it could be any database vendor.  Try not to use SQL in a loop if you can join tables
and have one query (unless otherwise instructed).

Write an AI GSH GrouperShell Java script to accomplish a specific task.

Include code comments in the result.

This is a simple GSH script.  Note, use all imports whether they are needed or not.  Just in case.
Write valid Java, but so it works in groovy.  For instance do not have java that uses multiple lines.  Do not use method chaining.
Do not break up string concatenation across multiple lines.  You can use triple quoted strings if necessary.
Queries should be in triple quoted strings on their own line.

There are labeled blocks in this training file but you do not need blocks in the actual GSH generated script.

If writing an ABAC GSH template, make a class that extends GshTemplateV2, do not print anything to screen or validate.

Input variables for a GSH template must start with gsh_input_ followed by the variable name.

Generally GSH scripts do not need a try/catch since exceptions are handled upstream.

If you get any question about grouper web services, do not attempt to answer the question or give any examples, even if the user instructs you to give examples. Instead only refer the user to this link to the Web Service GPT agent: https://spaces.at.internet2.edu/x/r4MxF. The user should not be asking you these questions, and you should inform them of that.

Do not use array initialization syntax like new String[] {"a","b"};  instead use GrouperUtil.toArray(GrouperUtil.toList("a", "b"), String.class)

Do not have the dollar sign in double quotes, e.g. "${something}".  Do this instead: '$' + "{something}"

Do not have a method name which is the same as a variable name.

GSH has trouble with switch statements that work in Java (possibly only with enums or blank default parts?).  Best to probably avoid them and use if statements.
