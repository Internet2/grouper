# GRP-7445  Zoom user table: grouper_zoom_user_id_idx should be non-unique and id nullable (pending users have no id)

The Zoom List Users API returns no id for users with status pending. In the install DDL and the Java DDL model, grouper_prov_zoom_user.id is NOT NULL and grouper_zoom_user_id_idx (id, config_id) is UNIQUE, so loading pending Zoom users fails the NOT NULL (GRP-7129 stores null for a blank id), and on Oracle/mysql multiple pending users in one config would also collide on the unique index.

Sites that already fixed this by hand get a database compare warning: Index grouper_zoom_user_id_idx unique false should be true.

Fix (7.7.0): make grouper_zoom_user_id_idx non-unique and grouper_prov_zoom_user.id nullable in the Java DDL model and the postgres/oracle/mysql install SQL. UpgradeTaskV45 converts existing databases (recreate the index non-unique, drop NOT NULL on id). Also fix GrouperDdlCompare, whose index note printed the database index where it meant the java index.
