# GRP-6984  Sync-back framework — flush ordering and concurrent-capture fixes

* Move the sync-back flush ({{{}loadDataToGenericProvisionerTables{}}}) out of {{loadDataToGrouper}} so it runs after {{{}retrieveFullIndividualTargetMemberships{}}}. Without this, {{prov_mship}} stayed empty when {{{}selectAllMemberships=false{}}}.
 * Extend {{isSelectEntitiesInGeneral}} / {{isSelectGroupsInGeneral}} in {{GrouperProvisioningBehavior}} to also consider {{canRetrieveAllData}} so framework-level gating matches what protocols like TrueFoundry actually do.
 * Synchronize {{recordTargetNativeUser}} / {{recordTargetNativeGroup}} / {{recordTargetNativeMemberships}} so concurrent captures from the framework's thread pool can't race on the {{LinkedHashMap}} canonical maps (observed in Duo selectByIds losing one of two users).
 * Null guards added in user/group/membership iterations in both full and incremental paths.
