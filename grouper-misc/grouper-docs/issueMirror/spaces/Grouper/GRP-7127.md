# GRP-7127  Test_privs_AccessResolverBulkGetPrivileges.testBulkMatchesPerRow fails: GrouperTest sets grant.all.read=true, so the explicit GrouperAll read grant is a duplicate

{{testBulkMatchesPerRow}} in {{edu.internet2.middleware.grouper.privs.Test_privs_AccessResolverBulkGetPrivileges}} (added by GRP-7071) fails in setup on every run with:
 * {{GrantPrivilegeAlreadyExistsException: membership already exists}} for group {{{}stem2:gAllRead{}}}, subject {{{}GrouperAll{}}}, field {{{}readers{}}}, thrown at line 83: {{gAllRead.grantPriv(SubjectFinder.findAllSubject(), AccessPrivilege.READ);}}

*Root cause*

{{GrouperTest.setUp()}} unconditionally sets {{groups.create.grant.all.read = "true"}} in the properties override map (GrouperTest.java line ~233 — the override map is cleared at the top of setUp, then this is set every time). With that flag on, {{Stem._grantOptionalPrivUponCreate(g, READ, GCGAR)}} (Stem.java line ~3016) auto-grants {{GrouperAll}} READ to every group as it is created. So by the time the test creates {{stem2:gAllRead}} and then explicitly grants {{GrouperAll}} READ, the membership already exists, and {{GrouperNonDbAccessAdapter.grantPriv}} throws {{GrantPrivilegeAlreadyExistsException}} on the duplicate. The test never reaches the actual assertion (bulk {{AccessResolver.getPrivileges}} at line ~91).

This is not environment-specific: the test source, {{{}GrouperTest.setUp{}}}, and the {{grantPriv}} duplicate-handling are byte-identical on {{GROUPER_7_BRANCH}} and {{{}GROUPER_6_BRANCH{}}}, so the test fails the same way on both — it appears to have never run green.

*Fix*

Add a {{setUp()}} override in the test that turns the flag off so the test controls {{GrouperAll}} read explicitly (which its {{gAllRead}} scenario requires):
 * {{protected void setUp() \{ super.setUp(); GrouperConfig.retrieveConfig().propertiesOverrideMap().put("groups.create.grant.all.read", "false"); }}}

With the flag off, the freshly created {{gAllRead}} does not auto-carry {{GrouperAll}} read, the explicit grant succeeds, and the test proceeds to exercise the batched {{getPrivileges}} contract it was written for. {{testBulkRootGetsAll}} in the same class only creates groups (no {{GrouperAll}} grant), so it is unaffected by the change and shares the fixed setUp.
