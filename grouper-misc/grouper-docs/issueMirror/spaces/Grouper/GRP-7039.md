# GRP-7039  Enable maintenance daemon to actually delete duplicate single-assign attribute assignments (currently log-only)

* {{GrouperDaemonDeleteMultipleCorruption.fixAssigns()}} (run by {{{}GrouperDaemonDeleteOldRecords{}}}, otherJob {{{}cleanLogs{}}}) already detects single-assign defs ({{{}multiAssignableDb = 'F'{}}}) with multiple assignments — including assignment-on-assignment owners — keeps the newest, and deletes the rest.
 * It did not clean the deprovisioning duplicates because it runs in log-only mode: {{loader.removeMultiAttributeAssignIfSingleAssignAttributeLogOnly = true}} (enabled but never deletes).
 * Action:
 ** Review the daemon's existing {{fixAssignsCount}} log output to confirm the detected duplicates are all legitimately removable (they are, for these deprovisioning attrs).
 ** Set {{loader.removeMultiAttributeAssignIfSingleAssignAttributeLogOnly = false}} in PennGroups prod so future duplicates self-heal.
 ** Optionally (GRP): consider flipping the base default to delete, since log-only means corruption accumulates silently and can break screens (the deprovision-a-user case).
 * Note: this is a backstop; Jira 1 stops the duplicates being created in the first place.
