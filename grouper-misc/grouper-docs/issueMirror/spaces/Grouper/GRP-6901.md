# GRP-6901  Failure to load a custom hooks class causes startup failure "'Grouper' has db/ddl version: 0"

Method initHibernateIfNotInittedHelper() test a few different things before setting up the session factory handler. First it maps some hardcoded classes to xml config files for hibernate. Then it tests lifecycle hooks, then it tests for existing of the temp directory.

Not much can go wrong with the xml config loading, since it's hardcoded class names. But the hooks classes could potentially be a problem, and less likely the tmp dir might fail somehow. If the hooks loading fails, it exits the method and doesn't set up the session factory, even though it's not really dependent on the hooks. The result is that it can't look up the grouper_ddl table because it needs a session to do that. The result is that it thinks the version is 0 and Grouper fails to start. It's worse depending on the version, due to GRP-6645, since it was trying to log at log level FATAL, but this was not being output, resulting in a mystery why the db version was 0.
