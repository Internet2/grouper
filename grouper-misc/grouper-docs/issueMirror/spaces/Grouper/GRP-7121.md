# GRP-7121  SAML ext-auth: keyStoreAlias / keyStoreType property renames are reversed, so setting the keystore alias/type silently fails

In {{ConfigUtils.java}} (grouper-ext-auth), the {{PROPERTY_RENAMES}} map that normalizes deprecated config property names to the PAC4J {{SAML2Configuration}} bean-property names has its key and value reversed for two entries:


 
 
PROPERTY_RENAMES.put("external.authentication.saml.keyStoreAlias", "external.authentication.saml.keystoreAlias");
PROPERTY_RENAMES.put("external.authentication.saml.keyStoreType", "external.authentication.saml.keystoreType");
 
{{propertyNameRename()}} does {{{}getOrDefault(name, name){}}}, treating the map key as the configured property name and the value as the rewritten name. The setter is then derived as {{set}} + capitalize(last segment). PAC4J's setters are {{setKeyStoreAlias(...)}} and {{{}setKeyStoreType(...){}}}, so the rewritten value must be {{...keyStoreAlias}} / {{{}...keyStoreType{}}}.

Because the entries are reversed:
 * A user who configures {{external.authentication.saml.keystoreAlias}} gets no match (the map key is the camelCase form), so it is passed through unchanged and the code derives {{{}setKeystoreAlias{}}}, which does not exist -> {{NoSuchMethodException}} -> "could not set keystoreAlias". The keystore alias is never applied.
 * The {{checkConfig()}} deprecation warning is also backwards: it tells a user who used the correct {{keyStoreAlias}} to switch to the broken lowercase form.

Impact: any deployment that needs to pin a specific keystore alias or type (e.g. a keystore holding more than one entry) cannot do so via SAML ext-auth. Deployments with a single-entry keystore are unaffected because PAC4J defaults the alias, which is why this went unnoticed.

*Fix:* swap the key/value in both {{put}} calls so the deprecated lowercase names map TO the canonical PAC4J names:


 
 
PROPERTY_RENAMES.put("external.authentication.saml.keystoreAlias", "external.authentication.saml.keyStoreAlias");
PROPERTY_RENAMES.put("external.authentication.saml.keystoreType", "external.authentication.saml.keyStoreType");
 
*Affected versions:* 6.1.0+ (bundled ext-auth). Present on {{GROUPER_4_BRANCH}} (module {{{}grouper-ext-auth{}}}) and the v7 line (module {{{}grouper-ext-auth-logic{}}}).

*Reported by:* Matt Campbell (via Slack).
