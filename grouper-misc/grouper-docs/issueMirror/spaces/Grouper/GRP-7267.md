# GRP-7267  UI accessibility: add a main landmark and a skip link to the page shells

No page in the Grouper UI had a main landmark, and there was no skip link, so screen reader and keyboard users had to traverse the repeated environment banner, logo, navbar, search box and left nav before reaching page content on every page.

WCAG 1.3.1 Info and Relationships (main landmark) and 2.4.1 Bypass Blocks (skip link).

Changes. The existing content wrapper was changed from a div to a main element, keeping its id, in all five page shells: index/index.jsp, public/index.jsp, index/indexCustomUiTopContainer.jsp, gshTemplate/indexGshSimplifiedUiTopContainer.jsp, and oauth/oauthAuthorize.jsp. The OAuth consent page had no content div of its own, so its consent container became the main element and was given the same id, so that a single skip link target works on every page. The webapp root index.jsp was left alone since it is a meta-refresh redirect with an empty body.

The landmark is anchored on the inner content element rather than the enclosing span9 main-content div, because on the two custom UI shells that enclosing div also holds the logo and the logged-in-as and logout row, which are not main content.

This is safe for the ajax driven UI because every server side reference to that id goes through GuiScreenAction.newInnerHtmlFromJsp, which the javascript applies with jquery .html(). Children are replaced, never the element, so the landmark survives every navigation and there is never more than one per page. No CSS or javascript selects that id, and all main-content CSS rules are class based, so changing the tag name is style neutral.

A new shared include, assetsJsp/skipLink.jsp, renders an anchor to the main landmark and is included as the first element inside body in all five shells, ahead of the environment banner, logo and navbar, so it is the first focusable element on the page. Supporting changes: a grouper-skip-link style in grouperUi2.css that parks the link off screen rather than using display none (which would remove it from the tab order) and reveals it pinned to the top left on focus with a high contrast outline; a new externalized text key guiSkipToMainContent; a tabindex of -1 on the main element in every shell so that activating the link moves focus rather than only scrolling; and a rule suppressing the user agent focus ring on that programmatic-only focus target, which would otherwise draw a box around the whole content area when the skip link is used.

Verified on a running UI. Exactly one main landmark per page, containing the h1, persisting across ajax navigation. First Tab from page load reveals the skip link, Enter moves focus onto the main element, and the following Tab continues from the first control inside main with the header and navbar skipped entirely. Layout unchanged and no console errors.
