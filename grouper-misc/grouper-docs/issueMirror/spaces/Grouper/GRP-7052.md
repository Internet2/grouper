# GRP-7052  When a user's target id changes, incremental should recalc and send over the user's memberships

If a user is deleted and recreated in the target (new native id), or matching resolves to a different target object, the new object does not have the memberships Grouper previously provisioned. Today the cache picks up the new target id but memberships are not re-sent until a full sync, which at Michigan scale can be a long wait.

Proposed: when the provisioner detects a target id change for an entity (cache update in grouper_sync_member), automatically mark that user's memberships for recalc in incremental so they are provisioned to the new target object. Same concept applies to group target id changes (re-send that group's memberships).

Test: recreate a user in the mock target with a different id, run incremental, verify the user's memberships are re-added to the new object.
