# GRP-7594  LibreChat provisioner

Add a LibreChat provisioner so Grouper groups and memberships can be provisioned to LibreChat (v0.8.5+), so people can share agents, prompts and MCP servers with a group whose membership Grouper keeps current.

Target: the LibreChat admin REST API (/api/admin/groups, /api/admin/groups/:id/members, /api/admin/users/search). Authentication comes from a web service external system; LibreChat has no API keys, only a short-lived JWT, so sites typically use httpAuthnType=dynamic (GRP-7593).

Behavior:
- Groups: create, update name/description, delete. LibreChat group name from the Grouper display name (configurable), description "Managed in Grouper: <group name>" (configurable).
- Groups are created with source=local and idOnTheSource=<prefix><grouper group uuid>, prefix configurable (default "grouper:"). The provisioner only reads and changes groups with that prefix, so groups made by hand or by other tools are never touched.
- Memberships: add/remove one member per call (the API has no bulk replace).
- Entities: matched by a configurable subject attribute (e.g. eppn) to the LibreChat user username, case-insensitive. LibreChat users are created on first login, so subjects without a LibreChat user are skipped until they log in; the next full sync picks them up. The provisioner never creates or deletes LibreChat users.
- Deleting a LibreChat group also removes its sharing grants (aclentries). A setting can empty the group instead of deleting it.
- Full and incremental sync.

Includes the mock service handler, tests, base properties, externalized text and documentation.
