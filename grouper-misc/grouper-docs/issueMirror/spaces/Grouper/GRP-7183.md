# GRP-7183  Abac row attribute in-list operator mishandles negative numbers

In the abac JEXL script analysis for row data field in-list operators (fieldName =~ [ ... ] and !~), the branch handling negative-number values inspected the wrong AST node. It tested jexlNode.jjtGetChild(1) — the whole array-literal node — instead of jjtGetChild, the current element in the loop. Since the array-literal node is never an ASTUnaryMinusNode, the branch was effectively dead, so a negative number in a row in-list was never matched correctly. Additionally, the negate call always operated on jjtGetChild(1).jjtGetChild(0) (the array's first element) rather than the element at the current index i, so even if reached it would have used the wrong value for every position after the first. Fixed to test and negate the per-element node (jjtGetChild), so negative numbers in row in-lists (e.g. myField =~ [-5, 10]) resolve to the correct bind values.
