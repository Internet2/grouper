# GRP-7356  messaging provisioner: allow formats to be configurable in jexl

Currently the format of outgoing messages is governed by a hardcoded Java enum  GrouperMessagingFormatType.EsbEventJson, and there is a corresponding drop-down option to with this format as the only option.

As an alternative if the implementer needs a specific format, allow an option for a translation script. They would then create a jexl Map object to map specific keys to values that are accessible (maybe just targetGroup, targetEntity, and targetMembership).



E.g. for the entity:

{noformat}${ {
	"subjectId": targetEntity.getSubjectId(),
	"netid": targetEntity.retrieveAttributeValueString("subjectIdentifier1"),
	"name": targetEntity.name,
	"email": targetEntity.email,
   }
}{noformat}
