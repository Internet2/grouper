# GRP-6981  Add canSyncBack DAO capability gating sync-back load flags

* Add {{canSyncBack}} field on {{GrouperProvisionerDaoCapabilities}} (default {{{}false{}}}) with {{isCanSyncBack}} / {{{}setCanSyncBack{}}}. A protocol declares this {{true}} by wiring its read path to feed {{{}GrouperProvisioningTargetNativeSync.record*{}}}.
 * {{LdapProvisioningTargetDao}} and {{GrouperScim2TargetDao}} set {{canSyncBack(true)}} alongside their existing capability setup.
 * {{GrouperProvisioningBehavior.isLoadEntitiesToGenericGrouperTable()}} / {{isLoadGroupsToGenericGrouperTable()}} / {{isLoadMembershipsToGenericGrouperTable()}} AND-gate on {{canSyncBack}} so capture calls become guaranteed no-ops on unsupported protocols (no call-site changes needed; record/mark already gate on behavior).
 * New {{validateLoadToGenericGrouperTableSupportedByDao}} in {{GrouperProvisioningConfigurationValidation}} surfaces a per-flag UI error when the operator enables a load flag on a protocol whose DAO hasn't opted in.
 * One new i18n key {{{}provisioning.configuration.validation.loadGenericTable.notSupportedByProtocol{}}}.
