## Comments

### Chris Hyzer - 2026-03-09T03:58:32.901+0000

When multiple daemon containers restart simultaneously (e.g. nightly restarts), each node's Quartz scheduler can fire the same job at the same time. The existing {{isJobRunning()}} check had a TOCTOU race — both nodes would check before either inserted a STARTED log entry, so both saw the job as not running and both proceeded. For the change log job this caused {{ConstraintViolationException}} on duplicate {{sequence_number}} values in {{{}grouper_change_log_entry{}}}.

*Changes:*
 # *SELECT FOR UPDATE to eliminate the race* ({{{}GrouperLoader.java{}}}) — Added {{claimJobIfNotRunning()}} method that uses {{SELECT FOR UPDATE}} on {{grouper_loader_log}} rows to serialize the check-and-claim across daemon nodes at the database level. Uses a two-tier strategy: first checks if entries exist in the last hour (common case — locks fewer rows), falls back to locking all entries for the job after extended downtime. The lock is held for only milliseconds.
 # *All job entry points protected* — Replaced the old {{isJobRunning()}} call with {{claimJobIfNotRunning()}} in all five Quartz job entry points:

 * {{GrouperLoaderJob.java}} — SQL/LDAP loader jobs and change log job
 * {{OtherJobBase.java}} — all OTHER_JOB daemons (provisioning, attestation, deprovisioning, workflows, etc.)
 * {{GrouperLoaderIncrementalJob.java}} — incremental loader jobs
 * {{GrouperReportJob.java}} — report jobs
 * {{FindBadMembershipsDaemon.java}} — bad membership finder

 

*3. ConstraintViolationException fail-fast* ({{{}ChangeLogTempToEntity.java{}}}) — When a constraint violation occurs during change log processing (duplicate sequence number from a concurrent daemon), the code now clears the sequence number cache and fails fast instead of retrying with batch size 1. The next scheduled run recovers cleanly.

*4. Random startup delay* ({{{}GrouperLoader.java{}}}, {{{}grouper-loader.base.properties{}}}) — Added configurable random delay of 0–15 seconds before starting the Quartz scheduler to stagger daemon nodes and reduce lock contention. Configurable via {{loader.schedulerStartDelayMaxSeconds}} (default 15, set to 0 to disable).
