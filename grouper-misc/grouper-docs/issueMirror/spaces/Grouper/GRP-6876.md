# GRP-6876  slow query on grouper_memberships_all_v

A WS REST GetMembershipsRequest for a group with no members is timing out and returning a 502. The underlying SQL query takes 150+ seconds because the {{grouper_memberships_all_v}} view joins {{grouper_memberships}} with {{grouper_group_set}} on {{{}ms.owner_id = gs.member_id AND ms.field_id = gs.member_field_id{}}}, but there is no index on {{grouper_group_set(member_id, member_field_id)}} to support this join.

The PIT table has the equivalent index ({{{}pit_gs_member_member_field_idx ON grouper_pit_group_set(member_id, member_field_id){}}}) but it was never added to the main {{grouper_group_set}} table.

This affects all queries that go through {{{}grouper_memberships_all_v{}}}, which includes the Hibernate-mapped {{MembershipEntry}} entity (used in MembershipFinder, StemViewPrivilegeLogic, MembershipRequireEngine, SyncToGrouper, loader incremental jobs, rules, etc.) as well as dozens of raw SQL queries.

*Fix:* Add the missing index to DDL install and upgrade scripts:
 {{CREATE INDEX group_set_member_member_field_idx ON grouper_group_set (member_id, member_field_id);}}
 
*Workaround:* Deployers can add the index directly to their database.
