# GRP-6843  TrueFoundry provisioner: use native TrueFoundry user ID as entity ID

The provisioner entity ID was incorrectly set to the user's email address. Fixed it to use the native TrueFoundry user ID (e.g. {{{}pt3vuwlxupmefpk8i9cj11du{}}}) returned by the subjects endpoint. Email is now stored as a separate {{email}} attribute and used for API calls (register, deactivate, role assignment, team membership). The native ID is used for SCIM display name PATCH requests. The TargetDao now builds an email-to-nativeId map during Retrieve All, and membership operations look up the email from the entity's {{email}} attribute. Fixes display name updates which previously failed because SCIM requires the native ID in the URL path.
