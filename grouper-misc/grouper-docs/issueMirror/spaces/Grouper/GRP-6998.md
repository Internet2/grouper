# GRP-6998  Attribute definition Type dropdown shows ???simpleAttributeUpdate.type.attr??? in English UI

On the attribute definition edit screen in the new UI, the "Type" dropdown renders the raw text-key marker {{???simpleAttributeUpdate.type.attr???}} (and the same for {{{}.perm{}}}, {{{}.limit{}}}, {{{}.type{}}}, {{{}.domain{}}}) instead of a human-readable label. Only the {{Service}} option resolves correctly.

_Root cause:_ {{grouper/conf/grouperText/grouper.textNg.en.us.base.properties}} defines only {{{}simpleAttributeUpdate.type.service{}}}. The French base file ({{{}grouper.textNg.fr.fr.base.properties{}}} lines 1777-1783) defines {{{}.attr{}}}, {{{}.domain{}}}, {{{}.limit{}}}, {{{}.perm{}}}, {{{}.type{}}}, {{.service}} — so the English file is missing five sibling keys.

_Steps to reproduce:_
 # Log in to Grouper UI in English ({{{}en.us{}}} locale).
 # Navigate to any attribute definition and click Edit.
 # Open the Type dropdown.
 # Observe {{???simpleAttributeUpdate.type.attr???}} etc. instead of "Attribute", "Permission", "Limit", "Type", "Domain".

_Fix:_ Add the missing English entries to {{grouper.textNg.en.us.base.properties}} next to {{{}simpleAttributeUpdate.type.service{}}}:


 
 
 
 
 
simpleAttributeUpdate.type.attr = Attribute
simpleAttributeUpdate.type.perm = Permission
simpleAttributeUpdate.type.limit = Limit
simpleAttributeUpdate.type.type = Type
simpleAttributeUpdate.type.domain = Domain
 
_Affects:_ Grouper v7 (and likely earlier — same gap exists in older branches if not patched).

_Workaround until patched:_ import the five keys as overrides on the Grouper config import screen against {{{}grouper.text.en.us.properties{}}}.
