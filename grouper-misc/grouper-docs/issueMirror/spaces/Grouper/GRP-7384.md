# GRP-7384  Duo provisioner sync-back: capture lastLogin and isEnrolled by default, and optional auth method counts per user

The Duo native sync-back (grouper_prov_user) only captures userName, email, and status by default, and native attribute capture is scalar only, so the phones / tokens / webauthncredentials / u2ftokens arrays on the Duo user object cannot be reported on. Institutions retiring SMS and phone callback need to know which users only have those methods.

Change 1: add lastLogin (/last_login) and isEnrolled (/is_enrolled) to the Duo default user sync-back attributes.

Change 2: new Duo provisioner boolean nativeAttributesEntitiesIncludeAuthMethods (default false). When true, derived per-user attributes are appended to the entity sync-back attributes (in addition to defaults or configured nativeAttributesEntities): pushPhoneCount, mobileOtpPhoneCount, pushPhoneLastSeen (activated phones only for push and mobile_otp), smsPhoneCount, voicePhoneCount, duoHardwareTokenCount (d1), hotpTokenCount (h6/h8), totpTokenCount (t6/t8), yubikeyOtpTokenCount (yk), webauthnCount, u2fCount. No phone numbers are stored.

Duo mock returns configurable phones / tokens / webauthn / u2f for tests.
