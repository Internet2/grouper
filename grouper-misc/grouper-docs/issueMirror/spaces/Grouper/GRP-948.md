# GRP-948  Rules UI

per discussion on the grouper-users list and after inspecting the use cases at https://spaces.internet2.edu/display/Grouper/Grouper+rules+use+cases, I'd suggest a rules UI be implemented in the following order of precedence:

1) inheritance: all use cases mentioned
2) composite-ng
  veto appears to be a derivative of this case, so include veto
3) disabled-date
4) reassign
5) forever
6) email notifications
