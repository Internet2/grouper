# GRP-7305  UI accessibility: config/admin screens have no h1 page heading (starts at h4)

An audit of the UI heading outlines found that object screens and most list screens are fine, but the config/admin screens (external systems, entity data fields, custom UI, subject sources, user lifecycle, gsh templates, global attribute resolver, sql sync, authentication, script tester, and their add/edit/details sub-screens) have NO h1 - their first heading is a page-title h4 in the blue-gradient page header (the same container the home page uses for its h1). Missing an h1 and starting the outline at h4 fails SC 1.3.1 / 2.4.6.

Fix: promote that page-title h4 (${textContainer.text[...MainDescription]}) to h1 across the 57 config JSPs that share the pattern, with the size-preserving class grouper-heading-as-h4 so the h1 renders at the original h4 size and the pages look unchanged. This gives each screen a proper single page-level h1. Verified live on a sample of the screens.
