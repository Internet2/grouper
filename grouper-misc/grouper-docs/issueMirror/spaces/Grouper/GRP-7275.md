# GRP-7275  Container: bump Rocky Linux base image from pinned 9.6 to the floating 9 tag

The grouper container Dockerfile pinned its base image to rockylinux/rockylinux:9.6, which was last rebuilt in May 2025. The image only reaches Rocky 9.8 because containerDockerfileInstallPackages.sh runs dnf update -y early in the build.

That has two costs: the update step has to pull down a very large number of superseded packages, which slows every build, and the superseded package files stay in the base layer while the replacements land in the update layer, so the final image carries both copies.

Change the base image to the floating major tag rockylinux/rockylinux:9, exposed as a new build argument ROCKY_VERSION so it can be overridden at build time, for example with --build-arg ROCKY_VERSION=9.8. A pinned minor was not kept because the build already runs an unpinned dnf update, so the pin bought no build reproducibility, and history shows the pin only moved twice in two years and drifted years behind each time.

The dnf update -y step is intentionally left in place. It still picks up security errata published after the base image snapshot; it is simply much cheaper now.

Applied to the 6 and 7 container branches.
