# GRP-7370  Option for /status endpoint to not disclose information

See [CWE-200: Exposure of Sensitive Information to an Unauthorized Actor|https://cwe.mitre.org/data/definitions/200.html]

This routinely comes up in security scans, so institutions want a way to mitigate the issue. The status endpoint is publicly available (UI may have passthrough, WS most commonly is public), discloses information of AWS EC2 hostname or DNS name, the Grouper software version, 
application uptime, diagnostic data, and a full list of all daemon job names.

In AWS a WAF is a feasible option. Otherwise, there should be a configuration parameter (grouper.properties?) to have the status endpoint be functional for health checks but not report any sensitive data. I.e., still return an HTTP code but have minimal text like “OK”, if any.

If users are using the status page in a browser for convenience, it’s more suitable to put it into a UI administrator page. Does anyone need to see this besides admins?
