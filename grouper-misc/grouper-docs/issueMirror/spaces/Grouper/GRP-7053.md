# GRP-7053  Full sync option that performs recalcs through incremental so it does not block

Add a mode where full sync is achieved by enumerating objects (groups, entities, memberships -- all of them, or just those suspected out of date) and feeding them as recalc events to the incremental provisioner at a controlled pace, instead of one long blocking full job. Incremental processes real-time events interleaved with the recalc backlog, so there is no multi-hour block.

Considerations:
 * Pacing config (e.g. up to N recalcs per incremental pass, real-time events first) so the backlog does not starve real-time changes.
 * Deletes: per-object recalc covers object state, but detecting target objects that should be deleted because they are no longer provisionable may still need a periodic comparison pass (which could run from the sync back tables instead of a full target retrieve).
 * Progress and completion: track the rolling full as a logical job with counts and start/end, so admins can see it advance and monitoring can confirm it finishes.
 * Scheduling: how this coexists with or replaces the scheduled full sync job.
