# GRP-6896  Provisioner framework: countInsertsUpdatesDeletes over-counts membership deletes in replaceMemberships mode

In GrouperProvisioningLogic.countInsertsUpdatesDeletes, the loop that counts membership deletes for replaceMemberships iterates ALL ProvisioningMembershipWrappers but is nested inside the per-group loop over targetObjectReplaces. This causes every deleted membership to be counted once per replaced group (N groups × D deletes instead of D). Additionally, target-only membership wrappers with no GcGrouperSyncMembership row cause a NullPointerException.

Fix: move the delete-counting loop outside the per-group loop so it runs once across all wrappers. Add a null check on getGcGrouperSyncMembership() to skip wrappers with no sync row (target-only orphans that were never tracked in grouper_sync_membership).
