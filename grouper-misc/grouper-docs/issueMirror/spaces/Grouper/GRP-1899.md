# GRP-1899  Daily report is not working with SMTPS

When using the parameters below in grouper.properties:

mail.smtp.server = xxxx.yyyy.zzzz
mail.smtp.user = xxx/yyy
mail.smtp.pass = yyyy
mail.smtp.ssl = true
mail.smtp.port = 587
mail.from.address = [xxx@example.com|mailto:xxx@example.com]

.we get the following error:

javax.net.ssl.SSLException: Unrecognized SSL message, plaintext connection?

Just out of curiosity, when we turned TLS off :

mail.smtp.ssl = false

now we get the following error:

javax.mail.MessagingException: Could not connect to SMTP host: xxxx.yyyy.zzzz, port: 25, response: 421

### Chad Redman  (unc.edu) - 2019-08-25T14:26:24.463+0000

My understanding is that 587 is STARTTLS, which starts out as plaintext before starting the session. It's port 465 that is SSL-wrapped smtp.

There are new properties in 2.4 patch 43, which enable STARTTLS now. Maybe try the starttls one instead of mail.smtp.ssl ?
{noformat}mail.smtp.starttls.enable = false
mail.smtp.ssl.trust =
mail.transport.protocol = smtp
mail.use.protocol.in.property.names = true
# mail.smtp.ssl.protocols =
# mail.smtp.socketFactory.class =
# mail.smtp.socketFactory.fallback = false
{noformat}

### Chad Redman  (unc.edu) - 2019-08-30T15:18:30.471+0000

Confirmed the settings are working for both ssl on 465 and 587 using starttls. More details on diagnostics are in GRP-2014.

Stefano, I'm guessing at your mail server setup, but I think what you will want to do is to first upgrade to 2.4.0 with at least patch 43, and then set:
{noformat}mail.smtp.port=587
mail.smtp.ssl=false
mail.smtp.starttls.enable=true
{noformat}
