# GRP-7603  Custom UI shows stale state after join or leave when a GSH script changes memberships

When a custom UI screen has a GSH script (gshScript) or a compiled template (gshTemplateConfigId) that runs on the join or leave button, the page redraws showing the state from before the click. A manual refresh shows the correct state.

Cause: UiV2CustomUi.joinGroup and leaveGroup compute the cu_ variables (the cuQuery results) before the script runs, and the page is drawn from those values. A script commonly changes memberships the queries read, for example adding the person to a trusted group that a cuQuery checks, so the redrawn page is stale. The only existing workaround is a redirectToUrl gated on cu_joinGroupButtonPressed or cu_leaveGroupButtonPressed to force a reload.

Fix: after the script or compiled template runs, recompute the screen logic (new helper recomputeLogicAfterScript) so the redrawn page and any redirectToUrl gate reflect what the script did. Screens without a script are unchanged, redirectToUrl is still honored, and the button-pressed variables are kept since they come from the container rather than the queries.
