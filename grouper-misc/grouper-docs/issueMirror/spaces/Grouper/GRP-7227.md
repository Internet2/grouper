# GRP-7227  Jamf provisioner: disable-instead-of-delete and ignore accounts by name/email

Adds two behaviors to the Jamf Pro admin-account provisioner.

Disable-instead-of-delete (entity setting, default false to match the SCIM provisioner): a delete disables the account (enabled=Disabled) instead of hard-deleting it; disabled accounts are filtered out of reads so they look absent; a later insert of the same person re-enables and refreshes the account rather than creating a duplicate. Works in both the bulk select and per-entity lookup paths.

Ignore list matches an account on name, email, or email_address (case-insensitive). Ignored accounts are filtered from reads and are never updated, disabled, deleted, or added to or removed from a role. An ignored account that reaches insert (an ignored subject placed in a provisioned group) surfaces as a per-member error rather than a silent skip, so the conflict is visible. A full-sync membership replace preserves ignored members already on a role, matching the incremental path.

Includes deterministic API and unit tests plus gated end-to-end tests for disable/reactivate, ignore-surfaces-as-error, and ignored-member preservation on full replace.
