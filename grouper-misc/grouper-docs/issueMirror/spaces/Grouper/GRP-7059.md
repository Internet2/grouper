# GRP-7059  Accessibility: Fix WAVE "Broken ARIA menu" on UI dropdown toggles (role=menu -> role=button)

A WAVE accessibility scan of the Grouper UI reports "Broken ARIA menu -- An ARIA menu does not contain required menu items" on the dropdown toggles throughout the app: the "Folder actions" / "Group actions" buttons, the "More" tab, and the per-row "more options" / action menus.

Root cause -- the dropdown trigger anchor carries {{{}role="menu"{}}}, e.g.:


 
 
 
<a data-toggle="dropdown" href="#" class="... dropdown-toggle"
aria-haspopup="true" aria-expanded="false" role="menu" ...>
Folder actions <span class="caret"></span></a>
 
The trigger contains only the label + caret -- the actual menu items live in the sibling {{{}<ul class="dropdown-menu">{}}}. So WAVE correctly sees a {{role="menu"}} element with no {{role="menuitem"}} descendants and flags it as a broken menu.

Fix -- change {{role="menu"}} -> {{role="button"}} on the trigger. It already has {{aria-haspopup="true"}} + {{aria-expanded}} (the standard menu-button pattern), and {{grouperUi.js}} already binds an Enter/Space -> click polyfill to {{{}a[role="button"]{}}}, so keyboard activation is preserved. Applied to all occurrences: 141 across 116 JSPs under {{{}grouper-ui/webapp/WEB-INF/grouperUi2{}}}.

Deliberately not done:
 * Did not move {{role="menu"}} onto the {{<ul>}} -- several menus are empty / ajax-populated on first open, so that would just relocate the same "empty menu" error (and populated ones would also need {{role="menuitem"}} on every item, plus divider/header handling).
 * Did not convert the {{<a>}} triggers to native {{<button>}} -- the tab-style "More" dropdown (styled by nav-tabs CSS that targets {{{}<a>{}}}) and the icon-only {{grouperDropdownToggleIconOnly}} dropdowns have no {{.btn}} class and render with default button chrome, which breaks their appearance.

Scope / affected: {{grouper-ui/webapp/WEB-INF/grouperUi2/**/*.jsp}}
