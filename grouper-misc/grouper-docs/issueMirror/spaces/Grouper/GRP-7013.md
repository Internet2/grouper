# GRP-7013  Provisioner failsafe logging and JUnit coverage

Add diagnostic logging and test coverage for provisioner failsafe so misconfigurations and bugs surface in the daemon log and in CI.
 * Logging in {{{}GrouperProvisioningFailsafe{}}}:
 ** {{{}processFailsafesSetupBean{}}}: one INFO line per provisioner run with the resolved state (use=true/false, thresholds in effect). Distinct INFO when {{showFailsafe=true}} but {{failsafeUse}} is blank/false — flag as likely misconfiguration.
 ** {{{}processFailsafesMaxGroupPercentRemove{}}}, {{{}processFailsafesMinOverallNumberOfMembers{}}}, {{{}processFailsafesMinManagedGroups{}}}: one DEBUG line per check with current count, delete count, add count, threshold, and decision.
 ** Route through {{GrouperProvisioningObjectLog}} so it lands in the same daemon DB log table as the rest of the provisioner output.
 * JUnit coverage (LDAP provisioner, alongside existing {{LdapSync*}} tests):
 ** {{{}showFailsafe=true{}}}, {{{}failsafeUse=true{}}}, {{{}failsafeMaxPercentRemove=1{}}}, {{{}failsafeMinGroupSize=10{}}}. Seed N members in target, remove >1% in Grouper, run full sync — assert {{OtherJobException}} with {{GrouperLoaderStatus.ERROR_FAILSAFE}} and target untouched.
 ** Same setup driven through the incremental change-log path — assert the same. This is the case that would catch a Griffin-style "incremental ignored the failsafe" bug.
