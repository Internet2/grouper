# GRP-7392  UI Clear config cache actions navigate (change the URL) instead of running as ajax

The two new Clear config cache actions on the configuration screen's More actions menu (GRP-7352 and GRP-7354, 7.6.0) run as page navigations instead of ajax calls. Clicking Clear config cache on all nodes changes the browser URL to UiV2Main.index?operation=UiV2Configure.clearConfigCacheAllNodes&configFile= , so a refresh, the back button, a bookmark, or a shared link runs the action again. Anything that changes state should be an ajax POST and should not put the operation in the URL.

Where: grouper-ui/webapp/WEB-INF/grouperUi2/configure/configureFilesMoreActionsButtonContents.jsp . Both menu items use href=?operation=UiV2Configure.clearConfigCache / clearConfigCacheAllNodes with onclick handleGuiV2LinkClick(...). handleGuiV2LinkClick is for navigating to a screen (a GET that updates the URL), not for performing an action.

Fix: make these links href=# with onclick ajax('../app/UiV2Configure.clearConfigCacheAllNodes', {formIds or optionalFormElementNamesToSend for configFile}); return false; , the same as other actions on these screens, e.g. configure.jsp removeProperties and configureUpgradeTasks.jsp upgradeTasksSubmit. The server side methods in UiV2Configure (clearConfigCache, clearConfigCacheAllNodes) should keep working as ajax targets. Consider rejecting a GET for them.

Please also look for other examples of the same pattern: a state-changing operation (clear, delete, run, submit, save, add, remove, sync, reset) reachable through handleGuiV2LinkClick or an href=?operation=... link. Start with recent changes (the 7.x releases, especially 7.5 and 7.6 UI commits, e.g. the GRP-7306 / GRP-7307 accessibility changes that converted anchors to buttons), then do a broader pass over grouperUi2 JSPs. Fix any you find in this issue or list them here.
