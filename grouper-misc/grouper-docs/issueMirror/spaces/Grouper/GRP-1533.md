### bert - 2017-06-27T17:21:42.171+0000

As I work to escape everything properly when some of the text is generated with JEXL expressions, I want to solicit some feedback:

The most common cases are:

# cn=$\{group.name\},ou=groups,dc=example,dc=edu
and
# cn=$\{group.name},$\{utils.bushyDn(group.name, "cn", "ou")},ou=groups,dc=example,dc=edu

I want to do all of this without a dn_escape( ) utils function that would have to be peppered into the LDIF templates. 

I believe the keys to making sure commas/etc are escaped properly are:
# Assume that the static part of the dn is escaped properly by the deployer. In other words, if a site wanted a folder/ou named ou=groups,with,commas,dc=example,dc=edu, it would have to be configured in pspng properties as ou=groups\,with\,commas. Of course, I don't think static OUs tend to have these characters.
# Make utils.bushyDn escape the RDN components as they are assembled
# Find the first RDN (the part before the first comma outside of a $\{ } block) (which assumes that $\{expressions} in the first RDN component are *not* structural), and escape characters in the entire value of the first RDN.

Note: Laying this all out sounds worse than it really is.

Please comment into this ticket if you envision dynamically generating initial RDNs with plusses, commas, etc. For example, using a $\{expression} to generate a Compound RDN (see bottom of [this page|http://example.com]) will not be supported by the sketch above because the plus within such an RDN would be escaped by the changes made to fix this Issue.
