# GRP-406  add a readonly mode for grouper

Grouper should be able to go into readonly mode where data can be read from the registry but not written.  The first pass is just to throw exceptions when writes occur, we can improve this by adding friendly messages to users.  This is a grouper.properties setting.



## Comments

### mchyzer - 2010-03-26T18:06:22.739+0000

There is a readonly mode for the Grouper API in svn in the 1.4 branch.
The immediate need for this is for Chicago and Penn's 1.5 upgrade, we can put the existing services in readonly mode, so the WS, UI, and GSH can be used against the current schema, the schema can be cloned, the upgrade can take place in the clone, then we can cut back.  The only disruption will be to read/write operations.

To use this, set this in the grouper.properties:

# set the API as readonly (e.g. during upgrades).  Any updates will throw an exception
grouper.api.readonly = true

Note that we are discussing having a database table to store config defaults or overrides so at some point we will be able to do this in one place.  Right now this is a gropuer.properties config only.
