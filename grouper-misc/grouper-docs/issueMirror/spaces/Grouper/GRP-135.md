# GRP-135  remove DTO's from the hibernate data layer

The business objects delegate javabean properties to DTO's... this is confusing for hooks, and also for the API in general.  Now that there is no GrouperSession associated with the business objects (just one to one with DTO), lets remove the DTO.

## Comments

### mchyzer - 2008-06-25T05:51:08.670+0000

The DTO beans (e.g. GroupDTO) were merged with the business objects (e.g. Group), and the hibernate layer now maps the business objects, and everywhere that used the DTOs (including hooks), now uses the business objects.  The public API doesnt change except that the DTO methods (that werent already available) are now available from the business objects.  Here are examples of refactorings:


No need to set DTO anymore, and DAO directly retrieves business object:

FROM:
    ns = new Stem();
    ns.setDTO( GrouperDAOFactory.getFactory().getStem().findByUuid(uuid) );

TO:

    ns = GrouperDAOFactory.getFactory().getStem().findByUuid(uuid) ;

Took out all the method chaining on javabean properties (since doesnt follow the javabean contract)

FROM:

RegistrySubject subj  = new RegistrySubject()
        .setId(id)
        .setName(name)
        .setTypeString(type);
        
TO:

RegistrySubject subj  = new RegistrySubject();
      subj.setId(id);
      subj.setName(name);
      subj.setTypeString(type);


Move all fields and getter/setter logic from DTO to business object

Business objects had createTime in Date format, DTO had whole number, so change:

FROM
  long createTime;
  public long getCreateTime() {
    return this.createTime;
  }

TO (and change hibernate mapping):
  long createTimeLong;
  public long getCreateTimeLong() {
    return this.createTimeLong;
  }

Business objects can be manipulated by DAO layer directly:

FROM:
      GrouperDAOFactory.getFactory().getStem().delete( stem._getDTO() );

TO:
      GrouperDAOFactory.getFactory().getStem().delete( stem );

Any methods which dealt with DTO's now deal with business objects:

FROM:
  protected GrouperSubject(GroupDTO g) 


TO:
  protected GrouperSubject(Group g) 

Stem used to return constant for create source...  switched to dto field... hmmm

FROM:
  public String getCreateSource() {
    return GrouperConfig.EMPTY_STRING;
  } 

TO:
  /** not sure why we dont expose this property... */
  public String getCreateSource() {
    return GrouperConfig.EMPTY_STRING;
  } 
  /** map this one to hibernate */
  public String getCreateSourceDb() {
    return this.createSource;
  } 

Maintain empty desription and null description.  Make a javabean property called descriptionDb, and
have the description property also

TO:
  public String getDescription() {
    String desc = this.description;
    if (desc == null) {
      desc = GrouperConfig.EMPTY_STRING;
    }
    return desc;
  } 

  public String getDescriptionDb() {
    return this.descriptionDb;
  }
