# GRP-7220  MCP server should identify itself in every result

MCP spec revision 2026-07-28 removed the initialize handshake, so there is no longer a single point where a server identifies itself to a client. The spec says servers SHOULD include io.modelcontextprotocol/serverInfo in the _meta of every result, so a client can tell what it is talking to without relying on prior connection state. Grouper returned server identity only in the initialize response.



Server name and version are now added to every result's _meta, set centrally where the JSON-RPC response is assembled so that every method and all tools carry it without touching any tool class. An existing _meta on a result is preserved, and an entry already present is left alone.



initialize keeps its top-level serverInfo field, which is where a client on 2025-03-26 looks for it, so that response now carries both — each era reads the location it knows about. server/discover previously built its own copy under _meta; that duplication is removed in favour of the shared helper.



Clients on 2025-03-26 are unaffected: this is an added field inside an object they already receive. Verified against a live 2025-era client across tools/list and tools/call for both read and write tools.
