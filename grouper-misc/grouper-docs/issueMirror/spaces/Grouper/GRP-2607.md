# GRP-2607  Add Unicon Office365 / Azure provisioner to projects and enhancements

Ref: [https://github.com/Unicon/office365-and-azure-ad-grouper-provisioner]

Unicon License is Apache 2.0, so compatible with Grouper's.

The reference source code is quite limited, making assumptions about the subject ids, deprovisioning the group upon removing the marker attribute, etc.

 

For possible enhancements, see:

  

1) [UNC Chapel Hill course group project notes|https://spaces.at.internet2.edu/display/Grouper/University+of+North+Carolina+-+Course+Groups+for+Office+365#UniversityofNorthCarolina-CourseGroupsforOffice365-ProvisioningtoOffice365], which added a number of enhancements

2) Kansas State added a different set of enhancements and fixes. Source is [available on Github|https://github.com/kstateome/office365-and-azure-ad-grouper-provisioner/tree/release].

### Chad Redman  (unc.edu) - 2020-03-01T05:23:33.502+0000

Summary of features from UNC maybe good to implement
 * Allow an HTTP proxy configuration (host and port)
 * Add more configuration parameters:

 -     - subject source
 -     - subject attribute (DONE, "idAttribute" was added to Unicon project 10/24/2019)
 -     - AD domain (DONE, "domain" was added to Unicon project 10/24/2019)

 * Optionally, removal of the sync attribute flag does not trigger deprovisioning of the O365 group, but rather removes the sync capability
 * Optionally, deletion of the group does not necessarily trigger deprovisioning from O365
 * Adding the sync attribute flag performs a full sync with O365, in case the attribute was added to an existing group;
 * Upon group creation, along with setting an attribute for the O365 group guid, also store the tenantId and the group name, which can be used to construct URL links to the group (outside of Sharepoint, the group’s guid is surprisingly not utilized in web links).
 * Optionally set visibility of created groups to private

Summary of features, bugfixes from Kansas State fork
 * Ability to do a full refresh
 * Added a hook to "schedule" a full sync: if the user wasn't found in Office 365. This is assumes users typically get added to office 365 in a few minutes of being provisioned for Office 365.
 * Made "MemberUser" to handle really slow user lookup for memberships on large groups.
 * Moved the O365 user lookup into an interface, so that potentially we can push this to the main fork, and not have our code break in the future. Renamed some classes as well. Updates to handle the renames.
 * handled nullpointerexceptions that occur if group is null (someone deleted the group before changelog processed add/remove
 * Added some handling due to state errors, such as trying to add/remove a user from a group in O365 when they've already been added or removed.
 * adding some unit tests for Office365ApiClient
 * Refactored the client abit. Made methods smaller, easier to test.
 * fixed an issue where the oAUTH token was failing to be generated.
 * Cleaned up 'error' when attempting to delete a member from a group that doesn't exist in the group.
 * Fixed an error where the tenantId was always being used instead of the domain passed into the function. This was preventing users in different domains from working appropriately.
 * method to pull any groups that are within any subfolders of the O365 groups folder. This should allow the fullsync provisioner to check membership of those groups.
 * Change the getUser method of the Office365API client class to lookup across the domains rather than specific lookup.
 * If grouperSubject is null, then don't try to add/remove the user from office365. You should assume ldap removal will eventually remove the person from the group as well as the unresolvable member deletion utility.
