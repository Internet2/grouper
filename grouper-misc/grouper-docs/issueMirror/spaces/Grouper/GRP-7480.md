# GRP-7480  MCP institutional_tools: owner argument descriptions say the owner is not the group or folder a template's inputs act on

h2. Problem

The {{institutional_tools}} MCP tool has optional {{ownerType}}, {{ownerGroupName}} and {{ownerStemName}} arguments, for a GSH template which runs on a group or folder. They were described as:

* {{ownerType}}: "Owner type for execution context. 'group' if running on a group, 'stem' if running on a folder. Optional for 'execute' action."
* {{ownerGroupName}}: "The fully qualified group name *to execute on*"

An AI model asked to get or change a group through a template which takes the group as an input read "the group name to execute on" as that group. It passed the group as the owner and left the template's own input empty, so the call was refused:

{noformat}Error in institutional_tools: ownerGroup a:b:c is not allowed to run this gsh template{noformat}

This happened repeatedly in the AI assistant in the Grouper UI, even with the template's own description saying to run it with no owner, because the tool definition is what the model reads first.

h2. Changes

The descriptions now separate the group or folder a template runs on from what its inputs act on:

* {{ownerType}}: the group or folder a template runs on, which is not necessarily what its inputs act on. {{group}} only for a template whose schema says {{executeOnGroupName}} is true, {{stem}} only for one whose schema says {{executeOnFolderName}} is true. If both are false the template runs with no owner: leave {{ownerType}}, {{ownerGroupName}} and {{ownerStemName}} out, and pass any group or folder the user asked about in the template's inputs
* {{ownerGroupName}} and {{ownerStemName}}: the group or folder the template runs on, only with the matching {{ownerType}}. Not the group or folder a template's inputs act on: that goes in {{inputs}}

Description text only. No change to how owners are checked or what a template can run on.
