# GRP-7452  Maven POMs publish wiki doc URLs instead of the GitHub SCM URL (flagged by Sonatype Central)

Sonatype Central support (ticket 128112, Release Size limit exemption request) flagged that the published POMs for grouperClient 7.4.0, grouper-installer 5.20.6 and grouper-scim 5.22.5 show a doc/wiki page instead of the source repo: https://spaces.internet2.edu/display/Grouper/Grouper+Client, https://spaces.internet2.edu/display/Grouper/Grouper+Installer, https://spaces.at.internet2.edu/display/Grouper/Grouper+SCIM+change+log+client. spaces.internet2.edu is retired.

Cause: child POMs set the project url element to a wiki doc page and have no scm block of their own. They inherit scm from grouper-parent (correct: https://github.com/Internet2/grouper), but Maven appends the artifactId on inheritance, so the effective scm url becomes https://github.com/Internet2/grouper/grouperClient etc, which is a 404.

Fix (v7): in grouper-parent set child.scm.url.inherit.append.path, child.scm.connection.inherit.append.path, child.scm.developerConnection.inherit.append.path to false (and child.project.url.inherit.append.path to false), set project url to https://github.com/Internet2/grouper, and remove the per-module wiki doc url overrides (grouperClient, grouper-ws/grouper-ws, any others) so every module publishes the GitHub repo as both url and scm url. Verify with help:effective-pom on each published module.
