# GRP-301  When searching for new members to add to a group, the links to page results do not maintain groupId

It was reported that removing a member just added to a group gave an exception. Chris added a fix which prevents the error, however, the fix cures the symptom rather than the problem - which is, in part, down to the groupId going missing. The next/previous links for the search should maintain the groupId and callerPageId. If they did you wouldn't get the option to remove members. However, fixing those parameters doesn't entirely solve the problem - you end up viewing members but still in find mode. Instead I think you should return to the search results - the alternative would be to list members but explicitly quit 'find' mode. We could have an additional button 'Assign members and go to group summary' so the user can choose.

Various workflows share the same machinery so it is quite likely that other things are not working properly and/or fixing one problem might create another.
