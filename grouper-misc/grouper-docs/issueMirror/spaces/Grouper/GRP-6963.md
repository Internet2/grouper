# GRP-6963  Generic provisioner sync back — move LDAP capture to GrouperProvisioningTargetNativeSync sibling

* Add {{GrouperProvisioningTargetNativeSync}} as a new typed sibling on {{GrouperProvisioner}} (alongside Configuration / Behavior / Data / Logic), following the existing {{grouperProvisioningXxxClass()}} factory pattern. Concrete base with three {{recordTargetNativeXxx}} methods, each gated internally by the corresponding {{GrouperProvisioningBehavior}} predicate.
 * Rename {{LdapProvisioningTargetNativeBuilder}} → {{LdapProvisioningTargetNativeSync}} extending the new base. Convert statics to instance methods; add {{widenLdapAttributeNamesForGroups/Entities(Set)}} (consult behavior internally), {{{}buildNativeGroup/User(LdapEntry){}}}, the two membership extractors, and {{captureGroupEntry / captureEntityEntry(entry, membershipAttr)}} convenience methods that pair build with record.
 * Override {{grouperProvisioningTargetNativeSyncClass()}} in {{LdapSync}} to wire the LDAP subclass.
 * Collapse all 6 LDAP DAO capture sites ({{{}retrieveAllGroups{}}}, {{{}retrieveGroups{}}}, {{{}retrieveAllEntities{}}}, {{{}retrieveEntities{}}}, {{{}retrieveGroupByDn{}}}, {{{}retrieveEntityByDn{}}}) from ~12-line blocks with inline {{Behavior}} reaches and static builder calls to 2-line {{widen…}} + {{capture…}} pairs. DAO call sites no longer reference {{{}Behavior{}}}, {{populateNative*}} booleans, or the builder's statics.
 * Reframe {{runNativeAttributesGroupsIncrementalAssertions}} in {{{}LdapProvisionerGenericTableTest{}}}: seed Grouper with both SUBJ0 and SUBJ1 so LDAP {{description}} lands multi-valued during the seed, then drive the incremental by adding SUBJ2 (exercises {{{}retrieveGroupByDn{}}}'s pre-write read which captures {{{}description=[SUBJ0, SUBJ1]{}}}). Documents the read-only 1-cycle-lag semantic explicitly.
