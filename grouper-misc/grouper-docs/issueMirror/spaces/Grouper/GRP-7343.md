# GRP-7343  Rule created with RuleApi cannot be edited in the UI because the check owner field is blank

h1. Description

A rule stores the group or folder it checks in one of two attributes: {{ruleCheckOwnerId}} (the uuid) or {{ruleCheckOwnerName}} (the name). Only one of the two may be set.

{{RuleApi}} stores the uuid. For example {{RuleApi.groupIntersection(actAs, adhoc, staff)}} assigns {{ruleCheckOwnerId}}. The UI rule wizard stores the name.

The UI can only read the name. {{RulePattern.getElementsToShow}} populates the group/folder field with {{ruleDefinition.getCheck().getCheckOwnerName()}} and never falls back to the uuid, so for a rule created with {{RuleApi}} the field comes up empty. Since that field is required, the rule cannot be edited in the UI at all, even to change an unrelated setting.

h2. Steps to reproduce

{noformat}grouperSession = GrouperSession.startRootSession();
adhoc = new GroupSave(grouperSession).assignName("test:adhoc").assignCreateParentStemsIfNotExist(true).save();
staff = new GroupSave(grouperSession).assignName("test:staff").assignCreateParentStemsIfNotExist(true).save();
subjectActAs = SubjectFinder.findByIdAndSource("GrouperSystem", "g:isa", true);
RuleApi.groupIntersection(subjectActAs, adhoc, staff);{noformat}

In the UI, go to {{test:adhoc}} > Rules and edit the rule.

* The "Group name of required group" field is blank.
* Saving fails with {{Group with uuid or name '' does not exist.}}

Expected: the field shows {{test:staff}}, and the rule can be edited and saved.

h2. Affected rule patterns

Group check owner:

* AddDisabledDateOnInvalidMembership
* AddMemberToGroupIfAddedToAnotherGroup
* AddMemberToGroupIfRemovedFromAnotherGroup
* RemoveInvalidMembershipDueToGroup

Folder check owner:

* AddCreatedGroupsToAnotherGroup
* SendEmailWhenGroupMemberInvalidDueToFolder
* RemoveInvalidMembershipDueToFolder
* AddDisabledDateOnInvalidMembershipDueToFolder

h2. Fix

Read path, {{RulePattern}}: when {{ruleCheckOwnerName}} is not set, resolve {{ruleCheckOwnerId}} to a name so the field is populated. Groups resolve with {{GroupFinder.findByUuid}}, folders with {{RuleEngine.findStemById}}, matching how the rest of the rules code resolves a check owner. A rule that already stores the name is unaffected and does no extra lookup.

Write path, {{RuleService.saveOrUpdateRuleAttributes}}: if a rule already stores its check owner as a uuid, keep storing a uuid when it is saved from the UI, so editing a rule does not change the way it stores its check owner. The uuid is captured where the code still knows whether the check owner is a group or a folder. Whichever of the two attributes is written, the other one is now cleared, so only one of them is ever set.
