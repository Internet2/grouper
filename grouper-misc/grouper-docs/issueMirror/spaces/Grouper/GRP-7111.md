# GRP-7111  capture membership writes into the sync-back mirror

Full sync serving memberships from the sync-back cache (grouper_prov_mship) needs that mirror to stay current on membership changes. Only SCIM/Adobe/Dropbox recorded membership writes into the native mirror; Okta and the other object-modeled-membership provisioners did not, so their membership mirror only refreshed on a target re-read and lagged under fullSyncMembershipsFromSyncBack.

Wire membership capture-on-write everywhere it was missing:
 * Okta: insert/deleteMembership now call recordTargetNativeMembershipInsert/Delete, so the membership mirror converges on the write pass.
 * Fan out the same to google, truefoundry (incl. replace), duo, azure, box, datadog, freshServiceRequester, remedyV2, teamDynamix.

Tests:
 * Each provisioner's membership add/remove converge test now asserts grouper_prov_mship after the write pass (pass A), isolating the new hook (the old two-pass assertion passed with or without it; the remove case is load-bearing). Okta gains combined all-three-axes add + update/delete tests.
 * Correct the stale "memberships captured on read only / no write-side capture" comments across these provisioners (group/user object read-path claims kept).

Config (GRP-7048):
 * Validate that fullSyncGroupsFromSyncBack requires fullSyncMembershipsFromSyncBack (both-or-neither pairing).
 * Drop selectAllEntities/selectAllGroups from the fullSyncUsers/GroupsFromSyncBack showEl; the runtime decision never depended on select-all.
