# GRP-7339  Provisioning folder regex overrides direct Do Not Provision of subfolder

# Set provisioning on app:google, 

* Folder scope: All objects in this folder or subfolders
* Provisionable regex: groupExtension matches ^authorized$

# Set provisioning on subfolder app:google:grouper

* Direct assignment: Yes
* Provisionable: No



Result: app:google:grouper:directory:admins:authorized is provisionable, with the explanation: groupExtension matches ^authorized$

## Comments

### Chris Hyzer - 2026-10-18T05:17:00.205-0400

Duplicate of GRP-7498. The regex was not the cause: app:google:grouper was set to do not provision with a blank folder scope (the UI hid the scope for do not provision), and provisioning treats a blank scope like only this folder. So for groups below its direct children that folder is skipped and app:google, with its regex, applies. Fixed in GRP-7498; existing folders need the upgrade steps there. Covered by SqlProvisionerTest.testDoNotProvisionFolderScopeWithRegexOverride.
