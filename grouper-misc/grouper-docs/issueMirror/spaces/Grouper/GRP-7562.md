# GRP-7562  Provisioner setting refreshEntityLinkIfLessThanAmount is documented but never used

Problem: provisioner.<id>.refreshEntityLinkIfLessThanAmount is documented in grouper-loader.base.properties (refresh target user link if less than this amount, default 20, shown in the advanced section of the provisioner UI). It is read into GrouperProvisioningConfiguration (getRefreshEntityLinkIfLessThanAmount), but nothing in the code calls the getter, so changing it has no effect. Admins reasonably expect it to make the incremental refresh entity links (for example the cached ldap_dn of users that were moved to another OU in the target), and it does not.

The similar setting refreshSubjectLinkIfLessThanAmount is used, in GrouperProvisioningLinkLogic.

Requested fix: wire refreshEntityLinkIfLessThanAmount up the same way refreshSubjectLinkIfLessThanAmount is used: when an incremental run has this many entities or fewer, re-retrieve them from the target and update the entity link and entity attribute value caches before translating memberships.
