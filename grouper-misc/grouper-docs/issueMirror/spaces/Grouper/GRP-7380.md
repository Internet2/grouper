# GRP-7380  Configuration review: config UI screen surfacing errors/warnings (AI review of config files and database)

Add a Configuration Review screen to the Grouper configuration UI (which today has a small number of links/sections). It surfaces configuration errors and warnings so admins can see what is missing or left at an insecure default, each with a recommended action. Admins have no easy way today to know that a default-open setting should be tightened; this screen makes that visible. Build it as an extensible framework so more checks can be added over time.

Part of the work is to have AI review the Grouper configuration (the properties files - grouper.properties, grouper-loader.properties, grouper-ui/ws configs, etc.) and decide what should be flagged as an error vs a warning, with the recommended fix. It can also inspect the database (e.g. config overrides in grouper_config, privileges, and other state) for risky or inconsistent configuration, not just the files.

Initial concrete checks (rules security, related to GRP-7359):

1. If rules.restrictRulesUiToMembersOfThisGroupName is blank, advise setting it to a power-user group (sysadmin/wheel). Rules run as GrouperSystem; gating who can add/edit rules to power users is recommended. (Per GRP-7359 non-sysadmins are already limited to privilege-validated patterns, but gating rule editing to power users is the safer posture.)

2. If rules.restrictRulesUiToMembersOfThisGroupName is blank AND rules.restrictRulesEmailSendersToMembersOfThisGroupName is blank, advise setting the email-sender group to a power-user group. sendEmail rules can send email to arbitrary recipients with an arbitrary subject/body evaluated as GrouperSystem (including ruleElUtils EL at fire time), so if neither gate is set, creating sendEmail rules should be limited to wheel/root. Setting one of these groups designates the trusted population.

Also flag rules.accessToApiInEl.group if it is set to a broad group, since membership there grants the full EL API (grouperUtil/forName) in rule EL evaluated as the actAs subject.

Complements the GRP-7359 rules UI privilege-escalation fix: that hardens the code path; this screen gives admins visibility into the config gates and other misconfiguration that further reduce abuse.
