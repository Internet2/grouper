# GRP-7514  Rule condition 'direct member with no end date' ignores memberships with a future start date

Reported by Vivek: a group needs every membership to have an end date. A custom rule does this: check membershipAdd on the group, if condition thisGroupHasImmediateEnabledNoEndDateMembership (Entity is a direct member of group with no end date), then veto. Adding a member with no end date is vetoed, and editing a membership to remove its end date is vetoed.

Problem: a membership with a future start date and no end date is allowed. The condition looks up the immediate membership with enabledOnly=true (RuleIfConditionEnum.thisGroupHasImmediateEnabledNoEndDateMembership calls findAllByGroupOwnerAndFieldAndMemberIdsAndType(..., "immediate", true), which adds ms.enabledDb = 'T'). A membership whose start date is in the future is saved with enabled = F, so it is not found, the condition is false, and the veto does not fire. When the start date arrives the membership simply becomes enabled; nothing re-checks it, so it stays open-ended.

Steps to reproduce (v7 UI): add the custom rule above to a group. Add a member with a start date in the future and no end date. The add succeeds.

Expected: the condition should find the direct membership whether or not it is enabled yet, and be true when it has no end date, so the veto fires.

Note: the same condition is used by the AddDisabledDateOnInvalidMembershipDueToGroup pattern (RuleApi.groupIntersection). With the fix, that pattern would also put an end date on a future-start membership with no end date when the entity leaves the required group, which seems correct.
