# GRP-7115  Fan out full-sync-from-sync-back to Google/SCIM/Azure; per-axis path, managed-attr capture, guardrail, framework fixes

Builds on GRP-7048 (Okta full-sync-from-sync-back). Extends the feature to per-axis provisioners and fans it out.

*Shipped:*
 * {*}Capability rename{*}: {{canRetrieveAllDataExcluding*}} -> {{canFullSync\{Entities,Groups,Memberships}FromSyncBack}} (path-neutral; the old name implied the combined {{{}retrieveAllData{}}}, which per-axis targets don't have).
 * *Adapter per-axis cache-first* ({{{}GrouperProvisionerTargetDaoAdapter{}}}): skips the bulk {{retrieveAll\{Groups,Entities,Memberships}}} for any axis served from the cache, so per-axis provisioners use the feature with no retrieval-code change.
 * {*}Managed-attribute capture{*}: each provisioner's sync-back default must include every attribute Grouper manages (translates + {{{}update=true{}}}), or a cache-reconstructed object looks dirty and triggers a spurious update every run (the "4 vs 2" class of bug). Fixed Google ({{{}givenName{}}}/{{{}familyName{}}}), SCIM ({{{}givenName{}}}/{{{}familyName{}}}/{{{}formattedName{}}}/{{{}emailValue{}}}/{{{}emailType{}}}), Azure ({{{}description{}}}).
 * *Guardrail* ({{{}GrouperProvisioningLogic.warnMissingManagedAttributesForSyncBack{}}}): when from-cache is on, warns for any managed target attribute not in the effective capture set. Advisory, per axis.
 * *Rename map on the bean* (Google {{{}email{}}}<->{{{}primaryEmail{}}}) as the single source of truth for native<->grouper attribute names; base normalize/auto-inject over it. Capture stays in the native-sync class, not the DAO.
 * {*}Framework fix — {{isSelectMembershipsInGeneral()}}{*}: now returns true if the raw {{selectMemberships}} flag is set OR the target retrieves memberships by group/entity for a selected axis ({{{}canRetrieveMembershipsAllByGroup/Entity{}}}). Previously it collapsed to the raw flag under {{{}customizeMembershipCrud{}}}, under-reporting group-centric targets (SCIM/Azure) and blocking groups-from-cache. *Shared method (6 call sites); no-op for targets with {{selectMemberships}} set (Okta/Google), so it corrects an under-report rather than flipping any existing true.*
 * {*}Provisioners{*}: Google (all axes, verified green), SCIM (users verified; groups/memberships unblocked by the framework fix), Azure (users enablement + {{description}} capture; from-cache provisioner tests deferred - see follow-up).
 * {*}Config docs{*}: indent the dependent sync-back fields; IMPORTANT caveats on the "Full sync ... from cache" toggles (capture every managed/matching attribute).
 * {*}Tests{*}: turned off {{logCommandsAlways}} in provisioner test utils.
