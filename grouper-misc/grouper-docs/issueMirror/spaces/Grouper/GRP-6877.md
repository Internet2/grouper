# GRP-6877  Folder membership export should have a configurable max size

The new folder group memberships CSV export (GRP-6658) has no limit on the number of rows it can export. On a large stem (e.g., root or a top-level org folder), this could load millions of memberships into memory at once, potentially causing an OutOfMemoryError on the UI container.

Added a configurable maximum export size with a pre-flight count check. If the count exceeds the max, an error message is shown to the user asking them to narrow their search using filters. This applies to both the regular membership path and the point-in-time (PIT) path.

_Changes:_
 * New \{{MembershipFinder.findCountForMember()}} method that performs a lightweight count-only query (does not load rows into memory). Automatically handles both regular and PIT queries. Saves/restores query options so the finder is reusable after the count call.
 * {\{grouper.membership.export.maximumFolderExportEntries}} config property (default 800,000, set to -1 for no limit) in \{{grouper.base.properties}}
 * Pre-flight count check on both PIT and non-PIT export paths in \{{UiV2Stem.groupMembershipsInFolderExport()}}. Returns a user-facing error message with the actual count and the configured limit.
 * Externalized error text showing formatted numbers
 * Unit tests: regular count, stem-scoped count, filtered count, empty group, PIT count, finder reusability after count, and security enforcement (non-privileged user only sees memberships on groups they can READ)
