# GRP-137  allow state of DB of object to be stored and compared

For hooks (e.g. notification), it is nice to know what has changed about an object which is being persisted to the DB.  This can be used in other circumstances as well.  

## Comments

### mchyzer - 2008-06-30T04:11:55.103+0000

Note, this probably only applies to "pre" hooks.  The state is cleared before "post" or "postCommit" hooks.  Now you can see if something have changed (applies to any of the core hibernate mapped objects):

boolean objectChanged = group.dbVersionIsDifferent();

To get the list of fields which have changed in comparison with the DB, call:

Set<String> differentFieldNames = group.dbVersionDifferentFields();

To get the value of the db or current object of one of these field names:

Object value = group.fieldValue(fieldName);
Object dbValue = group.dbVersion().fieldValue(fieldName);

Some of the field names are not actual fields, e.g. for groups, the attributes for "extension", will just return "extension", even though the extension is in the attribute map.  And a custom attribute will return attribute__someName.  fieldValue() will know what to do.

Note, you should not call these methods if there is nothing in the DB (e.g. before an insert or after a delete).

This is high performance and does not generate extra queries.

To maintain, the code which generates field constants and the list of fields included in the comparison is in GenerateFieldConstants.java.  The generated code (see in Group.java) should not be edited by hand, run the main method in GenerateFieldConstants for a certain class (specified in main() ).  If a field should not be included in either field constants or in the db compare (e.g. due to not being hibernated directly), annotate as such, e.g.

  @GrouperIgnoreDbVersion 
  @GrouperIgnoreFieldConstant
  private Member cachedMember = null;
