# GRP-7531  Entra ID provisioner: manage mail-enabled security groups and distribution groups via Exchange Online

The Entra ID (Azure) provisioner cannot create or manage membership of mail-enabled security groups or Exchange distribution groups. Microsoft Graph exposes these groups read-only; writes must go through Exchange Online.

Approach: in the existing Azure provisioner, keep all reads on Graph (groups and members are readable there, and the Graph id equals the Exchange ExternalDirectoryObjectId). Route only writes for mail-enabled non-Unified groups through the Exchange Online REST endpoint that the ExchangeOnlineManagement v3 PowerShell module uses internally: POST https://outlook.office365.com/adminapi/beta/{tenantId}/InvokeCommand with a body of CmdletInput (CmdletName + Parameters), using an app-only token for scope https://outlook.office365.com/.default. No pwsh in the container is needed.

Pieces:
- AzureGrouperExternalSystem: add SCOPE_EXCHANGE_ONLINE = https://outlook.office365.com/.default alongside the existing scopes.
- GrouperAzureTargetDao: one helper (exoInvokeCommand(cmdletName, params)) and branches in insertGroups, updateGroups, deleteGroups, insertMemberships, deleteMemberships for mail-enabled non-Unified groups. Cmdlets: New-DistributionGroup (-Type Security for mail-enabled security), Set-DistributionGroup, Remove-DistributionGroup, Add-DistributionGroupMember, Remove-DistributionGroupMember.
- Opt-in provisioner config (default false), key added to grouper.base.properties.
- AzureMockServiceHandler: handle /adminapi/beta/{tenant}/InvokeCommand for those cmdlets, plus tests.
- Docs on the Entra ID provisioner wiki page.

Gotchas:
- Pass BypassSecurityGroupManagerCheck=true on member add/remove and group set/remove since the app is usually not in ManagedBy.
- Treat already-a-member on add and not-a-member on remove as success so retries and full syncs converge.
- After New-DistributionGroup, store the returned ExternalDirectoryObjectId; Graph may not see the new group for a minute or more, so matching must not recreate it, and immediate member adds should be retryable.
- No batching: one call per member; handle 429 throttling with backoff. Avoid Update-DistributionGroupMember (full replace) except possibly on create.
- Pass members by Entra object id. Users without a mailbox or mail user cannot be members; report per membership, do not fail the batch.
- New groups need an Alias / PrimarySmtpAddress translation. Security groups need closed join/depart restrictions (default for Type Security).
- Synced-from-on-prem groups cannot be edited in Exchange Online; those must be managed in AD.

Permissions: Entra app needs the Exchange.ManageAsApp application permission plus an Exchange role, preferably RBAC for Applications with a management scope rather than tenant-wide Exchange Administrator.

Risk: the InvokeCommand endpoint is undocumented by Microsoft (though it is what the official module uses and is widely relied on). Keep all calls in the single helper so it can be swapped to the documented Exchange Online Admin API (if it covers distribution groups) or a pwsh fallback without touching DAO logic.
