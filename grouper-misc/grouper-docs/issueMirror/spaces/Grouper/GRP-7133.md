# GRP-7133  Interfolio provisioner: bulk retrieve entities via csv_report

Improves the Interfolio entity provisioner's bulk retrieve so it can match on the institution user id.

Background: the byc users/search endpoint does not return the institution user id, so it cannot be used to match on that attribute. The csv_report endpoint returns the full roster including that id.

Changes:
 * Add {{retrieveAllUsersViaCsvReport}} in GrouperInterfolioApiCommands: {{{}GET /byc/core/tenure/\{databaseId}/users/csv_report{}}}, quote-aware CSV parse driven by the header row, keyed on the institution user id, skipping rows with a blank id. Adds {{parseCsvLine}} and case-insensitive {{csvValue}} helpers.
 * csv_report is unreliable on large reports (the connection is dropped mid-response, returning a 400 with a "Connection reset by peer" body), so the retrieve retries up to 10 attempts with a 5s pause and a fresh HMAC signature per attempt.
 * The report body begins with a double UTF-8 BOM; strip all BOMs so the first column parses (otherwise the first attribute comes back null and every row shows as changed).
 * csv_report does not include the pid, so add {{resolvePid}} to resolve it lazily via byc search only when a write (update/unsubscribe) is needed. {{retrieveEntity}} stamps the searched institution user id on a single byc hit.
 * InterfolioTargetDao.retrieveAllEntities now calls csv_report instead of paging byc users/search; the unused page-size constant is removed. update/deleteEntity resolve the pid lazily before writing.
 * createUser/updateUser send the email lowercased.
 * InterfolioMockServiceHandler gained a csv_report route emitting the report header and rows.
 * Tests updated: match on the institution user id, and the rpt/fs flag lookups are case-insensitive since email is now stored lowercase.
