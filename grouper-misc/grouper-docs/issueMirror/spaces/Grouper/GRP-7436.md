# GRP-7436  Provisioning ignoreIfMatchesValue (group, entity, membership attributes) is parsed but never applied

targetGroupAttribute.N.ignoreIfMatchesValue, targetEntityAttribute.N.ignoreIfMatchesValue and targetMembershipAttribute.N.ignoreIfMatchesValue are documented, shown in the config UI and loaded into GrouperProvisioningConfigurationAttribute.ignoreIfMatchesValues, but nothing reads them, so a deployment that configures one believes objects are protected and they are not.

Apply it in full and incremental sync after matching: removeIgnoredGroupsAndEntities (before insertGroups) pulls group and entity containers where either the Grouper or the target side has a matching value (any value of a multi-valued attribute, honoring caseSensitiveCompare) and flags their state ignoredDueToAttributeValue; removeIgnoredMemberships (before compareTargetObjects) pulls membership containers that match or whose group or entity was flagged. Ignored objects are never inserted, updated or deleted, are not errors, and are counted as ignoredGroups, ignoredEntities, ignoredMemberships. An upgrade task warns deployments that have it configured, since it will start taking effect.

## Comments

### Chris Hyzer - 2026-10-04T16:14:21.887-0400

Fixed: targetGroupAttribute.N / targetEntityAttribute.N / targetMembershipAttribute.N ignoreIfMatchesValue (with showAttributeValueSettings=true) was loaded but never applied. It is now applied in full and incremental sync, via two shared methods in GrouperProvisioningLogic: removeIgnoredGroupsAndEntities (after group/entity matching, before inserts) and removeIgnoredMemberships (after membership matching, before compare).

Checked after matching, so an object is ignored if either the Grouper side or the target side matches. An ignored group/entity is never inserted, updated or deleted, and neither are its memberships (including target-only membership rows that only reference it by value, e.g. entity_uuid). Not an error and not in the insert/update/delete counts; counted as ignoredGroups, ignoredEntities and ignoredMemberships in the job log. Group/entity state has a flag ignoredDueToAttributeValue so only truly ignored containers cause membership ignores.

groupAttributes / entityAttributes: values of ignored entities/groups are stripped from the membership attribute on both sides. An ignore value on the membership attribute itself (e.g. the group subjectId attribute, or the entity memberOf attribute) ignores just those values (memberships), not the container -- this also keeps values for target accounts that are not in Grouper.

Tests: SqlProvisionerIgnoreIfMatchesValueTest (membershipObjects full/incremental/case, group+entity+membership tables, groupAttributes, entityAttributes, membership-attribute values, nothing configured). Upgrade note added to the v7 upgrade instructions: anyone who configured ignoreIfMatchesValue should review it since it now takes effect.
