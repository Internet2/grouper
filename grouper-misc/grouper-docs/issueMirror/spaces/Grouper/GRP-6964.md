# GRP-6964  wsBearerToken external system: rename serviceUrl property to endpoint and document upgrade migration

*Contributed by Vincent Bonamy*

_Background_
 * Commit cb9e3920 on GROUPER_7_BRANCH consolidated the wsBearerToken external system to use a single {{grouper.wsBearerToken.<configId>.endpoint}} property for all {{httpAuthnType}} values.
 * The previous {{grouper.wsBearerToken.<configId>.serviceUrl}} property (used only when {{{}httpAuthnType = oauthClientCredentials{}}}) has been removed.
 * After upgrade, any unrenamed config will fail at runtime with: {{Undefined or blank property: grouper.wsBearerToken.<configId>.endpoint}}

_Affected provisioners_
 * Adobe (shipped as {{{}oauthClientCredentials{}}})
 * Okta (shipped as {{{}oauthClientCredentials{}}})
 * Any locally-defined wsBearerToken external system using {{httpAuthnType = oauthClientCredentials}}
 * Not affected (already used {{{}endpoint{}}}): Datadog, TrueFoundry, FreshServiceRequester, SCIM

_Upgrade_
 # *Inventory.* Configuration → {{grouper-loader.properties}} → filter {{{}serviceUrl{}}}. For each {{grouper.wsBearerToken.<configId>.serviceUrl}} row, record: configId, full key, value, and source (database vs on-disk file).
 ## Note: also check in GSH templates or daemons or other Java e.g. in grouper.properties or grouper-loader.properties
 # *Pre-upgrade sanity check.* External systems → open each affected wsBearerToken system (Adobe, Okta, any local with {{{}httpAuthnType = oauthClientCredentials{}}}) → Test connection. Note which ones currently pass.
 # *Upgrade Grouper.*
 # *Delete the old keys.* Configuration → {{grouper-loader.properties}} → filter {{serviceUrl}} → select the checkboxes and delete all.
 # *Re-import with renamed keys.* Config actions → Import config file → {{{}grouper-loader.properties{}}}. Paste the inventoried entries as {{{}key=value{}}}, but change each key from {{…serviceUrl}} to {{{}…endpoint{}}}. For example:

grouper.wsBearerToken.adobe.endpoint=<original value>
grouper.wsBearerToken.okta.endpoint=<original value>
 
 # *Verify.* Test connection on each affected external system; result should match step 2. If a system did not pass Test connection before the upgrade, run one of its daemons instead and confirm success.

*Note:* if step 1 shows the source is the on-disk {{grouper-loader.properties}} (not the database), skip steps 4–5 for that configId. A sysadmin instead edits the file on every Grouper host (loader/UI/WS), renames the key from {{grouper.wsBearerToken.<configId>.serviceUrl}} to {{grouper.wsBearerToken.<configId>.endpoint}} (value unchanged), and restarts. Step 6 still applies.
