# GRP-7105  SCIM provisioner diagnostics: cross-check configured target attributes against the target's /Schemas

*Background*

Provisioning diagnostics for SCIM does not compare the provisioner's configured target attributes against what the target actually advertises in its SCIM {{{}/Schemas{}}}. As a result, common misconfigurations are invisible until they cause silent data problems in production - for example mapping an attribute the target treats as read-only or derived (a write that returns success but is silently ignored, causing a perpetual dirty-diff), putting an immutable attribute in the update set, or failing to map an attribute the target marks as required (creates get rejected).

Verified against a live CrowdStrike SCIM tenant that the target exposes this information: {{GET /Schemas}} returns each attribute's {{mutability}} (readOnly / readWrite / immutable) and {{required}} flag, so diagnostics can validate the configuration against it up front.

*Change*

Add a "Target schema cross-check (SCIM /Schemas)" section to provisioning diagnostics that fetches {{{}/Schemas{}}}, flattens complex sub-attributes (e.g. {{{}name.givenName{}}}, {{{}emails.value{}}}), and for each configured target entity/group attribute reports:
 * *Action needed* - the attribute is {{readOnly}} in the schema but is mapped for write; the target will silently ignore writes to it (should be unmapped).
 * *Warning* - the attribute is {{immutable}} in the schema but is in the update set; it can be set on create but updates will be rejected.
 * *Warning* - the schema marks an attribute {{required}} but it is not mapped; creates may be rejected.

Provisioner attribute names are resolved to schema attribute names by direct match plus a small alias map for the complex/derived cases ({{{}givenName{}}} -> {{{}name.givenName{}}}, {{emailValue}} -> {{emails.value}} or {{{}email{}}}, etc.).

New pieces:
 * {{GrouperScim2SchemaAttribute}} - holds one flattened schema attribute (resource, name, mutability, required, type).
 * {{GrouperScim2ApiCommands.retrieveScimSchemas}} - GETs and flattens {{{}/Schemas{}}}.
 * {{GrouperProvisioningDiagnosticsContainer.appendScimSchemaCrossCheck}} - the diagnostics section, wired into the run after validation.
 * Generic SCIM mock support for {{/Schemas}} (opt-in per test) plus a test that maps an attribute for write, marks it read-only in the mock schema, and asserts the cross-check flags it.

*Failsafe*

The section is best-effort and fully self-contained: it is wrapped in try/catch/finally, so if the target does not expose {{{}/Schemas{}}}, returns an unexpected payload, or the cross-check itself errors, it degrades to a single gray note (and logs) rather than affecting the rest of the diagnostics run. Targets without a {{/Schemas}} endpoint simply show the note.
