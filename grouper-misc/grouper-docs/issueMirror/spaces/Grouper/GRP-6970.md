# GRP-6970  Add ABAC example demonstrating composite, scripted group, and row-based scripted policy patterns

* Add {{edu.internet2.middleware.grouper.abac.AbacExample}} (extends {{{}GshTemplateV2{}}}) that builds three equivalent litellm read/write policy structures from one template
 * Composite variant under {{app:litellm_c:service:policy}} — {{_allow}} (manual union of {{_allow_manual}} + {{{}_allow_automatic{}}}), {{_allow_automatic}} = {{_allow_automatic_orgs}} ∩ {{{}ref:affiliations:affiliation_staff{}}}, {{_allow_automatic_orgs}} = {{basis:orgs:org_AB}} ∪ {{{}basis:orgs:org_BC{}}}, policy = {{_allow}} MINUS {{_deny_manual}}
 * Scripted group-based variant under {{app:litellm_ag:service:policy}} — one scripted ABAC group whose JEXL collapses the composite chain using {{'group:name'}} shorthand
 * Scripted row-based variant under {{app:litellm_a:service:policy}} — JEXL uses {{entity.hasRow('affiliation', ...)}} against the {{affiliation}} data row (fields {{{}affiliation_org{}}}, {{{}affiliation_name{}}})
 * Composites are created via {{Group.addCompositeMember(CompositeType, leftFactor, rightFactor)}} after group save
 * Scripted groups are marked with {{etc:attribute:abacJexlScript:grouperJexlScriptMarker}} and the JEXL is stored under {{etc:attribute:abacJexlScript:grouperJexlScriptJexlScript}}
 * Prereq groups ({{{}basis:orgs:org_AB{}}}, {{{}basis:orgs:org_BC{}}}, {{{}ref:affiliations:affiliation_staff{}}}) and the {{affiliation}} data row must already exist; the latter is populated by the {{OTHER_JOB_abacAffiliationFullSync}} daemon
