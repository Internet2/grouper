# GRP-7412  When target entity id changes, adding it to a group deletes other members of the group in incremental

In Okta, target-only entity IDs can change for whatever reason. When this happens, the incremental does not pick up on the change correctly. If a user is added to a group with an inconsistent ID, the first incremental will fail. The second incremental will add the user correctly, but *delete all other members from the group*.

# In SQL, change the remote id (simulates a user changing IDs in Okta). Either changing the cache bucket id or the mock table user id has the same effect.

{code:sql}update grouper_sync_member set member_from_id2 = 'abcde' where subject_identifier = 'banderson';
{code}

OR

{code:sql}insert into mock_okta_user (select email, 'bandersonXXX', first_name, last_name, 'abcde' from mock_okta_user where login = 'banderson');

{code}
