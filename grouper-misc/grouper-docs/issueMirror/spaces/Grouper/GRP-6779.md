# GRP-6779  Config import fails with duplicate key constraint when properties already exist in database

*Problem:* Importing properties via the UI configuration import fails with {{ConstraintViolationException}} (duplicate key on {{{}grpconfig_unique_idx{}}}) for properties that already exist in the database. The import should detect existing properties and update them, but instead tries to insert new rows.

*Root cause:* In {{{}UiV2Configure.configurationFileImportSubmit(){}}}, line 1202 replaces all spaces with {{\u0020}} unicode escapes before calling {{{}Properties.load(){}}}. This causes spaces around {{=}} separators (e.g., {{{}key = value{}}}) to be treated as part of the key name, resulting in keys with trailing spaces (e.g., {{"myKey "}} instead of {{{}"myKey"{}}}).

When the import looks up existing DB records using these space-suffixed keys, no match is found. It then calls {{configurationFileAddEditHelper2}} which trims the key before saving — but since no existing record was found, it does an INSERT with the trimmed key, which already exists in the DB.

*Fix:* Trim keys in {{configurationfileImportSubmitHelper()}} in both the lookup-set-building loop and the processing loop (after retrieving the value with the original key).
