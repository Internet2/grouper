# GRP-6902  Grouper DB password can't have equals sign (=) within first two characters

When ConfigDatabaseLogic first connects to Grouper, it tries Morph.decryptIfFile() on the password, and there is no way to avoid it. Despite the name, it tries to decrypt even if it's not a file, but if the decryption fails it just uses the unencryped string.

The decryption works by *first base64 decoding the plain password* and trying to decrypt the result. If that fails, it assumes it's not encrypted.

If you have an equals sign (=) in the original password, the base64 decoding sees that as the stop character for base64, and ignores everything after it. But for either the original password or the truncated version, the decryption will fail, so the decryption is a no-op and you get back the original password.

If the equals sign is in the first two characters, it's not enough to decode, so you get an empty set of bytes to decrypt. This {*}doesn't throw an exception in decryption{*}. The decryption succeeds, and it returns the decryption result which is a blank string. This results in the fun-to-debug postgres error "org.postgresql.util.PSQLException: The server requested SCRAM-based authentication, but the password is an empty string." Yet everything you look for in the hibernate properties, environment variables, jar versions, database settings, etc. all show the password is set just fine.
