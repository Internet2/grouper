# GRP-5551  do not create user folders before user authenticates

When using the grouperUi.autoCreateUserFolderName  feature.
If a user AuthN's ( to SSO ) but fails to be in the require.group.for.logins  access control they still have a folder created for them in Grouper.
While this seems "minor" it indicates that there could be other "pre-authentication" issues with the UI.
AKA: The user failed to "AuthN/AuthZ" and objects were created in Grouper as a result.
Obviously  the user name is a string that gets passed in and used to create a folder. And I don't know that the code path/process could be exploited.
But it seems much more rational to check the  require.group.for.logins  access control  and throw the error before any objects are created in Grouper.
