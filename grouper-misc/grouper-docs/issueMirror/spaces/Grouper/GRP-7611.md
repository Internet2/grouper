# GRP-7611  SCIM: paged GET /Users with filter groups.value eq to page group members

GET /Users only accepts an eq filter on id or identifier and returns at most one user; startIndex is not implemented. So there is no standard way to page the members of a group.

Change: support SCIM paging on GET /Users (startIndex and count, capped by ws.scim.maxResultsPerPage) with filter=groups.value eq "<groupId>", which lists the members of that group a page at a time (paged in the database, only members the caller may see), in addition to the existing id and identifier lookups.

In list responses the groups attribute of each user is not embedded (it can be large), unless a setting turns it on; a single user lookup keeps it.

Also: unit tests, document any new settings, update the SCIM documentation, and an upgrade note.

Related: GRP-7609 depends on this one (it must be done first or in the same release). Also GRP-7610 (PATCH /Groups), GRP-7612 (deprecate /Memberships).
