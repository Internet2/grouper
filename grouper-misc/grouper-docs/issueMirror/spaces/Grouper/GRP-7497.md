# GRP-7497  Duo admin role provisioner: use role_id, support custom admin roles and role priority

The Duo admin role provisioner only used the legacy Duo admin API "role" field, which Duo is deprecating in favor of "role_id", and which cannot assign custom admin roles. Requested on the Grouper Slack: use role_id so custom admin roles can be provisioned.

Changes:
- Create and update administrators send role_id only (never the legacy role param). Reads use role_id, falling back to the legacy role name if role_id is not returned. integration_manager is treated as application_manager.
- Role values in Grouper (group metadata or group display extension) can be a Duo role id (e.g. help_desk, or a custom role id) or a role name (e.g. Help Desk, Administrator, a custom role name), case insensitive. Note the role_id for Administrator is service_manager.
- Custom role names are resolved via GET /admin/v1/admin_roles (Admin API application needs Grant administrators - Read and Grant resource - Read). This is only called if a value is not a built-in role. If it fails, built-in roles and raw role ids still work.
- New optional provisioner config provisioner.<configId>.rolePriority: JSON of role id or name to integer priority, higher wins when an administrator is in several role groups. Built-in defaults: owner 800, service_manager 700, application_manager 600, user_manager 500, security_analyst 400, help_desk 300, billing 200, read_only 100. Custom roles not listed default to 150. Ties go to the alphabetically first role id. Invalid JSON is a config validation error.
- An unknown role value no longer throws Invalid role names; it is sent as a role id and Duo rejects that administrator if it is not valid.
- Grouper side values are normalized to role ids before comparing with Duo, so existing configs see no changes on the first sync after upgrade.
- Mock Duo service supports role_id and admin_roles, and returns the auth failure reason in 401 responses. New unit and mock provisioning tests.

Backwards compatible, no upgrade step: existing role names in group metadata or display extensions, and a role default of Read-only, keep working.
