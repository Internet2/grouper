# GRP-7496  Folder create hangs forever when a folder privilege inheritance rule fires (self-deadlock in StemViewPrivilegeLogic.addStemPrivilegeIfNeeded)

Reported on Grouper 7.5.0 with PostgreSQL: creating a folder under a parent folder that has a folder privilege inheritance rule sometimes hangs forever. The request never returns and nothing is logged. The folder create transaction stays open (idle in transaction) holding its locks, and retries of the same folder name queue behind it.

Cause: Stem.internal_addChildStem runs in a Hibernate transaction (A). _grantDefaultPrivsUponCreate inserts the creator's grouper_stem_view_privilege row (member, new stem, S) in transaction A. Then the stemCreate rule fires the inheritance rule, which calls Stem.grantPriv -> StemViewPrivilegeLogic.addStemPrivilegeIfNeeded. That method checked for and inserted the view privilege row with GcDbAccess on a separate pooled connection (B). B does not see A's uncommitted row, so it inserts the same row and blocks on the primary key until A ends. A never ends because its thread is waiting on B. The database cannot detect it since one side of the wait is in the application.

Conditions: the creator is not wheel/root (or privileges.assignAdminToWheelOrRootOnCreate is true), the creator has a grouper_last_login.last_stem_view_need within security.folders.view.privileges.recalcChangeLog.ifNeededInLastSeconds (default 7 days), and the inheritance rule grants a folder privilege directly to the creator subject.

Fix: addStemPrivilegeIfNeeded now does the check and insert with HibernateSession.bySqlStatic(), so it joins the caller's transaction when there is one and still runs on its own otherwise. Test: StemViewPrivilegeTest.testFolderCreateWithInheritedPrivilegeNoDeadlock.

Workaround until patched: set security.folders.view.privileges.recalcChangeLog.ifNeededInLastSeconds = 0 in grouper.properties (folder view privileges are then fully recalculated when needed instead of maintained incrementally). To clear a stuck create, end the idle in transaction session (pg_terminate_backend).
