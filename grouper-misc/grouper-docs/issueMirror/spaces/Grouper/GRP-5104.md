# GRP-5104  Provisioner retrieve AD objectSid and objectGuid as string instead of binary

If you want to use an unchanging id for an AD group to detect renames, you could potentially use objectSid or objectGuid which are unique for each group in AD. However, these are binary values, and Grouper is unable to store them in the cache table. I don't see other good options, unless you use the group idIndex or uuid, but it needs the right kind of object to be able to store the value into a custom attribute.

### Bert Bee-Lindgren - 2023-11-04T03:39:34.850+0000

>base64?

That's a really good question!

I was thinking that, too, but then I realized that it won't be directly usable in future searches in Base64, as objectSid=<base64> won't match anything.

 

Here are three choices:
 * Base64 and special handling when it's being used
 * Do the special handling early and store as escaped bytes which _can_ be used directly. See [http://blog.schertz.name/2008/03/searching-ad-for-a-user-account-with-a-sid/]
 * Convert bytes to standard Sid format (S-1-5-21-1077035949-4083587494-3467333957-1607) which I think might be directly searchable (still need to test this). The challenge is that I think this  might only work for objectSid and not for objectGuid. [https://stackoverflow.com/a/21818633] is a java class to convert back and forth from bytes.
