# GRP-6940  Restructure provisioner attr tables as per-provisioner catalog and widen target id columns

* Restructure {{grouper_prov_user_attr}} and {{grouper_prov_group_attr}} into a per-provisioner attribute-name catalog: drop the per-user/per-group FK, add {{grouper_sync_internal_id}} (FK to grouper_sync, no cascade), unique index on {{{}(grouper_sync_internal_id, attribute_name){}}}. Catalog deduplication means N groups × M attribute names produces M catalog rows instead of N×M.
 * Update reporting view joins to walk through {{_attr_value}} (new chain: value → catalog, value → user/group)
 * Widen {{grouper_prov_user.target_user_id}} and {{grouper_prov_group.target_group_id}} from {{VARCHAR(256)}} to {{VARCHAR(1000)}} to accommodate LDAP DNs and other long target identifiers
 * Refactor {{{}GrouperProvisioningLogic{}}}:
 ** New {{GenericProvisioningAttrCatalog}} inner class (with {{hasNonEmptyValue}} flag so all-empty records don't influence catalog type)
 ** {{buildProvisioningAttributeRecords}} populates the catalog map; per-record {{internalId}} now points at the catalog FK
 ** New {{buildProvisioningAttrCatalogRowData}} builds catalog rows
 ** {{coerceTypedValuesToString}} extracted as a helper; preserves empties
 ** Full sync uses the GcTableSync phase split: catalog {{INSERTS_UPDATES_ONLY}} before value sync, {{DELETES_ONLY}} after; incremental uses {{INSERTS_UPDATES_ONLY}} only (catalog never deletes from incremental)
 * Preserve empty values: {{convertProvisioningValue}} and {{addProvisioningAttributeValue}} no longer drop blank/empty inputs; {{_attr_value}} row is emitted with both value columns NULL so reporting can distinguish "attribute present, value empty" from "attribute not present"
 * Add native-target → grouper-target fallback in {{loadDataToGenericProvisionerTables}} via new {{collectEntitiesForGenericReporting}} / {{collectGroupsForGenericReporting}} / {{collectMembershipsForGenericReporting}} helpers, so provisioners that don't run a target select ({{{}selectGroups=false{}}}) still populate the reporting tables
 * Add chunked-delete blocks in {{ProvisioningConfiguration.deleteProvisionerSyncRecords}} for {{grouper_prov_user_attr}} and {{grouper_prov_group_attr}} (no longer cascade-deleted from {{{}_user{}}}/{{{}_group{}}})
 * Mirror all DDL changes in {{{}GrouperDdl_Grouper_install_postgres.sql{}}}, {{{}_oracle.sql{}}}, {{{}_mysql.sql{}}}, {{{}UpgradeTaskV41.java{}}}, {{{}GrouperDdl7_2_0.java{}}}, and {{aiGsh/aiGshDdl.txt}}
 * Add {{LdapProvisionerGenericTableTest}} and register in {{AllLdapProvisioningTests}} (skeleton; will be tightened in follow-up once LDAP target_id resolution is settled)
