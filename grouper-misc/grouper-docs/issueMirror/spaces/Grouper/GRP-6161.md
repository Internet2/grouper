# GRP-6161  Add ability to add custom jexl classes everywhere

Right now, there are only a few places where you can use custom classes in jexl by defining them as properties:

- LDAP Loader: loader.ldap.el.classes
- External subjects: externalSubjects.customElClasses
- Subjects: subjectVirtualAttributeVariable_<key> = class names

There should be a way to optionally specify a custom utility class that can be used in all jexls. There are hacks to load custom classes like using '.class.forName(...) or grouperUtil.newInstance(...), but these feel like back doors into functionality and not an endorsed method or that will continue to work after upgrades.
