# GRP-7556  Lifecycle events Policy daemon: one failing email send aborts the run and loses notifications

*Summary* If sending an email throws (for example SMTP host unreachable, or a template error), {{OTHER_JOB_groupPolicyUserLifecycleFullDaemon}} fails after the earlier steps have already changed memberships. The retry never sends the email.

*Details* Step order in the daemon: end-date, {{removeUserFromGroup}}, {{emailUser}}, {{emailGroupAdmin}}. {{emailUser}} works from memberships that still exist. If {{removeUserFromGroup}} removed the membership and {{emailUser}} then throws, the next run finds no membership for that user and group, so the user is never notified. Seen with a template parse error and with {{UnknownHostException: mail}}.

*Expected:* a failed email should not abort the other recipients, and removal plus notification should not silently lose the notification (catch per recipient and log, record unsent emails, or send before removing).

*Related doc note:* {{emailManager}} is described on the User Lifecycle events wiki page but is not in the shipped {{actionType}} options ({{emailUser}}, {{emailGroupAdmin}}, {{removeUserFromGroup}}, {{addEndDateOnMembership}}).
