# GRP-7216  MCP server should return resultType on all results

MCP spec revision 2026-07-28 requires every result response to carry a resultType field indicating whether the request completed ("complete") or needs more client input ("input_required"). Grouper returned results without it, so a client on that revision receives a malformed result for every method.



resultType of "complete" is now set centrally where the JSON-RPC response is assembled, so it applies to initialize, tools/list, tools/call for all tools, and ping without touching any of the tool classes — which do not build their results consistently. It is not applied to JSON-RPC error responses, which carry an error member rather than a result, and it does not overwrite a value a method has already set (server/discover sets its own).

Note a tool that reports failure via isError: true still gets "complete": the request finished, and the tool's failure is content rather than a protocol error.

Clients on spec 2025-03-26 are unaffected — verified against a live 2025-era client across initialize, tools/list, and tools/call for multiple tools including an error result.
