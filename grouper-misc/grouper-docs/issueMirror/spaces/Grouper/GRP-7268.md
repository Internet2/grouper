# GRP-7268  UI accessibility: stop putting HTML markup in the title attribute of object links

Thirteen externalized text templates built object links whose title attribute contained HTML markup, for example a strong element, br elements and span elements with the grouperUiTooltip class. The markup is the content of the Bootstrap 2 tooltip these links use (rel=tooltip with data-html=true).

Putting markup in title has two consequences while the attribute is present. The accessible description of the link becomes a string of raw tags. And a native browser tooltip can render the literal markup, because Bootstrap only rewrites title lazily on the first hover or focus; on a freshly loaded page no trigger has been initialized yet, so the raw attribute is what is live.

Note this did NOT affect the accessible NAME of these links. They contain real text content, and a link takes its name from its contents, with title used only as a fallback. The name was always the object name. The defect was the description and the native tooltip, which is why this is filed as a modest improvement rather than a serious one.

WCAG 1.1.1 Non-text Content and 4.1.2 Name Role Value.

Changes. In the [en.us|http://en.us] and [fr.fr|http://fr.fr] base text files the attribute was renamed from title to data-original-title in the thirteen affected keys: guiAttributeDefShortLink, guiAttributeDefLink, guiAttributeDefNameShortLink, guiAttributeDefNameLink, guiGroupShortLink, guiGroupLink, guiGroupShort, guiStemShortLink, guiStemLink, guiServiceShortLink, guiServiceLink, guiServiceFolderShortLink, guiServiceFolderLink.

This is behavior preserving for the tooltip, per the bundled Bootstrap 2.2.2 source. getTitle reads data-original-title first, so the tooltip content is unchanged. fixTitle only overwrites when a title attribute is present or when data-original-title is not a string, so with the value pre-authored and no title attribute it is a no-op and the content survives initialization. Nothing else in grouper.js or grouperUi.js reads the title attribute. The net effect is that no title attribute containing markup ever exists in the DOM, while the tooltip works exactly as before.

Verified on a running UI after a Tomcat bounce, which is needed because the text templates are cached in the JVM and grouper.config.secondsBetweenUpdateChecks defaults to 600 seconds. On the main page, elements with a title containing angle brackets went from thirteen to zero, and the thirteen triggers now carry data-original-title; the only remaining title on the page is a legitimate plain text one. Dispatching a real mouseover still shows the tooltip and it renders parsed HTML, with the strong element and both grouperUiTooltip spans present as real elements and no escaped tags, confirmed visually as well. After Bootstrap initializes a trigger the title attribute stays absent and data-original-title is preserved. Ajax rendered lists were confirmed at scale: the My groups page has fifty four tooltip triggers, all on data-original-title, none with a bare title. No console errors.
