# GRP-6955  ABAC viz: parts-based tree with per-attribute and negated-leaf fixes

Refactor the ABAC scripted-group visualization so the visualization tree is
built directly from the analyzer's flat parts list rather than re-walking the
JEXL AST. The screen analysis table and the visualization now have a 1:1
correspondence — every row on the screen is a node in the graph, every node is
a row.

Changes:

- GrouperJexlScriptPart gains two fields:
    Connective connective (LEAF | AND | OR)  — what kind of part this is
    GrouperJexlScriptPart parentPart         — its owner in the tree
  Both populated during analysis; parentPart resolved post-pass via the
  outer + inner AST node map.

- buildVisualizationTreeFromParts replaces the old buildVisualizationTreeFromAst.
  Each part becomes one AbacReference; children are wired via parentPart; a
  plain top-level compound is flattened so edges hang directly off the ABAC
  group node.

- Each hasRow leaf now exposes its inner predicate's per-attribute sub-parts
  as child nodes in the graph (the same per-attribute rows that already show
  on the screen analysis table). RelationGraph.processAbacCompoundChildren
  recurses for any ref that has children, not just COMPOUND wrappers.

- Negation handling moved off the accumulator part onto the right per-clone
  via a new isNegatedOf(JexlNode) helper. NOT-branch SQL is appended to root's
  where-clause only on the accumulator pass; a clone fill pass leaves the
  clone's SQL un-negated, so a negated-leaf populationCount now reports the
  count of MEMBERS of the un-negated group instead of "everyone-minus-that"
  (e.g. "2 Not member of group X" instead of "1,765,754 Not member of group
  X"). The orphan "Member of group X" part the analyzer used to emit for
  negated references is removed.

- Long descriptions in viz boxes wrap with a layered cascade in
  grouperVisualization.js:
    1. hard breaks at " or " and " and "
    2. soft breaks at last space ≤ 50 chars (with orphan-tail backoff)
    3. comma-split for array literals
    4. force-hyphenate at 70 chars for unbroken tokens
  Wrap operates on the raw text before HTML escaping so multi-byte entities
  don't corrupt the position math.
