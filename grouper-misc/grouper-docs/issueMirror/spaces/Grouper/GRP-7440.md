# GRP-7440  grouper_file persistence moves from Hibernate to GcDbAccess

Move grouper_file reads and writes from the Hibernate mapping (Hib3GrouperFileDAO, hbm.xml, second level cache) to a GcDbAccess based DAO, in line with the long term plan to move off Hibernate. No behavior change for reports, workflow, or GSH template downloads.

Benefits: metadata lookups (id, file name, path) never load the file contents, contents are read only when needed and can be streamed to a download, and file contents are no longer held in the Hibernate second level cache. This also prepares for a binary (blob) contents column without depending on Hibernate blob mapping differences across postgres, oracle, and mysql.
