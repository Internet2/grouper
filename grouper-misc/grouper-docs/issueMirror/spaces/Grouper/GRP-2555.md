### Greg Haverkamp - 2020-01-16T00:38:08.701+0000

You probably don't need my assistance understanding what's going on. However, now that I've gone over the code the UI calls Group.addOrEditMember() while WS calls Group.addMember().  The former sees an existing disabled time, sees that it doesn't match the null that is being passed in from the UI, and sets it to null, and updates the member, causing the member to be enabled.  (I gather.)  The latter takes the absence of the arguments sent in my WS calls and calls Group.addMember(), which does its thing eventually leading to the Rules engine being invoked.  (Which it appears is not called by the update.)

 

So, ideally, I think adding a member in the UI would do essentially the same thing that adding a member via WS does.  Or, I suppose, if rules were triggered on a membership update, and I just needed another rule, I could do with that, too.
