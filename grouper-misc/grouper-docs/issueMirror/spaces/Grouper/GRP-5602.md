# GRP-5602  AttributeDef update privilege should not require read to be useful, or should imply it

It seems that having update on the attributeDef is enough to look up the attribute in the autocomplete when assigning an attribute. But you can't save it, with error:

Error: Subject Subject id: 800001278, sourceId: eduLDAP cannot read attributeDef etc:attribute:TestFolderFlagDef, Problem calling method assignAttributeSubmit on edu.internet2.middleware.grouper.grouperUi.serviceLogic.UiV2GroupAttributeAssignment

 

The privileges should be consistent between the lookup and the actual saving.
