## Comments

### Carey Black - 2022-08-17T16:22:01.685+0000

REF: [https://spaces.at.internet2.edu/display/Grouper/Grouper+rules]
"
actAs: subject that the rule will act as.  If blank, then it will be filled in with the user who created the rule (probably a bad idea since the person might leave at some point, unless it is a service principal).  There can be configurations in the grouper.properties (details) which allow users to act as other users or GrouperSysAdmin.
"

Please don't break this.

Instead of always running the "if condition as grouper system", please make the rule always ( and completely ) 'act as' the actAs user .
This can be useful for using "least privileged" service accounts instead of defaulting to GrouperSysAdmin ( AKA: unlimited access) and is consistent with the existing rules design.
