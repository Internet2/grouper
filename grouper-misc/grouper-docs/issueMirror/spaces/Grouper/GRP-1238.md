# GRP-1238  MySQL performance issues with permissions

Going to try avoiding the permission views.  More details later.

## Comments

### shilen - 2016-03-18T16:03:32.825+0000

MySQL was having issues running permission queries in cases where there were a large number of effective permissions due to a single attribute assignment involving a role with thousands of members (~10K) and an attribute with hundreds of children (~1K).  This would yield millions of effective permissions.

Running a simple query (either using PermissionFinder or the view grouper_perms_all_v directly) for all permissions involving one of the child attributes would end up causing MySQL to want to create a temporary table containing the results of the entire view and therefore would run out of disk space (it was using 60GB+ in my case).

The fix was to adjust the code to stop using this view (which generally solves the problem) and handle the queries using additional joins instead of the union (due to hibernate limitations).

The junit test PermissionPerformanceTest is an example test that would exhibit the issue before the fix but not anymore.
