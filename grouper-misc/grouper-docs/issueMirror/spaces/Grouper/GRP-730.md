# GRP-730  Encryption of the password for the service account used in LDAPPC-NG

I followed the instructions (https://bugs.internet2.edu/jira/browse/GRP-122) and encrypted the password for sources.xml and grouper.hibernate.properties and it's working fine, but if I try to put the file path in ldappc.properties password field it doesn't work.

ldappc.properties :
edu.vt.middleware.ldap.serviceCredential=/app/grouper/api/conf/grouperDevAD.pass

I assume LDAPPCNG is using the file path as the password since it locked the AD service account (password policy enforces locking after 5 failed attemps). Putting the clear text password back instead of the file path works.

### tzeller@example.com - 2012-02-24T06:04:32.509+0000

The ldap source adapter supports encrypted passwords as of version 2.1.0.

For example, ldap.properties may contain : 

 edu.vt.middleware.ldap.bindDn=cn=Manager,dc=example,dc=edu 
 edu.vt.middleware.ldap.bindCredential=/grouper.apiBinary/conf/ldap.pwd 

Where ldap.pwd contains the encrypted password. 

grouper.apiBinary> java -jar lib/grouper/morphString.jar 
 Enter the location of morphString.properties: conf/morphString.properties 
 Type the string to encrypt (note: pasting might echo it back): 
 The encrypted string is: l3hr1pI0A+Dd6HP/5BUCDw== 

grouper.apiBinary> echo l3hr1pI0A+Dd6HP/5BUCDw== > ldap.pwd

See https://bugs.internet2.edu/jira/browse/GRP-122
