# GRP-7503  UI: remaining state-changing actions navigate (change the URL) instead of running as ajax POST (follow-up to GRP-7392)

Follow-up to GRP-7392. GRP-7392 converted the Clear config cache actions and several screens (provisioning actions, loader enable/disable, reports, group rules, convert to role) from URL navigation (handleGuiV2LinkClick / guiV2link with ?operation=...) to ajax POST. These state-changing operations still put the operation in the URL, so a refresh, the back button, a bookmark, or a shared link runs the action again. Investigate each and convert to ajax POST (href=# with onclick ajax('../app/...'); return false;), or note why it is fine.

* Enable/disable via handleGuiV2LinkClick: SqlSync {{sqlSync/sqlSyncConfigurations.jsp}}, subject sources {{subjectSource/subjectSources.jsp}}, custom UI {{customUi/customUiConfigs.jsp}}, global attribute resolver {{globalAttributeResolver/globalAttributeResolverConfigs.jsp}}, WS trusted JWTs {{authentication/wsTrustedJwts.jsp}}
* Delete via guiV2link (confirm, then navigate): daemon {{admin/adminDaemonJobsContents.jsp}}, {{admin/adminDaemonJobsViewLogsMoreActions.jsp}}, subject source, SqlSync, custom UI, global attribute resolver, WS trusted JWT, MCP recipe {{mcp/mcpRecipes.jsp}}
* Delete in all entityDataFields screens: {{entityDataFields.jsp, entityDataProviders.jsp, entityDataProviderQueries.jsp, entityDataProviderChangeLogQueries.jsp, entityDataRows.jsp, privacyRealms.jsp}}
* Delete in all userLifecycle screens: {{userLifecycleActions.jsp, userLifecycleEvents.jsp, userLifecyclePolicies.jsp, userLifecyclePolicyParts.jsp}}
* Local entity WS JWT key: {{UiV2LocalEntity.deleteWsJwtKey / deleteWsJwtKeyCreateNew}} in {{localEntity/localEntityWsJwtKeyMoreActionsButtonContents.jsp}}
* Folder rules: {{UiV2Stem.deleteRuleOnStem}} in {{rules/rules.jsp}} and {{stem/rulesTableHelper.jsp}} (group rules were converted in GRP-7392 commit 5)
* Object types: {{UiV2GrouperObjectTypes.removeObjectTypeFromFolder / removeObjectTypeFromGroup}} in {{grouperObjectTypes/objectTypeObjectSettingsView.jsp}}
* Check: {{UiV2AttributeDefName.deleteAttributeDefName}} ({{attributeDef/attributeDefContents.jsp, attributeDefNameMoreActionsButtonContents.jsp}}) and {{UiV2AttributeDefAction.deleteAttributeDefAction}} may only open a confirm screen (fine as a navigation) -- verify. Note the attributeDefContents.jsp href uses a second ? instead of &.
* Server side: converted operations can still be triggered from a crafted {{UiV2Main.index?operation=X&...}} link, since grouperUi.js runs the initial URL operation as an ajax POST with the CSRF header on page load (e.g. {{UiV2GrouperLoader.disableJob}}, {{deleteRuleOnGroup}}, {{removeProvisioningOnGroup}}, {{UiV2ProvisionerConfiguration.deleteProvisionerConfiguration}}). Consider an allowlist of view operations (or a denylist of state-changing ones) for operations arriving from the URL, as GRP-7392 suggested (reject GET).
* Accessibility: converted actions are {{<a href="#" onclick>}} in dropdown menus; consider buttons / {{grouper-linkbutton}} per the GRP-7306 / GRP-7307 pattern.
