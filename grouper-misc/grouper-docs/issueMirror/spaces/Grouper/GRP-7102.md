# GRP-7102  SCIM2 provisioner cannot match groups by externalId (only id and displayName)

*Background*

The SCIM2 provisioner matches target groups only by {{id}} (direct {{{}GET /Groups/\{id}{}}}) or {{displayName}} ({{{}filter=displayName eq "..."{}}}). {{GrouperScim2TargetDao.retrieveGroupHelper()}} never consults the configured group *search* attributes, so there is no way to match a group on {{externalId}} - even though {{externalId}} is already a writable group target attribute and the base config already parses {{{}groupSearchAttributes{}}}. This is asymmetric with the entity side, which searches by {{userName}} and (when configured) {{{}emailValue{}}}.

Matching groups only on {{displayName}} is fragile: a group rename in Grouper or in the target breaks the match, and it offers no stable, rename-proof key.

Verified against a live CrowdStrike SCIM tenant that this is a real, usable target capability: {{externalId}} persists on group create, is echoed back, and {{filter=externalId eq "..."}} returns the correct group. So the target supports it; only Grouper was not exercising it.

*Change*
 * {{{}GrouperScim2TargetDao.retrieveGroupHelper(){}}}: after id/displayName lookups miss, if {{externalId}} is a configured group search attribute, retrieve the group with a server-side {{{}filter=externalId eq "..."{}}}. Mirrors the existing entity {{emailValue}} search path. No new config keys - it consumes the existing {{{}groupSearchAttributes{}}}.
 * {{{}GenericScim2MockServiceHandler.getGroups(){}}}: capture the outgoing group filter ({{{}lastGroupsFilter{}}}) so tests can assert it, mirroring {{{}lastUsersFilter{}}}.
 * New test {{GrouperAwsProvisionerScimSettingsTest.testGroupSearchByExternalId()}} proving a group is found via the externalId filter when id/displayName do not match.

*Out of scope / follow-ons*
 * Entity matching by {{externalId}} (today entities match on id/userName/email only).
 * A UI-surfaced group filter-strategy control analogous to {{{}scimEmailFilterStrategy{}}}; this change relies on the existing generic {{groupSearchAttributes}} config.
