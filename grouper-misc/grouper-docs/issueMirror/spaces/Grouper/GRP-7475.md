# GRP-7475  Provisioner sync-back incremental sync does not remove grouper_prov_mship rows for memberships removed or replaced through write hooks

When a provisioner removes a member through a write hook (for example a SCIM PATCH op=remove on a group’s members), or replaces a group’s whole member list (SCIM PATCH op=replace), the sync-back hooks {{recordTargetNativeMembershipDelete}} and {{recordTargetNativeMembershipReplace}} only update the in-memory native membership map.

* *Full sync:* works, because its flush reconciles all of {{grouper_prov_mship}} to that map.
* *Incremental sync:* fails. {{loadDataToGenericProvisionerTablesIncremental}} only sees this run’s map keys. It deletes rows only for membership wrappers marked {{isDeleteResultProcessed}}, which these hook writes do not set, and it inserts the keys in the map. A removed key is simply missing from the map, so its row is never deleted.

Result: after an incremental remove or replace, the target is correct but {{grouper_prov_mship}} still has the old membership until the next full sync. Anything reading the sync-back tables (reports, full sync from the sync-back cache) sees memberships that no longer exist. This was already the case before GRP-7474.

Fix:

* {{GrouperProvisioningData}} tracks, per run, the memberships removed by write hooks ({{targetNativeMembershipDeletes}}) and the groups whose members were replaced, with the new user set ({{targetNativeMembershipReplacedGroups}}).
* The delete hook records the removal. The insert hook clears it if the same membership is added back in the run. The replace hook records the group’s new member set.
* The incremental flush deletes the recorded removals by target group and user id, using the same delete as the existing {{isDeleteResultProcessed}} path.
* For replaced groups, the flush reads the group’s {{grouper_prov_mship}} rows and deletes those whose user is not in the new set, in batches of 900, so large groups do not overflow an in-list. Missing rows are inserted from the map as before.
* The flush’s “nothing to do” check now accounts for replaced groups.
* Full sync is unchanged.
