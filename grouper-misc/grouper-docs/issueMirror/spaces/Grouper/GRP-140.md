# GRP-140  setters on business objects should not have database side effects

calling some setters (e.g. group.setExtension()) will store the data to the database inside the setter.

This is not ideal because:

1. It is generally not expected that setters store data
2. It could be more efficient to have one store method, e.g.

group.setAttribute("something", "whatever");
group.setExtension("ext");
group.setDisplayExtension("disp ext");
group.store();

3. For hooks, the hooks would fire with each setter, instead of potentially one hook for all the activity
4. Although there are still methods that cause database side effects, generally it is better to explicitly kick that off with the DB api or a store() method
5. Multiple calls to setters should occur in one transaction

### mchyzer - 2008-07-08T14:42:02.225+0000

This is fixed.  Here are the upgrade instructions (also listed in the change log):

Merge your grouper.properties with the grouper.example.properties.  Pick up the new property: grouper.setters.dont.cause.queries (if missing, defaults to false)

If you set this to true, refactor your the following methods:
  - group.setAttribute(), group.setExtension(), group.setDescription(), group.setDisplayExtension() to call group.store() afterwards (could be after multiple calls)
  - stem.setDescription(), stem.setExtension(),  stem.setDisplayExtension(),  to call stem.store() afterwards (could be after multiple calls)
  - member.setSubjectSourceId(), member.setSubjectId(), to call member.store() afterwards (could be after multiple calls)

Those methods are already refactored in the UI, web services, GSH, API.  Let me know if other non-setters should be changed too...  my thought is in a future release (and after using hooks a bit), we can identify more methods....

e.g. if the code is:

someGroup.setAttribute("whatever", "something");

change to:

someGroup.setAttribute("whatever", "something");
someGroup.store();

### mchyzer - 2008-07-08T14:47:04.705+0000

Also, if you have the setting set to false (or left out of grouper.properties, group.store() is a no-op.

The store() method is just a call to the DAO to store the object:

  public void store() {
    if (GrouperConfig.getPropertyBoolean(GrouperConfig.PROP_SETTERS_DONT_CAUSE_QUERIES, false)) {
      GrouperDAOFactory.getFactory().getStem().update( this );
    }
  }

If there is more to do, then that is done in the grouper hibernate api (e.g. onPreUpdate()).  So if you dont call store(), but you just persist the object with the DAO, you are good to go.  It wont work if you use the hibernate native API (which you shouldnt use anyways, since hooks wont work)...
