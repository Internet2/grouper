# GRP-7345  Don't default add grouperExternal and/or grouperEntities to new installations

Both grouperExternal and grouperEntities default to being created for a new Grouper installation. Local entities could be used for self-service subjects you can set oidc auth on. External subjects seems to be for federated SSO when you don’t have comanage or some other external system to set up entities. It’s basically a SQL subject source just with hard coded ddl and queries.

I haven’t seen either of these used much in the wild. If they are not in use, it adds needless calls to subject searches and resolution as it tries to resolve identifiers in all defined and enabled sources.

{{grouperEntities}} is defined in subject.base.properties. Being in a base file, there is no way to completely remove it. Setting {{subjectApi.source.grouperEntities.enabled = false}} does make it disabled, so maybe that improves performance?

{{grouperExternal}} is defined solely in java, including the ddl and search queries. Whether it’s an enabled subject source is governed by grouper.properties {{externalSubjects.autoCreateSource}}. Setting this to false and restarting is effective at removing it, although the empty GROUPER_EXT_SUBJ table remains.
