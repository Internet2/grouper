# GRP-7290  grouper-provisioner skill: build a new provisioner in layered commits so the backportable part is its own commit

The grouper-provisioner skill is a 14-section checklist of what a provisioner needs. It says nothing about how the work should be committed, and that turns out to decide how much hand surgery a backport costs.

CCure and Jamf are a natural experiment from the same era. CCure isolated sync-back in its own commit (GRP-7181 'Add sync-back to the CCure provisioner', 94 sync-back tokens; the two base commits have zero). Backporting was mechanical: skip one commit, take the rest, and all six applied clean to v4 with no hand editing. Jamf wove sync-back into the base commit instead (GRP-7221, 58 sync-back tokens in 'add Jamf Pro admin-account provisioner'), so there was no commit to skip. v6 needed a modified pick that stripped 11 capture calls across JamfTargetDao and JamfApiCommands, removed setCanSyncBack(true), and deleted two dead memberNativeIds lists, then a follow-up divergence commit to record it. v4 needed the same work again.

The progress-reporting layer proved it a second time. CCure's progress reporting was a separate commit, so when it turned out to depend on assignProgressLabelTarget (an API v4 does not have, since GRP-7154 was not backported), the fix on v4 was one git revert of one file. Folded into the base commit it would have been surgery on CCureApiCommands.

Proposed layering, each its own commit: 1. base provisioner, everything in the current checklist, no sync-back and no progress labels, complete and testable on its own since this is the layer v4 and v6 get. 2. fixes and polish, one commit each, independently revertable. 3. progress reporting. 4. sync-back, last, v7 and later only.

Underlying rule: a commit should not mix code that backports with code that does not. Anything gated on a capability older branches lack (sync-back, compiled GSH, progress labels, job pause) belongs in its own commit so a backport is 'skip commit N' rather than reconstructive surgery. Cross-reference from the cherry-pick skill's 'New provisioners and external systems ARE backported' section, which currently tells you to strip sync-back by hand without noting it is avoidable at authoring time.
