# GRP-7107  SCIM provisioner diagnostics: validate the configuration against GET /ServiceProviderConfig

*Background*

SCIM provisioning diagnostics does not read the target's {{{}/ServiceProviderConfig{}}}, so the capabilities the target advertises are never checked against how the provisioner is configured. Mismatches (the target does not support PATCH while the provisioner uses PATCH for updates and memberships, the target does not support filtering while the provisioner matches by attribute, or a configured page size larger than the server's filter {{{}maxResults{}}}) are invisible until they cause failures or capped result sets at sync time.

Verified against a live CrowdStrike SCIM tenant that {{/ServiceProviderConfig}} advertises this information (patch supported, bulk not supported, sort not supported, filter supported with {{maxResults}} 100, etc.), so diagnostics can validate against it up front.

*Change*

Add a "Service provider capabilities (SCIM /ServiceProviderConfig)" section to provisioning diagnostics. It fetches {{{}/ServiceProviderConfig{}}}, reports the advertised capabilities (patch, bulk, sort, filter with maxResults, etag, changePassword), and flags:
 * {{patch.supported = false}} while the SCIM2 provisioner uses PATCH for entity updates and memberships.
 * {{filter.supported = false}} while the provisioner matches entities/groups by attribute.
 * a configured page size greater than the server's filter {{maxResults}} (list/filter requests may be capped by the server).

It reports "consistent" when nothing is flagged, and degrades to a note if the target does not expose {{{}/ServiceProviderConfig{}}}.

New pieces:
 * {{GrouperScim2ServiceProviderConfig}} - holds the parsed capabilities (a null field means the capability was not advertised).
 * {{GrouperScim2ApiCommands.retrieveScimServiceProviderConfig}} - GETs and parses {{{}/ServiceProviderConfig{}}}.
 * {{GrouperProvisioningDiagnosticsContainer.appendScimServiceProviderConfigValidation}} - the diagnostics section, wired into the run after validation.
 * Test that sets a page size larger than the mock's advertised filter maxResults and asserts the mismatch is flagged.

*Failsafe*

Best-effort and self-contained: wrapped in try/catch/finally so any failure (no {{/ServiceProviderConfig}} endpoint, unexpected payload) degrades to a single note rather than affecting the rest of the diagnostics run. All cross-check findings are warnings (not errors), so they do not fail a diagnostics run on their own.
