# GRP-7471  Builder API for the built-in app and policy group templates, and expose them to MCP and the UI AI assistant

The built-in folder templates (app template GrouperNewServiceTemplateLogic, policy group GrouperTemplatePolicyGroupLogic, and tier structure GrouperTierStructureLogic) live in grouper-ui, so they can only be run from the UI. Move them into the API behind builders like GroupSave, and offer them through MCP.

Plan:

* Move ServiceAction, ServiceActionArgument, ServiceActionType, GrouperTemplateLogicBase and the template logic classes into grouper core (e.g. edu.internet2.middleware.grouper.app.templates). Replace TextContainer.retrieveFromRequest() with GrouperTextContainer, and GroupStemTemplateContainer with a small core input bean.
* Add builders, e.g. AppTemplateSave and PolicyGroupTemplateSave: assignParentStemName, assignKey, assignFriendlyName, assignDescription, one assign per optional piece (the UI checkboxes, same defaults), save() returns what was created. save() checks privileges up front, validates the parent/child selections, and runs in one transaction (today there is none, so a failure leaves a partial structure).
* UI keeps the same screen (the action list still draws the checkboxes) and calls the builders on submit.
* MCP: list the built-ins as entries in institutional_tools next to the GSH templates (same as the UI Run template dropdown), honoring grouper.template.<key>.enabled (GRP-7376). Execute runs the builder. The confirmation summary lists every folder, group, type and rule to be created. Protected-folder and readwrite-scope checks run on the parent folder and every name to be created (like folder_save parent folders, GRP-6806).
* Tests: builder tests in core (structure, privileges, rerun, rollback), MCP tool and summary tests, manual UI regression of the template screens.
* Docs: MCP user guide institutional_tools section, template docs.

Depends on the security question in the companion Jira about steps that run as root (grouperType, inheritedPrivilege): the builder must check STEM_ADMIN on any existing folder it attaches rules or types to.
