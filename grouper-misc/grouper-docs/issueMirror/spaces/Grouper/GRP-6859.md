# GRP-6859  counts in data provider are artificially inflated

In {{{}GrouperDataProviderLogic.calculateAndStoreChanges(){}}}, the daemon log insert/update/delete counts in non-readonly mode include internal bookkeeping records that should not be counted:
 # *History record inserts* (field assign hst, row assign hst, row field assign hst) were being added to {{insertCount}} — these are internal PIT records, not actual data changes
 # *New Member row inserts* were being added to {{insertCount}} — these are Grouper infrastructure, not data provider records
 # Some delete/insert counts were using *change log entry collection sizes* instead of actual record collection sizes

This caused the non-readonly insert count to be drastically higher than the readonly count for the same data. For example, a pursual data provider full sync showed ~63K inserts in readonly mode but ~1.9M inserts in normal mode.

The fix removes the history/member counting from the loader log tallies and uses actual record collection sizes instead of change log entry sizes, making the non-readonly counts consistent with the readonly counts.
