# GRP-7110  Full sync: resolve groups from the sync-back cache instead of retrieving from the target

Adds {{{}provisioner.<configId>.fullSyncGroupsFromSyncBack{}}}, the groups analogue of the users and memberships options. When on, full sync reconstructs the target groups from {{grouper_prov_group}} (+ {{_attr}} / {{_attr_value}} / {{{}grouper_dictionary{}}}) instead of pulling them from the target.

Same cache-first model: empty group cache → normal target group retrieval (repopulates the cache); non-empty → serve from cache as the target group set, so the normal compare adds groups present in Grouper but not the cache and removes stale ones. Reconstructed groups are re-recorded as native groups so the end-of-run generic-table flush preserves their rows.

Coupling: for targets whose memberships are fetched by iterating groups (e.g. Okta), groups-from-cache uses a *both-or-neither* pairing with memberships -- {{fullSyncGroupsFromSyncBack}} only takes effect on a run where memberships are _also_ served from the cache. That way the group pull is only skipped when the per-group member iteration is skipped too, so the membership retrieval never loses its group list. (For Okta specifically the group pull is cheap, so this axis is mostly for completeness / for targets with many groups.)

Gated by DAO capability {{canRetrieveAllDataExcludingGroups}} and request flag {{{}retrieveGroups{}}}. Wired for Okta; hidden for Adobe/Duo/TrueFoundry (memberships derived from the user pull) and LDAP (batches).

Tests (Okta): warm-cache (reconstruct + skip the group pull, with the per-group iteration also skipped) and add/remove (a group in Grouper but not the cache is provisioned; one in the cache but not Grouper is deprovisioned; verified against {{{}mock_okta_group{}}}).
