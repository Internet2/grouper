# GRP-7014  LDAP/SQL groupAttributes failsafe never counts member deletes on full sync

For provisioners using {{groupAttributes}} or {{entityAttributes}} membership type (LDAP groups whose members are stored as multi-valued {{member}} attributes, SCIM-like groups with embedded members, etc.), {{GrouperProvisioningFailsafe.processFailsafesMaxGroupPercentRemove}} never sees any deletes on a full sync. {{groupUuidToMembershipDeleteCount}} is empty so the failsafe short-circuits and the provisioner ships the deletions to the target. This is the actual cause of the failsafe-not-firing report from Griffin Rogers (Internet2 list, 7.0.3).

*Root cause*
In {{{}GrouperProvisioningCompare.compareAttributeForUpdateValueMembershipOnly{}}}, the recalc branch for the membership attribute (the full-sync / recalc path) at {{GrouperProvisioningCompare.java:837-955}} iterates the target collection's deletes, runs every skip/guard check, and at line 950 calls {{addInternal_objectChange(... delete ...)}} to record the change — but it never increments {{membershipDeleteCount}} or calls {{{}countDeleteMembershipObjectCount(...){}}}. The non-recalc branch at line 573-575 does both. Result: deletes get sent to the target but the failsafe counters stay at zero.

*Fix*
In the recalc delete loop (immediately before line 950), after the {{isDeleteMembership}} guard already in place at line 938, add:


 
 
 
this.membershipDeleteCount++;
countDeleteMembershipObjectCount(
provisioningMembershipWrapper == null ? null : provisioningMembershipWrapper.getGrouperProvisioningMembership());
 
Mirroring the non-recalc branch. Same fix applies to both {{groupAttributes}} and {{entityAttributes}} modes — they share this method.

*Test*
Covered by {{LdapProvisionerFailsafeTest.testFullSyncFailsafeMaxPercentRemove}} and {{testIncrementalFailsafeMaxPercentRemove}} added under GRP-7013. Both tests currently fail on full/incremental for LDAP {{groupAttributes}} until this fix lands; with the fix they pass.

*Deployer impact*
Behavior change: any provisioner in {{groupAttributes}} or {{entityAttributes}} mode with failsafe configured ({{{}showFailsafe=true{}}} and {{{}failsafeUse=true{}}}) will now actually enforce per-group {{failsafeMaxPercentRemove}} thresholds. Sites that set thresholds but were relying on (or unaware of) the silent no-op should review their thresholds before upgrade.
