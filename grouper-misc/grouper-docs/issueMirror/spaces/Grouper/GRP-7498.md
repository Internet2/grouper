# GRP-7498  Provisioning UI does not show folder scope for do not provision, blank scope only excludes direct children

In the provisioning UI, when you set a folder to do not provision, the folder scope dropdown is hidden. The folder is saved with a blank provisioningStemScope.

The provisioning calculation (GrouperProvisioningService.calculateProvisioningAttributes) only applies a folder setting to objects deeper than the direct children when the scope is literally sub. A blank scope is treated like one (only objects directly in this folder). So a do not provision folder under a provisioned ancestor only excludes the groups directly in that folder. Groups in its subfolders keep inheriting provisioning from the ancestor and are still provisioned.

This is confusing because the provisioning settings view shows a blank scope as All objects in this folder or subfolders, but it behaves as only this folder. The workaround was to edit the provisioningStemScope attribute assignment by hand.

Fix: the folder scope dropdown now shows for do not provision as well as provision (provisioningObjectSettingsEditHelper.jsp). It defaults to all subfolders, so new do not provision settings save sub.

Also, saving provisioning settings compared the scope with blank defaulted to sub, so re-saving a blank scope folder as sub was treated as no change and nothing was written. The comparison (GrouperProvisioningService.grouperProvisioningAttributeValuesDifferent) now compares the raw scope, so re-saving in the UI or with the GSH below writes sub. The provisioning calculation is unchanged.

Upgrade instructions: existing do not provision folders saved from the UI before this fix have a blank scope and still behave as only this folder. Run this query to find them. It assumes the default provisioning folder etc:provisioning, change the attribute names if your provisioningInUi.systemFolder or grouper.rootStemForBuiltinObjects is different.

select gs.name as folder_name, gaav_target.value_string as provisioner_config_id
from grouper_stems gs
join grouper_attribute_assign gaa_marker on gaa_marker.owner_stem_id = gs.id and gaa_marker.enabled = 'T'
join grouper_attribute_def_name gadn_marker on gadn_marker.id = gaa_marker.attribute_def_name_id and gadn_marker.name = 'etc:provisioning:provisioningMarker'
join grouper_attribute_assign gaa_target on gaa_target.owner_attribute_assign_id = gaa_marker.id and gaa_target.enabled = 'T'
join grouper_attribute_def_name gadn_target on gadn_target.id = gaa_target.attribute_def_name_id and gadn_target.name = 'etc:provisioning:provisioningTarget'
join grouper_attribute_assign_value gaav_target on gaav_target.attribute_assign_id = gaa_target.id
where exists (select 1 from grouper_attribute_assign gaa, grouper_attribute_def_name gadn, grouper_attribute_assign_value gaav where gaa.owner_attribute_assign_id = gaa_marker.id and gaa.enabled = 'T' and gadn.id = gaa.attribute_def_name_id and gadn.name = 'etc:provisioning:provisioningDirectAssign' and gaav.attribute_assign_id = gaa.id and lower(gaav.value_string) = 'true')
and not exists (select 1 from grouper_attribute_assign gaa, grouper_attribute_def_name gadn, grouper_attribute_assign_value gaav where gaa.owner_attribute_assign_id = gaa_marker.id and gaa.enabled = 'T' and gadn.id = gaa.attribute_def_name_id and gadn.name = 'etc:provisioning:provisioningDoProvision' and gaav.attribute_assign_id = gaa.id and length(trim(gaav.value_string)) > 0)
and not exists (select 1 from grouper_attribute_assign gaa, grouper_attribute_def_name gadn, grouper_attribute_assign_value gaav where gaa.owner_attribute_assign_id = gaa_marker.id and gaa.enabled = 'T' and gadn.id = gaa.attribute_def_name_id and gadn.name = 'etc:provisioning:provisioningStemScope' and gaav.attribute_assign_id = gaa.id and length(trim(gaav.value_string)) > 0)
order by 2, 1;

For each folder returned, decide which scope you want. If the folder should exclude everything underneath it (usually what was intended), either open the folder provisioning settings in the UI, pick All objects in this folder or subfolders, and save, or run this in GSH (only changes the scope, keeps the other settings and metadata):

new ProvisionableStemSave().assignStemName("a:b:c").assignTargetName("myProvisioner").assignProvision(false).assignStemScope(Stem.Scope.SUB).assignReplaceAllSettings(false).save();

Then run a full sync for the provisioner so groups in those subfolders are removed from the target.
