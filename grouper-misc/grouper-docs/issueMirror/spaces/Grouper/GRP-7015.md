# GRP-7015  Incremental provisioner can send changes to target without evaluating failsafe

* The incremental provisioner sets up the failsafe bean at the top of {{provisionIncremental}} via {{{}processFailsafesAtStart{}}}, but the actual {{processFailsafes()}} evaluation only happens in one nested branch at {{GrouperProvisioningLogic.java:3688}} — inside the {{else (not isFullSync) → if (isHasIncrementalDataToProcess())}} path, after the change-log-driven {{compareTargetObjects}} call. Confirmed by the GRP-7013 incremental test ({{{}LdapProvisionerFailsafeTest.testIncrementalFailsafeMaxPercentRemove{}}}): the {{failsafe=}} debug-map summary shows {{enabled … : configured (checks not yet run)}} and the deletes get applied to LDAP with the loader log status {{{}SUCCESS{}}}.
 * Other incremental sub-paths reach {{compareTargetObjects}} / {{sendChangesToTarget}} without a matching {{{}processFailsafes(){}}}. Suspect candidates (need confirmation in code): the membership-recalc branch under {{{}convertMembershipsToRecalc{}}}, the membership-with-recalc-where-group-is-not-recalc path, and any branch where {{isHasIncrementalDataToProcess()}} is false at the outer gate but a comparison still produces deletes.
 * Net effect: an admin who configured {{showFailsafe=true}} + {{failsafeUse=true}} + aggressive thresholds can still see large incremental membership removals pushed to the target without the failsafe firing — same end-user symptom Griffin reported.
 * Fix direction: relocate {{processFailsafes()}} so it runs immediately before {{sendChangesToTarget}} on every code path (incremental and full), rather than being co-located with one specific {{compareTargetObjects}} call. Audit all {{sendChangesToTarget}} invocations in {{GrouperProvisioningLogic}} and {{{}GrouperProvisioningLogicIncremental{}}}; gate each on a preceding {{{}processFailsafes(){}}}.
 * Test: {{LdapProvisionerFailsafeTest.testIncrementalFailsafeMaxPercentRemove}} will pass once this lands — it currently documents the bug via an assertion message showing the bean-was-configured-but-checks-not-run state.
