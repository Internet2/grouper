# GRP-3509  Reports should be able to not send email when there is no data in the report.

It would be very helpful if a report could only send email when there is data in the report.

Example: Run a report every hour looking for data and only notify when there is data to review.

### Carey Black  (osu.edu) - 2021-07-09T17:31:09.408+0000

I look forward to the new feature! Thanks for the quick turnaround! 

FWIW: I was thinking about reports that would find "data only when there is something to review or do", but might often be empty results. The having the list of data is important, when there is data. However, having a "blank file and a notification to go look at a blank file" is not helpful.

Examples:
 * Groups with memberships that are going to expire in N days.(Alert Updaters of the group so that no one is surprised when users are automatically removed.)

 ** This could also be reported but not notified on too. So that managers could "look back when needed". And a second "notify" report could be triggered when the count is large enough. :)
 ** Most useful when only some of the members get expiration dates, or there are "fall off dates" that user might fall out in mass unless someone does something first.


 * PIT report of memberships removed from a group ( might rarely happen, and could be "ok/expected" at times but should be "able to be fixed" manually if needed. )
 * Report on new groups created in a folder/structure. ( Might not happen every hour/day, and might be good to keep an eye on for some apps. )
 * Report of groups with no memberships for N days ( Might be time to delete them? )
 * Report of all groups in a fold not being updated for N days ( Might be an abandoned set of groups? )
 * Report of grouper security groups with no members. ( Who is driving this app now? )

etc...
