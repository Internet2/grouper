# GRP-4419  fix welcome email disabled

Marwan Shaher (9/21)
  5:38 PM
Grouper 2.6.15.1 and Azure Provisioner:
This is a wording thing, but it also looks like the options are reversed . A provisioner is setup with the Group configuration option of "Show metadata for 'welcome email disabled'" set to true . Then created two groups and assigned the Azure provisioner to them with the group types set to "Unified group (365, mail enabled)":
GrouperCreated_Test_UnifiedGroup_0005   with 'welcome email disabled' set to true
GrouperCreated_Test_UnifiedGroup_0006   with 'welcome email disabled' set to false
Members of both groups got the welcome email.
From the incremental provisioner logs:
......... GrouperCreated_Test_UnifiedGroup_0005', id = '576051c6a214427e81009c3ceb2ba2a7', metadataJson = '{"md_grouper_welcomeEmailEnabled":true,"md_grouper_azureGroupType":"unified"}' 
........ GrouperCreated_Test_UnifiedGroup_0006', id = 'afd0138120d34e93a956c05f684bf66a', metadataJson = '{"md_grouper_welcomeEmailEnabled":false,"md_grouper_azureGroupType":"unified"}'
It looks like the md_grouper_welcomeEmailEnabled values should be reversed to match the values that were assigned to them. Or perhaps the displayed option should instead read "welcome email enabled" .
