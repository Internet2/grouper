# GRP-7453  Container image ships jackson-dataformat-cbor 2.17.2 with jackson-core 2.22.1 (container poms do not import jackson-bom)

The 7.7.0 image has jackson-core and jackson-databind 2.22.1 and jackson-annotations 2.22 in /opt/grouper/grouperWebapp/WEB-INF/lib, but jackson-dataformat-cbor-2.17.2.jar, which comes in through aws-java-sdk-core 1.12.796.

GRP-7432 manages Jackson with jackson-bom in grouper-parent, but the poms under grouper-container (grouper-api-container, grouper-uiDaemon-container, grouper-ws-container) do not inherit grouper-parent. They depend on the published grouper, grouper-ui and grouper-ws artifacts, and a dependency's own dependencyManagement does not apply to its transitive dependencies, so Maven mediates cbor to the version aws-java-sdk-core asks for.

Fix: import com.fasterxml.jackson:jackson-bom (same version as jackson.version in grouper-parent) in the dependencyManagement of the three container poms, so every Jackson module in the image is one aligned version. Verify with: docker run --rm i2incommon/grouper:<version> bash -c "ls /opt/grouper/grouperWebapp/WEB-INF/lib | grep -i jackson" (all jackson jars should be 2.22.x). No known CVE in cbor 2.17.2; this is an alignment fix, mixed Jackson module versions can fail at runtime with NoSuchMethodError.
