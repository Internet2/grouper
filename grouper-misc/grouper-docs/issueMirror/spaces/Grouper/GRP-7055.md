# GRP-7055  GcPersistableHelper reflects over JDK class fields, throwing InaccessibleObjectException on Java 17

* {{GcPersistableHelper.heirarchicalFields()}} walks a class and all its superclasses, calling {{field.setAccessible(true)}} on every declared field to map result-set columns onto object fields.
 * When invoked for a JDK scalar type (e.g. {{{}GcDbAccess.selectList(String.class){}}}, {{{}select(Long.class){}}}, {{{}select(Integer.class){}}}), it attempts to reflect over JDK-internal fields such as {{{}java.lang.String.value{}}}.
 * On Java 17+ the platform modules are strongly encapsulated, so {{setAccessible(true)}} on a {{java.base}} field throws {{java.lang.reflect.InaccessibleObjectException}} unless the JVM was started with {{{}--add-opens java.base/java.lang=ALL-UNNAMED{}}}. Grouper's Tomcat and GSH runtimes pass {{{}--add-opens{}}}, but plain-{{{}java{}}} callers embedding the grouperClient/GcDbAccess API (and direct standalone runs) do not, and crash.
 * Fix: in {{{}heirarchicalFields(){}}}, return immediately when the class is null or a JDK class ({{{}java.*{}}} / {{{}javax.*{}}}). For scalar selects the value comes from the first result column, not from field reflection, so returning no fields is the correct behavior and avoids the exception. This also cleanly stops the superclass recursion at {{{}java.lang.Object{}}}.
 * No behavior change for normal persistable beans: the recursion previously only reached {{Object}} (which has no declared fields), so existing column mapping is unaffected.
