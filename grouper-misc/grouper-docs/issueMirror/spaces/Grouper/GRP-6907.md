# GRP-6907  Batch pass-through change log temp entries for better ABAC performance

When large ABAC data loads occur (e.g. pursualTerm with 1.3M entries), the change log temp to change log daemon processes entries one at a time, taking ~7 hours at ~50 records/sec due to per-entry transaction overhead.

ABAC data entries (dataRowFieldAssign, dataRowAssign, dataFieldAssign) are pure pass-throughs — they have no per-row Java processing (no PIT updates, no cache sync, no flattening). They just get copied from the temp table to the entity table.

This change accumulates consecutive pass-through entries into a batch (default max 1000) and saves/deletes them together, dramatically reducing transaction overhead. When a non-pass-through entry is encountered (e.g. membership, group, privilege changes that need PIT processing), the batch is flushed first to maintain correct ordering.

Changes:
 * New config: changeLog.changeLogTempToChangeLog.passThroughBatchSize (default 1000, set to 1 to disable)
 * Externalized text for passThroughBatchSize and previously missing longRunning* settings
 * Added longRunning* and passThroughBatchSize to the daemon edit screen
 * Unit test with 3 scenarios: batch limit hit, interleaved pass-through/non-pass-through ordering, and batching disabled
