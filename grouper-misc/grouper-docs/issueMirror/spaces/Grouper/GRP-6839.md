# GRP-6839  Incremental provisioning IllegalStateException in filterNonRecalcActionsCapturedByRecalc when membership matches both group and entity recalc

During incremental provisioning, if a membership wrapper matches both a recalc group and a recalc entity, {{iterator.remove()}} is called twice on the same HashMap iterator position. The second call throws {{IllegalStateException}} because the element was already removed after the first call. This crashes the entire incremental provisioning run, preventing any changes from being provisioned.

The fix adds a {{continue}} after the first {{iterator.remove()}} (line 1629) so that when a membership is removed by the group-recalc check, the entity-recalc check is skipped for that entry.

This was observed in production on the {{entraId}} (Azure/Entra ID) provisioner with 1,653 changelog entries queued.
