# GRP-7226  MCP protected resource metadata names the MCP endpoint as the authorization server instead of the issuer

The OAuth 2.0 Protected Resource Metadata served at /.well-known/oauth-protected-resource listed the MCP endpoint URL in authorization_servers, so it advertised [https://server/grouper-ws/mcp|https://server/grouper-ws/mcp] while the authorization server metadata at /.well-known/oauth-authorization-server published its issuer as [https://server/grouper-ws|https://server/grouper-ws]. RFC 9728 defines authorization_servers as a list of issuer identifiers, not resource URLs.



A client builds the URL it fetches authorization server metadata from out of the authorization_servers value, and RFC 8414 section 3.3 requires it to discard that metadata unless the issuer it finds there is identical to the value it started from. A client making that check would therefore reject Grouper's authorization server metadata and be unable to complete discovery.



This did not break clients in practice, because the MCP servlet is mapped at /mcp/* and serves well-known metadata requested under that path, so a client appending the well-known path to the MCP URL still reached the metadata. The mismatch only affected clients that enforce the issuer comparison.



authorization_servers now carries the issuer identifier. The resource field is unchanged and still names the MCP endpoint, which is correct and matches the audience that access tokens are bound to.
