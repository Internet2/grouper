# GRP-7278  Upgrade Bouncy Castle to 1.85.2 for the 32 CVEs fixed in 1.85

grouper-parent pinned bouncyCastle.version at 1.84. A coordinated batch of 32 CVEs against Bouncy Castle for Java was disclosed in early August 2026 and reported in the CISA vulnerability bulletin SB26-222. Every one of them is described as affecting Bouncy Castle for Java before 1.85, so all 32 apply to the 1.84 pin. Grouper uses bcprov-jdk18on and bcpkix-jdk18on, which are the BC-JAVA artifacts these advisories cover. The separate BC-FJA (FIPS) advisories in the same bulletin do not apply, since Grouper does not use bc-fips.

Several are verification bypasses rather than availability issues, which matters more than usual for an access management product. CVE-2026-59639: CMS verifySignatures returns true for SignedData containing zero signers. CVE-2026-59638: the JSSE hostname verifier has CN fallback enabled by default despite being documented as opt-in. CVE-2026-8763: Name Constraints bypass via a trailing dot in rfc822Name and URI. CVE-2026-58062: a stapled OCSP response is accepted without being bound to the certificate being checked. CVE-2026-12860: RSA PKCS#1 verification skips the last two hash bytes in the NULL-omitted path. CVE-2026-59652: LDAP filter injection in the legacy jdk1.4 LDAPStoreHelper.

The remainder are largely unbounded allocation and denial of service issues in parsers and keystore loaders, plus several AEAD tag handling problems: CVE-2026-12185, CVE-2026-12802, CVE-2026-12803, CVE-2026-12816, CVE-2026-12817, CVE-2026-12852, CVE-2026-13506, CVE-2026-13586, CVE-2026-14682, CVE-2026-15055, CVE-2026-58059, CVE-2026-58060, CVE-2026-58061, CVE-2026-58063, CVE-2026-59640, CVE-2026-59641, CVE-2026-59642, CVE-2026-59643, CVE-2026-59644, CVE-2026-59645, CVE-2026-59646, CVE-2026-59647, CVE-2026-59648, CVE-2026-59649, CVE-2026-59650, CVE-2026-59651.

The fixes landed in 1.85. This change goes to 1.85.2, the current release, which is 1.85 plus subsequent patch fixes. One line in grouper-parent/pom.xml; the version is a managed property, so the modules that consume Bouncy Castle pick it up without further edits.

Worth noting for anyone verifying this: an OSV or GHSA query by Maven coordinate and version still reports 1.84 as clean, because these advisories are not yet mapped to the Maven package version ranges even though the individual CVE records exist. A clean package query is not evidence of no exposure here.

Applied to the 7 branch. Note the 6 branch pins the same 1.84 version and has identical exposure; that is not covered by this issue.
