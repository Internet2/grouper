# GRP-2191  if a composite is used in visualization, it should show both factors and overall (if allowed)

lets discuss this please...

## Comments

### Chad Redman  (unc.edu) - 2019-07-17T02:16:51.174+0000

The current behavior is this: only the starting node (or all the groups in a folder if starting from a folder) will walk both the parents and the children, while all the other nodes continue following the same trajectory of parents of parents and children of children. This prevents a full walk of the tree in both directions, which would basically be spidering all the objects and getting the whole database no matter where you started from. Where one of the factors gets missed is if starting from a factor or its child, the composite group will be reached as its parent, but it will only get the parents of the composite group, not the children which includes the other factor.

There is an easy approach which is a minor code change, but has larger effects on the graph. If a group is reached as a parent and happens to be a composite, treat it as a special case and gets its children too (which normally doesn't happen). This will guarantee both factors are seen. But visiting children is currently a recursive method, so it won't just get the factor, it will follow all the factor's children recursively. So it will potentially add a lot more groups to the graph besides just the one group. See the attachment for an illustration.

Is that ok? The alternative is to just follow the children of the composite to get the other factor, but not recursively. Also easy to do, just would need to add some flags to the existing methods. !Composite-follow-children-effect.png!
