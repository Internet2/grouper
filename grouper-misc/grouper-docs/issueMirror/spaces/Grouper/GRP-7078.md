# GRP-7078  Add capability-gated sync-back CRUD integration tests across all provisioners

The provisioning framework can capture target objects back into the generic provisioning mirror tables (grouper_prov_group, grouper_prov_user, grouper_prov_mship) on read ("sync-back"). Coverage was previously limited to a couple of protocols plus per-provisioner smoke tests. This adds full, SCIM-parity, capability-gated sync-back CRUD coverage for every provisioner and wires it all into one harness.

What was done:
 # New per-provisioner sync-back CRUD converge tests: insert/update/delete of groups, entities, and memberships, full and incremental, plus orphan/broken-target capture. Each test is gated on the DAO capabilities (canInsert/Update/Delete\{Group,Entity}, canInsert/Delete/ReplaceMembership) so a provisioner is only exercised for operations it actually supports (e.g. no replace-membership test where replace is unsupported, no entity-update test where update is unsupported). New coverage: azure, box, datadog, duo, freshServiceRequester, google, okta, remedyV2, teamDynamix, truefoundry, alongside the existing scim/ldap protocol tests.
 # Migrated group/entity object capture from typed beans to raw JSON for the 10 provisioners above, so nested/native payloads (e.g. JSON:API /attributes/..., per-target field names) are captured faithfully into the mirror.
 # New single harness SyncBackAllProtocolsTestHarness aggregating every sync-back test (populate + select-by-ids + the CRUD converge matrix + incremental, per provisioner), leading with the fast no-Tomcat AllProvisioningTargetNativeSyncTests pass.

Product/mock fixes uncovered by the new coverage:
 * OktaMockServiceHandler: the OAuth bearer token now emits a relative expires_in. It was emitting an absolute epoch, so the client cached the token effectively forever and then 401'd mid-suite once the mock's token row expired.
 * OktaProvisionerTestUtils: stopped unconditionally dropping the entity-CRUD keys (insertEntities/updateEntities/deleteEntities/deleteEntitiesIfGrouperDeleted) from per-test config; they are now honored when customizeEntityCrud is turned on (so a test can legitimately disable orphan deletes).
 * RemedyMockServiceHandler: getUsers/getMemberships/getGroups now honor the real Remedy q= filter (scoped per-login and per-group reads), and a latent getUser named-parameter binding was fixed.

Known target limitations (intentionally skipped, documented in-test, each a candidate follow-up):
 * Remedy retrieveGroup is served from a bulk retrieveAllGroups cache (no by-id group GET in the Remedy API), so selectAllGroups=false cannot exclude orphan groups. Datadog's scoped retrieve is list-all-then-filter with the same effect.
 * Duo updateDuoGroup gates on "desc" while the payload carries "description", so a description update is not pushed; Duo's scoped by-name retrieve has a 5-minute cache that bypasses capture.
 * TrueFoundry sync-back captures team memberships only; role memberships are not wired into the capture path.
 * Adobe group rename cannot converge because matching is by name.

Result: the full sync-back suite passes.
