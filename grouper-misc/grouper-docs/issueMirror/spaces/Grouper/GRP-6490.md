# GRP-6490  incremental loader that works on groups subjects instead of "people"

Here’s the use case.   

We have a SQL_GROUP_LIST loader.   We have a process that indicate when that group’s membership has changed.

I would rather ask the incremental loader to re-evalute the users a given group.Our other incremental loaders (and ChatGPT) suggest that I should be sending the individual members of the group through the incremental loader… but that loader is responsible for for +100K groups.   I don’t want to say “{_}liamr changed, reload all of his groups”{_}.   I want to say “{_}IAM shibboleth admins changed, please shore up the membership of{_} {*}_that one group_{*}”.This is probably associated with the JIRA card I made recently (https://todos.internet2.edu/browse/GRP-6459).

I guess the feature request would be something like {_}if the subject_source = g:gsa, re-evaluate the group membership{_}.
