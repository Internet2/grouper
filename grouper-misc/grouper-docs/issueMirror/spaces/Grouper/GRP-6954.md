# GRP-6954  Azure external system: certificate auth via v2.0 token endpoint

Adds certificate-based authentication for the Azure external system, alongside
the existing client-secret flow.

When grouper.azureConnector.<configId>.authenticationType = certificate, the
connector now:
  - posts to the v2.0 OAuth token endpoint (/oauth2/v2.0/token) instead of v1.0
  - builds a signed JWT client_assertion from the configured private key and
    certificate thumbprint
  - requests an access_token with scope = <resource>/.default

Config keys consumed (already present in grouper-loader.base.properties as
commented templates):
  - grouper.azureConnector.<configId>.authenticationType   (clientSecret | certificate)
  - grouper.azureConnector.<configId>.privateKey           (PEM, supports encrypt file ref)
  - grouper.azureConnector.<configId>.certificateThumbprint  (hex)
  - grouper.azureConnector.<configId>.clientSecret         (still used for clientSecret auth)

Validation in retrieveAdditionalSettings now branches on authenticationType so
the right required-property errors surface depending on which auth mode is
configured.

Backward compatible: connectors with no authenticationType (or
authenticationType = clientSecret) keep using the v1.0 endpoint with the
existing client_secret behavior.

Test plan:
- Configure a connector with authenticationType = certificate, valid PEM and
  thumbprint pointing at an Azure app registration that has a certificate
  credential; verify token retrieval and a Graph call succeed.
- Configure a clientSecret connector and verify no regression.
- Set authenticationType = certificate but leave privateKey blank; verify the
  external system test screen reports the expected validation error.
