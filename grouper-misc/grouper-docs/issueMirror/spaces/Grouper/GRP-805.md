# GRP-805  [psp] provisioning all group members via bulk sync takes a long time

Provisioning all members via bulk sync takes a long time, 25+ hours for a group with 25k members.

## Comments

### tzeller@example.com - 2012-06-12T17:25:46.029+0000

One fix is to add a group data connector to psp-resolver.xml which does not retrieve memberships :

  <!-- The GroupWithoutMermbershipsDataConnector returns attributes representing the group whose name is the principal name. 
    No memberships (groups or members) should be returned by this data connector to improve performance of identifier resolution. -->
  <resolver:DataConnector
    id="GroupWithoutMermbershipsDataConnector"
    xsi:type="grouper:GroupDataConnector">
    <grouper:Filter ... />
  </resolver:DataConnector>

So that resolving a group identifier (groupDn) does not query for memberships :

  <!-- The LDAP DN of a group. For example, "cn=groupExtension,ou=stem,ou=groups,dc=example,dc=edu". -->
  <resolver:AttributeDefinition
    id="groupDn" ...>
    ...
    <resolver:Dependency ref="groupNameInStem" />
  </resolver:AttributeDefinition>

  <resolver:AttributeDefinition
    id="groupNameInStem" ...>
    ...
    <resolver:Dependency ref="GroupDataConnectorWithoutMembersOrGroups" />
  </resolver:AttributeDefinition>

Because psp-resolver.xml will contain more than one group data connector, the psp will call GroupFinder.findByName() twice instead of once, which may impact performance, but which should be ameliorated by grouper caching.

The same may be done for the memberDn attribute and member data connector.
