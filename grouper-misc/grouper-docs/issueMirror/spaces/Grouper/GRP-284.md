# GRP-284  add enabled/disabled dates to memberships

Shilen and I are working to add enabled/disabled dates to memberships.  We would like to incorporate this with the re-architecting of the membership storage in the registry (for performance reasons).

This would be three columns in the memberships table: disabled_timestamp (millis since 1970), enabled_timestamp (millis since 1970), enabled (T|F).

All queries that hit the memberships table would need to incorporate checking that the enabled flag is T

There would be a loader process which checks the dates, and would enabled or disable immediate memberships based on the timestamps.

The enabling would set the flag to T, and do everything else that a group.addMember() would do (make sure the composite memberships and virtual effective memberships are available).

The disabling would set the flag to F and do everything else that a group.deleteMember() would do (delete the composite memberships and virtual effective memberships).

Queries of memberships could make sure that the enabled membership does not have a disabled timestamp (belt and suspenders), and if so, perhaps try to recalc the memberships or throw away expired memberships from the resultset.

Note: in the future, the "enabled" flag could be used for more reasons, e.g. prerequisites (approvals or trainings etc)

So here are the scenarios I think we have to deal with.  Does this seem right?

1.  addMember when membership does not exist -- Just add membership and any groupSets and composites like we do now.
2.  addMember when membership is expired -- Delete the old membership object and then add the membership and any groupSets and composites.
3.  delMember when the membership is active -- Just delete the membership and any groupSets and composites like we do now.
4.  delMember when the membership is expired -- Just delete the membership object.

5.  disableMember when the membership is active -- Just set the expired flag and delete any groupSets and composite memberships.
6.  disableMember when the membership is already expired -- Do nothing.
7.  disableMember when the membership does not exist -- Error.

8.  enableMember when the membership is already active -- Do nothing.
9.  enableMember when the membership is expired -- Just set the expired flag and add any groupSets and composite memberships.
10.  enableMember when the membership does not exist -- Error.

### mchyzer - 2009-11-09T03:16:38.079+0000

- you can assign these via GSH:

membership = group.getImmediateMembership(Group.getDefaultList(), subject, true, true);
membership.setDisabledTime(GrouperUtil.toTimestamp("2009/11/02"));
membership.update();

- there is a loader job that you can configure in the grouper-loader.properties

#quartz cron-like schedule for enabled/disabled daemon
#leave blank to disable this, the default is 12:01am, 11:01am, 3:01pm every day: 0 1 0,11,15 * * ? 
changeLog.enabledDisabled.quartz.cron = 0 1 0,11,15 * * ?

- you can run this via gsh for testing

loaderRunOneJob("MAINTENANCE__enabledDisabled");

I also added some support in the lite UI
