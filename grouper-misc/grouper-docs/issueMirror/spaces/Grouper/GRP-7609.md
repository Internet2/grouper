# GRP-7609  SCIM: Group responses do not embed members unless ws.scim.groupResponseIncludesMembers is true

SCIM Group responses (GET /Groups/{id}, the GET /Groups list, and the create and update responses) embed every member of the group, unpaged. A large group makes a large, slow response, and a list response does this for every group on the page.

Change: add ws.scim.groupResponseIncludesMembers (grouper-ws.properties, default false). When false, Group responses do not include the members attribute. When true, members are embedded as they are today.

REQUIRED BEFORE THIS SHIPS: GRP-7611 (paged GET /Users with filter groups.value eq "<groupId>") must be done first, or in the same release. Without it, turning members off leaves SCIM clients no standard way to read a group's members.

REQUIRED UPGRADE INSTRUCTION: this changes what clients get back, so the release that ships it must have an upgrade step: Group responses no longer list members by default; read a group's members with paged GET /Users?filter=groups.value eq "<groupId>" (GRP-7611), or set ws.scim.groupResponseIncludesMembers=true in grouper-ws.properties to keep the old behavior.

Also: document the setting in the base properties, add a configuration review warning when it is on, and a unit test.

Related: GRP-7610 (PATCH /Groups to add and remove members), GRP-7612 (deprecate /Memberships).
