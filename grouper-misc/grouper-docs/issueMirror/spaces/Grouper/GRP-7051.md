# GRP-7051  Standardize container log file naming (grouper.yyyy-MM-dd.log), use direct write rollover to stop blanked archives, env var for log retention age

Reported at Michigan with container logs written to the host (single JVM, single writer per file). The container log4j2.xml (container_files/grouperWebapp/WEB-INF/classes/log4j2.xml) configures each RollingFile appender with a fixed fileName plus dated filePattern and rename-based DefaultRolloverStrategy, e.g. fileName="{{/opt/grouper/logs/grouper.log}}", filePattern="{{/opt/grouper/logs/grouper.log}}.%d\{yyyy-MM-dd}", daily TimeBasedTriggeringPolicy, and a per-appender Delete after 30 days.

Problem: after the nightly rollover, something still points at the previous file and writes a line to it, and the previous day's dated file ends up empty or with only a line or two -- a full day of logs is lost. DefaultRolloverStrategy rolls by renaming the live file to the dated name, and a rename silently replaces an existing file, so any double rollover or stale RollingFileManager (second logger context from Tomcat classloaders or the log4j 1.x bridge, manager re-created across the boundary, etc.) wipes the archive. Raising log4j2 status logging (status="debug") across a midnight boundary would pin the exact trigger, but the fix below removes the failure class regardless.

Proposed changes:
 # Direct write rollover, no renames. Remove the fileName attribute and use DirectWriteRolloverStrategy so events are written straight to the dated file. A duplicate or late rollover is then harmless (worst case an extra append to the correct file).
 # Standardize the file name pattern as <base>.%d\{yyyy-MM-dd}.log -- date in the middle, .log extension preserved (better for editors, tailers, and log shippers that key off the extension). Main log: grouper.%d\{yyyy-MM-dd}.log. Recommend a grouper.<component> base for the others so one glob covers the whole directory:

 * grouper.log -> grouper.2026-06-12.log
 * grouperDaemon.log -> grouper.daemon.2026-06-12.log
 * provisioning.log -> grouper.provisioning.2026-06-12.log
 * grouper_ws.log -> grouper.ws.2026-06-12.log
 * grouper_ws_longRunning.log -> grouper.ws_longRunning.2026-06-12.log
 * catalina.out -> grouper.catalina.2026-06-12.log

 # Env var for retention age, one Delete for the whole logs dir. Replace the six per-appender Delete blocks with a single Delete (attached to the main grouper appender, which rolls daily since the root logger writes there) that cleans everything matching grouper.*.log, with the age driven by an env var (log4j2 env lookup with default, no entrypoint templating needed):



 
 
 
<RollingFile name="file_grouper_error" filePattern="/opt/grouper/logs/grouper.%d\{yyyy-MM-dd}.log">
<PatternLayout pattern="..."/>
<Policies>
<TimeBasedTriggeringPolicy interval="1"/>
</Policies>
<DirectWriteRolloverStrategy>
<Delete basePath="/opt/grouper/logs/" maxDepth="1">
<IfFileName glob="grouper.*.log" />
<IfLastModified age="P${env:GROUPER_LOG_FILE_AGE_DAYS:-30}D" />
</Delete>
</DirectWriteRolloverStrategy>
</RollingFile>
 
<RollingFile name="file_grouper_daemon" filePattern="/opt/grouper/logs/grouper.daemon.%d\{yyyy-MM-dd}.log">
<PatternLayout pattern="..."/>
<Policies>
<TimeBasedTriggeringPolicy interval="1"/>
</Policies>
<DirectWriteRolloverStrategy/>
</RollingFile>
 
(IfLastModified keeps the live dated files safe since they are modified constantly. If legacy base names are kept instead of the grouper.<component> scheme, the Delete needs an IfAny with multiple globs -- the single grouper.*.log glob is the reason to rename.)
 # Apply across all standard log files. All six file appenders are in this one config; the source-tree log4j2.xml files (grouper/conf, grouper-ui and grouper-ws webapps) are console-only and unaffected. Update the wiki/container docs that list log file names.

Migration notes:
 * The live file is now the dated one; there is no {{/opt/grouper/logs/grouper.log}}. Tail and monitoring scripts watching fixed names need updating (or maintain symlinks outside log4j).
 * Existing old-style archives (grouper.log.2026-06-11, provisioning.log.2026-06-10, catalina.out.*) do not match the new glob; either clean them up once manually or carry temporary extra delete conditions for the old patterns for one retention period.
 * New env var GROUPER_LOG_FILE_AGE_DAYS, default 30, documented with the container env vars.
