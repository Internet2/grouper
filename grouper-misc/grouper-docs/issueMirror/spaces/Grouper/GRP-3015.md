# GRP-3015  container prints env vars (which can be passwords) to logs 

Jonathan (Jj!) Johnson 10:42 AM
I see you're offline, but will leave a note anyway: this line should be removed: [ https://github.internet2.edu/docker/grouper/blob/2.5.37/container_files/usr-local-bin/librarySetupFiles.sh#L68 ]. it can disclose secrets, like it did to me last friday

## Comments

### Chris Hyzer - 2020-11-09T17:48:44.201+0000

Hello,

 

Grouper has a security vulnerability, affecting the following versions of Grouper:

 

- 2.5.36, 2.5.37

 

You are affected if you using one of these versions and have secrets in plain text in environment variables in the Grouper container.  On startup the container prints out all env vars to the logs.

 

Exploitation of this vulnerability could lead to administrators at your institution who can view container logs to be able to view passwords that were in plain text in env vars.  For full details, please see the advisory linked below.

 

https://todos.internet2.edu/browse/GRP-2705

 

Thanks to JJ from Unicon for identifying this problem.

 

These two containers (2.5.36.1 and 2.5.37.1) are identical to the previous version but have only this issue fixed.  When 2.5.38+ is out, this is fixed there too.

You could patch this file in your container:

[https://github.internet2.edu/docker/grouper/commit/5e92e18cf5e96ef99c0e21a9a92fa513ff81cd27]

Depending on where the logs are logs, or if you have secrets in env vars, you might want to change your passwords or take other remediation.

### Chris Hyzer - 2020-11-09T17:55:15.694+0000

Note, in order to change your morph string secret you need to unencrypt and re-encrypt all uses of the secret.  The Grouper team can help if needed.
