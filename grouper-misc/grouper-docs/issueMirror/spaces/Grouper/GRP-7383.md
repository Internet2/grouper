# GRP-7383   Configurable hook that blocks deletes and membership changes from MCP clients



Type: Enhancement
Component: MCP / Web Services

*Problem*
Grouper protects the etc folder and system groups from MCP changes, but that list is fixed. An admin can't protect other sensitive folders, such as payroll or ref groups, from AI clients. The only option today is to turn a tool off for the whole system. An MCP client acting as a user with admin rights can delete groups there, or empty them first by removing members.

*Proposed enhancement*
Add a Grouper config setting where admins list folders to protect from MCP. For every folder listed, and everything under it, MCP must refuse the following for all users, sysadmins included:

# deleting groups or folders
# adding or removing members, including replacing all members at once
# changing composites, eligibility requirements or provisioner removal, and overwriting an existing group
# changing attributes on those groups, folders or their memberships (e.g. loader or eligibility
settings that could remove members)

Acceptance criteria

# Each blocked action returns a clear message naming the protected folder and pointing to the Grouper
UI.
# A group moved into a protected folder is also protected under its old name if any exists
# A folder with a similar name (e.g. app:payrollX vs app:payroll) is not affected.
# Creating groups and editing a group's description or display name in a protected folder still work.
# No behavior changes when no folders are configured.
