# GRP-3506  grouperClient with -jar and grouper.client.properties is not read correctly

_(no description)_

## Comments

### Chad Redman  (unc.edu) - 2021-08-01T04:03:50.067+0000

Since grouperClient is reading from ConfigPropertiesCascadeBase, this probably stopped working at that point, since only the classpath grouper.client.properties is part of the hierarchy, not anything from the filesystem.

If it's just for setting the host and credentials, GRP-2762 added ways to inject this through environment properties:

grouper.client.base.properties
{code}
 grouperClient.webService.url.elConfig = ${elUtils.processEnvVarOrFile('GROUPER_CLIENT_WS_URL')}
grouperClient.webService.login.elConfig = ${elUtils.processEnvVarOrFile('GROUPER_CLIENT_WS_LOGIN')}
grouperClient.webService.password.elConfig = ${elUtils.processEnvVarOrFile('GROUPER_CLIENT_WS_PASSWORD')}
grouperClient.ldap.url.elConfig = ${elUtils.processEnvVarOrFile('GROUPER_CLIENT_LDAP_URL')}
grouperClient.ldap.login.elConfig = ${elUtils.processEnvVarOrFile('GROUPER_CLIENT_LDAP_LOGIN')}
grouperClient.ldap.password.elConfig = ${elUtils.processEnvVarOrFile('GROUPER_CLIENT_LDAP_PASSWORD')}
{code}

There are a few ways to get this working:

1) Set GROUPER_CLIENT_WS_* env variables per the intended base properties elConfig
2) grouperClient main() can set an override map based on filesystem ./grouper.client.properties (or have a command line property to pass in an arbitrary file to set them)
3) Set the properties in the database config, so we can get rid of a local grouper.client.properties entirely
4) Add file:./grouper.client.properties to the hierarchy. May be messy because all hosts running Grouper will be looking for this file
5) Allow setting the host, user, and passwords via command line parameters

 Solutions #1 + #3 may be the right answer, and so nothing needs to be done, and people should just not expect a local property file to work. Adding capability in #2 depends on whether anyone needs more than just setting the hosts and credentials when running from the command line. For example, if you want to connect to localhost with SSL, you need to set grouperClient.https.customSocketFactory = edu.internet2.middleware.grouperClient.ssl.EasySslSocketFactory so it doesn't do certificate checking (?). But would you ever need to do that with a custom property file, and not have a single setting in the database for it?

Has this only become an issue because of the recent Grouper training? Regarding the training, the workarounds above are not enough to fix it, because it also needs (a) to set grouperClient.https.customSocketFactory in order to allow the self-signed certificate, and (b) to have the grouper WS endpoints not protected by Shibboleth.
