# GRP-264  group delete was not in transaction, can cause loss of privileges without deleting group

right now the include/exclude hook will fail if some of the helper groups already exists, and it should absorb those groups and use them...

e.g. 

group already exists with name:
> 'test:isc:nandt:emchen:test5_source_systemOfRecord'


## Comments

### mchyzer - 2009-04-03T18:34:49.326+0000

also, the person who did the include/exclude should be an admin the groups being created...

### mchyzer - 2009-04-11T10:07:20.622+0000

The issue here was not that the group was not being reused, but rather that I believe a group delete failed, and since it wasnt using a transaction, privileges were removed before the group was deleted.  Since the group existed with no privileges, the group could not be reused, and it cause an error.  I added a transaction around group delete in 1.4 (1.5 already had this for auditing I believe), so we shouldnt get in this state again...
