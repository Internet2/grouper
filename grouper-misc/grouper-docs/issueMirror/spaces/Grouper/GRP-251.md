# GRP-251  improve organization of junit tests

There are 500+ test classes in the base package... need to organize so we can keep them under control

## Comments

### mchyzer - 2009-03-20T19:58:36.196+0000

A few strategies were done to organize the test classes:

1. When multiple test classes with few tests inside and nothing specific (nothing in setup() or no fields), then consolidate.  e.g. TestComposite0-20 when into TestComposite

2. Mirror the API's package structure where possible.  e.g. make new packages: cfg, validator, filter, etc.  Move the corresponding test classes there

3. If there are still a good number of tests in an area, make a package.  e.g. membership, group, member

4. Each package should have an AllTests suite (though named uniquely, e.g. AllMembershipTests).  This is used by eclipse (when right clicking) to auto generate the lists of test classes inside (though dont add the suite itself)

5.  All the old suites where removed (e.g. integrationSuite, etc)

6. In order to take advantage of Eclipse's auto add feature, SuiteDefault was renamed to AllTests.  This is a junit standard anyways, so it will make it easy to find for new people. (changed in gsh, build.xml, etc)

7. Some tests had non standard names, so I renamed so it follows the general grouper convention e.g. TestGroup or TestMembership for a test class
