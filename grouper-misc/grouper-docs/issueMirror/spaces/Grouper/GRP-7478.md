# GRP-7478  MCP GSH templates: mcpReadonlyWhen setting so calls which change nothing run without approval in the UI AI assistant

h2. Problem

A GSH template exposed to MCP is either readonly for MCP ({{mcpReadonly}}) or not. A template which is not readonly is treated as a change on *every* call, whatever its inputs say. In the AI assistant in the Grouper UI that means every run waits for the user to approve it, even a call which only looks something up.

Many templates do both. For example, a template might have a {{get}} action, and make its {{create}}, {{update}} and {{delete}} two step, where a call without {{confirm=true}} only returns a plan. With such a template, creating one group took at least four approvals plus a typed "go ahead":

* the {{get}} (a read)
* the plan (changes nothing)
* probably a second plan
* the confirm

h2. Changes

h3. New template setting: {{mcpReadonlyWhen}}

* {{grouperGshTemplate.<id>.mcpReadonlyWhen}} is a comma separated list of {{input=value}} pairs, e.g. {{gsh_input_action=get, gsh_input_confirm=false}}
* A call matching *any one* pair is classified as a read:
** the UI assistant runs it without an approval box
** over MCP it counts against the readonly throttle and is logged as readonly
* It does *not* change who can run the template: {{executeTemplate}} still requires MCP readwrite (group and session or OAuth scope) for any template which is not {{mcpReadonly}}
* Matching compares what the template will actually receive:
** input names with or without the {{gsh_input_}} prefix
** a blank or missing value takes the input's default (a required input has none)
** both sides converted with the input's {{convertToType}}, so a boolean {{false}} also matches {{f}} or {{no}}
** strings match exactly, with no trimming
* Anything ambiguous counts as a write: an unknown input, a file input, a value which does not convert, an input given twice (with and without the prefix), or config which cannot be read
* A template without the setting behaves exactly as before
* Documented in {{grouper.base.properties}} and the GSH template wizard text, including the author's promise: a listed value must never change anything, and the template's decorate code must not change the default, type or required setting of a listed input

h3. Clearer refusal when only the scope is missing

When a readwrite template is refused only because the session's or OAuth client's scope leaves out readwrite, for a user who is in the readwrite group, the message now says it is the scope, and that the user can widen it and ask again. Before, it said the user needed readwrite access.

h3. UI assistant system prompt

One sentence added: when a tool result says to show the user a plan and get their agreement before a change, show the plan and then ask for the change straight away. The approval box is that agreement, so the user is not asked twice.
