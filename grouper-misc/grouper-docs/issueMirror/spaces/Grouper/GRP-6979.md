# GRP-6979  Map-keyed canonical native-target capture store with sync-back-read mark/clear scaffolding

* Replace the three native-target capture lists on {{GrouperProvisioningData}} with {{{}LinkedHashMap{}}}s keyed by {{targetId}} / {{MultiKey(targetGroupId, targetUserId)}} so duplicate captures resolve last-write-wins instead of accumulating, and so write-shadowing can index. Public list getters return snapshots via {{{}GrouperUtil.listFromCollection{}}}.
 * Rewrite {{recordTargetNativeUser}} / {{recordTargetNativeGroup}} / {{recordTargetNativeMemberships}} on {{GrouperProvisioningTargetNativeSync}} to {{map.put}} instead of {{{}list.add{}}}.
 * Add {{syncBackUserNativeIdsToRead}} / {{syncBackGroupNativeIdsToRead}} {{{}LinkedHashSet{}}}s on {{GrouperProvisioningData}} plus four scaffolding methods ({{{}markSyncBackUserForRead{}}}, {{{}markSyncBackGroupForRead{}}}, {{{}clearSyncBackUserForRead{}}}, {{{}clearSyncBackGroupForRead{}}}) on the sync class. Mark is gated on the corresponding load behavior flag; clear is unconditional. {{record*}} clears the matching id automatically.
 * Drop redundant native-target maps and {{buildNativeIndexes}} from {{GrouperProvisioningDataIndex}} (no external callers; canonical maps live on {{{}Data{}}}).
 * Comment out the two SCIM {{createScimUser}} / {{createScimGroup}} POST-response capture calls in {{GrouperScim2ApiCommands}} with TODO referring to the future write-shadow precision pass (the end-of-run flush currently runs before create phases, so a capture there would land in an already-flushed map).
