### bert - 2017-03-28T14:22:00.827+0000

I've just written a [wiki page about pspng full-sync|https://spaces.internet2.edu/display/Grouper/PSPNG+and+Full+Syncs]. 

The useful part is that the Full Sync class/schedule is only queuing the groups to be reconciled as well as an optional clean-up-extra-groups message. Once everything is queued, the Full Sync quartz operation completes, and the initiated reconciliations occur asynchronously. 

So... I would expect that the easiest way to get accurate status information is for the Full-Sync initiator to monitor the full-sync queues into which it dropped a bunch of commands.

Does this make sense from the point of view of quartz, the loader and the status page?

### bert - 2017-03-28T14:34:32.280+0000

I think the most information will come from adding information to the messages (FullSyncQueueItem class) that the full-sync thread updates when processing is started and finished. Filling-in inserts/updates/deletes/totalCountOfMemberships fits into this model as well.

Then, the Full-Sync quartz-run method can hold onto those FullSyncQueueItem objects and tally them up periodically to provide a progress bar as well as, of course, decide when they're all done.

This is a pretty quick fix. I'll update this ticket this before Friday with an update.
