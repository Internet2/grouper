# GRP-7098  Entity "data field assignments" page misrenders sparse columns for subjects with multiple data rows

*Affected:* Grouper 7.2.1, entity "data field assignments" screen (subject view). Display-only; stored data and JEXL evaluation are correct.

*Symptom.* For a subject with multiple rows in the same data row, a field that is null on one row and populated on another is rendered against the wrong row. Fully-populated columns (a value on every row) line up correctly; only sparse columns are displaced. A column that is null across all of the subject's rows is dropped from the table entirely.

*Example.* A subject has two {{person_role}} rows: a staff affiliation with no {{{}title{}}}, and a student affiliation with {{title}} set. The page shows the {{title}} on the staff row and {{-}} on the student row, reversed from what is stored.

*Verified display-only.*
 * Querying {{grouper_data_row_field_asgn_v}} (and {{grouper_data_row_field_assign}} / {{{}grouper_data_row_assign{}}}) shows the {{title}} assignment tied to the same {{data_row_assign_internal_id}} as the student role's value, i.e. stored on the student row.
 * Two mirror-image scripted ABAC groups confirm evaluation agrees with storage:



 
 
entity.hasRow('person_role', "role=='<STUDENT_CODE>' && title=='<TITLE>'")
entity.hasRow('person_role', "role=='<STAFF_CODE>' && title=='<TITLE>'")
 
The subject lands in the student group and not the staff group. Stored data and JEXL agree; only the page is wrong.

*Root cause.* {{UiV2Subject.viewDataFieldConfigs}} built a {{{}Map<dataRowConfigId, Map<dataFieldConfigId, List<String>>>{}}}, flattening each field's values into a position-indexed list and discarding {{{}data_row_assign_internal_id{}}}. A field only gets a list entry when it has a value on a row, so a null on an earlier row makes that field's list shorter and shifts later values up. {{subjectViewDataFieldConfigContents.jsp}} then rebuilt rows by walking {{rowIndex}} from 0 to the longest list and reading {{{}entry.value[rowIndex]{}}}, which assumes every field's Nth element belongs to the same logical row - only true when every field is fully populated. All-null fields never became a map key, so their column was dropped.

*Fix.* Preserve row identity end to end:
 * {{GrouperDataRowAssignView}} carries {{{}dataRowAssignInternalId{}}}; the DAO query selects {{{}gdrav.data_row_assign_internal_id{}}}.
 * {{UiV2Subject}} groups values into one map per physical row (keyed by internal id), with a separate ordered column list, exposed via a new {{GuiSubjectDataRowConfig}} bean.
 * The JSP iterates real rows and looks up each cell by field id ({{{}row[fieldConfigId]{}}}), rendering {{-}} when a row has no value for that field. No positional reconstruction remains, so a null in one row can no longer push a value into another.

*Known remaining gap (separate/minor).* A field that is null across every one of the subject's rows still won't render a column, since there is no stored assignment to drive the header. Could be addressed later by sourcing columns from the data row config's field list rather than from the assignments present.
