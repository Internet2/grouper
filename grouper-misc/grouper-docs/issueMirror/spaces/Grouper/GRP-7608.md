# GRP-7608  Discuss and decide: access settings that allow everyone when blank (ws.client.user.group.name and others)

Discuss and decide (do later): several settings that decide who may use a powerful feature mean everyone when left blank, and blank is the shipped default.

Settings (blank today means):
- ws.client.user.group.name (grouper-ws.properties): any authenticated subject can call the web services.
- rules.restrictRulesUiToMembersOfThisGroupName (grouper.properties): any group or folder admin can use the rules UI.
- grouper.abac.edit.if.in.group (grouper.properties): any group admin can edit scripted (ABAC) groups, which the daemon evaluates as root.
- grouper.recentMemberships.edit.if.in.group (grouper.properties): same for recent-memberships loaders.
- externalSubjects.groupAllowedForEdit (grouper.properties) and require.group.for.inviteExternalSubjects.logins (grouper-ui.properties): anyone can edit or invite external subjects where external subjects are on.
- grouper.selfService.jwt.groupNameAllowedToManage (grouper.properties): anyone can manage self-service JWT keys (check the exact blank behavior in the code).
Also check the other base properties files for the same pattern (descriptions that say if blank, anyone / all).
Probably leave as is: require.group.for.logins and require.group.for.membershipUpdateLite.logins (open UI login is intended; privileges still apply), but say so in the docs.

Proposed design to discuss:
1. Blank means wheel and root only. Allowing everyone takes an explicit value (a documented keyword or the EveryEntity group), so wide open is a visible choice.
2. Ship a real default group where it fits (for example etc:webServiceClientUsers), created by GrouperCheckConfig like the wheel group.
3. Configuration review warning when a setting is explicitly set to everyone; startup WARN listing settings whose meaning changed.
4. Upgrade: either (a) an upgrade task writes the explicit everyone value for sites upgrading with the setting blank, so behavior is unchanged and the choice is visible, or (b) a hard break with an upgrade instructions row. Recommendation: (a).

Questions to decide:
- Which of these settings to change (the rules one is already partly covered: send-email expressions and EL rules are sysadmin only).
- What everyone looks like: keyword or the EveryEntity group.
- Upgrade path: (a) or (b).

Done when: the design is agreed, the defaults are changed with the review warning and upgrade handling, docs and upgrade rows are written, and tests cover blank (wheel only), a group, and the explicit everyone value.
