# GRP-7293  Box provisioner group update silently drops attributes whose grouper and box spellings differ

GrouperBoxTargetDao.updateGroup builds its field-name set from ProvisioningObjectChange.getAttributeName(), which yields the GROUPER side attribute names, i.e. the names configured in targetGroupAttribute.N.name. It passes that set to GrouperBoxApiCommands.updateBoxGroup, which passes it on to GrouperBoxGroup.toJson(fieldNamesToSet).

toJson tested the BOX json spellings instead: external_sync_identifier, invitability_level, member_viewability_level. So contains() returned false for every one of them and those keys were omitted from the PUT body entirely. Box receives an update with nothing to change, answers 200, and grouper then marks the group provisioned and counts an update. The failure is completely silent and repeats on every sync.

Only attributes whose two spellings differ are affected. description, id, name and provenance are spelled identically in both schemes, which is why this has gone unnoticed: those were the only group attributes most sites had configured.

Insert is not affected, because createBoxGroup calls toJson(null) and therefore sends every field.

GrouperBoxUser.toJson already tests the grouper spellings (isExemptFromDeviceLimits, canSeeManagedUsers, maxUploadSize, spaceAmount), so the group bean was the lone outlier. The config UI reinforces the grouper spelling as the correct one: the dropdown for targetGroupAttribute.N.name offers only invitabilityLevel and memberViewabilityLevel, so an operator cannot configure the box spelling even deliberately.

Suggested fix: change the three contains() checks in GrouperBoxGroup.toJson to the grouper names (externalSyncIdentifier, invitabilityLevel, memberViewabilityLevel). The emitted json keys stay as the box spellings, so nothing on the wire changes. That makes the group bean consistent with the user bean and requires no config change from any site.

Observed at Penn on Grouper v7. We configured invitabilityLevel and memberViewabilityLevel as target group attributes with select, insert and update enabled, in order to manage box group invitability from grouper. The full sync reported groupUpdatesAfterCompare of 4 and an update count of 4 for three consecutive days while box retained the old values throughout, which the box enterprise admin confirmed independently from the box console. After correcting toJson the PUT body carries the fields as expected.
