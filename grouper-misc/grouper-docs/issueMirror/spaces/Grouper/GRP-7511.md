# GRP-7511  OIDC external system: support certificate (private_key_jwt) client authentication instead of client secret

The OIDC external system (grouper.oidcExternalSystem.<configId>.*, used for UI/WS OIDC login) only supports a client secret. GrouperOidc requires clientSecret and always authenticates to the token endpoint with ClientSecretBasic. There is no way to use a certificate (private_key_jwt client authentication, OIDC Core section 9 / RFC 7523), which Microsoft Entra app registrations support in place of a client secret.

The Azure/Entra external system already has authenticationType = clientSecret or certificate (signed JWT client_assertion), and WsBearerTokenExternalSystem also builds a client_assertion, but neither applies to OIDC user login.

Proposed: add an authentication type option (client secret or certificate) to the OIDC external system, with private key / certificate / key id fields, and use the Nimbus PrivateKeyJWT client authentication in GrouperOidc when certificate is selected. Reuse the existing JWT signing code from the Azure / WsBearerToken external systems. Make clientSecret not required when certificate is selected. Add externalized text for the new wizard fields, and tests.
