# GRP-7160  UI: development only form based login option (grouper.is.ui.formAuthn)

Adds a form based login option for the Grouper UI as a development convenience: it shows an HTML login form instead of the native HTTP BASIC popup, which automated or headless browsers cannot drive.

It is gated and both conditions must hold:

* config: grouper.is.ui.formAuthn = true (in grouper.hibernate.properties), and it only takes effect when grouper.is.ui.basicAuthn is false
* environment: not production; it is ignored (and a warning is logged) when grouper.env.name is blank, prod, or production

Credentials are checked by the same Authentication path as BASIC auth, so the grouperPasswordConfigOverride_UI_<user>_pass entries and the grouper_password table are what accept a login.

It is wired dynamically inside GrouperUiFilter (which is registered programmatically in CommonServletContainerInitializer), not via a web.xml login-config, since the Servlet API does not allow setting an auth-method at runtime. The login form posts back to the same URL with the username and password, and on success the user flows through via request.getRemoteUser() exactly like BASIC auth.

Do not enable in production. This is intended for local development and automated UI testing only.
