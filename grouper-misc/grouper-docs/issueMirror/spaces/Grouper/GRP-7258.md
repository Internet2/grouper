# GRP-7258  Upgrade PostgreSQL JDBC driver to 42.7.13 for security

Bump the PostgreSQL JDBC driver from 42.7.11 to 42.7.13 in grouper-parent/pom.xml.

This addresses CVE-2026-54291 / GHSA-j92g-9f8w-j867 (high, CVSS:4.0/AV:N/AC:H/AT:P/PR:N/UI:N/VC:N/VI:H/VA:N/SC:N/SI:L/SA:N), which affects pgjdbc 42.7.4 through 42.7.11 and is fixed in 42.7.12. Under channelBinding=require, the driver could silently downgrade from SCRAM-SHA-256-PLUS with channel binding to plain SCRAM-SHA-256 without it, when the server presented a certificate whose signature algorithm has no tls-server-end-point channel-binding hash, for example Ed25519, Ed448 or post-quantum algorithms. An attacker able to intercept the TLS connection could use that to strip the man-in-the-middle protection channel binding is meant to provide. Two things combined: the bundled scram-client returned an empty byte array instead of failing when it could not derive the binding hash, and pgjdbc itself only checked that the server advertised a -PLUS mechanism, never that the negotiated mechanism actually used channel binding. 42.7.12 enforces the policy in pgjdbc's own code, independently of the scram-client version. There is no configuration workaround on an affected release.

Grouper does not set channelBinding anywhere in its configuration, so the default prefer policy applies and Grouper is not believed to be exposed, but the dependency still scans as vulnerable and should be current.

Going to 42.7.13 rather than stopping at 42.7.12 also picks up a sizeable set of fixes, notably several XA correctness fixes (autoCommit no longer saved and restored around XA protocol SQL, which fixes the second-phase-commit-must-be-issued-using-an-idle-connection failure on pooled datasources; prepare() no longer mutates XA state on a failed PREPARE TRANSACTION), the driver no longer nulling the contextClassLoader of shared ForkJoinPool common pool worker threads, prepared-statement cache invalidation after DDL and after a reported search_path change, a spin-forever case removed from the Statement cancel state machine, and PKIX trust anchors built without a KeyStore so FIPS JVMs work.

One packaging change is worth calling out. 42.7.11 and 42.7.12 declare no dependencies at all; 42.7.13 newly declares two runtime dependencies, org.checkerframework:checker-qual and com.github.waffle:waffle-jna. checker-qual is annotations only and harmless. waffle-jna only supports Windows SSPI authentication, which Grouper does not use, and it transitively brings jna, jna-platform, caffeine and jcl-over-slf4j. jcl-over-slf4j would put a second org.apache.commons.logging.LogFactory on a classpath that already ships the real commons-logging 1.3.5, which is a classic split-brain logging break. waffle-jna is therefore excluded in the dependencyManagement entry, which keeps the runtime classpath identical to what 42.7.11 produced.

Other behavior defaults that changed in 42.7.13 and are worth knowing about if anything looks different: flushCacheOnDdl defaults to true, so the prepared-statement cache is invalidated after CREATE/DROP/ALTER; reWriteBatchedInserts now merges up to 32768 rows into one multi-values INSERT instead of capping at 128, tunable via the new reWriteBatchedInsertsSize property; and classLoaderStrategy defaults to driver-first, which now falls back to the thread context classloader when the driver classloader cannot resolve a class named by a connection property.
