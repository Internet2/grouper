# GRP-434  UI paging when browsing hierarchy does not work properly

At one time a complete list of all stems and groups was retrieved and paging carried out on the entire result set. At some point paging was added to the API to increase efficiency by only instantiating objects that are required for display, however, it does not allow for an offset which takes account of any stems. 

## Comments

### Gary Brown - 2010-05-14T09:01:34.110+0000

I think this was probably broken since 1.4. Not sure paging was ever set to return an incrementing page number.

I've added an algorithm to work out the smallest page size and appropriate page number where a single page can retrieve all the required results, taking into account the offset due to any stems. Typically such a page size returns unwanted results so these need to be discarded. In addition, the UI may discards results depending on the browse mode and user permissions. I updated the code to reduce the result size when results are discarded. 

I think there is still some potential for issues due to discarding of results
