# GRP-7199  ABAC data field example snippet always uses field=='value'; make it data-type aware (timestamp, integer, boolean)

In the data fields UI (entity/data fields listing), the auto-generated example JEXL snippet shown for each ABAC data field is hardcoded to a field-equals-'value' pattern -- entity.hasRow(rowAlias, predicate) where the predicate is fieldAlias=='value' -- regardless of the field data type. Source: grouper-ui UiV2EntityDataFields.java, setJexlSnippet, around line 2713.

For a date/time (timestamp) field this default is misleading: timestamps are compared with the timeFromNow(...) helper and with hasAttributeBetween(...) ranges, not string equality. A graduation_date field, for example, renders as graduation_date=='value', which is not valid usage. Integer fields likewise should not use a quoted 'value' (a number is expected), and boolean fields are truthy so they need no comparison at all.

Suggestion: make the fallback snippet data-type aware using the field data type (GrouperDataFieldType). string -> fieldAlias == 'value'; integer -> fieldAlias == 0; boolean -> bare fieldAlias (truthy); timestamp -> fieldAlias < timeFromNow('2 months'). The per-field zeroToManyExamplesHtml already supplies rich, correct examples; this change only affects the generic fallback snippet.
