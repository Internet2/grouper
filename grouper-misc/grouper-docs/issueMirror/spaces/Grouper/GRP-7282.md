# GRP-7282  v4/v6 only: TargetDaoRetrieveAllDataRequest needs read-only isRetrieveEntities/Memberships/Groups so target DAOs backported from v7 compile unchanged

On v7 a target DAO can be told to skip part of the target read in the retrieve-all pass, via isRetrieveEntities / isRetrieveMemberships / isRetrieveGroups on TargetDaoRetrieveAllDataRequest. v6 has no such path, so those methods do not exist there.

Every target DAO written on v7 guards on them. When one is backported to v6 it fails to compile, and the guard has to be unwrapped by hand each time - which is easy to miss, since the method names do not look like the feature they belong to. This already happened backporting the Jamf provisioner for 6.4.0.

Fix on v6: add the three accessors as read-only methods that always return true, matching v6 behaviour of always retrieving everything. Deliberately no setters - code that tries to turn a retrieval off should fail to compile rather than silently do nothing, because that code does not belong on v6. Backported DAOs then keep their guards unchanged and differ from v7 only by deletions.

v6 only. v7 already has these, backed by real fields.
