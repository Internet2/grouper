# GRP-7466  Duo sync-back blanks user details for members of managed groups

The Duo provisioner sync-back (GRP-7384) captured users from the group members call GET /groups/{id}/users. That call only returns user_id and username per member, not the full user, and it runs after the full user read in the same cycle. So for members of managed groups, the full record was replaced with blanks: no status, email, is_enrolled, last_login, and zero phone/token/webauthn counts.

Fix: do not capture users for sync-back from the group members call; the full record comes from the user reads (retrieveDuoUsers, retrieveDuoUser, retrieveDuoUserByName). The Duo mock now returns only user_id and username from /groups/{id}/users, matching real Duo, so callers cannot accidentally depend on a full user there.
