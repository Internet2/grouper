# GRP-7047  Provisioning sync back: bulk re-retrieve changed groups and entities from target to keep the mirror current after writes

Make the provisioning sync-back ("mirror") tables (grouper_prov_group and
grouper_prov_user plus their attribute tables) a trustworthy local copy of the
target after the write phase, so a later full sync can trust the mirror instead
of always re-retrieving everything from the target.

Scope of this ticket: group and entity (user) objects only -- insert, update,
and delete:

- Capture-on-write: when a create or update returns the resource
  representation, register it like a read so the end-of-run drain skips
  re-reading it.
- Drain re-read: any target id that was written but whose representation was
  not returned is collected and bulk re-read at the end of the run (covers
  inserts, updates, and no-body / PUT-style updates).
- Deletes verify rather than assume: after a delete, re-read to confirm the
  object is actually gone before dropping it from the mirror. A broken target
  that acks a DELETE but keeps the row (or soft-deletes) keeps its mirror row.
- The full-sync mirror flush is moved to the end of provisionFull (matching
  incremental) so write-phase changes are reflected.
- Thread-safety: the native id-to-object maps are synchronized (parallel
  capture threads during retrieve).

Out of scope, tracked separately: keeping memberships current. Memberships are
still rebuilt from the read-phase snapshot and only drop via the
missing-endpoint cascade (when a group or user record disappears); a standalone
membership change on a surviving group is not yet captured or re-read.

Tests: ScimProvisionerGenericTableTest -- create/update/delete convergence,
update with body-returned vs 204 no-body, and broken-target-delete-stays.
