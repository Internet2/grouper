# GRP-7217  MCP server should return caching hints on cacheable results

MCP spec revision 2026-07-28 requires servers to include ttlMs and cacheScope on results with resultType: "complete" returned by server/discover, tools/list, prompts/list, resources/list, resources/templates/list, and resources/read. Grouper implements the first two of those and returned neither field, so clients had no freshness hint and defaulted to treating every response as immediately stale.



tools/list returns cacheScope: "private" and ttlMs of 60 seconds. Private is required because the tool list is filtered by what the caller is authorized for, so a shared cache must not serve one user's list to another. The 60 seconds matches the existing server-side cache of MCP group memberships, since a shorter client TTL could not make a membership change take effect any sooner.

server/discover returns cacheScope: "public" and ttlMs of one hour. Its content — supported versions, capabilities, server identity, and the configured instructions — is the same for every caller and changes only on upgrade or reconfiguration.

Note these are caching hints only and are not what enforces authorization; tools/call re-checks access on every invocation, which the spec explicitly requires servers not to rely on cacheScope for.
