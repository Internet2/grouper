# GRP-7288  v7 container quickstart sets GROUPER_AUTO_DDL_UPTOVERSION to v6.*.*, so v7 DDL is never applied

grouper_container_v7 container_files/usr-local-bin/libraryPrep.sh, prep_quickstart, sets GROUPER_AUTO_DDL_UPTOVERSION='v6.*.*' when the variable is unset. This is a leftover from when the v7 container was forked from v6; the v4 and v6 containers correctly set v4.*.* and v6.*.* respectively.

That env var feeds registry.auto.ddl.upToVersion (grouper.hibernate.base.properties line 157). GrouperDdlUtils.autoDdlFor expands a trailing .*.* to .9999.9999 and returns autoDdlUpToVersion.greaterOrEqualToArg(grouperVersion). GrouperVersion's regex is ^[vV]?(\d+)[._](\d+)[._](\d+)$, so the v prefix parses fine and the value becomes 6.9999.9999. For any v7 DDL version the comparison is 6.9999.9999 >= 7.x.x, which is false, so v7 DDL changes are skipped.

Effect: anyone running the v7 container quickstart without explicitly setting GROUPER_AUTO_DDL_UPTOVERSION gets a database built only to v6 level, with no error that names the cause. Because the value is only applied when unset, every quickstart that follows the published compose file is affected.

Fix: change the default in prep_quickstart to v7.*.* in grouper_container_v7.
