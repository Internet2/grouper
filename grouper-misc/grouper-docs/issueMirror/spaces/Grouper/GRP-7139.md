# GRP-7139  false positive on loader not deleting a group via like string

Skipped 1 group(s) matching the groups like pattern that do not have loader metadata for this loader.

Add some unit tests to make sure all the various cases work to delete or skip or report.

A SQL {{GROUP_LIST}} loader with a {{grouperLoaderGroupsLike}} string only deletes groups that carry _this loader's_ metadata ({{{}grouperLoaderMetadataGroupId{}}} = the loader's group + {{{}grouperLoaderMetadataLoaded=true{}}}). Groups whose name matches the like pattern but that this loader never created are *skipped* (protected from deletion) and logged. This is the GRP-7073 behavior; there is currently *no unit test* covering it (GRP-7073 and GRP-7074 each touched 0 test files).

*Environment*

Postgres backend. Only the 4 built-in test subjects exist ({{{}test.subject.0{}}}–{{{}3{}}}, source {{{}jdbc{}}}).

*Setup* — on a group holding the loader config (e.g. {{{}test:testGroup2{}}}), set:
 * {{grouperLoaderType}} = {{SQL_GROUP_LIST}}
 * {{grouperLoaderDbName}} = {{grouper}}
 * {{grouperLoaderGroupsLike}} = {{test:loaderSmoke:%}}
 * {{grouperLoaderQuery}} (membership):



 
 
select 'test:loaderSmoke:grp1' as GROUP_NAME, subject_id as SUBJECT_ID, subject_source as SUBJECT_SOURCE_ID
from grouper_members where subject_source = 'jdbc'
  * {{{}grouperLoaderGroupQuery{}}}:



 
select 'test:loaderSmoke:grp1' as GROUP_NAME union all select 'test:loaderSmoke:grp2' as GROUP_NAME
 
*Steps*
 # Run once → {{grp1}} and {{grp2}} created and stamped with this loader's metadata.
 # Hand-create an unmanaged group {{test:loaderSmoke:manual}} (matches the pattern, no loader metadata).
 # Drop {{grp2}} from both queries, run again.

*Expected*
 * {{grp2}} deleted (loader-owned, removed from source) — after membership sync (GRP-7090 ordering).
 * {{test:loaderSmoke:manual}} survives; job log: {{Skipped 1 group(s) matching the groups like pattern that do not have loader metadata for this loader.}}

*Actual* — {_}(fill in what you saw){_}.

*Verification SQL* — inspect which groups carry this loader's metadata:
 
 
 
 
select g.name, cn.name as meta_key, cv.value_string as meta_value
from grouper_groups g
join grouper_attribute_assign ma on ma.owner_group_id = g.id
join grouper_attribute_def_name mn on ma.attribute_def_name_id = mn.id
and mn.name = 'etc:attribute:loaderMetadata:loaderMetadata'
join grouper_attribute_assign ca on ca.owner_attribute_assign_id = ma.id
join grouper_attribute_def_name cn on ca.attribute_def_name_id = cn.id
left join grouper_attribute_assign_value cv on cv.attribute_assign_id = ca.id
where g.name like 'test:loaderSmoke:%'
order by g.name, cn.name;
 
{{grouperLoaderMetadataGroupId}} = the loader's own group id; that's the key GRP-7073 matches on.
