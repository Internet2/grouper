# GRP-5504  GSH export should export the state of loaders and enabled on import if enabled in source

Ray Walker
  1 day ago
In searching through documentation and this Slack channel to find methods to script/automate grouper from environment to environment I’ve run across the usage of Grouper Export to GSH for loader based groups:
https://spaces.at.internet2.edu/display/Grouper/Grouper+export+to+a+GSH+script
When importing/running those on another environment, all works (as long as all the associated stuffs are also there,) loader job created, but the loader job isn’t enabled or initialized (first run?) Analyzing the GSH shows nothing that would indicate such either.
Is there a way to accomplish this with GSH, or other automated fashion (non UI)…?
Side note: I do see references to future API stuffs here (Attribute name “Schedule job”) : https://spaces.at.internet2.edu/display/Grouper/Grouper+-+Loader+GSH

i guess we need to export the enabled state of the job and set that on import?  its not trivial, you need to get a schedule
Scheduler scheduler = GrouperLoader.schedulerFactory().getScheduler();
Then you need to get a job key (could get the DB or construct)
String jobKey = grouperLoaderType.name() + "__" + group.getName() + "__" + group.getUuid()
Then schedule
      JobKey jobKey = new JobKey(jobKey);
      scheduler.resumeJob(jobKey);
