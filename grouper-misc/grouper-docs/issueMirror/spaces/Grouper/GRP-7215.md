# GRP-7215  MCP server should implement server/discover

MCP spec revision 2026-07-28 removed the initialize handshake, so a client on that revision has no way to learn which protocol versions a server speaks. That revision requires servers to implement server/discover, which returns supported versions, capabilities, and server identity. Grouper returned -32601 Method not found, leaving such a client to guess whether the server was broken, legacy, or something else — the spec's own compatibility matrix describes this case as failing ambiguously.



server/discover is now answered, returning resultType, supportedVersions, capabilities, instructions, and serverInfo under _meta per the DiscoverResult schema. It advertises 2025-03-26 only, since that is what the server actually implements — the point is to give a definite answer a dual-era client can act on, not to claim conformance to the newer revision. Clients on 2025-03-26 are unaffected, as they never call this method.

ttlMs and cacheScope are omitted; they belong to the separate caching utility and should be added with the rest of CacheableResult.
