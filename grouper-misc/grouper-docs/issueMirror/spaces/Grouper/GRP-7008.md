# GRP-7008  CLAUDE.md — document Grouper Java style rule against streams and lambdas

* Add a "Java language constructs" section to {{CLAUDE.md}} under Development Guidelines
 * Rule: avoid Java streams ({{{}.stream().map().filter().collect(...){}}}), lambda expressions used as functional arguments, {{{}Optional{}}}, {{{}Collectors{}}}, and method references in new code
 * Allowed: anonymous inner classes (long-established IDE/debugger support, straightforward to read)
 * Rationale: weak stack traces, awkward breakpoint behavior, less familiar to long-time Grouper developers; explicit {{for}} loops and conditionals are the house style
 * Includes opportunistic-conversion clause: existing stream code may be converted when touched for unrelated reasons, but sweeping removal is not a goal
