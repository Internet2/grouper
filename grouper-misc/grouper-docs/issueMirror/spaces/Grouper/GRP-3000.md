Actually, I saw this on the PIT audit filter for group memberships. So the formatting is in multiple places

### Chad Redman  (unc.edu) - 2020-10-22T19:01:49.827+0000

There is no global setting for date formats – each page can choose its own. Some pages that use yyyy/MM/dd kk:mm or yyyy/MM/dd kk:mm aa (kk is the hour from 1-24).
 * status servlet
 * PIT membership view
 * audit entries

 

My preference would be to make this configurable (grouper-ui.properties?) Too much variation in individual choice – no need to start a culture war :)

### Chad Redman  (unc.edu) - 2020-10-24T18:30:24.551+0000

Link to GRP-3002, where some of these have moved into UI configs

### Chad Redman  (unc.edu) - 2020-10-24T18:39:54.829+0000

Summary of defaults (some of which are configurable if still not good enough):

 
|*Description*|*Config value*|*Change*|*Sample*|
|Group member PIT start/end|uiV2.group.PITMembership.dateFormat|yyyy/MM/dd kk:mm aa -> yyyy/MM/dd h:mm aa|2020/10/31 24:19 AM -> 2020/10/31 12:19 AM|
|audit entry date (used many places)|uiV2.audit.dateFormat|yyyy/MM/dd kk:mm aa -> yyyy/MM/dd h:mm aa|2020/10/31 24:19 AM -> 2020/10/31 12:19 AM|
|status servlet startup|hardcoded|yyyy/MM/dd kk:mm -> yyyy/MM/dd HH:mm:ss|2020/10/31 24:19 -> 2020/10/31 00:19:23|
|status servlet last error|hardcoded|yyyy/MM/dd kk:mm:ss -> yyyy/MM/dd HH:mm:ss|2020/10/31 24:19:23 -> 2020/10/31 00:19:23|
