# GRP-1925  status servlet should list/inspect jobs from a DB table list and not from config files.

When running lots of "loader_CHANGE_LOG_consumer" jobs it is likely not advisable to run them inside the web application. However, that means that the status servlet  ( /status?.... ) is blind to the jobs that are only running in the daemons.

Please change the logic for how the jobs are found to look at the whole set from the DB and not based on the configuration file settings to "include" those jobs.

Likely also the "other" jobs are affected similarly as well. But I have not verified that.

 

 

Or is there a way to setup the configuration so that a job is known to the UI, but never run in the UI?
