# GRP-7311  UI consistency: standardize form/field labels to no trailing colon

Form and field labels across the UI are inconsistent about trailing colons - within a single screen some labels have a colon (Group filter:, Subject source:) and some do not (Membership type, Member search); the object summary Fields rows all use colons (Name:, Path:, ID path:, Created:). This is a visual-consistency issue, not accessibility.

Standardize to NO trailing colon on field/form labels. Scope: about 187 label-style text keys (keys named *Label/*Filter/*Header/*Column/*Title/*For whose value ends in a colon), out of ~322 values that end in a colon total. Do NOT strip colons from instructional/sentence text (e.g. Enter the following:) - only field labels. This is a grouperText properties edit (CRLF, needs a Tomcat bounce). Separate from the accessibility work; the My folders filter is handled under its own accessibility item (GRP-7310).
