# GRP-565  delete old change log entry records

grouper_change_log_entry has all records, and doesnt need them.

## Comments

### mchyzer - 2011-02-26T06:56:33.139+0000

There is a setting in grouper-loader.properties:


# number of days to retain db rows in grouper_change_log_entry.  -1 is forever.  default is 14
loader.retain.db.change_log_entry.days=14

Also there is a new index on created_on.

Note, if you have a LOT of entries, the first time this query runs, it could choke the DB, so we should have some upgrade advice on that...

### mchyzer - 2011-02-26T07:00:13.768+0000

You should remove old records on upgrade to 2.0, if there are lots, since deleting 2 million records with a delete statement in oracle could be bad.  e.g. if you have 2560000 records in the table, this will clear out everything but 60k of them in a way that doesnt make oracle choke... note, make sure the grouper loader is not running when you do this...

create table change_log_entry_temp as select * from grouper_change_log_entry gcle where gcle.SEQUENCE_NUMBER > 2500000;
truncate table grouper_change_log_entry;
insert into grouper_change_log_entry (select * from change_log_entry_temp);
commit;
analyze table grouper_change_log_entry compute statistics;
drop table change_log_entry_temp;
