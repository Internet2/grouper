# GRP-7050  On a user error in incremental, re-retrieve the user from target and refresh the cache and sync back

When a user-level error occurs (e.g. a membership change fails in incremental because the cached target user data is stale, or the user was deleted and recreated in the target), the error is recorded in grouper_sync_member. Confirm and ensure the retry path retrieves that user from the target again (recalc style) so that:
 * the matching id / target id attribute value caches in grouper_sync_member are refreshed,
 * the sync back tables (grouper_prov_user etc.) are updated with the fresh native object,
 * the failed operation is retried against accurate data.

Add test coverage: recreate a user in the mock target with a new id so the cache is stale, cause an incremental error, verify the next pass re-retrieves the user, updates cache and sync back, and succeeds.
