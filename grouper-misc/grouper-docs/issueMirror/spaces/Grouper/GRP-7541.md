# GRP-7541  Scripted groups: move the UI's save checks and save into core, save in one transaction, and count only the whole script on save

h2. Summary

The checks the UI's loader screen runs before saving a scripted (JEXL) group, and the save and remove themselves, move out of UiV2GrouperLoader into a new core class, GrouperAbacScriptedGroup. Behavior stays the same, except for the fixes and the one message change below. This lets other callers, such as MCP and the AI assistant, save a script with the same checks and the same code.

h2. Problems fixed

* The save wasn't atomic. The marker, the script and the subject sources were three separate writes with no transaction around them. If one failed partway, the group was left half a scripted group, for example with the marker but no script.
* The save was slower than it needed to be. Before saving, the UI ran the full analysis, which runs one count query for every part of the script. The save only uses the count for the whole script, for the maximum membership size check. On a big script, saving took about as long as clicking Analyze.

h2. Change

* New class GrouperAbacScriptedGroup:
* checkScriptForSave runs the UI's checks in the same order: a script is given, GrouperAbac.validScript, the analysis in save mode (an error or a warning refuses), and the maximum ABAC membership size for the user. It stops at the first problem and returns it as a message, worded with the existing UI text keys.
* internal_saveScript saves the marker, the script and the subject sources in one transaction. Sources that match the defaults aren't kept, as before. It writes only what changed.
* internal_removeScript removes the marker, and the script and sources with it. Members are left as they are, as before.
* Methods that read or write as root without a privilege check are named internal_. Callers must check PrivilegeHelper.canEditAbacLoader first. The UI's save and remove do. Switching a scripted group to another loader type removes the script after checking only the new type's privilege, as it always has; that is unchanged here.
* GrouperLoaderJexlScriptFullSync.analyzeJexlScriptHtml gets a countParts option. When false, only the whole script is counted. The privilege checks and warnings still run on every part. The existing signature still counts every part, so the Analyze button and other callers don't change.
* UiV2GrouperLoader's save, remove and loader-type switch call the new methods.

h2. Behavior change

When a save is refused because the analysis gives an error or a warning, the UI now shows that message, for example "You are not allowed to read the group: 'x'". Before, the save failed with a generic error. The Analyze button has always shown these messages.

The one warning that refuses a save is that unresolvable or deleted entities match the script. That has always refused a save; now the user sees why, with up to 10 of their subject ids, as Analyze shows them.
