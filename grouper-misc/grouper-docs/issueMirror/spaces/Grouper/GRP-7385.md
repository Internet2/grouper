# GRP-7385  MCP recipe screens must not allow expression language in recipe fields

The MCP recipe add and edit screens (GRP-7324) use the generic configuration module form, which lets any editable field be marked as expression language. Recipe content owners (groupNameCanEdit) and members of grouper.mcp.recipe.groupNameCanAdminInUi are not required to be sysadmins, so they should not be able to enter expression language. It is evaluated server side, both when the form posts and whenever the saved config is loaded.

Fix: add GrouperConfigurationModuleBase.isExpressionLanguageAllowed() (default true, so other modules are unchanged). GrouperMcpRecipeConfiguration returns false: the form does not evaluate or keep expression language for recipe fields, validatePreSave rejects any recipe field in expression language mode, and the recipe screens do not show the expression language checkbox.

Found in the 7.6.0 pre-release review. Recipes are new in 7.6.0, so no released version is affected.
