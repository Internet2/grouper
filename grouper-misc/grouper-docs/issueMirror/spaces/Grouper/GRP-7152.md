# GRP-7152  Azure provisioner: refresh cached bearer token before expiry using a safety margin

AzureGrouperExternalSystem.retrieveBearerTokenForAzureConfigId caches the OAuth bearer token with its expires-on time and reuses the cached token whenever expiresOnSeconds*1000 is still greater than the current time. There is no safety margin: a token that is valid at the moment of the check but has only a second or two of life left will be handed to the next Graph HTTP call, and if that request is slow the token can expire in flight and Graph rejects it with a 401.

Fix: treat the cached token as expired when it is within a configurable refresh margin (default 60 seconds) of its expiry, so a fresh token is fetched proactively instead of at the exact expiry boundary. This mirrors the standard OAuth client practice of refreshing early. Access tokens are valid for roughly an hour, so refreshing a minute early is cheap and eliminates the mid-flight-expiry race.

Location: AzureGrouperExternalSystem.retrieveBearerTokenForAzureConfigId, the cache-hit branch that compares expiresOnSeconds to the current time. Scope: hardening only; this is separate from the Directory_ExpiredPageToken pagination-cursor failure, which is tracked on its own issue.
