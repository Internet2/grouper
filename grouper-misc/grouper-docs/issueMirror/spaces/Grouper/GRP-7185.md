# GRP-7185  CCURE provisioner treats empty results as error

*Liam:* I think what’s happening is that when Grouper queries CCURE for an entity that has no corresponding Personnel record in CCURE, CCURE returns a valid empty result set, {{[]}}. The CCURE provisioner then appears to treat that empty result as an error — {{Invalid JSON node, no data or is missing GUID: null}} — rather than classifying the entity as “not found” or “not provisionable.”

As a result, Grouper/provisioning may still attempt to process associated memberships for that entity, even though the target Personnel object/GUID could not be resolved. In that case, I’d expect the provisioner to skip or object-error the dependent membership with a clearer “target entity not found / not provisionable” message. For delete operations, an empty result may be better treated as “already absent” rather than an error.

*Gail*: That's the problem we discussed a while back -- {{getallwithcriteria}} returns an empty result with a 200. Apparently 200 here means "search executed successfully",  not "found something".
