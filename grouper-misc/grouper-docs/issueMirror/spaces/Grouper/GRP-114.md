# GRP-114  The grouper_memberships.parent_membership column does not always get populated correctly

One example on how to reproduce:

1.  Create a group test3 and add a member X.
2.  Create a group test1 and add test3 as a member.
3.  Create a group test2 and add test1 as a member.

The parent membership of the membership with owner_id=test2, member_id=X, and list_type=list is incorrect.  One affect of this is that if you now delete the group test2, this membership does not get deleted.

### shilen - 2008-08-15T15:01:23.395+0000

Here are a summary of the issues addressed in this issue:


1.  Parent memberships are not always recorded correctly for effective memberships.
2.  Depth is not always recorded correctly for effective memberships.
3.  In some cases, effective memberships are added to composite groups instead of composite memberships.
4.  Duplicate memberships are sometimes created when a membership is added to a group where the group is a factor of a composite.
5.  Access and naming privileges are not added correctly when adding members to a composite group and the composite group has privileges to a stem or group.
