### Chad Redman  (unc.edu) - 2019-05-05T22:56:10.817+0000

Really weird behavior. The issue is that svg can't handle non-breaking spaces (\xa0 in your example, but nbsp html entity also has issues). If there are extra spaces in the group description or name, to graphviz dot output is just the spaces. But if you look at the svg source, it's converted to nbsp and can't be displayed. But the svg is obviously drawn. So maybe it's not really nbsp, but when you look at the source it represents it that way.

Entity #160; is the equivalent and works as a replacement. Maybe we can convert 2+ spaces to this using JS regexp?

 

Edit: Tried it, and the workaround doesn't work. Even if the dot code has  #160, the svg converts it to nbsp which then can't be read as valid svg!

 

Maybe just collapse all multiple spaces into a single space?

### Chad Redman  (unc.edu) - 2019-05-06T16:47:53.351+0000

See https://bugs.chromium.org/p/chromium/issues/detail?id=340794
Issue 340794: Serialization of SVG with non-breaking spaces inside of an HTML document is broken


Resolution:
> Allow overriding the serialization rules in MarkupAccumulator
> 
> Add a flag for overriding the default policy of basing the serialization
> on the type of the owner document.
> 
> Use in XMLSerializer to force serialization of character entities based
> on XML rules.


The fix for Grouper is to use XMLSerializer.serializeToString(node) which forces xml with \u00a0, instead of ($).html() which incorrectly uses nbsp entities.

Note that the result *must* be saved as UTF-8, as the browser still doesn't like ascii \xa0 outside of unicode.
