# GRP-7086  Add sync-back to the Interfolio provisioner

h2. Background

The Interfolio provisioner (entity-only; provisions faculty users and grants/removes RPT and optional FS access) did not populate Grouper's generic provisioning reporting tables. Add sync-back so the target users Grouper reads off Interfolio are recorded in {{{}grouper_prov_user{}}}, consistent with the other web-service provisioners.
h2. What was added
 * A new {{InterfolioProvisioningTargetNativeSync}} that builds a native user record from the raw Interfolio {{users/search}} JSON: {{target_user_id}} is the Interfolio pid, and by default {{{}first_name{}}}, {{{}last_name{}}}, and {{email}} are captured. It's JSON-pointer based, so an operator can capture any other {{users/search}} field via {{{}nativeAttributesEntities{}}}.
 * Wiring: the DAO advertises {{{}canSyncBack=true{}}}, the provisioner returns the native-sync class, and the capture is hooked at the {{searchUsers}} read seam (a no-op unless an Interfolio provisioner with sync-back is active).
 * This is *entity-only* sync-back — no group or membership capture, matching the provisioner's scope.

h2. Testing
 * Unit tests of the build path ({{{}InterfolioProvisioningTargetNativeSyncTest{}}}): defaults applied, pid is the id (not an attribute), missing-id returns null, and the static dispatcher is a no-op when there is no current provisioner. These run without Tomcat.
 * Existing provisioner and API tests unchanged and passing.

h2. Docs

Updated the Interfolio provisioner page and developer notes with a sync-back section (capture seam, {{{}grouper_prov_user{}}}, default attributes, entity-only).
