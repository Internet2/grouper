# GRP-7299  UI accessibility: fix duplicate ids on group screen and disclosure/menu ARIA on the page shell

Two related page-shell / group-screen accessibility fixes (items 14 and 3 of the accessibility action plan).

Item 14 - duplicate ids in the live DOM on the group screen. groupSummary.jsp reused two ids that also appear elsewhere on the same screen: the summary provisioning link used groupMoreActionsProvisioningButtonId (also on the more-actions menu item, which the provisioning browser tests target after opening the menu) and a details container used groupDetailsId (also the header details div, which the header show/hide JS targets). The two summary-side copies were renamed to groupSummaryProvisioningLinkId and groupSummaryDetailsId; the canonical ids stay on the elements the existing JS and tests reference. This also removes the strict-locator ambiguity the tests would otherwise hit.

Item 3 - disclosure/menu ARIA on the shared shell (index.jsp). The Show more options split-button menu and the Quick links collapse both carried a redundant role=button on a native button; both now drop it and gain aria-controls pointing at the element they open (main-more-options and demo2). The Quick links button also carried a malformed ariahaspopup attribute, removed - a collapse is a disclosure, not a menu, so it has no popup.

Scope note: the broader finding that id=more-action-button is hardcoded in about 50 more-actions menu JSPs (a wider duplicate-id issue that also blocks aria-controls for those menus) is tracked separately and not part of this change.
