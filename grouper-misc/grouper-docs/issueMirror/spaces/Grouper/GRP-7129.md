# GRP-7129  Zoom loader: store null (not empty string) for pending Zoom users with a blank id

Pending Zoom users are returned by the Zoom API with a blank {{id}} - the account exists in Zoom but has not yet been assigned a Zoom user id. The loader was writing that blank value straight into the sync table as an empty string.

The sync table has a unique index on {{{}(id, config_id){}}}. On Postgres, multiple NULLs are allowed in a unique index, but multiple empty strings collide - so more than one pending user would either violate the unique index or fail the table sync.

Fix: when the Zoom user's {{id}} is blank, write {{null}} into the {{id}} column instead of {{{}""{}}}, so each pending row is treated as distinct.
 * File: grouper/src/grouper/edu/internet2/middleware/grouper/app/zoom/GrouperZoomLoader.java
 * Method: user-to-table row build in {{GrouperZoomLoader}} (around the {{gcTableSyncRowData.setData(rowData)}} call)
