# GRP-7521  MCP GSH templates: mcpReadonlyJexl replaces mcpReadonlyWhen, as a JEXL expression like the other template settings

GRP-7478 (7.9.0) added the GSH template setting mcpReadonlyWhen: comma separated input=value pairs naming the calls of a writing template which change nothing, so the AI assistant in the UI runs them without asking the user to approve first. No other Grouper setting has values in that format, and it needed its own parser.

Replace it with grouperGshTemplate.<configId>.mcpReadonlyJexl, a JEXL expression like the template input settings showEl and validationJexl. The inputs are variables by name, with defaults filled in and values converted to the input's type the way the template gets them when it runs. For example: `${gsh_input_action == 'get' || gsh_input_confirm != true}`

A call counts as changing nothing only when the expression evaluates to true. Anything else, including an error, a blank result or an input which cannot be converted, means the user is asked to approve, as before. These calls still need MCP readwrite access, as before.

mcpReadonlyWhen is removed, not kept as a fallback. A template which set it needs mcpReadonlyJexl set instead; until then its calls are all treated as writes, so the user is asked to approve each one, which is the safe direction.
