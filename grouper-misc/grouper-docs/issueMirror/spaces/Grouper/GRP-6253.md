# GRP-6253  grouper v5 should not start if the membership cache is not mostly populated

_(no description)_

## Comments

### Chris Hyzer - 2025-08-09T18:14:55.578+0000

Before upgrading to v5, you need to run the v4.20.0+ daemon to populate the SQL membership cache tables. 

If you are already in v5 in a version previous to {color:#1d1c1d}v5.17.2, then upgrade to v5.17.2
as an intermediary upgrade, run the sqlCacheFullSync daemon, then get to the eventual v5 version.
{color}

When you are done and upgraded to v5 and the sql cache table is populated (either from v4 or v5),
if upgrading from v4 then also wait for upgrade task to finish, set this in grouper.hibernate.properties to reduce Grouper startup time.  This should be done after you have been running
v5.17.2+ for a couple weeks.
{code:java}registry.checkMembershipCacheIsPopulated = false {code}

### Chris Hyzer - 2025-08-13T19:34:18.858+0000

or use this container env var
{code:java}GROUPER_CHECK_MEMBERSHIP_CACHE_IS_POPULATED=false {code}
