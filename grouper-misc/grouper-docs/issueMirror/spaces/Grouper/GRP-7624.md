# GRP-7624  Remove the Apache Ant dependency from the DDL code

Grouper ships Apache Ant (ant and ant-launcher) only because of the DDL code, not to run Ant builds:

- GrouperDdlUtils creates a GrouperAntProject (a subclass of org.apache.tools.ant.Project) and a DefaultLogger to capture output when it runs a DDL script, and calls org.apache.tools.ant.util.StringUtils.endsWith.
- The embedded copy of Apache DdlUtils (edu.internet2.middleware.grouper.ext.org.apache.ddlutils.task.*: DatabaseTaskBase, Command, DatabaseCommand, WriteSchemaToDatabaseCommand, WriteDataToDatabaseCommand, DumpMetadataTask, PlatformConfiguration, VerbosityLevel, ...) was written as Ant tasks: the classes extend Task and throw BuildException.

Because ant is a direct dependency of grouper (grouper/pom.xml), it is in the container image, and image scanners flag every Ant CVE even though Grouper does not use the affected parts (e.g. CVE-2026-78254 in the ftp and scp tasks, see GRP-7622).

Long term: remove the Ant dependency.
- Replace GrouperAntProject and DefaultLogger in GrouperDdlUtils with plain logging.
- Replace org.apache.tools.ant.util.StringUtils.endsWith with a local helper.
- Remove or rewrite the unused ddlutils task classes so nothing extends Task or throws BuildException (check which ones Grouper actually calls; most are only for running DdlUtils from an Ant build file).
- Drop ant and ant-launcher from grouper/pom.xml and grouper-parent/pom.xml, and confirm neither jar is in the image.

Test: a fresh install, a DDL upgrade and the DDL compare on Postgres, Oracle and MySQL.
