### Chris Hyzer - 2026-02-27T20:50:48.267+0000

in grouper-ui.properties, you should have something like this:
 
{code:java}grouper.is.extAuth.enabled.elConfig = ${elUtils.defaultIfBlank(elUtils.processEnvVarOrFile('MY_EXT_AUTH_ENABLED'), 'false')} {code}
Then in the UI container set that env var to true, and ignore in other envs, its false by default

Note: in v6.0.2+ this is fixed and you dont have to do that

### Chad Redman - 2026-03-27T16:28:48.697+0000

The actual issue had to do with the Grouper startup and the order of operations. It was adding the servlet filter for authentication before checking whether the container needed to. Because the filter was there, it was expecting properties to be defined. The proper fix was to check the properties first, and not even register the servlet filter unless it needed to.

Also, the integration tests now test a WS and daemon container to ensure they are not impacted. Previously, it was only testing a UI container, so the issue wasn't detected.
