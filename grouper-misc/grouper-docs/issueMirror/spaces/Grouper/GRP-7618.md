# GRP-7618  Security review follow-ons for 7.10.0: behavior and configuration changes

Follow-on behavior and configuration changes from the 2026 security review (GRP-7572 to GRP-7585, released in 7.9.1) that landed on GROUPER_7_BRANCH after 7.9.1 and ship in 7.10.0. The commits use the original issue numbers. See "v7 Upgrade instructions from v7" for what operators need to check.

- 27f53f768460 (GRP-7577): remove the legacy VOOT connector (edu.internet2.middleware.grouperVoot.VootServlet). It was only active if added to the WS web.xml by hand; remove any VootServlet servlet, mapping, filter mapping and security constraint for /voot/* before upgrading or the WS webapp will not start
- 24a6e834e994 (GRP-7580 commit 3): RabbitMQ TLS checks the broker host name with a configured trust store too (hostnameVerification, default true; 7.9.1 checked it only with the JVM default trust store), with a clear error and a configuration review warning
- 2edaaad5c4c4 (GRP-7580): provisioner.<configId>.trustTargetToRelinkEntities (default false) lets matching re-link an entity to another target account, with a configuration review warning
- 091991ec5265 (GRP-7585): workflow daemons exit cleanly when workflow is off (WARNING if old workflow data exists) instead of erroring every run
- 0a4030dbf486 (GRP-7572): configuration review checks for ESB, WS, workflow, messaging and UI, and base config docs; changeLog.consumer.membershipRequire.elfilter default also handles GROUP_ADD and GROUP_UPDATE; ws.allowJsonWrapper defaults to false
- fa3f0b069701 (GRP-7582 commit 3): configuration review lists objects with unsafe ids, XML import gives new objects with unsafe ids a generated id, escape stack traces in subject source diagnostics, plain subject label in folder memberships CSV export
