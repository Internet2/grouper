# GRP-7279  Upgrade RabbitMQ amqp-client to 5.35.0 for six advisories affecting 5.28.0

grouper-parent pinned amqp-client.version at 5.28.0. Six published advisories affect that version. The highest fix version among them is 5.33.1; this change goes to 5.35.0, the current release.

Reachable from Grouper, since these are in the wire protocol parsing path and apply to any deployment whose Grouper connects to a broker: CVE-2026-69219 (HIGH), oversized LongString or bytes length in ValueReader triggers an out of memory condition through unchecked allocation, fixed in 5.33.1. CVE-2026-69220 (HIGH), unbounded recursive table and array nesting in ValueReader causes a StackOverflowError denial of service, fixed in 5.33.1. CVE-2026-61634 (LOW), the client accepts broker frames larger than the negotiated AMQP frame_max, fixed in 5.33.0. CVE-2026-63335 (MODERATE), a malformed body frame triggers a raw command assembler exception, fixed in 5.31.0.

Not reachable from Grouper, but fixed by the same bump: CVE-2026-63337 (HIGH), unvalidated Class.forName in the JSON-RPC ProcedureDescription helper. Grouper does not use com.rabbitmq.tools at all, so this code path is never entered. The JSON-RPC handling in GrouperMcpServlet is Grouper's own and is unrelated to the RabbitMQ helper.

CVE-2026-63336 (MODERATE) needs a caveat. The advisory concerns the no-argument useSslProtocol overload installing TrustEverythingTrustManager by default. RabbitMQConnectionFactoryImpl passes an explicitly constructed SSLContext to useSslProtocol, so it does not depend on that default and the library upgrade does not change its behaviour. However, that same method installs TrustEverythingTrustManager itself when a TLS version is configured without a truststore path and passphrase, which reproduces the same weakness in Grouper's own code. That is not fixed by this upgrade and is being raised separately.

One line in grouper-parent/pom.xml; the version is a managed property, so consuming modules pick it up without further edits. Applied to the 7 branch.
