# GRP-7441  GcDbAccess optimistic locking annotation (version column check on update/delete)

Add optimistic locking to GcDbAccess object persistence via a new annotation attribute, @GcPersistableField(optimisticLockVersion = true), on a long/Long field (e.g. hibernateVersionNumber / hibernate_version_number). This is needed to move tables off Hibernate (e.g. grouper_file in GRP-7440) without silently losing the optimistic locking Hibernate provides today.

Insert: null version is set to 0. Update: set ..., version = old+1 where pk = ? and version = old; 0 rows updated throws a new GcStaleObjectException, success sets the field to old+1. Delete: adds the version check too. A non-null version means previously persisted, so a stale update never falls through to an insert (defaultUpdate / manually assigned primary keys).

Respects dao.optimisticLocking: Grouper sets a static switch on GcDbAccess at startup; when false the version still increments but is not checked. Batch store (storeBatchToDatabase / storeListToDatabase) refuses versioned classes for now since per-row batch counts are unreliable on some drivers. Classes without the annotation behave exactly as before.
