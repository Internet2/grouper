# GRP-7219  MCP server should validate the Origin header to prevent DNS rebinding

The MCP spec requires servers on the Streamable HTTP transport to validate the Origin header on incoming connections and respond with HTTP 403 when it is present and not allowed. This has been a requirement since spec revision 2025-03-26 and Grouper did no such check.



doPost now rejects a request whose Origin this server does not allow, with HTTP 403 and a JSON-RPC error body. The check runs before authentication so credentials from an unrecognized page are never processed.



Three cases are allowed: a request with no Origin at all, which is every command line and server to server client since only browsers send the header; a request whose Origin is this server itself, which is not cross origin; and a request whose Origin matches a configured

grouper.mcp.allowedOrigin.<configId>.regex pattern. With no patterns configured no cross origin browser request is allowed, which is the secure default and matches how the OAuth redirect URI allowlist already behaves — a deployment opts in to browser based clients rather than opting out.



The check is on doPost only. doGet serves the OAuth well-known discovery metadata, which browsers legitimately fetch cross origin during the authorization flow, so validating there would break authorization. doPost is the entire JSON-RPC surface and is what the attack targets.
