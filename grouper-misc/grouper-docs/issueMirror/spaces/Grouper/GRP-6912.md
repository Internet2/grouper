# GRP-6912  TrueFoundry provisioner test fixes for entity id matching and manager-group incremental sync

Several TrueFoundry provisioner tests were failing because of mismatches between
the test setup and the provisioner's actual behavior:

1. createMockUsers pre-created mock TrueFoundry users with a random UUID as
   the user id, but the provisioner config uses email as the entity id
   (translateFromGrouperProvisioningEntityField=email).  The provisioner
   therefore treated the pre-created user (id=UUID) as a different entity
   from the Grouper-translated one (id=email), causing a spurious
   deactivate + create cycle that left memberships in an incorrect state.
   Fix: create mock users with id = email.

2. The userDeactivate test looked up users by id = userIdX (the old UUID).
   After the id-is-email change, queries now look up by email.

3. The teamManagersFromManagerGroup test exercised both full and
   incremental sync, but the original setup put SUBJ2 as the sole manager
   via managersGroup with no direct membership in teamGroup.  After the
   swap, the test expected SUBJ2 to remain as a regular team member, which
   is impossible since managersGroup was his only path into the team.
   Additionally, the swap made two managersGroup changes back-to-back,
   which did not produce an effective-membership change on teamGroup in
   incremental mode (SUBJ0 was already a direct team member), so the
   translator never recomputed the managers attribute.
   Fix: restructure the test to keep SUBJ0 out of the team initially, and
   split the swap into two separate changes each followed by its own
   provision — remove SUBJ2 from managersGroup (he leaves the team), then
   add SUBJ0 to managersGroup (he enters the team as a manager).  Each
   single change now produces an effective membership change that
   incremental can detect via the group-group dependency link.
