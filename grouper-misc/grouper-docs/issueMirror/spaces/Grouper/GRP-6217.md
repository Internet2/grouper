# GRP-6217  SQL sync incremental with timestamp, continually selects the most recent update

In Grouper, the grouper_sync_job table for incrementalAllColumns SQL sync converts and stores the timestamp of the latest update column value into a long field. But SQL and java timestamps have 3 more digits of precision. So when the incremental query runs

{code}select ... where "tstamp" > ?{code}

The SQL timestamp for the latest record(s) are likely going to be greater than the value of the truncated bind variable it got from grouper_sync_job. This means the latest value will get selected and compared again, every time the incremental runs.
