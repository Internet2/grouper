# GRP-7149  Data provider SQL query: clarify subject id column must not have a case-sensitive quoted mixed-case alias (Postgres/Oracle)

GrouperSqlDataProviderQueryTargetDao wraps the configured provider query and references the subject id column by name, unquoted, e.g. SELECT DISTINCT LOWER(subjectId) FROM (SELECT subjectId FROM (...configured query...) innerQuery) outerQuery. On databases that fold unquoted identifiers (Postgres, Oracle), if the operator gives the subject id column a case-sensitive double-quoted mixed-case alias (e.g. rspmail AS a double-quoted subjectId), the wrapper reference folds to a different case and the column is not found (Postgres: column subjectid does not exist). Reported on upgrade 5.22.4 to 7.2.1, Postgres 14.7.

The subject id attribute is compared case-insensitively everywhere else in the data provider logic, so the fix is guidance, not a behavior change: operators should give the subject id column a plain unquoted alias so it folds consistently. Other columns are unaffected because they are returned via select * and mapped through case-insensitive JDBC metadata.

Resolution: added config-screen field descriptions for providerQuerySqlQuery and providerQuerySubjectIdAttribute (and the change log query subject id / timestamp counterparts) documenting the constraint, and updated the wiki data provider page.
