If somehow you can get the entitySubjectIdentifier attribute added, it's not searchable, so it is effectively not useful. The reason is probably that entities are now in the UI with UiV2Subject.viewSubject, not UiV2Group.viewGroup. This causes the attribute to set owner_member_id and not owner_group_id. The entity finder queries have not been updated to reflect that, and try to join on owner_group_id which is null, thus not finding any results.

This whole way of creating an alternate subject identifier should be deprecated. The attribute's value needs to start with the folder path anyway, so it's not like you can use an arbitrary identifier. If you need a specific name, then just name the group that way.
