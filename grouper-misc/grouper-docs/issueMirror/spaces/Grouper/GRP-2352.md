I like where this is going. One of the concepts coming out of the Auckland discussion was the move from "group management" to "access governance", and that there should be "no unmanaged access control policies". That should be true when using "adhoc" (i.e. ACLs) independently for some legacy authorization group/role or when supplementing ABAC policy groups.  So the grouper "adhoc" type could be a signal to the IAM analyst of what the intent of the group is and its impact to policy management, etc.  "adhoc" groups could come with some default config for attestation, etc.
