# GRP-7276  Docs: note that the Jira REST API also answers on the vanity host in the grouper-jira skill

The grouper-jira skill doc already explains that the GRP tracker is one Jira Cloud instance answering on two names: grouper.atlassian.net as the API base, and todos.grouper.internet2.edu as the vanity display URL. What it did not say is what happens if you point REST at the vanity host.

It works. A REST v3 GET against the vanity host returns 200 with the same API token, and the response self-reports that host in the self field. Without that stated, someone who tries it and sees it succeed can reasonably conclude the API base moved, and start rewriting the recipes.

Added a short paragraph recording that behavior, while keeping the guidance to use grouper.atlassian.net for REST so every recipe in the doc stays uniform. Documentation only; no recipe, host, or transition id changed.
