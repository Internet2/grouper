# GRP-7460  MCP group_find approximate name search can repeat or skip groups between pages

group_find always pages (50 by default), but its approximate name search (FIND_BY_GROUP_NAME_APPROXIMATE) only sorts when the caller passes sortString. Hib3GroupDAO.findAllByApproximateNameSecureHelper adds no default order.



Without an order, the database doesn't guarantee the same row order from one query to the next, so page 2 can repeat or skip groups from page 1.



The groups-in-folder search (FIND_BY_STEM_NAME) was not affected: it already sorts by display name when no sort is given.



Fix: when group_find pages and no sortString is given, it sorts by displayName. The tool description now says so. A sortString the caller passes still wins.



Only the MCP tool changes. Web service clients paging the same search without a sort are unaffected by this change.
