# GRP-4633  do not have default etc EveryEntity privs

Gettes: We have grouper configured as “default deny” for viewing in the UI.  An unpriv’d user logins to grouper and should only be able to see what they need to see.  In etc: the attributes:entities:*  and attributes:permissionLimits:* appear to be visible to EveryEntity (privs are read,update).  Is this intentional/necessary?  I am hoping to limit questions from users as to “what’s this?”

### Chris Hyzer - 2023-03-26T15:58:05.747+0000

These privs default to false now, and EveryEntity will be removed on an automated upgrade step. If you want the previous behavior (which is it recommended against, dont make these public, make them view/read by a power users group), you can set these to true in grouper.properties (new default is false)
{code:java}
# allow every entity to be able to read and assign subject identifiers to local entities they own
# note: there is also: grouper.permissions.limits.builtin.createAs.public
# {valueType: "boolean", required: true}
grouper.attribute.allow.everyEntity.privileges = true

# if the permissions limits should be readable and updatable by GrouperAll (set when created)...
# note there is also: grouper.attribute.allow.everyEntity.privileges
# {valueType: "boolean", required: true}
grouper.permissions.limits.builtin.createAs.public = true

 {code}
