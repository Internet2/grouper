# GRP-7248  Restrict full stack traces in MCP errors to a configured group

  Problem

  

The MCP specification says servers should sanitize tool outputs. Grouper's MCP server returned full Java stack traces in tool error responses to any MCP user, disclosing internal class names, SQL, file system paths, third party library versions, and container internals to the AI client and to whoever operates it.



  There were two distinct sources:

# 30 catch blocks across the MCP tool classes appended GrouperUtil.getFullStackTrace(e) to the error message.

# The WS layer. 14 MCP tools return wsResults.getResultMetadata().getResultMessage() verbatim, and WsResultMeta.appendResultMessageError(Throwable) puts a full stack trace in that message when ws.throwExceptionsToClient is true, which is its default. This one is easy to miss because the stack never passes through MCP code.



  Change



  New config in grouper.properties:



  # {valueType: "group"}

  grouper.mcp.users.canSeeStackTraces = $$grouper.rootStemForBuiltinObjects$$:sysadmingroup



Members of the group get the exception message plus the full stack trace. Everyone else gets the exception message only. Blank disables stack traces for all MCP users. The exception is always logged on the server regardless, so nothing is lost for troubleshooting from the logs.
