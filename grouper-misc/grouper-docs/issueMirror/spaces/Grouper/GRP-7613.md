# GRP-7613  Loader ldapLookup: decide whether a time-limited or partial LDAP search should fail like the loader search

In 7.10.0, loader LDAP searches (GrouperLoaderResultset, through LdapLoaderSearchResultCodes.callForLoader) fail the job when the directory cuts a search off with TIME_LIMIT_EXCEEDED or returns PARTIAL_RESULTS, instead of syncing a partial result, unless ldap.<configId>.searchIgnoreResultCodes is set explicitly.

The ldapLookup helper available in loader expressions (LdapLookup, put in the loader variables by LoaderLdapUtils) is not wrapped: its searches still ignore TIME_LIMIT_EXCEEDED, SIZE_LIMIT_EXCEEDED and PARTIAL_RESULTS by default. A bulk lookup (assignBulkLookup) that the directory cuts off returns fewer entries, so some values do not translate, and a loader that uses the lookup to map members can then drop those members.

Decide whether ldapLookup searches made while a loader job runs should fail the same way as the loader's own searches (run them inside callForLoader), or keep today's behavior. Considerations: it could make loader jobs that work today fail at sites whose lookups hit time limits or Active Directory referrals; the opt-out would be the same ldap.<configId>.searchIgnoreResultCodes setting.

If changed: a unit test, and a release note.
