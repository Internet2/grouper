# GRP-6454  Log matching DDL versions at "info" level

I'm somewhat peevish about log messages that are logged at too high of a criticality; I like to filter logs to include level "warning" and higher in routine monitoring and when verifying upgrades.

The DDL version check logs at "warning" level even if the versions are correct. This patch fixes that.

## Comments

### Chris Hyzer - 2026-06-30T01:24:23.004+0000

The DDL version check logs the {{Grouper ddl object type 'X' has db/ddl version: N ...}} line at WARN even when the db and Java versions match (nothing is wrong). For sites that monitor logs at WARN and above (routine monitoring, upgrade verification), this is noise on every startup, indistinguishable from a real warning.

A simple switch of these two lines from {{LOG.warn}} to {{LOG.info}} would not work on its own: the default log config sets {{edu.internet2.middleware}} to WARN, so a hard switch to INFO would make the version line vanish entirely on a WARN-only logger -- the message would be lost, not just relocated.

*The fix (two parts):*

*1. Code* ({{{}GrouperDdlEngine.java{}}}, both version-check sites) -- make the healthy-case level conditional so the line is never silently dropped:


 
 
 
 
 
if (LOG.isInfoEnabled()) {
LOG.info(versionStatus);
} else {
LOG.warn(versionStatus);
}
 
The mismatch path ({{{}LOG.error{}}}) is unchanged -- real version problems still log at ERROR.

*2. Config* (default {{{}log4j2.xml{}}}) -- a logger that enables INFO for the DDL engine, which makes part 1 route the healthy-case lines to INFO instead of WARN:


 
 
 
<Logger name="edu.internet2.middleware.grouper.ddl.GrouperDdlEngine" level="info" additivity="false">
<AppenderRef ref="stderr"/>
</Logger>
 
*Net effect:* when the schema is current, the version lines log at INFO (out of WARN-level monitoring); on a real mismatch it still logs at ERROR. Operators who keep the DDL logger at WARN still get the version line via the fallback, so nothing is lost.

Other INFO statements in the class are install-only (the {{Ddl db name is}} line) or fatal-failure-only (the install stack trace, currently lost when INFO is off), so enabling INFO for this class adds no routine log volume.
