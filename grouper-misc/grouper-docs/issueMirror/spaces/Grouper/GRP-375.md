# GRP-375  loader should reconfigure without restarting

Hello,

after creating a new group in the Admin UI with the type grouperLoader and an attribute grouperLoaderQuartzCron, the running loader daemon did not notice it and thus did not update the group at the required times.  Restarting the "gsh.sh -loader" process fixed the problem so it was not a case of bad group configuration.

- Is there a way to configure the loader to notice new entries?

If not:
- Is there way to tell the Grouper loader process to reread the
  grouperLoaderQuartzCron entries, so that it does not miss any
  scheduled task (a risk when restarting)?
  E.g. something like the common "kill -HUP pid" on Unix.


Thanks in advance for your answers!
