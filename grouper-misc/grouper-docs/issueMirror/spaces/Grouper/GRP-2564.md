# GRP-2564  Internationalization broken by  grouper_v2_4_0_api_patch_55 and grouper_v2_4_0_ui_patch_34

_(no description)_

## Comments

### Olivier SalaÃ¼n - 2020-01-24T12:38:45.678+0000

We noticed that Grouper 2.4.0 with latest patches applied fail to apply internationalization on Grouper UI. Looking at latest commits on the project we suspected this one: [https://github.com/Internet2/grouper/commit/9e68666d079e2288b602fe4f2f7486fa7751feac#diff-4766db6beeb0239bb2ad7260fbbc7896]

 

We had the confirmation that grouper_v2_4_0_api_patch_55 and grouper_v2_4_0_ui_patch_34 introduced the bug as follows:
 # installed a fresh Grouper 2.4.0 telling the installer to install patches up to grouper_v2_4_0_api_patch_54 and grouper_v2_4_0_ui_patch_33,
 # configured grouper-ui.properties to configure fr_fr locale
 ** grouper.text.bundle.1.language = fr
 ** grouper.text.bundle.1.country = fr
 ** grouper.text.bundle.1.fileNamePrefix = grouperText/grouper.text.fr.fr
 # checked that the Grouper UI speaks French
 # ran the Grouper installer again to apply patches grouper_v2_4_0_api_patch_55 and grouper_v2_4_0_ui_patch_34 ONLY
 # noticed that the Grouper UI is back to English

No significant error found in Grouper logs.

Attached are screenshots showing the translations problem.

### Chris Hyzer - 2020-01-24T19:16:14.585+0000

it works, but you need to adjust it to this.  then keep your file as is: 

 

grouperText/grouper.text.fr.fr.properties

 
{code:java}
###########################################
## Text bundles for UI
###########################################

# language for this bundle
# {valueType: "string", regex: "^grouper.text.bundle.([0-9]+).language$"}
grouper.text.bundle.1.language = fr

# country for this bundle
# {valueType: "string", regex: "^grouper.text.bundle.([0-9]+).country$"}
grouper.text.bundle.1.country = fr

# filename in the package grouperText that is before the .base.properties, and .properties
# {valueType: "string", regex: "^grouper.text.bundle.([0-9]+).fileNamePrefix$"}
grouper.text.bundle.1.fileNamePrefix = grouperText/grouper.textNg.fr.fr
 {code}

### Olivier SalaÃ¼n - 2020-01-31T11:08:12.164+0000

I did some remote debugging of the code (with grouper_v2_4_0_api_patch_55 and grouper_v2_4_0_ui_patch_34).

In GrouperConfig::textBundleFromCountry() method the loop through properties only finds grouper.text.bundle.1.filenamePrefix

### Olivier SalaÃ¼n - 2020-01-31T14:54:44.034+0000

Eventually I got it: grouper.text.bundle.* properties are no more loaded from grouper-ui.properties but from grouper.base.properties. 

It would be a good idea to:
- update https://spaces.at.internet2.edu/display/Grouper/Grouper+internationalization
- remove these properties from https://github.com/Internet2/grouper/blob/master/grouper/conf/grouper-ui-ng.base.properties
- add a notice/warning in https://spaces.at.internet2.edu/display/Grouper/v2.4+Release+Notes
- make the code complain if these properties are found in grouper-ui.properties
