# GRP-7589  Custom UI user environment table: render admin-configured labels as HTML again, keep data cells escaped

The 2026-Nov security review (GRP-7582, output escaping) changed customUiGroup.jsp so that the custom UI "user environment" table (shown to members of groupCanSeeUserEnvironment) and the screen-state text table HTML-escape every cell. Institutions that put formatting in their custom UI labels on purpose, for example <b>Title</b><br />Explanation or an <a href> link to a related folder or policy, now see the tags as literal text.

The label, variable name and variable type cells come from admin-written custom UI config (the customUiUserQueryConfigBeans attribute, often pointing to a text key such as ${textContainer.text['..._cu_...']}). That is the same trust level as the custom UI header, instructions and button texts, which the security fix leaves as raw HTML on purpose. Escaping the label does not add protection: anyone who can set a label can also set the header.

Change: render the label (and the variable name and type) as HTML again, the same way as the header and instructions. Keep these cells escaped, because they can carry data from a URL, a query or an outside system: variable value, script result, default, end-if-matches, and anything else built from request or query data. The description column stays as it is.

Test: a label with <b>, <br /> and <a href> renders as HTML; a url-type variable whose value contains markup is still shown as text.
