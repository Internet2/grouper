# GRP-7125  Daemon logs "Job actions" menu should include Failsafe approve (and per-run actions)

On the Daemon logs view (Home > Miscellaneous > All daemon jobs > Daemon logs, filtered to a job) you can see failed runs, including status {{{}Error_failsafe{}}}, in the log table (Status / Loaded group / Job type / counts / Log ID, etc.). The view has a "Job actions" dropdown at top right.

*Problem*

When a run shows {{{}Error_failsafe{}}}, the action to clear it -- Failsafe approve -- is driven from the separate Admin > All daemon jobs screen, not surfaced in context on the Daemon logs view where the error is actually displayed. Reviewing the failed run and acting on it happen on two different screens, so an admin has to navigate away from the evidence to approve.

*Request*

Ensure the Daemon logs "Job actions" dropdown exposes the relevant in-context actions for the currently filtered job, at minimum:
 * Failsafe approve
 * Run now
 * View config / view job message

so an admin can approve the failsafe (or re-run) directly from the log entry that shows the error, without switching screens.

*Project note*

This is a Grouper product UI concern (Internet2 GRP project, which is on-prem and cannot be filed via MCP -- draft for manual filing).
