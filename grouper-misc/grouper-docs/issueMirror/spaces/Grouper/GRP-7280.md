# GRP-7280  MCP consent screen should pick folders, groups, and subjects for the read-write data scope instead of typing them

  The read-write data scope on the MCP OAuth consent screen was three textareas of

  comma separated names. Nothing checked that what was typed existed or that the

  user could see or update it, so a typo produced a consent which looked right and

  matched nothing, and the token recorded intent which did not correspond to any

  real access. The names were only validated for existence, as root.



  Replace each textarea with a combobox plus Add, and a list of what has been

  picked with a remove link on each row. Adding and removing happen in the browser;

  each pick is a hidden field in the consent form, so nothing is held on the server

  for a consent page somebody abandons.



  The pickers offer only what the user can act on:

* folders they can see, via a new UiV2Stem.stemViewFilter

* groups they can UPDATE, via the existing UiV2Group.groupUpdateFilter

* subjects, via the existing UiV2Group.addMemberFilter



  Folder visibility is deliberately not a naming privilege check. Group privileges

  in Grouper are independent of privileges on the folder holding the group, so

  somebody can hold UPDATE on many groups without holding anything on their

  folders, and filtering on CREATE or STEM_ADMIN would hide exactly the folders

  they need to name.



  The hidden fields carry the id the combobox returns. The scope is stored by name,

  so the ids are resolved once on submit rather than on every pick, batched into one

  query per type. Resolution runs as the consenting user with the same privileges

  the picker used, so an id for anything they could not have picked does not resolve.



  A pick which fails to resolve refuses the consent rather than being dropped. An

  empty folder and group list does not mean "no groups" to the enforcement in

  GrouperMcpAuthUser, it means that dimension is unscoped, so silently dropping a

  pick would widen the consent instead of narrowing it.



  Also in this change:

* the maximum folder, group, and subject counts are enforced in submitAuthorize,

    which is the endpoint that issues the code and was reachable without the page

    or the ajax validation

* the root folder is kept out of the scope; its name is the empty string, which

    restricts nothing while still counting as a restriction

* UiV2Stem.stemViewFilter is added to the GET allow list in GrouperUiRestServlet,

    which combobox autocomplete requires
