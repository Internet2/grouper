# GRP-7202  Zoom loader fails: writes null id for pending Zoom users into NOT NULL grouper_prov_zoom_user.id

h3. Symptom

OTHER_JOB_pennZoomLoader fails on every run once the Zoom account inventory contains any user in pending status. The full-table sync into grouper_prov_zoom_user aborts with a not-null constraint violation, so the whole loader job ends in ERROR and no Zoom user data is refreshed at all.

{noformat}ERROR: null value in column "id" of relation "grouper_prov_zoom_user" violates not-null constraint{noformat}

In our case 9 pending accounts (a mix of shared mailboxes and individuals whose provisioning had been started but not completed) were enough to take the loader down completely. Because the sync batches rows, only the alphabetically first pending email appeared in the stack trace, which made the blast radius look smaller than it was.

h3. Root cause

Regression from commit c8c7327 (GRP-7129, 2026-07-10) in GrouperZoomLoader.loadUsersToTable. It deliberately substitutes null for a blank Zoom id before the row is handed to the table sync:

{code:java}gcTableSyncColumnMetadata = this.loadUsersToTableGcTableSyncTableBeanSql.getTableMetadata().lookupColumn("id", true);
if (StringUtils.isBlank((String) zoomUser.get("id"))) {
  rowData[gcTableSyncColumnMetadata.getColumnIndexZeroIndexed()] = null;
}{code}

But the id column is declared required in Grouper's own DDL, in GrouperDdl2_6_1.addGrouperProvZoomUserTable:

{code:java}GrouperDdlUtils.ddlutilsFindOrCreateColumn(grouperFileTable, COLUMN_GROUPER_PROV_ZOOM_USER_ID,
    Types.VARCHAR, "40", false, true);   // required = true -> NOT NULL{code}

So the code writes a value the schema forbids. Any Zoom tenant with at least one pending user hits this on the first loader run after upgrading past c8c7327.

h3. The premise in that commit's comment is also wrong

The comment added by c8c7327 justifies the null by reasoning about a unique index on (id, config_id), saying postgres allows multiple nulls but multiple empty strings would collide. That is not the index the sync keys on. loadUsersToTableUniqueKeyColumnNames is set to email plus config_id, and grouper_zoom_user_email_idx is the unique index on (email, config_id). Two pending users with a blank id and different emails would not have collided on the sync key, so the null substitution was not needed to make the sync work.

Related discrepancy worth a look while in this code: addGrouperProvZoomUserIndex declares grouper_zoom_user_id_idx as unique, but in our upgraded database that index exists as a non-unique btree on (id, config_id). If the intent really is a unique (id, config_id), that intent is not being realized on upgrade, and it would also be violated by more than one null-id row on databases where nulls are not distinct. If the intent is non-unique, the code should say false.

h3. Local workaround

We dropped the constraint by hand to get the loader running again:

{code:sql}ALTER TABLE grouper_prov_zoom_user ALTER COLUMN id DROP NOT NULL;{code}

The loader succeeded immediately after, syncing about 120,000 Zoom users. This is not a real fix: it is a local divergence from Grouper's DDL, and the next grouper-ddl run can put NOT NULL back and take the loader down again.

h3. Suggested fix

Skip pending users instead of inserting an illegal row. Hoist the blank-id check above row construction in loadUsersToTable and continue, and count the skips into debugMap so the daemon log reports how many pending accounts were passed over. A pending Zoom account has no Zoom user id and cannot be acted on by the web services anyway, so there is nothing lost by leaving it out of the reporting/deprovisioning table.

If the pending accounts should instead be represented in the table, then the DDL needs to make id nullable (and grouper_zoom_user_id_idx must not be unique), so that code and schema agree. Either way the current state, where the code writes null into a column the DDL marks NOT NULL, should not ship.

h3. Affected code

* edu.internet2.middleware.grouper.app.zoom.GrouperZoomLoader, loadUsersToTable (the blank-id-to-null block)
* edu.internet2.middleware.grouper.ddl.GrouperDdl2_6_1, addGrouperProvZoomUserTable and addGrouperProvZoomUserIndex
