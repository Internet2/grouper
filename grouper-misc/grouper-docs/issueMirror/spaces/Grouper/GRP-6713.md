# GRP-6713  v4-only grouper-box (legacy connector not provisioning framework) does not work

h3. Changes made

*1. {{grouper-parent/pom.xml}} line 199* — Updated okhttp version:
 * {{3.14.7}} → {{4.12.0}}

*2. {{grouper-parent/pom.xml}} line 845* — Added managed dependency for {{okhttp3:okhttp}} itself (not just {{{}logging-interceptor{}}}) to ensure consistent version resolution across all modules.

*3. {{grouper-misc/grouper-duo/pom.xml}} lines 41-53* — Removed the stale {{com.squareup.okhttp:okhttp}} exclusion (okhttp 2.x groupId, had no effect on duo-client 0.7.1 which uses okhttp3) and updated the comment.
h3. Root cause

{{duo-client}} was upgraded to {{0.7.1}} (in GRP-6522) which is compiled against {{okhttp3:4.12.0}} (Kotlin-based). But the project pinned {{okhttp.version}} to {{{}3.14.7{}}}. The {{CertificatePinner$Pin.Companion}} field is a Kotlin construct that only exists in okhttp 4.x, so at runtime it fails with {{{}NoSuchFieldError{}}}.

The old exclusion for {{com.squareup.okhttp:okhttp}} was a no-op — that's the okhttp *2.x* Maven groupId, while duo-client 0.7.1 uses {{com.squareup.okhttp3:okhttp}} (3.x/4.x groupId).
h3. Compatibility

Retrofit 2.7.2 (used by grouper-azure) is compatible with okhttp 4.x — okhttp 4.x maintains binary compatibility with 3.x consumers (same {{okhttp3.*}} package namespace).
