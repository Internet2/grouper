# GRP-7036  GSH Java template compilation — filters on the GSH template inventory list

* Phase 5. Builds on GRP-7034 (inventory compile-status columns) and GRP-7011 (modes/types). Design doc {{grouper/temp/trash/gshCompileImprovement.html}}, section "Unified admin inventory" — "Filters answer the obvious questions: migration backlog (mode = interpreted), broken artifacts (compile status = failed), ownership view (filter by type)."
 * Add three filter dropdowns above the GSH template inventory list: {*}Type{*}, *Mode* (interpreted/compiled), and *Compile status* (Compiled OK / Compile failed / Source file missing), each with an "(all)" option.
 * {{UiV2GshTemplateConfig.viewGshTemplates}} reads the three filter params from the request and filters the list of {{GuiGshTemplateConfiguration}} with explicit loops (no streams), comparing against {{getTemplateType()}} / {{getTemplateMode()}} / {{{}getCompileStatus(){}}}. The selected filter values are stored on {{GshTemplateContainer}} so the dropdowns repopulate after each filter.
 * Each dropdown's {{onchange}} re-renders the list via the standard {{ajax(...)}} helper, passing all three current selections so filters combine.
 * Externalized text for the filter labels and the "(all)" option in {{grouper.textNg.en.us.base.properties}} only.
 * No new unit test: the filtering is trivial controller glue, and exercising it requires the full UI request harness; the underlying compile-status computation is already covered by {{{}GshTemplateCompileStatusTest{}}}. Verified manually on the screen.
 * Note: filtering by compile status forces computing every template's status (cached per source hash), the same cost as rendering the column. The async background pre-warm + progress indicator on first load is a separate follow-up JIRA.
