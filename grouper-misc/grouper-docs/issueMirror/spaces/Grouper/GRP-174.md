# GRP-174  Re-importing repository fragments to a new location does not behave as expected

XML exports contain Group and Stem ids. If re-imported to the same repository the import will fail because of unique constraints.

The first version of the import/export tool allowed for relative exports so that individual groups or stems and their children could be exported and then imported in a different location. Rather than export complete path names the path representing the starting point for an export would be replaced with *. On an import the * would be replaced with the path for the import location. This does not work if the id is present.

For composites group ids are always used and no attempt is made to export a relative path prefixed with *.

If exporting a stem without the -includeParent option the stem itself should not be exported - just the children - but the stem is exported.

Most users of the tool will export / import the whole repository  and that should be working OK. I'm not sure how much of what appears to be wrong  now was always wrong or has been broken subsequently

### Gary Brown - 2008-10-30T23:05:29.416+0000

Could do with more testing...

I've added a -childrenOnly option for exporting stems i.e. ignore the actual stem and export child groups/stems only. And a -ignoreInternal option for importing which forces the importer to create new ids.

There is a new default export property:
  export.uuids=true
If overidden and set to false neither group nor stem uuids will be expotred

There is a new default import property
  import.data.ignore-internal-attributes-and-uuids=false
Whatever the value here the command line option -ignoreInternal effectively makes the value true.

There was also a bug - use of Boolean.getBoolean rather than Boolean.parseBoolean.

I updated the GSH XmlImport and XmlExport classes to add chaining methods for -childrenOnly and -ignoreInternal.

I tested against a QuickStart database - exporting the Arts faculty folder children. Created a new folder - artf-copy - and imported into this new folder. Groups and stems, including composite groups, were correctly created.
