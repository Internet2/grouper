# GRP-6938  Add phase-controlled DML to GcTableSync to support FK-ordered parent/child syncs

* Add {{GcTableSyncPhase}} enum to {{grouperClient.jdbc.tableSync}} with values {{INSERTS_UPDATES_DELETES}} (default), {{{}INSERTS_UPDATES_ONLY{}}}, and {{DELETES_ONLY}}
 * Add {{gcTableSyncPhase}} field on {{GcTableSync}} with {{getGcTableSyncPhase()}} / {{setGcTableSyncPhase(...)}} (chainable); pass through to the subtype's {{syncData}} call
 * Add overloaded {{{}GcTableSyncSubtype.syncData(debugMap, gcTableSync, phase){}}}; default implementation honors only {{INSERTS_UPDATES_DELETES}} (subtypes opt in via override)
 * Override on {{fullSyncFull}} to honor all three phases
 * Refactor {{runInsertsUpdatesDeletes}} to accept a phase and conditionally run the delete and insert/update blocks
 * Lets callers preserve foreign-key integrity across parent/child tables without {{{}ON DELETE CASCADE{}}}: insert/update parent first, child sync runs in full, then delete parent
 * Add {{TableSyncTest.testPersonSyncFullPhases}} covering all three phases end-to-end (insert/update without delete, delete without insert/update, default no-op on converged state)
