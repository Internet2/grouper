# GRP-7048  Full sync option to not retrieve users from target when they are already in the sync back tables

At 800k users, retrieving all users from the target dominates full sync runtime. Once the sync back tables are kept current on change, add an option for full sync to resolve users from grouper_prov_user instead of retrieving everyone from the target.

Options to consider:
 * Only retrieve from the target users that are missing from the sync back tables (new users), using the cached native object for the rest.
 * And/or only re-retrieve users with a reason to be re-read: error state in grouper_sync_member, recalc flag, or cached object older than a configurable max age.
 * Keep an occasional true full retrieve on a schedule to correct drift.

Config suggestion: provisioner.<configId>.fullSyncUsersFromSyncBack = true, plus a max age setting.
