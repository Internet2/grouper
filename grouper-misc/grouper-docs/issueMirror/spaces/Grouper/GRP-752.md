# GRP-752  The baseStem should be omitted (optionally) from ldap DNs 

When using the baseStem property (edu.internet2.middleware.psp.baseStem) in ldap.properties, this value is added as part of the DN with the groupsBaseDn. This could be an optional behaviour.

Related to that, the baseStem isn't provisioned automatically to the LDAP when adding groups and stems in it. Exceptions are thrown when doing any kind of provisionning as well as when doing basic searches in the Grouper UI. Manually creating the OU for the baseStem solves that problem and everything is working normally

## Comments

### tzeller@example.com - 2012-03-14T15:45:03.378+0000

The attribute definition which returns ldap dns created from grouper names now provides the ability to omit the base stem from the resulting ldap dn.

For the grouper name

 "edu:courses:course"

if the base stem is blank or omitted, the resulting ldap dn will be :

 "cn=course,ou=courses,ou=edu,ou=groups,dc=example,dc=edu"

If the base stem is "edu", the resulting ldap dn will be :

 "cn=course,ou=courses,ou=groups,dc=example,dc=edu"

see https://spaces.internet2.edu/display/Grouper/Grouper+Provisioning

  <!-- The LDAP DN of a group. For example, "cn=groupExtension,ou=stem,ou=groups,dc=example,dc=edu". -->
  <resolver:AttributeDefinition
    id="groupDn"
    xsi:type="psp-grouper-ldap:LdapDnFromGrouperNamePSOIdentifier"
    structure="${edu.internet2.middleware.psp.structure}"
    sourceAttributeID="groupNameInStem"
    rdnAttributeName="cn"
    baseDn="${edu.internet2.middleware.psp.groupsBaseDn}"
    baseStem="${edu.internet2.middleware.psp.baseStem}">
    <!-- Dependencies which return a "groupNameInStem" attribute whose value is the group name. -->
    <resolver:Dependency ref="groupNameInStem" />
  </resolver:AttributeDefinition>
