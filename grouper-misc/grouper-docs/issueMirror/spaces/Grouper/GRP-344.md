# GRP-344  Provision list attributes using Ldappc

Ldappc provisions members into LDAP group objects, but it does not provision READers, UPDATErs, ADMINs, or custom list attributes into LDAP groups. Enhance group-attribute-map capability to extend to list attributes.

## Comments

### tzeller@example.com - 2009-10-30T01:44:24.900+0000

The initial integration with the shibboleth attribute resolver GRP-329 will extend the group-attribute-map capability (resolver-attribute-map) for attributes, but not lists where an LDAP lookup is required. This requires some reworking of the LdapDataConnector. The experimental SPML2 based LDAPPC should handle this. 

### tzeller@example.com - 2010-06-17T01:32:27.052+0000

From the grouper plugin for shibboleth wiki :

https://spaces.internet2.edu/display/GrouperWG/Grouper+and+Shibboleth+Integration

The following example will return an attribute named "admin" whose values are the "name" of every Subject which has the ADMIN privilege on a group

<resolver:DataConnector id="GroupDataConnector" xsi:type="grouper:GroupDataConnector">
  <grouper:Attribute id="admins" />
</resolver:DataConnector>

<resolver:AttributeDefinition id="admin" xsi:type="grouper:Subject" sourceAttributeID="admins" >
  <resolver:Dependency ref="GroupDataConnector" />
  <grouper:Attribute id="name" source="jdbc" />
</resolver:AttributeDefinition>
