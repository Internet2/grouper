# GRP-6918  Datadog provisioner fails demoting team admin due to invalid role value

* When the Datadog provisioner removed admin privileges from a team member, it sent {{PATCH /api/v2/team/\{teamId}/memberships/\{userId}}} with {{{}role: "member"{}}}.
 * Datadog rejects this with HTTP 400: {{{}invalid role value: member. Only 'admin' is supported, or omit role to remove admin privileges{}}}.
 * Fix: when demoting an admin, omit the {{role}} attribute from the PATCH body instead of sending {{{}"member"{}}}. The user stays a team member and loses only the admin flag, matching Datadog's documented behavior.
 * Updated {{DatadogApiCommands.updateTeamMembershipRole}} to accept a null/blank role and omit the field from the JSON when blank.
 * Updated {{DatadogTargetDao.updateGroup}} to pass {{null}} for the role on admin delete (previously {{{}"member"{}}}).
 * Updated the Datadog mock service handler to match the real API: rejects non-admin role values with 400, treats omitted role as demote to member.
 * Extended {{teamAdminMetadata}} provisioner test to cover a demote+promote swap in addition to the initial promote, for both full-sync and incremental modes.
 * Updated {{testUpdateTeamMembershipRole}} and {{testRetrieveTeamsWithAdmins}} to pass {{null}} (not {{{}"member"{}}}) for demote calls.
