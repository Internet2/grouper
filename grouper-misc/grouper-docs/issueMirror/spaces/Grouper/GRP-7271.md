# GRP-7271  grouper-jira skill: document todos.grouper.internet2.edu as the same Cloud instance as grouper.atlassian.net

The grouper-jira skill (grouper-misc/grouper-docs/skills/grouper-jira/SKILL.md) did not explain that the GRP tracker answers on two hostnames. People commonly refer to it by the vanity display URL todos.grouper.internet2.edu, which led to it being mistaken for a Jira Server/Data Center instance, or for the frozen on-prem tracker, and therefore to the wrong REST API version and description format being used.

Clarified in the skill that grouper.atlassian.net is the API baseUrl and must be used for REST, while todos.grouper.internet2.edu is only a vanity displayUrl for the SAME Cloud instance. A todos.grouper.internet2.edu link therefore does not mean the project moved off Cloud: /rest/api/3, ADF descriptions, and the documented transition ids all still apply. Confirmed with GET /rest/api/3/serverInfo, which reports deploymentType Cloud, baseUrl https://grouper.atlassian.net and displayUrl https://todos.grouper.internet2.edu. That endpoint is unauthenticated, so it is now recommended as the one call that settles which flavor you are talking to.

Also kept the warning that the OLD on-prem tracker at bare todos.internet2.edu (no dot-grouper-dot) is a different, frozen instance that must not be touched, and noted that the Confluence wiki has the same arrangement with displayUrlConfluence docs.grouper.internet2.edu, cross referencing the grouper-confluence-edit skill. The skill description was updated so it also triggers when a user names the vanity URL.
