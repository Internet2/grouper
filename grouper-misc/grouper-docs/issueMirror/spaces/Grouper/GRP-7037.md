# GRP-7037  GSH Java template compilation — AI instructions and wiki docs for compiled GSH templates

* Phase 6 (documentation / conversion). Design doc {{grouper/temp/trash/gshCompileImprovement.html}}, Phase 6.
 * AI instruction set for compiled GSH templates (Grouper 7.3.0+), kept separate from the legacy interpreted files so the AI GSH agent stays correct across all supported Grouper versions:
 ** New {{grouper/misc/aiGsh/aiGshInstructionsCompiled.txt}} — compiled-Java rules: real idiomatic Java (none of the Groovy workarounds), the base class and method per templateType (gsh/abac, provisioner, daemon, daemonChangeLog, report, customUi, hook, library), class requirements, inputs, the library/inter-template sharing patterns, house style (no streams/lambdas).
 ** New {{grouper/misc/aiGsh/aiGshCompiled.txt}} — one worked compiled example per type, with all APIs verified against the code.
 ** The legacy {{aiGshInstructions.txt}} / {{aiGsh.txt}} are unchanged (interpreted Groovy, all versions). Both compiled files state up front that compiled mode is 7.3.0+ only and to confirm the user's version.
 ** {{CLAUDE.md}} AI/GSH section updated to point to the compiled files for 7.3.0+ and the legacy files for interpreted/older versions.
 * Confluence wiki drafts (copy-paste HTML) under {{{}grouper/temp/trash/gshCompiled/{}}}:
 ** {{writing-gsh-templates-in-java.html}} — reference: enabling compiled mode, class requirements, base-class-per-type table, worked example, inputs, statics/classloader/hot-reload, sharing patterns, compile-on-save and inventory.
 ** {{migrating-a-groovy-gsh-template-to-java.html}} — conversion steps, "workarounds you can drop" table, before/after, AI-assist workflow, common gotchas, and a prominent *"must be completed before upgrading to v9"* callout (v9/v10 removes the Groovy path; the v9 upgrade fails if interpreted templates remain).
 ** {{debugging-a-compiled-gsh-template-in-an-ide.html}} — remote-debug setup, breakpoints in template source, hot-reload and multi-JVM notes.
