# GRP-2170  change logging for EventLog session starts from INFO->DEBUG

In the grouper logs, the EventLog class logs some auditing type actions like adding, deleting, or updating objects. But it also logs every time a session is created with a "session: start" entry, which I don't think is useful except for debugging. In a healthy setup without many errors, these "session: start" entries end up being most of the grouper log. Since both the actions and the session starts are logged at INFO level, there is no way to filter out the useful information from the less than useful.

FYI this info-level logging was added Dec 15 2005, so v0.9.

### Chad Redman  (unc.edu) - 2019-08-12T00:10:02.849+0000

Instead of changing log level, I took the logging out of EventLog (which doesn't log the caller line so it's of limited usefulness) and moved it directly into GrouperSession. To get back similar behavior as before, set log4j "log4j.logger.edu.internet2.middleware.grouper.GrouperSession = INFO".

 

FYI, the equivalent "session: stop" logging was unceremoniously removed a number of years ago.
