# GRP-7386  Only wheel or root can enter expression language in UI configuration forms

Expression language in configuration values is evaluated server side, so entering it should be a sysadmin capability. Today whether a field can be expression language is decided by a checkbox the form posts, and some configuration screens can be opened by people who are not sysadmins (e.g. daemon jobs via uiV2.admin.daemonJobs.must.be.in.group).

Changes: GrouperConfigurationModuleBase honors the posted expression language flag only if the module allows it and the current Grouper session subject is wheel or root (no session means no). For other people the posted text is literal and never evaluated, and a field that is already expression language in config is kept as is rather than overwritten. The configFormElement tag throws if it would render the expression language checkbox for a subject who is not wheel or root, and the daemon job screens pass the checkbox flag based on the viewer.

Follow on to GRP-7385.
