# GRP-7533  WS bearer token external system: configurable additional HTTP headers (e.g. anthropic-version), so the Anthropic Test button passes

Problem: the WS bearer token external system (grouper.wsBearerToken.<configId>.*, class WsBearerTokenExternalSystem) can only send its authentication header (httpHeader, or apiKeyHeaderName for client credentials). There is no way to configure other HTTP headers that a target API requires. Example: the Anthropic API needs an anthropic-version header on every request, so the external system Test button for an anthropic bearer token external system always fails (GET with no anthropic-version gets an error), even though the key is correct. The Grouper UI AI assistant works only because GrouperAiAnthropicClient adds anthropic-version itself. Other APIs need things like an Accept header, a tenant id header, or an API version header.

Add a configurable list of additional HTTP headers to the WS bearer token external system.

New config in grouper-loader.base.properties, in the wsBearerToken section (use the usual numbered-config pattern with showEl, like other external systems):

# Number of additional HTTP headers to send on every request with this external system
# {valueType: "integer", order: <after httpHeader>, regex: "^grouper\\.wsBearerToken\\.(\[^.\]+)\\.numberOfAdditionalHeaders$", formElement: "dropdown", optionValues: ["0", "1", "2", "3", "4", "5"]}
# grouper.wsBearerToken.myWsBearerToken.numberOfAdditionalHeaders =

# Name of additional HTTP header 0, e.g. anthropic-version
# {valueType: "string", required: true, showEl: "${numberOfAdditionalHeaders > 0}", regex: "^grouper\\.wsBearerToken\\.(\[^.\]+)\\.additionalHeader\\.0\\.name$"}
# grouper.wsBearerToken.myWsBearerToken.additionalHeader.0.name =

# Value of additional HTTP header 0, e.g. 2023-06-01
# {valueType: "string", required: true, showEl: "${numberOfAdditionalHeaders > 0}", regex: "^grouper\\.wsBearerToken\\.(\[^.\]+)\\.additionalHeader\\.0\\.value$"}
# grouper.wsBearerToken.myWsBearerToken.additionalHeader.0.value =

# If the value is a secret: store it encrypted, mask it in the UI, and never log it
# {valueType: "boolean", defaultValue: "false", showEl: "${numberOfAdditionalHeaders > 0}", regex: "^grouper\\.wsBearerToken\\.(\[^.\]+)\\.additionalHeader\\.0\\.valueIsSecret$"}
# grouper.wsBearerToken.myWsBearerToken.additionalHeader.0.valueIsSecret =

(repeat for indexes 1 to 4, with showEl numberOfAdditionalHeaders > n)

How it should work:
- In WsBearerTokenExternalSystem.attachAuthenticationToHttpClient(), after the authentication header is added, add each configured additional header with grouperHttpClient.addHeader(name, value). That method is used by the external system Test button and by every caller (provisioners, the AI agent, etc.), so the headers go on every request, including retries
- If valueIsSecret is true: the value is a password-type config (encrypted in the database config, masked in the UI) and the header is passed to grouperHttpClient.addDoNotLogHeader(name) so it is never logged. Otherwise the header can be logged like any other
- A header name must not be blank and must be a valid HTTP header token. Validate in the external system config validation (validatePreSave or equivalent), with a clear error on save
- Do not allow an additional header to replace the authentication header: if a name equals the configured httpHeader (default Authorization) or apiKeyHeaderName, case-insensitive, fail validation on save
- If a caller later sets the same header itself (e.g. GrouperAiAnthropicClient sets anthropic-version), the caller's value wins, so existing code does not change behavior. Make sure the header is not sent twice
- Blank numberOfAdditionalHeaders or 0 means no change from today

Example that should make the Anthropic Test button succeed:
grouper.wsBearerToken.anthropic.endpoint = https://api.anthropic.com/v1
grouper.wsBearerToken.anthropic.httpHeader = x-api-key
grouper.wsBearerToken.anthropic.prependBearerTokenPrefix = false
grouper.wsBearerToken.anthropic.accessTokenPassword = <key>
grouper.wsBearerToken.anthropic.testUrlSuffix = models
grouper.wsBearerToken.anthropic.numberOfAdditionalHeaders = 1
grouper.wsBearerToken.anthropic.additionalHeader.0.name = anthropic-version
grouper.wsBearerToken.anthropic.additionalHeader.0.value = 2023-06-01

Tests:
- Unit test that attachAuthenticationToHttpClient adds the configured headers, marks secret ones as do-not-log, and adds nothing when numberOfAdditionalHeaders is blank or 0
- Validation tests: blank name, invalid name, and a name equal to the auth header are rejected
- Caller-set header wins over the configured one, and is sent once

Docs: update the WS bearer token external system wiki page with the new settings and the Anthropic example, and the AI assistant (grouper.ai.agent) setup docs so the Test button can be made to pass.

Found in the TechEx 2026 Grouper MCP/AI training: lesson 07 tells attendees to ignore the failed Test button on the anthropic external system. When this ships, the lesson can add the two header lines and testUrlSuffix instead.
