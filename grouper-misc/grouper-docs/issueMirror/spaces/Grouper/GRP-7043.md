# GRP-7043  membership requirements: require group lookup loses configs when two configs share a require group

In MembershipRequireEngine.membershipRequireConfigBeans(), the block populating the
requiredGroupNameToConfigBean map got by attribute name but put by require group name.
The get always missed, so every config created a fresh set, and when two
membershipRequirement configIds pointed at the same requireGroupName the second put
replaced the first set, losing the first config from the lookup.
 
requiredGroupNameToConfigBean() feeds the changelog consumer's MEMBERSHIP_DELETE
handling, so when a member was removed from the shared require group the consumer
would only clean that member out of groups under one of the configs. The full sync
daemon was unaffected and would catch the rest on its next run.
 
Fixed the get to use the group name and added testSharedRequireGroup asserting both
config beans are returned for a shared require group.
