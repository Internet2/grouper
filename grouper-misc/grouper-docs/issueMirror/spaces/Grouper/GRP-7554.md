# GRP-7554  Data field/row lifecycle triggers use end_time < and never match recent removals

*Summary* {{dataFieldRemove}} and {{dataRowRemove}} triggers only find history rows that ended more than a year ago, so a recently removed value or row never creates a lifecycle event.

*Cause* {{UserLifecycleFullDaemon}} computes {{endTimeBeforeMicros = now - 365 days}} and passes it to:

* {{GrouperDataFieldAssignHstDao.selectByDataFieldInternalIdAndEndTimeBefore}} ({{... and end_time < ?}})
* {{GrouperDataRowAssignHstDao.selectByDataRowInternalIdAndEndTimeBefore}} ({{... and end_time < ?}})
* the matching {{GrouperDataRowFieldAssignHstDao}} method (data row column triggers)

This selects history older than one year. The wiki ("looks back roughly one year") and the membership triggers ({{start_time > microsUntilLastYear}}, {{flattened_add_timestamp > ...}}) expect rows newer than the cutoff, i.e. {{end_time > ?}}.

*Steps to reproduce*

# Set {{grouperDataRow.hr_position.rowDataStorePit = true}}.
# Define event {{hrPositionLost}} with trigger {{dataRowRemove}}, row {{hr_position}}, and run the full sync so {{grouper_lifecycle_event_config}} has a row.
# Delete a user's job from the source table, run the data provider full sync. A row appears in {{grouper_data_row_assign_hst}} with {{end_time}} = now.
# Run {{OTHER_JOB_userLifecycleFullDaemon}}.

*Expected:* a row in {{grouper_lifecycle_event}} for that user. *Actual:* none. Running the daemon's query by hand: {{end_time < now-365d}} returns 0 rows, {{end_time > now-365d}} returns 1.

*Suggested fix:* change the comparison to {{>}} in the DAO methods (and rename the methods/parameter, e.g. {{...AndEndTimeAfter}}).
