# GRP-7408  Data provider DAOs query 1000 members per batch instead of 200

The data provider full sync (GrouperDataProviderLogic.syncFull) loads existing Grouper data with GrouperDataRowAssignDao, GrouperDataRowFieldAssignDao and GrouperDataFieldAssignDao selectByProviderAndMembers, and GrouperDictionaryDao selectByDataProviderAndMembers. Each of these chunks member internal ids into SQL IN lists of 200.

For a large provider (525k members, 3.6M row field assigns) that is roughly 8,000 database round trips, about 34 minutes of a 37 minute full sync (millisRetrievedFromGrouper 2025539). Each individual query is fast; the time is in the number of round trips.

Raise the chunk size to 1000 in those four DAOs (Oracle allows at most 1000 items in an IN list; Postgres and MySQL allow more). This is about 5x fewer round trips with the same SQL.

Possible follow-up: for a full sync, load each subject id range batch with one join per table (filtered by provider and subject id range against grouper_members) instead of IN lists.
