# GRP-3626  Add member text box should not encode character entities (e.g. &amp;) in display name

When adding a member to a group, if a group display name is, for example, "basis:Human Resources:Employee:Department:Budget & Finance (10810):Budget & Finance staff", what appears in the text box after subject resolution is "basis:...Budget &amp;amp; Finance (10810):Budget &amp;amp; Finance staff". So the character entities are escaped (or maybe double escaped?) when appearing in the field.

## Comments

### Chad Redman  (unc.edu) - 2022-01-21T05:29:55.820+0000

The dojo combo box logic class was serializing the filtered objects with an id and a label, and encoding html entities on both of these. It didn't need to do that, since they are for internal javascript values, and not for generating html.

No idea why, when it was doing the encoding of the label, the dojo widget unencoded it when displaying in the found results, but left it as is when putting the chosen result in the textbox.
