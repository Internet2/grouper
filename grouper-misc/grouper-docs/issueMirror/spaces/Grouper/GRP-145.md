# GRP-145  move gsh, loader, usdu into the grouper source tree

_(no description)_

## Comments

### mchyzer - 2008-07-21T21:11:29.146+0000

This is done.

GSH, usdu, and loader are now in the grouper source path.  This reduces the amount of code/config, consolidates unit tests, make deployment less risky since they are integrated, makes deployment easier (fewer steps), etc.

All the unit tests are now integrated in the grouper SuiteDefault test suite.

The build.xml (in init) will generate the batch and shell scripts (though there arent any variables, maybe they will be customized).  It also fixes line endings and unix permissions.  I assume in a binary distribution the scripts will be ready to use.  The scripts are in grouper_home/bin.  The current dir when executing the scripts must be grouper_home or grouper_home/bin.  The grouper_home/conf dir will be the config dir.  If the script is kicked off from other than the allowed dirs, a descriptive error will be displayed and the script will exit.

We could at some point make a dummy extension so we know all the build scripts etc for extensions still work.  (e.g. one that prints out how many groups are in registry or something)

Also, I added ant-contrib to the grouper build file.  It has worked well with WS, and it makes
conditionals very easy to code and maintain.

    <!-- if there is no loader bat/sh, copy from example -->
    <if>
      <not>
        <available file="bin/grouperloader.bat" />
      </not>
      <then>
        <copy file="bin/grouperloader.example.bat" tofile="bin/grouperloader.bat" />
      </then>
    </if>
    <if>
      <not>
        <available file="bin/grouperloader.sh" />
      </not>
      <then>
        <copy file="bin/grouperloader.example.sh" tofile="bin/grouperloader.sh" />
      </then>
    </if>
