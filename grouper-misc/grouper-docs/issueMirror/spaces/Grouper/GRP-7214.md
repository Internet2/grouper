# GRP-7214  MCP server should not require the Mcp-Session-Id header

The MCP servlet returned HTTP 400 for any request other than initialize that did not carry an Mcp-Session-Id header. Sessions and that header were removed from the Streamable HTTP transport in MCP spec revision 2026-07-28, so clients on that revision send no session id and never call initialize — every request failed, and with a Tomcat HTML error page rather than a JSON-RPC error, so the client could not interpret the failure.



The server kept no state against the session id: it was minted on initialize, echoed back in a response header, and never looked up or validated (any non-blank value passed). The header is now accepted but optional. Clients on spec 2025-03-26 are unaffected, since a session id is still minted for them on initialize.



MCP_PROTOCOL_VERSION stays at 2025-03-26 — this removes the transport blocker but does not make the server conformant to 2026-07-28, which still needs server/discover, resultType, and CacheableResult fields.
