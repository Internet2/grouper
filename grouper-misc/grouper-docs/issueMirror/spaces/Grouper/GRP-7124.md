# GRP-7124  Data provider failsafe boolean should default globally and allow blank (inherit), not mandate true/false

The per-provider failsafe enable flag on Grouper data providers ({{{}grouperDataProvider.<id>{}}} / the {{failsafeUse}} "Failsafe enabled" attribute) must be set to an explicit {{true}} or {{false}} once the provider config exists. There is no way to leave it blank/unset so it falls back to an upstream global default.

*Current behavior*
 * Once a data provider is configured, the failsafe boolean is a required true/false.
 * A blank value is not accepted or not honored, so it cannot defer to a global setting.
 * The same pattern affects {{readOnly}} and other data-provider boolean attributes.

*Impact*
 * The default cannot be managed centrally -- every provider hard-codes its own value.
 * To change the intended default across providers you must edit each one individually.
 * Easy to get drift/inconsistency between providers, and no single knob to flip behavior fleet-wide.

*Desired behavior*
 * Define a global default for the data-provider failsafe boolean (and {{{}readOnly{}}}).
 * Allow the per-provider attribute to be left blank/unset and inherit that global default.
 * Resolution order: explicit per-provider value, else global default, with the effective value shown in the UI so it is clear what a blank is resolving to.
 * Apply the same blank-to-inherit treatment to the other data-provider boolean/threshold attributes for consistency.
