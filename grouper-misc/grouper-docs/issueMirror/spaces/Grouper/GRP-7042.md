# GRP-7042  membership requirements: exempt subject sources from eligibility checks (sourceIdsToIgnore)

The membership requirement feature (grouper.membershipRequirement.<configId>.*) vetoes
membership adds and removes existing members when the subject is not in the configured
require group. Today the check applies to subjects from every source (group subjects
g:gsa are hardcoded exempt). When the require group only contains people (e.g. an
employee population), subjects from other sources such as service principals can never
be added to a group with a requirement assigned, even though the requirement is only
meant to constrain people.
 
This adds an exempt source list, global with a per config override:
 
# comma separated subject source ids exempt from all membership requirements
grouper.membershipRequirement.sourceIdsToIgnore =
 
# per config override (blank means use the global setting)
grouper.membershipRequirement.<configId>.sourceIdsToIgnore =
 
Subjects from an exempt source pass the eligibility check without being in the require
group, in all three enforcement paths: the pre-add membership hook veto
(MembershipRequireEngine.validMember), the full sync daemon, and the changelog consumer
(both via MembershipRequireEngine.removeInvalidMembers). Group subjects (g:gsa) remain
always exempt. Blank config keeps current behavior, fully backward compatible.
 
Since the exemption is per configId, multiple requirements scoped to different sources
can be assigned to the same group, e.g. people must be in an employee group while
service principals must be in an approved service accounts group.
 
Changed:
- MembershipRequireConfigBean: new sourceIdsToIgnore field
- MembershipRequireEngine: config parsing (per config falls back to global), source
check in validMember, source exclusions in the removeInvalidMembers sql
- grouper.base.properties: documented both keys (grouper/conf and grouper-ui copy)
- MembershipRequireEngineTest: testSourceIdsToIgnoreHook (veto, global and per config
override), testSourceIdsToIgnoreFullSync (daemon keeps exempt members), and a
testConsumer addition covering the memberId scoped removal with an exempt source
configured (all sql bind segments exercised)
