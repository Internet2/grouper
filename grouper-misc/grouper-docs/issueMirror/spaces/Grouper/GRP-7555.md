# GRP-7555  Lifecycle events groupUserRemove event templates render wrong group variable values

*Summary* For trigger {{groupUserRemove}}, {{${groupName}}}, {{${groupDisplayExtension}}} and the other group variables render wrong values (the group's UUID, a timestamp, etc.).

*Cause* In {{UserLifecycleFullDaemon}}, the {{groupUserRemove}} branch loads the group with {{SELECT * FROM grouper_groups WHERE internal_id = ?}} and then reads the result columns by position ({{groupAttributes[0]}} as name, {{[1]}} as display name, and so on). With {{SELECT *}} column 0 is the group id, so every value is shifted. The {{groupUserAdd}} branch selects {{name, display_name, extension, display_extension, description}} explicitly and is correct.

*Observed* Event config {{groupUserRemoveGroup = ref:role:all_facstaff}}, privileged template {{HR position lost (removed from ${groupDisplayExtension})}} produced {{HR position lost (removed from 1788831614613)}}. With {{${groupName}}} it produced the group's UUID.

*Suggested fix:* use the explicit column list as in the {{groupUserAdd}} branch (check {{groupUserRemoveFromFolder}} too). The JEXL tester and pre-save validation use stub values, so they would not catch this.
