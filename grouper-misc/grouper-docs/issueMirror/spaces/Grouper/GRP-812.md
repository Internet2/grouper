# GRP-812  [psp] memory issue with bulk sync

It seems difficult to bulk provision a large number of new groups to LDAP.  If you're loading course terms and each term has 50,000 groups/500,000 memberships, you can easily run into memory issues.  Even if you give 3GB of memory to the bulk sync process, it gets to the point of doing constant full GCs and eventually throws an out of memory exception.  It seems that's the case because the bulk sync process keeps all the diffs in memory.  I wonder if it would make sense to either process the diffs immediately (rather than all at the end) so they don't have to be kept in memory.  Or write the diffs to a file (again so everything doesn't have to be kept in memory).

### tzeller@example.com - 2012-06-26T01:26:25.687+0000

(1) I changed the bulk sync code. It now looks like

 for each identifier
  calc(id)
  diff(id)
  sync(id)

instead of

  bulkDiff()
  for each diff in bulkDiff {
    ...
  }

to reduce the spml memory footprint.

(2) New configuration options control whether or not individual diffs and syncs are included in bulk responses, also to reduce memory consumption.

For the change log, in grouper-loader.properties :

 # Omit diff responses from bulk response to conserve memory.
 changeLog.psp.fullSync.omitDiffResponses = true

 # Omit sync responses from bulk response to conserve memory.
 changeLog.psp.fullSync.omitSyncResponses = true

And for gsh :

 bin/gsh.sh -psp -bulkSync --omitDiffResponses --omitSyncResponses
