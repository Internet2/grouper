# GRP-7362  GSH template form renders on a folder where the template is not configured to show

A GSH template form can be rendered on any folder by passing {{templateType}} in the URL, even when the template's folder show configuration excludes that folder. The template listing is filtered correctly, so this is only reachable by URL.

*To reproduce*

# Configure a gsh template with {{showOnFolders = true}}, {{folderShowType = certainFolders}}, and {{folderUuidToShow}} set to folder A.
# Browse to unrelated folder B. The "Template to run" dropdown correctly does not offer the template.
# Visit {{UiV2Main.index?operation=UiV2Template.newTemplate&stemId=<folder B>&templateType=<configId>}}.
# The template's form renders on folder B, with its description and inputs.
# Submit. It fails with a raw RuntimeException rather than a validation message.

*Cause*

{{UiV2Template.newTemplateHelper}} (grouper-ui/java/src/edu/internet2/middleware/grouper/grouperUi/serviceLogic/UiV2Template.java:1285) reads {{templateType}} from the request and renders the form. It resolves the stem or group and checks that {{templateType}} is non-blank, but never calls {{GshTemplateConfig.canFolderRunTemplate}} / {{canGroupRunTemplate}}.

The listing path does call it — {{GroupStemTemplateContainer.java:500}} and {{:511}} — which is why the dropdown is correct and only the direct URL is affected.

Execution is also protected: {{GshTemplateValidationService.validateOwnerType}} (grouper/src/grouper/edu/internet2/middleware/grouper/app/gsh/template/GshTemplateValidationService.java:94) throws

{noformat}ownerStem <name> is not allowed to run this gsh template{noformat}

so nothing executes against a folder outside the configured scope. {{securityRunType}} is enforced independently in {{validateSecurityRunType}}.

*Impact*

Not a privilege escalation — the template cannot be executed against an out-of-scope owner, and run security is unaffected. Two user-visible problems:

* A form is presented that cannot be submitted.
* The failure is an unhandled RuntimeException rather than a validation line, so the user sees an error instead of an explanation.

*Suggested fix*

In {{newTemplateHelper}}, after resolving the stem/group and reading {{templateType}}, call {{canFolderRunTemplate(stem)}} / {{canGroupRunTemplate(group)}} and, when false, skip rendering and add a validation message such as "this template is not available on this folder". That makes the URL path agree with the listing path and turns the exception into a message.
