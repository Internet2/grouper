# GRP-7500  UI: block clearing provisioner cache/state while a full or incremental sync job is running

The provisioner config screen actions "Clear all provisioning cache and state" and "Clear cache buckets" ran with no check for running sync jobs. Clear all deletes the grouper_sync membership, group, member, job and log rows and the grouper_sync row. Full and incremental syncs coordinate through heartbeats on the grouper_sync_job rows, so clearing state while a job is running lets a full and an in-flight incremental run at the same time, and the running job keeps working off in-memory sync data that no longer matches the database. A site on 6.3.0 reported about 150k memberships deleted in Entra this way while the full sync logged 0 deletes.

Now both actions refuse (with a UI error) if any sync job for the provisioner is running or pending with a heartbeat in the last 90 seconds, the same staleness rule the jobs use with each other. The message tells the admin to disable the full and incremental jobs and wait for them to finish, clear, enable and run the full job from the daemon jobs screen, then enable the incremental job after the full finishes.
