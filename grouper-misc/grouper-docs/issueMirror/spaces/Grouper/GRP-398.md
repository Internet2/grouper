# GRP-398  revise subject API

_(no description)_

## Comments

### mchyzer - 2009-09-02T05:55:39.524+0000

The subject API has been revised in the following ways:

Subject interface:
1. Its serializable, so you can safely keep a subject in a J2EE session
2. getAttributeValue(String) is documented that if it isi a multi-valued attribute, it should return the first value.  If none, return null.
3. getAttributeValueSingleValued(String) is a new method (blows up if multiple values)
4. getAttributeValueOrCommaSeparated(String) is a new method, for printing all attribute values at once (for UIs)
5. getSourceId() is a new method (why should you have to go through a source)
6. getTypeName() is a new method (why go through type)
7. documented that equals, hashcode, and tostring should exist and be based on sourceId and subjectId (should use static helpers from SubjectImpl)

SubjectImpl class.  This is an implementation of the Subject interface that all implmentations should be replaced with, or should subclass, or should delegate to.  This will me changes to the interface a lot easier, since it might not require recoding (e.g. getAttributeValueSingleValued() ).  Several Subject implementations have been removed from the Subject API and Grouper.

This is Subject API 0.4.6.
