# GRP-7066  Accessibility: Add labels to form controls flagged by WAVE "Missing form label"

Problem
WAVE reports "Missing form label" errors on Grouper UI pages: form controls
(select / input / textarea) that have no programmatically associated label, so
screen-reader users can't tell what the control is for. This fails WCAG 2.x
(1.3.1 Info and Relationships, 4.1.2 Name, Role, Value).

Scope
Grouper UI JSPs under grouper-ui/webapp/WEB-INF/grouperUi2/ (branch
GROUPER_7_BRANCH). A code scan suggests the issue affects a number of pages
(roughly ~100 JSPs as a rough, unverified estimate); WAVE on each running page
is the source of truth. Work will be done incrementally, one page (or small
group of related controls) at a time, each verified in WAVE.

Approach
- Preferred: associate a visible label via <label for="controlId"> when a label
  text already exists near the control.
- When there is no visible label by design (e.g. a search/filter box), add
  aria-label referencing externalized text:
  aria-label="${textContainer.textEscapeXml['ariaLabelXxx']}"
  with the key defined in
  grouper-ui/webapp/WEB-INF/classes/grouperText/grouper.textNg.en.us.base.properties
- No visual change to the UI (labels add semantics only).
- Decorative/no-op controls handled appropriately (no noise added).

Acceptance criteria
- On each page touched, WAVE reports 0 "Missing form label" errors.
- No new WAVE errors or alerts introduced.
- Page looks the same as before.
- Controls reachable by keyboard and announce a meaningful name in a screen
  reader (VoiceOver spot check).

Testing
- WAVE before/after on each affected page (record baseline, confirm cleared).
- Keyboard tab-through of the affected controls.
- VoiceOver spot check that each control announces its label.

## Comments

### Reed Hyzer - 2026-06-30T16:52:23.816+0000

*Summary*

Add programmatic labels to form controls across the Grouper UI (grouper-ui) that WAVE flagged as "Missing form label," so every input/select/textarea/checkbox/radio has an accessible name for screen readers. Targets were identified by running the WAVE browser extension on each screen.

*Background*

Many UI controls rendered with only a visible caption, a placeholder, or a {{<label>}} whose {{for}} didn't match the control's {{id}} — so assistive tech and WAVE saw them as unlabeled. This change associates each control with a name using the least-invasive method per case (no visual change).

*What changed (by area)*
 * *Table/list filters* (group/subject/stem/attr-def members & memberships, config, action filters): {{aria-label}} (mirroring the placeholder, or the established {{{}ariaLabelGuiEntityName{}}}).
 * *Select-all checkboxes* (privilege/membership/contents tables, ~24 files): moved the name into the wrapping {{<label>}} as visually-hidden {{sr-only}} text and removed the conflicting {{aria-label}} (fixes empty/duplicate label).
 * *Audit date filters* (5 audit pages): {{aria-label}} "From date" / "To date".
 * *Add-member widget* (group/subject/stem/attr-def headers, group import, visualization, loader edit, deprovisioning search, external invite): labeled the subject-search box and exact-match checkbox.
 * {*}Comboboxes (TomSelect){*}: {{grouperUi.js}} now copies the page's label onto the generated {{role="combobox"}} control and the hidden original input (TomSelect relocates the original {{{}<label>{}}}); plus repointed/added {{<label for>}} on ~25 combobox usages (attribute assignment, permissions, reports, workflow, etc.).
 * *Abbreviate textarea* ({{{}GrouperAbbreviateTextareaTag.java{}}}): added {{aria-label}} to the hidden "full text" textarea used on the configuration page, logs, provisioning, and other screens (cleared ~180 findings on the Configuration page alone).
 * *Config form elements* ({{{}ConfigFormElement.java{}}}): added {{{}aria-label{}}}s to config value controls and fixed a malformed {{{}<label for>{}}}.
 * *Admin/wizard selects* (daemon jobs add/edit/list, loader failsafe, rules, provisioning, provisioner config, subject-source compare, edit composite, deprovisioning affiliation, stem delete, history-chart scale, user-lifecycle types): repointed mismatched/orphaned {{{}for{}}}, added missing {{{}for{}}}, or added {{aria-label}} where no label existed.
 * {*}Attribute definition new/edit{*}: repointed the type/value-type select labels, converted the 12 "assign-to" text spans to {{{}<label for>{}}}, added {{{}id{}}}s to the multi-assignable/multi-valued checkboxes, and de-orphaned the "Assign to" group heading.
 * {*}Group edit{*}: fixed the user-lifecycle-policy radios ({{{}<span for>{}}} → {{{}<label for>{}}}).
 * *New-object pages* (folder/group/local-entity/attr-def-name/template): labeled the "name different than id" checkbox and the folder/group search box.
 * {*}Page title{*}: populated the empty {{grouperHomePageTitle}} ("Home") so the dashboard has a descriptive {{<title>}} (WAVE "uninformative page title").

*New text keys* (English {{.base}} only — confirmed sufficient with Chris): {{{}ariaLabelGuiSelectAll{}}}, {{{}ariaLabelGuiFromDate{}}}, {{{}ariaLabelGuiToDate{}}}, {{{}guiAbbreviateTextareaAriaLabel{}}}; and {{grouperHomePageTitle}} populated.

*Deployment notes*
 * JSP/JS/properties changes deploy with a normal republish + browser hard-refresh.
 * {*}Java changes require a Tomcat restart{*}: {{{}ConfigFormElement.java{}}}, {{{}GrouperAbbreviateTextareaTag.java{}}}.
 * {{grouperUi.js}} is referenced with a static {{?ver=}} — bump it on release so clients fetch the updated script.

*Verification*

WAVE was re-run on the reachable screens (groups, folders, subjects, attribute defs, configure, audits, daemon jobs, etc.) to confirm the "Missing form label" count dropped to 0. Deep admin/feature-gated screens (some provisioning, workflow, user-lifecycle, rules) are code-verified using the same patterns but not individually WAVE-verified.

*Out of scope / follow-ups*
 * Pre-existing *"Multiple form labels"* on the privilege/members *filter controls* — caused by the basic/advanced dual-layout duplicating {{{}<label for>{}}}; needs a structural fix (separate ticket).
 * Re-check {{dictSearchText}} in WAVE (already has a label; may have been mis-bucketed).
