# GRP-7057  Add primary key to grouper_stem_view_privilege on (member_uuid, stem_uuid, object_type).

{{grouper_stem_view_privilege}} currently has no database primary key — only two non-unique indexes. The Hibernate mapping ({{{}Hib3StemViewPrivilegeDAO.hbm.xml{}}}) already declares those three columns as a {{{}<composite-id>{}}}, so the application already treats the triple as the identity of a row. This change makes the database schema match the ORM contract.

Every table should have a primary key as a matter of good database practice: it enforces row uniqueness, documents the natural key, and enables features that depend on uniquely identifying a row (logical replication, for example, requires a primary key or replica identity to replicate UPDATE/DELETE).

This change is behavior-safe given how the table is maintained:
 * All three columns are {{{}NOT NULL{}}}, and together form the natural key (the same triple already used as the Hibernate composite-id).
 * Inserts are existence-guarded ({{{}select count(1) ...; insert only if 0{}}}), deletes are by the full triple, and there are no UPDATEs — so the constraint matches existing write behavior.

*Naming:* {{grouper_stem_v_priv_pk}} — follows the existing {{grouper_stem_v_priv_*}} index prefix on this table and stays within the 30-character identifier limit for Oracle compatibility.
h2. DDL (PostgreSQL)

Upgrade (table already exists):


 
 
 
ALTER TABLE grouper_stem_view_privilege
ADD CONSTRAINT grouper_stem_v_priv_pk
PRIMARY KEY (member_uuid, stem_uuid, object_type);
