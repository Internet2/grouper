# GRP-7194  oauthClientCredentials WS bearer token external system Test should validate the token grant when no test URL is configured

Context: WsBearerTokenExternalSystem supports httpAuthnType = oauthClientCredentials, which obtains a bearer token via an OAuth2 client-credentials grant (config keys tokenUrl, clientId, clientSecret, grantType).

Problem: the external system Test button (WsBearerTokenExternalSystem.test()) always fires an HTTP request at the configured endpoint and asserts the response code equals testHttpResponseCode (default 200). The token grant only happens as a side effect of attachAuthenticationToHttpClient. So Test conflates two separate questions: (a) can we authenticate and obtain a token, and (b) does a plain request to the endpoint return 200. When the endpoint is POST-only or multipart-only, or otherwise not a GET-200 health URL, Test reports failure even though the OAuth token was obtained successfully.

Symptom: a client-credentials external system whose endpoint accepts only multipart POST. The token grant succeeds, but the Test GET to the endpoint returns 500, so Test shows: Response code to <endpoint> expecting 200 but received 500. The existing knobs (testUrlSuffix, testHttpMethod, testHttpResponseCode, testUrlResponseBodyRegex) do not help when there is no GET-200 health endpoint to point at, and setting testHttpResponseCode to 500 would assert that a server error is success.

Proposed change (smart default): for httpAuthnType = oauthClientCredentials, make the endpoint HTTP probe optional. When no test URL is configured (no testUrlSuffix and no testHttpResponseCode), Test performs a token-only check: call retrieveBearerTokenForConfigId(debugMap, configId) and report success when a non-blank token is returned, surfacing the grant error otherwise. When a test URL or expected response code IS configured, keep the current endpoint-probe behavior. An optional override property grouper.wsBearerToken.<configId>.testTokenOnly can force token-only, but the default handles the common case with no extra config.

Expected outcome:

* oauthClientCredentials external system with no test URL configured: clicking Test performs the client-credentials grant and reports success once a token is obtained, without requiring the endpoint to return 200.
* Bad clientId, clientSecret, or tokenUrl: Test still fails, with a clear token-grant error (retrieveBearerTokenForConfigId already throws a useful error on failure).
* Existing configs that set a test URL or expected response code: unchanged endpoint-probe behavior, so the change is backward compatible.

Code pointers: edu.internet2.middleware.grouper.app.externalSystem.WsBearerTokenExternalSystem -- test() (the endpoint probe), attachAuthenticationToHttpClient() (the oauthClientCredentials branch), retrieveBearerTokenForConfigId() and generateAccessToken() (the grant, which already throws on failure).
