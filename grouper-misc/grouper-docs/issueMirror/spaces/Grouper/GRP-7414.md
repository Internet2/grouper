# GRP-7414  Report config viewers group picker excludes composite groups and requires UPDATE

On the folder/group report config screen (add and edit), the viewers group combobox uses filterOperation ../app/UiV2Group.groupUpdateFilter (reportConfigObjectAddHelper.jsp around line 117, and reportConfigObjectEditHelper.jsp around line 130). That filter is meant for picking a group to add members to: it searches with UPDATE privileges and assignCompositeOwner(false). So a composite group can never be picked as a report's viewers group, even if you type its full name or ID, and you also need UPDATE on the group.

A viewers group is only read (who can view, download and be emailed the report), so neither restriction makes sense. A composite is a normal choice, for example an intersection of a manual list and active employees. This has been the behavior since the reports feature was added (GRP-2063); the generic update filter was reused.

Workaround: create a plain group, add the composite to it as a member, and pick the plain group as the viewers group.

Fix: switch both JSPs to ../app/UiV2Group.groupReadFilter (READ privileges, composites allowed).

Testing: on a folder, add a report and confirm a composite you can READ (but not UPDATE) shows up in the viewers autocomplete and saves. Then edit the report and confirm the composite is still shown and still selectable. Add a unit test as appropriate.
