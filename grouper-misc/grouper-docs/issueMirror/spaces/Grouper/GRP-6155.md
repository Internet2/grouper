## Comments

### Chad Redman - 2025-05-09T16:52:48.588+0000

I think the fix would be to consider "tables" starting with "(" as a table, not a query. That way, it will behave like it previously did, which is to treat it like a table everywhere.

Also, if it starts with "[", or a single or double quote, these could be quoted tables. Basically it's faulty to consider every string with a space in it to be an executable query.

### Chad Redman - 2025-06-29T19:35:26.255+0000

Added a new grouperClient property `grouperClient.syncTable.personSource.tableFromType` and UI form field, which is either table or query. On multiple levels it defaults to table if blank or anything besides query. The only users that would need to do an upgrade step is if they actually had a query with a space in it, which is no longer assumed to default to query.

All tests in app.tableSync.TableSyncTest still pass.
