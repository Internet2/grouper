# GRP-667  Change log processor doesn't handle unassignment of the requireInGroups group type

When the requireInGroups group type is unassigned from a group, that causes a membership add, delete, and re-add of the same membership in the same transaction.  The membership that's being added, removed, and re-added is the "system of record" group that's used with this group type.  The change log processor, which processes changes sequentially, basically gets stuck at this change.
