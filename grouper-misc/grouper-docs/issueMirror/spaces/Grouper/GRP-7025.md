# GRP-7025  Datadog provisioner: getTeams mock does not page, leaving retrieveTeams multi-page path untested

DatadogMockServiceHandler.getTeams() returned every team in a single response and ignored
page[number]/page[size]. The production client retrieveTeams() already pages correctly, but
because the mock never sliced by page, the multi-page retrieval path was never exercised by any
test. A test dataset of >= the page size would also have caused the client's
"returnedCount < pageSize" break to never fire (infinite loop), so paging behavior could not be
tested at all.

This mirrors the retrieveRoles paging issue (separate ticket), but for teams it is test-coverage
only -- there is no production bug, since retrieveTeams already pages.

Fix:
- DatadogMockServiceHandler.getTeams now honors page[number] (0-indexed) and page[size], slices the
  result accordingly, and reports total/offset/limit in meta.pagination. Defaults to Datadog's small
  page size when page[size] is absent.
- Added DatadogProvisionerTest.testRetrieveTeamsPaging: inserts 105 teams and asserts all 105 are
  retrieved across pages with no duplicates.
