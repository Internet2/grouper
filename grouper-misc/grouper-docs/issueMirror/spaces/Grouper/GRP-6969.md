# GRP-6969  Upgrade task 41 fails on MySQL creating index on target_group_id/target_user_id (key too long)

* Grouper startup fails on MySQL during UpgradeTaskV41 with {{Specified key was too long; max key length is 3072 bytes}}
 * Failing statement: {{CREATE INDEX grouper_prov_grp_idx2 ON grouper_prov_group (target_group_id)}} — column is VARCHAR(1000), which exceeds InnoDB's 3072-byte index limit under utf8mb4
 * Same issue on {{grouper_prov_user_idx2}} over {{target_user_id}} VARCHAR(1000)
 * Fix: on MySQL, use a 100-char prefix index ({{{}target_group_id(100){}}} / {{{}target_user_id(100){}}}), matching the convention in UpgradeTaskV40/V14/V12
 * Updated both the upgrade task (UpgradeTaskV41.java) and the MySQL install SQL (GrouperDdl_Grouper_install_mysql.sql) so fresh installs and upgrades both work
