# GRP-6947  CSRF error when pressing Enter key on GSH template forms (group and stem context)

When a GSH template is displayed in the group or stem template UI and a user presses the Enter key while focused on a text input field, Grouper returns a CSRF error and the template does not execute.
h2. Steps to Reproduce
 # Configure a GSH template with at least one text input field and set it to show on groups or folders
 # Navigate to a group → Group actions → Templates → Run template
 # Select the template — the text input appears
 # Type any value into the text input field
 # Press *Enter*

h2. Expected Result

Template executes (same behavior as clicking the Submit button).
h2. Actual Result

Full-page CSRF error: "Maybe your session timed out and you need to start again. This should not happen under normal operation. CSRF error."
h2. Root Cause

Both {{grouperUi2/group/groupNewTemplate.jsp}} and {{grouperUi2/stem/stemNewTemplate.jsp}} define their forms with a native {{method="post"}} action:
{code:java}
<form id="newGroupTemplateFormId" class="form-horizontal"
method="post" action="UiV2Template.customTemplateExecute"
enctype="multipart/form-data">{code}
The Submit button is rendered as an {{<a>}} tag whose {{onclick}} calls {{{}guiSubmitFileForm(){}}}, which submits via Ajax and correctly includes the {{OWASPCSRFTOKEN}} from page state. However, pressing Enter in a text input triggers the browser's native form POST, which bypasses this Ajax handler entirely and sends the request without the CSRF token.
h2. Fix

Add {{onsubmit="return false;"}} to block native form submission on both JSPs, and add an {{onkeydown}} handler to intercept the Enter key and route it through {{{}guiSubmitFileForm(){}}}:


{code:java}
<form id="newGroupTemplateFormId" class="form-horizontal"
      method="post" action="UiV2Template.customTemplateExecute"
      enctype="multipart/form-data"
      onsubmit="return false;"
      onkeydown="if(event.key==='Enter' && event.target.tagName.toLowerCase() !== 'textarea'){if($('#newGroupTemplateFormId a.btn-primary').length){guiSubmitFileForm(event, '#newGroupTemplateFormId', '../app/UiV2Template.customTemplateExecute');}}">
{code}

The {{onsubmit="return false;"}} is safe to add because {{guiSubmitFileForm()}} uses {{ajaxSubmit()}} internally, which does not trigger the form's {{submit}} event — so the existing button-click path is unaffected.

The same fix applies to {{stemNewTemplate.jsp}} (using {{{}newStemTemplateFormId{}}}).

I'll be submitting a PR with this...
h2. Workaround

Click the Submit button with the mouse instead of pressing Enter. :)
h2. Verified On

Reproduced on Grouper 5.18.1 and confirmed present in 6.1.1 via quickstart container.
