# GRP-7592  JEXL scripted group incremental ignores DATA_ROWFIELD_ASSIGN events, so value changes inside an existing data provider row only reach groups at the next full sync

*Summary:* JEXL scripted group incremental ignores DATA_ROWFIELD_ASSIGN events, so value changes inside an existing data provider row only reach groups at the next full sync

*Type:* Bug
*Component:* ABAC / JEXL scripted groups, data providers
*Affects version:* 7.5.0 (also present on GROUPER_7_BRANCH at 0b25bd8e7f, 19 Nov 2026)

*Description*

When a data provider changes a field value inside an existing data row (same row key), {{GrouperDataProviderLogic}} writes {{DATA_ROWFIELD_ASSIGN_DELETE}} / {{DATA_ROWFIELD_ASSIGN_ADD}} change log entries. It writes {{DATA_ROW_ASSIGN_ADD}} / {{DATA_ROW_ASSIGN_DELETE}} only when a row key appears or disappears.

{{GrouperLoaderJexlScriptIncremental}} only reacts to MEMBERSHIP__, ATTRIBUTE_ASSIGN_VALUE__, DATA_FIELD_ASSIGN_* and DATA_ROW_ASSIGN_*. It never checks {{DATA_ROWFIELD_ASSIGN_*}}, even though {{EsbEventType}} already maps both events (with dataRowInternalId, dataFieldInternalId and memberInternalId). So any scripted group that depends on a row field value (for example {{entity.hasRow('roles', "status_code == 'B' && is_active")}}) stays stale until {{OTHER_JOB_grouperLoaderJexlScriptFullSync}} runs.

Code references (GROUPER_7_BRANCH):

* {{GrouperLoaderJexlScriptIncremental.java}} ~L184 and ~L196 (and the same checks at ~L373 / ~L421): only DATA_FIELD_ASSIGN_* and DATA_ROW_ASSIGN_* are collected
* {{GrouperDataProviderLogic.java}} L1932 / L2060 (DATA_ROWFIELD_ASSIGN_DELETE), L2239 (DATA_ROWFIELD_ASSIGN_ADD), against L1953 / L2207 for row add/delete
* {{EsbEventType.java}} L105 / L131: DATA_ROWFIELD_ASSIGN_DELETE / ADD already exist

*Steps to reproduce*

# A data row {{roles}} with row key {{role_key}} and fields such as {{status_code}} and {{is_active}}.
# A JEXL scripted group that filters on one of those fields.
# Change a field value in the source for an existing role (key unchanged) and run the data provider (full or incremental).
# The change log shows only dataRowFieldAssign delete/add entries for that member.
# The JEXL incremental runs (every minute) and the group membership does not change.
# Run the JEXL full sync: the membership is corrected.

*Observed in production (19 Nov 2026, 7.5.0)*

* Member A at 07:30:23–25: rowfield delete/add for {{status_code}} A → B, {{is_active}} true → false, {{ended_recently}} false → true. No dataRowAssign events.
* Member B at 07:35:50–52: rowfield delete/add for {{is_active}} true → false, {{ended_recently}} false → true. No dataRowAssign events.
* Neither person's scripted group membership changed until a manual JEXL full sync at 11:54. Without it, the change would have waited for the daily full sync at 02:00, about 18.5 hours later.
* Across 158 scripted groups, 29 had drifted from their source by midday (122 missing adds, 171 missing deletes). The full sync corrected exactly those totals.

*Expected*
A row field add/delete should trigger the incremental to recalc the affected member against the scripted groups that depend on that data row (or field), the same way DATA_ROW_ASSIGN_* and DATA_FIELD_ASSIGN_* do now.

*Suggested fix*
In {{GrouperLoaderJexlScriptIncremental}}, also handle {{DATA_ROWFIELD_ASSIGN_ADD}} / {{DATA_ROWFIELD_ASSIGN_DELETE}}: add the event's dataRowInternalId to {{dataRowInternalIdsChanged}} (and/or dataFieldInternalId to {{dataFieldInternalIdsChanged}}), and add the member to the set of subjects to recalc.

*Workaround*
Schedule {{OTHER_JOB_grouperLoaderJexlScriptFullSync}} to run after each data provider run.
