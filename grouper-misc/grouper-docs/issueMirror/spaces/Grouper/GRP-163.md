# GRP-163  Membership changes should not delete and re-add other immediate memberships

If a membership is changing for a group that's a factor of a composite, immediate memberships that have the composite group as a member are deleted and re-added to recompute memberships.  The code should figure out which memberships should change instead.  I would guess that this would be important for things like audit and notifications to prevent misleading information.
