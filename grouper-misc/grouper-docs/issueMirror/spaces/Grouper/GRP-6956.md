# GRP-6956  Raise default change log temp-to-entity page size for better ABAC daemon throughput

Background

The {{changeLogTempToChangeLog}} daemon processes {{grouper_change_log_entry_temp}} one page at a time, with each page running in its own transaction. Per page it:
 * Fetches up to {{changeLog.changeLogTempToChangeLogQuerySize}} rows from temp (default 1000).
 * Calls {{{}ChangeLogEntry.clearNextSequenceNumberCache(){}}}, forcing a {{SELECT MAX(sequence_number) FROM grouper_change_log_entry}} on the next insert.
 * Processes entries, accumulates into {{{}changeLogEntriesToSave{}}}, saves in {{hibernate.jdbc.batch_size}} (200) chunks.
 * Deletes processed rows from temp in 1000-id IN-list chunks.
 * Commits.

A {{tooManyChangeLogUpdatesSize}} (default 10000) circuit breaker stops the per-page loop early if fanned-out output rows blow past that threshold.

For large ABAC backlogs (e.g. 1M pass-through data entries after GRP-6907 batching), the page count itself becomes the bottleneck: 1000 commits, 1000 MAX queries against a growing change log table, 1000 page-fetch round trips.

Change

Raise the shipped defaults to give a 5x reduction in page count for large backlogs while preserving the 10x headroom ratio between page size and the fan-out circuit breaker:
 * {{{}changeLog.changeLogTempToChangeLogQuerySize{}}}: 1000 → 5000
 * {{{}changeLog.tooManyChangeLogUpdatesSize{}}}: 10000 → 50000

File: {{grouper/conf/grouper-loader.base.properties}}

Safety

Both values are user-overridable in {{{}grouper-loader.properties{}}}, so deployments that prefer the old behavior can revert per-instance. The new page size is well inside Oracle / Postgres / MySQL safety margins for this workload (narrow inserts into a sequence-ordered table plus PK-keyed deletes from a temp table). Order semantics are unchanged — sequence numbers are still assigned monotonically per row in temp-table order.

Follow-ups (not in this ticket)
 * Persist the sequence-number cache across pages within a single daemon run to eliminate per-page {{{}MAX(sequence_number){}}}.
 * Optionally bulk-insert pass-through batches via direct JDBC, bypassing Hibernate session overhead.
