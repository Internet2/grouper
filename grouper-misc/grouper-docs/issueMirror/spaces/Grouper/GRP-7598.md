# GRP-7598  GSH templates: allowUiFromNoOwner lets the UI run a template with no owner folder or group

GSH templates can run without an owner folder or group only from WS and MCP, via allowWsFromNoOwner. Many templates are really operations (counts, lookups, app integrations) where the owner is meaningless, so callers pass a placeholder folder like etc:templates, and the UI cannot run them without an owner at all.

Add grouperGshTemplate.<configId>.allowUiFromNoOwner (default false, gsh templates only). When true the UI can run the template with no owner on the simplified screen. It is separate from allowWsFromNoOwner, which keeps its meaning for WS and MCP, because WS and MCP callers pass their own entry gates (ws.client.user.group.name, the MCP groups) and UI users do not: opening a template to the UI is its own decision, and no template becomes UI-runnable on upgrade. The owner stays optional: an owner that is passed is still checked against showOnFolders / showOnGroups and VIEW, and an owner id that was sent but does not resolve stops the screen instead of being dropped. A privilegeOnObject template with no owner is denied.

The Run template button on the GSH templates screen uses the configured default group or folder if there is one, else, with allowUiFromNoOwner, opens the simplified screen with no owner. Both no-owner settings now show together above the show on folders / groups settings. Saving a gsh template that cannot run from anywhere (both no-owner flags and both show flags off), or a no-owner-only template with privilegeOnObject, is a validation error.

### Chris Hyzer - 2026-11-23T01:05:31.637-0500

Also in this change: when the simplified screen cannot go on (the template needs a folder or group, the folder or group was not found, or the user may not run the template) it now shows a message instead of a blank page. The message is the same whether or not the template, folder or group exists.

Old urls keep working: for a template with allowUiFromNoOwner, a folder id is ignored if the template does not show on folders, and a group id is ignored if it does not show on groups, so the template runs with no owner. If the template does show on folders or groups, the folder or group in the url must be found, or the screen stops.
