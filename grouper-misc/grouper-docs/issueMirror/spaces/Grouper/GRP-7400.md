# GRP-7400  MCP OAuth consent screen refuses read-write scope on protected folders and groups

Follow-on to GRP-7383 (configurable folders protected from MCP writes). MCP refuses every write to the etc folder, system groups, and folders listed in grouper.mcp.protectedFolders (and everything under them), but the OAuth consent screen still let a user grant read-write scope on those folders and groups. That consent could never be used, and the person approving it would not find out until the AI client started failing.

Change: the consent screen now refuses a read-write folder that is, or is under, a protected folder or etc, and a read-write group that is a system group or is in a protected folder or etc. The error names the picked folder or group. A folder which only contains a protected folder (e.g. app when app:payroll is protected) is still allowed; the MCP tools block writes to the protected part. The check runs in the live validation and again on submit, so a hand-built request cannot skip it.
