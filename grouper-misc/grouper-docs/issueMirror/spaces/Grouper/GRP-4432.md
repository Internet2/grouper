# GRP-4432  Rewrite SCIM 2 service to remove dependence on J2EE and TomEE

The current WS Scim service is using libraries from Penn State, which require J2EE to work. If this were written using a different library, we could remove the dependence on J2EE and ship Grouper with a regular Tomcat.

https://spaces.at.internet2.edu/display/Grouper/Grouper+TIER+SCIM+server

## Comments

### Chad Redman - 2022-10-20T05:33:05.834+0000

Checked in the initial implementation of this. It mostly emulates the formats of the Penn State J2EE implementation, and most of the differences is due to following the RFC more closely.

This is part of the grouper-ws module, and inherits the same authentication behavior as the rest of WS. The Penn State only had Basic auth.

The uris for the endpoints start with /scim/v2. For example, [http://localhost:8080/grouper-ws/scim/v2/Groups]

 # Summary of changes going to new library

Groups - /grouper-ws/scim/v2/Groups
------
 - No longer sending non-standard attribute "baseUrn"
 - No longer sending non-standard attribute "resourceType" (this should be meta.resourceType instead)
 - No longer sending TIER extensions "schemas[]" attribute that was replicating its own key
 - No longer wrapping TIER extensions in a non-standard "extensions" object
 - Newly sending group name in standard core field "externalId"
 - Changed key: members[].ref -> members[].$ref
 - Removed members[].type (not clear whether it's permissable or not)
 - Newly sending members[].display which is the subject's name
 - Changed error messages
From: Resource bogusGroupUuid not found
To: edu.internet2.middleware.grouper.exception.GroupNotFoundException: Cant find group by uuid: bogusGroupUuid
—
From: Resource idIndex:bogusIdIndex not found
To: java.lang.NumberFormatException: For input string: \"bogusIdIndex\"
—
From: Resource systemName:bogusName not found
To: edu.internet2.middleware.grouper.exception.GroupNotFoundException: Cannot find group with name: 'bogusName'"
—
From: name must contain atleast one colon (:)
To: java.lang.IllegalArgumentException: name must contain at least one colon (:)

 - Error message status (rarely) changed from String to error code string (e.g. "NOT_FOUND" -> "404")
 - Now able to set description via the TierGroupExtension extension
 - Add/replace memberships via /Groups POST/PUT working
 - For update, TierMetaExtension.resultCode changed from "SUCCESS_UPDATED" -> "SUCCESS"
 - For update, description is being set correctly and not cleared out
 - In list responses, renamed "resources" to standard "Resources"

 

Users - /grouper-ws/scim/v2/Users
------
 - No longer sending non-standard attribute "baseUrn"
 - No longer sending non-standard attribute "resourceType" (this should be meta.resourceType instead)
 - No longer wrapping TIER extensions in a non-standard "extensions" object
 - Changed error messages
From: only eq comparison operator is allowed without grouping.
To: java.lang.IllegalArgumentException: Only eq filter supported
—
From: only id and identifier attribute names are allowed
To: java.lang.IllegalArgumentException: only id and identifier attribute names are allowed

 - Extension schema "urn:ietf:params:scim:schemas:extension:enterprise:2.0:User" included by default. Field "employeeNumber" set to subjectId
 - In list responses, renamed "resources" to standard "Resources"
 - Error message status (rarely) changed from String to error code string (e.g. "BAD_REQUEST" -> "400")
 - Newly returning a list of group memberships

 

Memberships - /grouper-ws/scim/v2/Memberships
-----------
 - No longer sending non-standard attribute "resourceType" (this should be meta.resourceType instead)
 - No longer wrapping TIER extensions in a non-standard "extensions" object
 - Changed keys for owner and member: ref -> $ref
 - Removed owner.systemName which is not standard
 - Changed error messages
From: Membership with id bogus:bogus doesn't exist.
To: edu.internet2.middleware.grouper.exception.MembershipNotFoundException: could not find membership with uuid: 'bogus:bogus'
—
From: Resource bogus:bogus not found
To: edu.internet2.middleware.grouper.exception.MembershipNotFoundException: could not find membership with uuid: 'bogus:bogus'
—
From: Group with uuid value bogus doesn't exist.
To: edu.internet2.middleware.grouper.exception.GroupNotFoundException: Cant find group by uuid: bogus
—
From: Membership with id bogus:bogus doesn't exist.
To: edu.internet2.middleware.grouper.exception.MembershipNotFoundException: could not find membership with uuid: 'bogus:bogus'
—
From: owner or member propery is missing in the request body.
To: java.lang.IllegalArgumentException: owner or member property is missing in the request body.

 - In list responses, renamed "resources" to standard "Resources"
 - Able to set enabled and disabled dates without JSON conversion errors
 - When failing to delete a membership because it wasn't found, now returns a normal error instead of an uncaught stacktrace
 - Error message status sometimes changed from String to error code string (e.g. "BAD_REQUEST" -> "400")

 

Service Provider - /grouper-ws/scim/v2/ServiceProviderConfig
----------------
 - No longer sending non-standard attribute "baseUrn"
 - No longer sending empty "extensions" object
 - Attribute patch.supported sending false now; PATCH wasn't supported before, but falsely claimed it was
 - Attribute filter.maxResults increased from 100->1000
 - Attribute filter.supported changed false->true
 - Attribute bulk.supported changed true->false; bulk.maxPayloadSize and bulk.maxOperations are set to 0

 

Resource Types - /grouper-ws/scim/v2/ResourceTypes
---------------
 - Response is a normal JSON array; Removed totalResults, startIndex, itemsPerPage, and top-leval schemas attribute
 - No longer sending non-standard attribute "baseUrn"
 - No longer sending non-standard attribute "resourceType" (this should be meta.resourceType instead)
 - Non-standard "schemaUrn" renamed to standard "schema"
 - Meta.location for groups was incorrect; value changed /ResourceTypes/Group -> /ResourceTypes/Groups
 - Attribute schemaExtensions.schemaUrn -> schemaExtensions.schema
 - Name attribute changed:
 - User -> User Account
 - Description attribute changed:
 - Top level ScimUser -> Top level SCIM User
 - Top level ScimGroup -> Top level SCIM Group
 - Id for Membership changed: urn:tier:params:scim:schemas:Membership -> Membership
