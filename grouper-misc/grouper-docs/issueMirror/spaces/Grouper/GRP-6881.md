# GRP-6881  Add composite and functional indexes to speed up data provider full sync for data field subject source

The data provider full sync ({{{}syncFull(){}}}) runs several queries per batch against the Grouper PostgreSQL database that lack optimal indexes:
 # {{Hib3MemberDAO.selectByDataProviderAndSubjectIdRange()}} does {{WHERE gm.internal_id IN (SELECT gdfa.member_internal_id FROM grouper_data_field_assign gdfa WHERE data_provider_internal_id = ?)}} and the {{selectByProviderAndMembers()}} methods in {{{}GrouperDataFieldAssignDao{}}}, {{{}GrouperDataRowAssignDao{}}}, and {{GrouperDataRowFieldAssignDao}} filter by {{{}data_provider_internal_id = ? AND member_internal_id IN (...){}}}. The existing single-column indexes on {{member_internal_id}} require a filter step on {{{}data_provider_internal_id{}}}. Drop the old single-column indexes and add composite indexes on {{(member_internal_id, data_provider_internal_id)}} which satisfy both conditions in a single index lookup.

 # The range query uses {{lower(gm.subject_id) >= ? AND lower(gm.subject_id) <= ?}} which prevents use of any existing index on {{subject_id}} because {{lower()}} is not indexed. A functional index {{grouper_members_subject_id_lwr}} on {{lower(subject_id)}} allows PostgreSQL to use an index scan for the range predicate instead of a sequential scan of {{{}grouper_members{}}}.

 {{DROP INDEX fld_assgn_mbrs_intrnl_id_idx;}}
 
{{CREATE INDEX grouper_fld_asgn_prvdr_mbr_idx ON grouper_data_field_assign (member_internal_id, data_provider_internal_id);}}
 
{{DROP INDEX rw_assg_mbr_intrnl_id_idx;}}
 
{{CREATE INDEX grouper_rw_asgn_prvdr_mbr_idx ON grouper_data_row_assign (member_internal_id, data_provider_internal_id);}}
 
{{CREATE INDEX grouper_members_subject_id_lwr ON grouper_members (lower(subject_id));}}
 
For the pennperson data provider with ~40K subjects, the full sync was taking 7+ minutes. These indexes should bring it down to seconds.
