# GRP-277  subject search should sort subjectId or attribute matches to the top in unsorted list

If a search is done by name (e.g. in UI), and that name matches a subjectId or an attribute of the subject, then put that subject to the top of the list.  Note, if the list is short enough that there is sorting done on the list, then dont worry about it.

## Comments

### mchyzer - 2009-05-18T16:56:02.436+0000

This is done in the SourcesXmlResolver class, in grouper.  So if the UI returns a long list of unsorted subjects, then the ones that match subjectId or any attribute will be on top. A use case is I know the loginId of a user is "smith", I search for "smith", and I get a long list of unsorted subjects.  Not the user with the loginId of "smith" will be at the top.

Note, since I enumerate attribute values, Im not sure all source implementations will be efficient here, so you can turn this off if there are problems (in grouper.properties):

grouper.sort.subjectSets.exactOnTop = false
