# GRP-7148  Config value auto-detected as encrypted when its Base64-alphabet characters happen to form valid AES ciphertext (e.g. data provider query SQL)

When saving a config value (for example a Data Provider Query "SQL query"), Grouper decides whether the value is already encrypted by testing whether Morph.decrypt(value) returns non-blank without throwing (DbConfigEngine and GrouperConfigHibernate.isPasswordHelper). If that "succeeds", the value is stored encrypted and masked as *******.

Crypto.decrypt calls Base64.decodeBase64, which silently discards every character that is not in the Base64 alphabet. So a free-form string full of spaces, commas and parentheses (like a SQL query) has its remaining letters/digits decoded, and if that byte length lands on a valid AES block with valid PKCS5 padding, doFinal succeeds and returns garbage - a non-blank result. The value is then misdetected as ciphertext and silently stored encrypted.

Reported on Slack: a Data Provider Query SQL statement kept saving as "encrypted". Changing a single character (emplclass vs empl_class) toggled the behavior, because it shifts the residual Base64 byte alignment. The config id / key name did NOT contain pass/secret/private, so this is distinct from the known key-name false-positive.

The detection code is shared, so this can affect any free-text config value saved through the DB config editor (a JEXL script, an LDAP filter, a long text property), not only data provider query SQL.

Steps to reproduce:
- Configure a Data Provider Query, paste a real SQL query into the SQL query field, save.
- Intermittently (depending on the exact query text) the value is stored encrypted and shown as *******.

Fix:
Require the value to be strict, non-chunked Base64 before trusting a successful decrypt. Added Morph.isEncrypted(String) which returns true only if the value is strict Base64 (only A-Za-z0-9+/, up to two trailing =, length a multiple of 4) AND decrypts to non-blank. Real ciphertext (padded Base64 output of Crypto.encrypt, no whitespace) still detects; text containing any non-Base64 character does not. Used it in DbConfigEngine and GrouperConfigHibernate.isPasswordHelper. Added MorphTest coverage.

Affects: v4, v6, v7.
