# GRP-6950  Add Azure (Entra) certificate-based authentication for app registrations

Adds support for certificate-based authentication (signed JWT client_assertion)
to the Azure (Entra) external system, alongside the existing client_secret flow.
Also makes most Azure connector keys optional with sensible defaults so the
connector can be configured cleanly under either auth mode.

== What's new ==

* Authentication type selector on the Azure external system:
  - clientSecret (default, existing behavior)
  - certificate (new, signed JWT against the v2.0 token endpoint)

* New external-system fields (only shown when authenticationType=certificate):
  - privateKey (PEM, PKCS#8 or PKCS#1, single-line flattened or file path,
    Morph.decryptIfFile resolved; sensitive/password type so encrypted at rest
    and masked on edit)
  - certificateThumbprint (SHA-1, hex, 40 chars; used as JWT x5t header)

* Cert-auth flow (AzureGrouperExternalSystem):
  - Builds signed JWT with x5t header from thumbprint, RS256 signature
    over the standard Microsoft client_assertion claims (iss, sub, jti,
    aud=v2.0 token endpoint, nbf, exp)
  - POSTs to /oauth2/v2.0/token with grant_type=client_credentials,
    scope=https://graph.microsoft.com/.default,
    client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
  - Falls back to existing clientSecret flow when authenticationType is unset
    or set to clientSecret

* Mock service handler (AzureMockServiceHandler) now validates the JWT
  client_assertion (signature + claims) so the cert path round-trips end-to-end
  in tests and dev.

== Configuration model cleanup ==

The following Azure connector keys, previously marked required, are now
optional with explicit defaults baked into both the base config metadata
and the runtime lookup:

  Key                    Default
  ---------------------  ----------------------------------
  loginEndpoint          https://login.microsoftonline.com/
  resource               https://graph.microsoft.com
  resourceEndpoint       https://graph.microsoft.com/v1.0/
  graphEndpoint          https://graph.microsoft.com
  graphVersion           v1.0
  groupLookupAttribute   displayName
  authenticationType     clientSecret

This eliminates a class of bugs where a missing optional key caused
runtime NullPointerException-shaped failures (e.g. members@example.com URLs
constructed as "null/directoryObjects/...") and removes user-facing
required-validation errors on fields that always had safe Microsoft-published
defaults. clientSecret/privateKey/certificateThumbprint are now mutually
gated by showEl on authenticationType so the UI only requires what the
selected auth mode needs.

Runtime sites converted from propertyValueStringRequired to
propertyValueString(key, default):

  - AzureGrouperExternalSystem (loginEndpoint, authenticationType, resource)
  - GrouperAzureApiCommands     (resourceEndpoint x4)
  - GrouperAzureTargetDao       (resourceEndpoint x3)
  - CustomUiAzure               (loginEndpoint, resource, graphEndpoint,
                                 graphVersion)
  - AzureMockServiceHandler     (matching sites for the mock)

== UI ==

New externalized text labels/descriptions for authenticationType, privateKey,
certificateThumbprint, and refined clientSecret descriptions. Plus
descriptions for the existing logAuthenticationResponseBody, proxyUrl,
proxyType fields that were previously unlabeled.

== Tests ==

* AzureProvisionerTestUtils.setupAzureExternalSystemCertAuth() — helper
  that generates a fresh in-memory keypair, computes the SHA-1 thumbprint,
  and writes a cert-auth external-system config.

* GrouperAzureProvisionerTest.testFullSyncAzureCertAuth — full sync
  round-trip exercising the cert path: signed JWT → token endpoint →
  Graph batch calls → group/users/memberships landing in the mock DB.

== Backwards compatibility ==

Existing clientSecret-based external systems continue to work unchanged.
authenticationType defaults to clientSecret when unset, and the legacy
clientSecret field is unchanged.
