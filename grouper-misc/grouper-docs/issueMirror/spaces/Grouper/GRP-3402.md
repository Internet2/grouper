### Chad Redman  (unc.edu) - 2021-07-22T02:58:15.030+0000

In this case it does fix it. The other important fix for this was GRP-2176: "move grouper externalized text from ui to api" and GRP-2182: "add javax servlet api to ui and ws so gsh works completely" (2.5.0 and 2.4.0 patch 95). That change meant that when not running from the UI, GrouperTextContainer will get the locale from the value of grouper.text.bundle.0.* (default en_us). So the GrouperTextContainer.textOrNull() calls are probably all fine in gsh.

Other configs, e.g. the StemTemplateContainer for creating a non-gsh template, were all UI based, even though they had API-like logic in there that could have been separated from the UI (they were also in a bean package but weren't really bean-like). Those were a lot harder to interface from GSH, and required mock HttpSession and HttpServletRequest objects to work.
