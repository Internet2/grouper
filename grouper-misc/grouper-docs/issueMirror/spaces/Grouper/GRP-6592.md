# GRP-6592  Grouper log messages ( from various sources) should be consolidated and accessable via the UI.

Requiring deployments to have external systems to monitor URLs, DB tables, or polling the system in order to understand the state of the Grouper system is a burden to adoption.

It also requires "advanced knowledge" of "what is always a problem". ( In a system that is constantly changing and advancing. )

 

There should be "always alert" conditions that the system knows is an issue and those should be surfaced via the UI (and maybe via a WS/GSH method for more advanced use cases) that could be a "error message bus" concept that is surfaced in the UI.

This UI error visibility can also be extended to improvements in the provisioners and external system errors that Grouper recievs from outside sources as well.

Which might also lead to different levels of access to different error log messages.

It might even be wise to use a concept like "attestation" so that errors are known to be reviewed and "cleared" by responsible parties for that "source system" of the error.
