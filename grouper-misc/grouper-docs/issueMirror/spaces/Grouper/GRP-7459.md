# GRP-7459  Loader job fails intermittently with "Cant find log map label 'overallOrSubjobLog'" when GrouperLoaderLog debug logging is enabled

Affects Version/s: 4.x, 5.x, 7.x (code is the same on GROUPER_4_BRANCH, GROUPER_5_BRANCH and GROUPER_7_BRANCH)
Related: GRP-6283 (null pointer on loader logging)

Description:

Loader jobs fail intermittently with the error below. It happens on larger jobs (this one had about 21k source rows), and the same job usually succeeds on a later run.

Root cause:

GrouperLoaderLogger keeps its per-thread log maps (overallLog, subjobLog, groupManagement, ...) in a ThreadLocal<SoftReference<Map<...>>>:

private static ThreadLocal<SoftReference<Map<String, Map<String, Object>>>> threadLocalMap ...
threadLocalMap.set(new SoftReference(uberMap));

# GrouperLoaderJob.execute() sets up overallLog when the job starts.
# The job then fetches rows from the source without touching the log map. For a large source this can take a while and use a lot of heap.
# The JVM is allowed to clear soft references, and it does so sooner when free heap is low and the reference hasn't been used recently. Both are true during a big fetch.
# On the next access, retrieveUberMap() sees the reference is gone and quietly creates a new empty map.
# addLogEntry("overallOrSubjobLog", "rowsFromExternal", ...) in syncOneGroupMembership() is the first log call after the fetch. It finds neither subjobLog nor overallLog. Its only exception is for the literal label overallLog, so it throws, and the group sync fails.

GRP-6283 fixed the same root cause in doTheLogging() by returning when the map is null. addLogEntry() still throws.

The bug only shows up when the edu.internet2.middleware.grouper.app.loader.GrouperLoaderLog logger is at DEBUG. Every GrouperLoaderLogger method returns early otherwise. The shipped grouper/conf/log4j2.example.xml sets that logger to debug, so many deployments are exposed by default.

Impact: A diagnostic logging feature fails real loader jobs. Memberships for the affected group don't sync on that run.
