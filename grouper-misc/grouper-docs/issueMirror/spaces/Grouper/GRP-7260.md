# GRP-7260  UI should not block converting a group to a composite when the group has members

In the UI, converting an existing group to a composite is blocked when the group still has immediate members. The screen shows an error reading: Error: this group cannot be a composite until it has no members.  Remove all members and try again.

The block happens before the composite editor is even shown, so an admin has to leave the screen, delete every immediate member by hand, and come back. For a group with many members that is tedious, and it also destroys the membership list before the admin can see whether the composite will produce the result they expect.

Where it comes from: the guard is group.isHasMembers() in UiV2Group.java, at roughly line 5217 on the path that displays the composite screen and again at roughly line 5442 on the save path. The message is the externalized text key groupCompositeErrorCannotHaveMembers in grouper.textNg.en.us.base.properties.

Request: do not show this error and do not block the conversion. Reasonable options are to drop the restriction entirely, or to let the admin open the screen and proceed with a warning that any existing immediate members will no longer apply once the group becomes a composite, optionally offering to remove them as part of the save.

Seen in Grouper 7.4.0.
