# GRP-5790  WS find groups with FIND_BY_EXACT_ATTRIBUTE only works with legacy attributes

{code}
curl -X POST --user GrouperSystem:pass -H "Content-Type: application/json; charset=UTF-8" http://localhost:8080/grouper/servicesRest/v4_0_460/groups --data '
  "WsRestFindGroupsRequest": {
    "wsQueryFilter": {
      "queryFilterType": "FIND_BY_EXACT_ATTRIBUTE",
      "stemName": "test",
      "groupAttributeValue": "policy",
      "groupAttributeName": "etc:objectTypes:grouperObjectTypeName"
    },
    "includeGroupDetail": "T",
  }
}
'
{code}

This ends up calling Hib3GroupDAO.findAllByAttr(...), which specifically adds the legacy attribute prefix to the attribute name before searching for it. It is impossible to find other attributes that don't have the legacy prefix.

## Comments

### Chad Redman - 2024-12-02T02:31:29.759+0000

Fixed to work for any attribute, not just legacy attributes, while maintaining some legacy support. If the attribute name does not contain a colon (:), assume it's a legacy attribute and add the legacy prefix. Otherwise, use the name as is.

Note that the FIND_BY_APPROXIMATE_ATTRIBUTE was not changed, and will continue to only work for legacy attributes. Since it only looks for a value and the name isn't specified, fixing this would open up the risk of returning different results for users after an upgrade.
