# GRP-6939  If ddlUtils directory is not writeable, ddl quietly fails with no error

When creating the ddl_worker table, it tries to create a sql file of commands to run. Method GrouperUtil.newFileUniqueName() tries to create the file, and if that fails, it doesn't log the error. It only throws the exception assuming somewhere up the chain somebody will log it. But nothing ever does. It just quietly fails, and the worker table doesn't exist when Grouper starts, and that's the first indication something didn't work.

A separate improvement is that it has the DDL as a string already, so what is the point of saving it to a file just to read it back into a string. This might have been for legacy reasons, but files shouldn't be necessary anymore.
