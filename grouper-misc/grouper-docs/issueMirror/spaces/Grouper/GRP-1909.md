# GRP-1909  Allow blank description in new groups created by group list loaders (override "auto-created by grouperLoader")

For groups loaded via group list loaders, new groups get created with description "auto-created by grouperLoader" if the description is blank or unset in the loader job. There should be a way to allow the description to be blank (a allowBlankDescription property?)

### cer28 - 2019-02-28T19:12:21.136+0000

I have something that works. New loader property loader.allowBlankDescriptions defaults to true. If it's false, it reverts to the current behavior –  the existing "... auto-created" description gets set whenever the description is blank.

However, this will clear out the description for any loaded group if the loader job isn't calculating it. Is this ok? Personally, I want it to work this way, but it does mean a potentially large amount of audited changes.

### cer28 - 2019-03-02T19:07:31.672+0000

The idea would make sense if there was a chance someone changed a description from "auto-loaded" to something else, and were relying on the non-blank enforcement to know it wouldn't be modified by the loaded. But it's not doing that. The current behavior is to blindly pass the name, display, and description to GroupSave() whether or not the group existed and regardless of the current values, so the group is always in sync with the incoming data. I haven't tested, but that should mean if you modified the description but the job wasn't calculating a description, it would be set back to "auto-loaded..."

Plus, it would lead to different group sync behavior depending on whether the group had already existed.
