# GRP-2391  Ability to advance a Change Log consumers last_sequence_processed value to force it past blocking errors that can be skipped

There are occasionally error conditions that happen to Change Log consumers that require manually advancement of the last_sequence_processed  value for the job to "just move on" with the events. Currently an Grouper SysAdmin needs to use SQL to do that.

 

It would be very helpful if the UI could support that functionality.

 

Perhaps the Miscellaneous --> "All daemon jobs" page could have a button to "advanced the value by one" for jobs that are "Change Log Consumers"?

 

Maybe this could also be done via a WS call too?
