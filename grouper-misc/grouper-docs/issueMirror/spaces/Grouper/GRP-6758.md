# GRP-6758  Change MCP OAuth scope restriction logic so unspecified dimensions are open

Changed the MCP OAuth readwrite scope behavior so that when {{consentReadwriteScopeRestricted}} is true, dimensions (folders/groups, subjects) that are left blank are treated as unrestricted (open) rather than fully blocked, as long as at least one other dimension has values. If all dimensions are empty, everything is still blocked.

*Example:* If a user scopes folders to "test" but leaves subjects blank, they can now operate on any subject within groups under "test". Previously, all subject operations would have been blocked.

*Changes:*
 * {{GrouperMcpAuthUser.java}} — Added {{hasAnyReadwriteScopeValues()}} helper; updated {{{}isGroupInReadwriteScope(){}}}, {{{}isStemInReadwriteScope(){}}}, {{isSubjectInReadwriteScope()}} to allow access for empty dimensions when other dimensions are scoped
 * {{GrouperMcpScopeTest.java}} — Updated mixed-scope tests, added new tests for unscoped dimensions and all-empty scenario, fixed test setup issues (stem creation, attribute privilege grants)
 * {{mcpWikiUserGuide.html}} / {{mcpWikiAdminGuide.html}} — Updated scope restriction documentation to reflect new behavior
