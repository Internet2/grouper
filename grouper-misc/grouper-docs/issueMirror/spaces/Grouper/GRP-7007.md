# GRP-7007  GSH template dropdown validation message includes blank placeholder and has non-deterministic order

* The validation message {{'X' is not valid. Valid values are 'Y'.}} for dropdown inputs includes an empty placeholder, so for a CSV-configured dropdown with values {{def, ghi}} the message reads {{Valid values are ', def, ghi'.}}
 * Root cause: {{GshTemplateInputConfig.getDropdownKeysAndLabels()}} prepends {{new MultiKey("", "")}} to the keys list for the UI dropdown's blank initial option (line 143). {{GshTemplateValidationService}} line 521 reuses that same list to build the validation message, dragging the empty placeholder into the human-readable error
 * Secondary issue at the same line: {{Collectors.toSet()}} returns a {{{}HashSet{}}}, so the order of values in the message is non-deterministic across JVMs / JDK versions
 * Fix: filter out blank keys and use a {{LinkedHashSet}} for deterministic order. Rewrite the stream as an explicit {{for}} loop per the new house-style rule in CLAUDE.md
 * Failing test: {{GshTemplateExecTest.testValidateDropdownValues}}
 * Discovered while building Phase 2 of GRP-7006; not caused by that work — pure pre-existing bug
