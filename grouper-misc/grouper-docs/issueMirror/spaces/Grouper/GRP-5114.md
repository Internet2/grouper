### Chad Redman - 2023-11-13T05:55:05.925+0000

I didn't see the commit, so maybe there is time to improve this more. This should at least include the LB address AND the client address, for debugging purposes. Per the apache docs, "%a" is the original client address from the forward header, but only honored if GROUPER_APACHE_REMOTE_IP_TRUSTED_PROXY or GROUPER_APACHE_REMOTE_IP_INTERNAL_PROXY is set. There is also the %\{X-Forwarded-For}i header, which should be the same value if that's the header you're using. But I think %a is better for debugging, at least if you're using Shib, since you want shib to get the actual client address, not the proposed one that may not be honored if your proxy addresses aren't right.

 

I actually have a customer with two load balancer hops, so we log all 3. The client address has its own header, the first LB has X-forwarded-For, and the second LB is the raw address. So our config looks like this.

 
{code}LogFormat "httpd;access_log;%{ENV}e;%{USERTOKEN}e;%a %{X-Forwarded-For}i %h %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-Agent}i\"" combined
LogFormat "httpd;access_log;%{ENV}e;%{USERTOKEN}e;%a %{X-Forwarded-For}i %h %l %u %t \"%r\" %>s %b" common
LogFormat "httpd;access_log;%{ENV}e;%{USERTOKEN}e;%a %{X-Forwarded-For}i %h %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-Agent}i\" %I %O" combinedio
{code}
