# GRP-7255  SqlProvisionerTest expects entity updates that a target-assigned entity_uuid can no longer produce

SqlProvisionerTest asserted 2 entity updates in getTargetObjectUpdates().getProvisioningEntities() for the ldapPa test case. That expectation is stale: the correct count is 0.

entity_uuid is assigned by the target, so configureLdapPaTestCase blanks its translation. Grouper therefore computes no value for that attribute and has nothing to change. The expectation of 2 dates from when the attribute was translated from the Grouper entity id, which differed from the random uuid the test seeds, so every provisioned entity produced one update.

Neither of the other two entity attributes in that config can produce an update either. The dn attribute is only read, into the entity attribute value cache. The employeeId attribute already equals the subjectId Grouper would write.

Corrected the assertion to 0 and recorded the reasoning inline so the number is not read as arbitrary.
