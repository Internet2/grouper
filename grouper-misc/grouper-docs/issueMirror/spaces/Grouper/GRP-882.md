# GRP-882  PSP real-time provisioning performance slow

CMU reports that the PSP takes hours to real-time provision groups ~ 30K users.  Would like to see this improved as much as possible

## Comments

### gettes - 2013-03-11T13:12:30.412+0000

From the discussion on the dev call about 2 weeks prior to this post there was the following description of the problem.   We see one thread essentially dedicated to modifying group objects, another thread for modifying user objects (we do isMemberOf processing) and a third thread appearing to be dedicated to searches.  An LDAP server can do a lot more work.  From the dev discussion it seemed like we could pursue 2 avenues.   We have users who want to provision for themselves composite groups based on institutional groups - for us this is currently memberships of about 30K.  We are seeing it take about 8 hours to provision a single group of 30K, with ismemberof, and any grouper operations performed during this time get queued up behind so everyone sees an 8 hour delay.

(1) if there are many operations of the same type (like an addMember) for the same object then scoop up all those and apply as a single update.  If object A has an Add then a Delete then, if you can properly process all these as a single operation with integrity, do so - otherwise, these would be multiple operations.  Of course, there are many LDAP libs out there and many allow for applying changes to an object all at once.

(2) by doing 1 - we could then increase, by a property setting, the maximum number of threads in the pool to modify LDAP.  This would allow us to expand to maybe 30 threads and perform 30 simultaneous operations.  This would dramatically increase the bandwidth and the throughput of LDAP operations.  Even if an LDAP operation were still 1 per second (as we are casually observing now) then we could cut processing time to at least 1/3rd the time but probably closer to 1/10th the time.  By combining item 1 - it should go even faster!

(3) while this is an issue for PSP in incremental mode - similar improvements to bulk might see similar dramatic increases in performance.
