# GRP-7285  MockServiceServlet error says "Cant find mock name for 'null'" - it prints className instead of the mock name it could not find

MockServiceServlet.service() reports the wrong variable when it cannot resolve a mock handler. It prints className, which is null by definition inside that if block, instead of the mock name it actually failed to find. So the error always reads "Cant find mock name for 'null'" and never says which mock was requested.

{code:java}String className = urlToHandler.get(mockServiceRequest.getMockName());
mockServiceRequest.getDebugMap().put("mockHandlerClassName", className);
if (className == null) {
  throw new RuntimeException("Cant find mock name for '" + className + "'");
}{code}

Fix - print the mock name, and it is worth listing the registered names since the usual cause is a stale deployment that predates a newly added mock:

{code:java}String className = urlToHandler.get(mockServiceRequest.getMockName());
mockServiceRequest.getDebugMap().put("mockHandlerClassName", className);
if (className == null) {
  throw new RuntimeException("Cant find mock name for '" + mockServiceRequest.getMockName()
      + "', expecting one of: " + GrouperUtil.setToString(urlToHandler.keySet()));
}{code}

Why it matters. A provisioner test failed against a mock service tomcat that was running classes built before the jamf and ccure mocks existed. The message said "Cant find mock name for 'null'", which suggests the servlet failed to parse the url. It had parsed it fine - it simply had no handler registered for jamf. With the mock name in the message the cause is obvious immediately; without it the investigation went through url parsing, servlet mapping and the provisioner code first.

Reproduce: request /grouper/mockServices/<anyUnregisteredName>/whatever against any grouper. Present on GROUPER_6_BRANCH and GROUPER_RELEASE_7.4.0 - MockServiceServlet.java is byte identical between them, so please fix on v7 and let it backport normally.
