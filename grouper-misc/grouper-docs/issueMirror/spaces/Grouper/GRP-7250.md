# GRP-7250  GSH template list screen errors out entirely when a template config references a group that does not exist

When a GSH template config references a group by name in a run or show key (for example defaultRunButtonGroupUuidOrName, groupUuidCanRun, or groupUuidsToShow) and that group does not exist, the entire GSH templates list page fails to render.

The list page (WEB-INF/grouperUi2/gshTemplate/gshTemplateConfigs.jsp) iterates every template config and, to draw the Run button, calls GshTemplateConfiguration.getGroupId (around line 833), which throws RuntimeException: could not find configured default run button group for gsh template configId <configId>. That propagates up through UiV2GshTemplateConfig.viewGshTemplates and aborts rendering of the whole page.

Impact: one misconfigured template takes down the GSH templates list for every template and every user. You cannot even open the config editor from the list to fix the bad config, because reaching the editor requires the list page to render. The only recovery is to re-import a corrected config or create the missing group out of band.

Requested fix: the list screen should degrade gracefully when a referenced group or folder is missing. Catch the lookup failure per template row and render that row with a warning or error indicator (and still expose its edit action) instead of throwing, so the rest of the list stays usable and the misconfigured template can be corrected from the UI.
