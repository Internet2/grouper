# GRP-2238  enabled/disabled membership screen shows enabled when not

add a membership via web service with time component in future of enabled date

java -jar grouperClient.jar --operation=addMemberWs --groupName=test:testGroup --subjectIdentifiers=test --subjectSources=jdbc --enabledTime="2019/06/27 19:40:00" --debug=true

Note: if you want to remove the user:

java -jar grouperClient.jar --operation=deleteMemberWs --groupName=test:testGroup --subjectIdentifiers=test --subjectSources=jdbc --debug=true

This user does not come up as a member of the group (enabled today, but in future in time)

show enabled/disabled, and see user

query DB for date:

SELECT immediate_mship_enabled, immediate_mship_enabled_time FROM grouper_memberships_all_v gmav, grouper_groups gg, grouper_members gm, grouper_fields gf
WHERE gmav.member_id = gm.id AND gmav.owner_group_id = gg.id AND gf.name = 'members'
AND gmav.field_id = gf.id AND gg.name = 'test:testGroup' AND gm.subject_id = 'test' AND gm.subject_source = 'jdbc'

enabled: F: enabled_time: 1561664400000: Thu Jun 27 2019 19:40:00

### Shilen Patel - 2019-08-09T11:28:34.766+0000

The issue is that the isEnabled() method on the Membership object returns based on the enabled/disabled timestamps instead of the enabled flag (which is calculated and fixed by the daemon when the timestamps are reached).

To address this issue, I'll change the isEnabled() method to instead use the enabled flag.  On this screen, I'll also display the enabled/disabled dates with times.

This should address the bug.  I'll create a separate Jira to address some of the other improvements - allow an enabled/disabled date when adding a memberships and allow times as input.
