# GRP-7245  Add grouper-gte-cert AI skill for fixing the GTE self-signed certificate

Added a new shared AI skill, grouper-gte-cert, under grouper-misc/grouper-docs/skills, alongside grouper-jira, grouper-release and grouper-wiki-edit. The README list of available skills was updated to match.

Problem it addresses: the Grouper Training Environment container generates its httpd certificate with commonName=localhost.localdomain and no subjectAltName. Chromium has required subjectAltName since Chrome 58 and ignores commonName for hostname matching, so the certificate is invalid for every hostname rather than merely untrusted. A person browsing normally can click through the interstitial, but an AI assistant's built-in browser pane has no proceed button, so the training environment is unreachable from it until the certificate is replaced.

The skill documents the full procedure: confirm the container is actually running before blaming the certificate, regenerate the certificate inside the container with CN=localhost plus subjectAltName for DNS localhost and IP 127.0.0.1, and reload with httpd -k graceful. It calls out two traps that cost real time in practice. First, GTE typically runs in Docker on a remote VM reached over an SSH tunnel, so it is easy to run the openssl command on the VM host instead of inside the container; the prompt and a missing httpd binary are the tells, and the repo helper gte-shell opens the correct shell. Second, apachectl on this image is a systemd wrapper and the container has no systemd, so apachectl graceful fails while the certificate regenerates successfully, making it look like the fix did not work.

Trusting the new certificate is covered for macOS (security add-trusted-cert into the login keychain, after deleting any previous certificate sharing the CN=localhost subject) and for Windows (certutil -addstore -user Root, which needs no administrator rights). The Windows section is marked as not yet verified on a Windows install. Verification steps check the certificate and the trust separately, since they fail independently.

The skill also notes that the fix lives in the container filesystem and is therefore lost whenever the container is recreated, and points at GRP-7239 for the one-line base/Dockerfile change in the grouper_training repo that would stop the problem recurring.
