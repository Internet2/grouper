# GRP-5082  ldap loader LDAP_GROUPS_FROM_ATTRIBUTES should allow specifying parent stem

The grouper ldap loader does not allow to specify where groups should be written, and always puts them under <parent stem of loader group>:groups:<groupName>.  This makes organization difficult because we'd like to put loaders that create other groups in etc:loaders, but we want the loaded groups in basis:some:path:to:<groupName>.

### Chris Hyzer - 2023-11-04T00:45:41.041+0000

note: there is a setting to allow ad hoc locations for ldap loaders...
{code:java}
# by default the top folder for an ldap group of groups is the folder where the config group lives.
# set to false if you want to be able to provision groups to anywhere
# {valueType: "boolean", required: true}
loader.ldap.requireTopStemAsStemFromConfigGroup = true

 {code}
You will need to look at all your jobs if you change this, but it could be helpful.  Maybe we should default to false in v5+?  :)

### Vivek Sachdeva - 2023-11-08T06:58:18.047+0000

When 

loader.ldap.requireTopStemAsStemFromConfigGroup = true

if the parent of the final group name exists then use the final group name

if not, then if the parent of the parent of the group exists then use that as the final group name

and this is the result of the loader job, if the parent folder of the parent folder of the group exists then use the original group name. 

If you're changing the name then the final group name should reflect that.
