# GRP-1321  WebService should also accept "application/json" and "application/xml"

When using these languages, and their keywords for the content types json and xml.  The rest client generates headers with "application/json" and "application/xml". 

Using these keywords, makes simple calls to the ws easier.

Also, these may be the appropriate values:  http://www.iana.org/assignments/media-types/media-types.xhtml

### cer28 - 2018-05-15T18:48:05.027+0000

Bumping this. The standard content type for json is "application/json" per [rfc 4627|https://www.ietf.org/rfc/rfc4627.txt]. If using SoapUI I need to always override the default content type of text/x-json in order to work. If using OkHttp3 client, there is no workaround to override the application/json it adds, so Grouper WS is unusable with it.

 

Similar with text/xml, although [RFC 3023|https://www.ietf.org/rfc/rfc3023.txt] says that both are valid options for the content type. We should also change this to accept either.
