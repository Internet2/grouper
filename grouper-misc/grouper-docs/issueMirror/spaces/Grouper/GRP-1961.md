# GRP-1961  gsh findSubject mixes type and source when passed

The two-argument findSubject(id, source) ignores the source.

 
{noformat}groovy:000> findSubject("grouper-wsuser", "INVALID_SOURCE")
===> Subject id: grouper-wsuser, sourceId: jdbc, name: grouper-wsuser
{noformat}
 

It needs a middle argument in order to work.

 
{noformat}groovy:000> findSubject("grouper-wsuser", null, "INVALID_SOURCE")
ERROR edu.internet2.middleware.subject.SourceUnavailableException:
Cant find source with id: 'INVALID_SOURCE', Possible source id's: 'g:isa', 'g:gsa', 'grouperEntities', 'grouperExternal', 'jndi', 'jdbc',

groovy:000> s = findSubject("grouper-wsuser", null, "jdbc")
===> Subject id: grouper-wsuser, sourceId: jdbc, name: grouper-wsuser
{noformat}
 

The middle value per groovysh.profile is supposed to be type. But it's ignored because there is no 3-argument findUser java method. There is only a 2-argument method, and the second argument is source.

 
{noformat}groovy:000> s = findSubject("grouper-wsuser", "person", "jdbc")
===> Subject id: grouper-wsuser, sourceId: jdbc, name: grouper-wsuser
groovy:000> s = findSubject("grouper-wsuser", "INVALID_TYPE", "jdbc")
===> Subject id: grouper-wsuser, sourceId: jdbc, name: grouper-wsuser

groovy:000> s.type
===> person
{noformat}

### cer28 - 2018-12-06T17:30:31.635+0000

This is what the help shows as documented gsh calls:

addSubject(id, type, name)
findSubject(id)
findSubject(id, type)
findSubject(id, type, source)

In both of the findSubject examples, the findSubject type parameter is ignored (since dbf9aa08a2e7 7/22/2011). Originally, there was an implemented SubjectFinder.findById(id, type, source) that this called. The method is still there but deprecated (since 6f630f59e49b 3/2/2011), with the type value ignored.

tldr; finding a subject by id and type was last useful in 1.6.3, and no longer worked since 2.0.0.

### Chad Redman  (unc.edu) - 2019-09-05T02:58:12.600+0000

It's actually working per the gsh documentation
{quote}
findSubject(id)
findSubject(id, type)
findSubject(id, type, source)
{quote}

So there is no two-argument findSubject(id, source). What should be more explicit in the documentation is that type is completely unused and is essentially a placeholder.

While this could be improved by redoing the api and using (id, source) instead of an unused placeholder parameter, we'd have to worry about whose scripts this will break.
