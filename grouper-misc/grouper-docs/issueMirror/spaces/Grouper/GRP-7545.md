# GRP-7545  sqlCacheFullSync/sqlCacheInitialPopulator fails on active PIT owners with null id or no live object: skip them, finish the sync, end in ERROR with fix instructions

The sqlCacheFullSync daemon (v6/v7) and the v4 sqlCacheInitialPopulator fail with RuntimeException: Cannot convert to long: null (SqlCacheInitialPopulatorDaemon.java:243 in v4) when an active PIT group, stem, or attribute def has a null source_internal_id / source_id_index. This has been seen at multiple v4 sites.

In v4 the PIT id columns are only populated by the populator's own backfill, which copies the id from the live object. An active PIT row whose live object no longer exists (PIT out of sync) keeps a null id, and STEP 3 (add rows to grouper_sql_cache_group) fails on it, so the whole cache build stops. In v6/v7 the ids are set on insert, but the same orphaned active PIT rows still get sql cache rows for objects that do not exist.

Fix: at the start, find active PIT groups/stems/attributeDefs (older than the change log temp cutoff) with a null id or no live object, ignoring objects with pending entries in grouper_change_log_entry_temp. Put the count and a sample of names in the job message. Skip those rows in STEP 3 and when loading PIT data, finish the rest of the sync, then set the job status to ERROR with instructions: run CHANGE_LOG_changeLogTempToChangeLog until grouper_change_log_entry_temp is empty, run new SyncPITTables().showResults(true).syncAllPITTables(), then run the job again.
