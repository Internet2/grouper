# GRP-7369  Make a more robust report daemon

Complex reports written in SQL or GSH, with CSV or raw output, are something that can be added to a group or folder. Two problems: 1) it uses attributes, so the source size is limited to the 4000 characters of the attribute value field; 2) If it’s a global report not associated with a particular group, you still need to pick a random group/folder to put in on, and then remember which one so you can find it again.

GSH templates use a different model, where the function is global so not tied to a group. It also uses configs, so the source is a linefeed-escaped config parameter.

There are are two types of daemon reports currently in Grouper. The Csv report daemon taks a single SQL query, and outputs either to a local file or an SFTP external system. A notification job daemon takes either a group name for memberships, or a SQL query, and only emails. Neither of these allow for more complex GSH/Java report construction.

Instead of creating a fourth type of report, the Script daemon could be extended to handle reports. You could already do that with a script daemon since you can write any code. Added capability could be things like output type, output target (email, local file, SFTP, S3), and input/output variables like the group report does. I think adding a new Script type of report to the existing [gsh, sql] options would bring up report-related fields. The existing feature of the option to use inline script or file would be useful.

It might be useful to store the report results in a blob for a period of time in case the upload or email fails. Not sure how that would be accessed, other than maybe log the url in the job log.
