# GRP-7333  MCP group_save removeComposite fails with leftFactorGroup is required even when factors are supplied

The MCP tool group_save with action removeComposite always fails, reporting that leftFactorGroup is required, even when leftGroupName and rightGroupName are both passed. The error text shows left and right arriving as null, which suggests the tool is not mapping the supplied factor parameters onto the composite save.

Attempt 1, with only groupName supplied (the group does have an existing composite):

{noformat}group_save(action=removeComposite, groupName=some:folder:someGroup)

Error in group_save action removeComposite: leftFactorGroup is required,
Problem saving composite: Group[name=some:folder:someGroup,uuid=...],
  left: null, null, right: null, thread: 53b175a5{noformat}

Attempt 2, additionally supplying compositeType, leftGroupName and rightGroupName exactly matching the existing composite as reported by group_find with includeCompositeInfo. Same failure, and left and right are still null in the error:

{noformat}group_save(action=removeComposite,
           groupName=some:folder:someGroup,
           compositeType=INTERSECTION,
           leftGroupName=some:folder:someGroup_candidates,
           rightGroupName=some:other:populationGroup)

Error in group_save action removeComposite: leftFactorGroup is required,
  left: null, null, right: null{noformat}

Expected: removeComposite removes the composite definition from the group. The tool description for removeComposite says it removes the composite definition from a group, and does not document leftGroupName or rightGroupName as required for that action (they are documented as required for addComposite and updateComposite).

Notes. addComposite, updateComposite and addGroupType on the same group all work normally. updateComposite with the identical factors returns NO_CHANGE, so there is no way to force a composite rebuild through the MCP tools once a composite exists. No workaround found via MCP; the composite has to be removed in the Grouper UI instead.

Found against PennGroups production while scripting a policy group build out.
