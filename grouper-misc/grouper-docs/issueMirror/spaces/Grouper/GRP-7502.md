# GRP-7502  Log remote user in Tomcat access log for WS and MCP requests (grouperRemoteUser request attribute)

The container Tomcat access log pattern uses %{grouperRemoteUser}r to log the authenticated user. That request attribute is only set by the UI filter (GrouperUiFilter), so for grouper-ws traffic (regular WS and the /mcp endpoint) the user field is always logged as a dash.

%u does not help either since Bearer token (OAuth, OIDC, JWT) and Grouper DB Basic auth do not set a container principal.

Fix: wherever WS or MCP authenticates the caller (trusted JWT, OIDC, jwtUser, Basic, custom WsCustomAuthentication, container auth, MCP OAuth), also set the grouperRemoteUser request attribute so the existing container access log pattern logs the user for WS and MCP requests.

### Chris Hyzer - 2026-10-18T06:41:13.707-0400

Format: token auth (JWT, OIDC, MCP OAuth) sets REMOTE_USER to sourceId::::subjectId; for the access log only the subjectId is logged so it reads like the UI. Basic, container, and custom auth log the login id as-is.

### Chris Hyzer - 2026-10-18T06:41:38.419-0400

Change from previous behavior (access log output only):

Before: with the container Tomcat access log pattern (%{grouperRemoteUser}r), the user field for all grouper-ws requests (regular WS and /mcp) was always a dash.

After: the user field is populated for authenticated grouper-ws requests. Token auth (JWT, OIDC, MCP OAuth) logs just the subjectId (not sourceId::::subjectId). Basic, container, and custom auth log the login id. Unauthenticated requests (OAuth token endpoint, well-known discovery, failed auth) still log a dash.

No functional change: authentication, authorization, and the REMOTE_USER request attribute are unchanged. A custom access log pattern using %u is unaffected. The UI is unchanged. Only log parsers that expect a dash in that field for grouper-ws requests would notice.
