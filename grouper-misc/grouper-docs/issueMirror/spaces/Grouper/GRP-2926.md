# GRP-2926  Privilege errors in application template

When creating a GDG application template structure, the inherited privileges break if ruleActAsSubjectId value is set to a user no longer in the wheel group. We are using external accounts with shib auth, {color:#e8912d}{color:#172b4d}rules.act.as.group = etc:sysadmingroup{color} {color}NOT set at the system level.

Steps to reproduce:
 # Create a new application template structure as a user in the groups.wheel.group
 # Remove user from wheel group
 # Attempt to create a new group or folder in the newly created template structure as an account with admin rights (wheel group or via security policy group).

Setting the ruleActAsSubjectId to a valid user the wheel group fixes the permissions.
