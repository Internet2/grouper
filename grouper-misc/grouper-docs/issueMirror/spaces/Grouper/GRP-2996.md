# GRP-2996  grouper should make sure logged in user hasnt changed

the UI should always make sure the Shib SP user hasn't changed.  But right now, if you login as one user and then kill the SP and IdP sessions and then login as another user via Shib, you're still logged in as the original user in Grouper, right?

## Comments

### Scott Cantor - 2020-10-20T16:45:50.457+0000

Not specific to Shibboleth at all of course, the problem applies any time you rely on RemoteUser or any other container mechanism for authentication, it's assumed to be applied per-request and not cached. If you wanted to cache, you'd have to cross-check every request (some people use a servlet filter for it I suppose).

There are potentially related implications to how logout is dealt with (obligatory point that logout's really hard and logout with SSO is borderline impossible to get right).

### Chris Hyzer - 2020-10-30T21:11:26.938+0000

You can revert this behavior in grouper-ui.properties, set this to true
{code:java}
# if the user id on each UI request must match (e.g. with shib)
# {valueType: "boolean", required: true}
grouper.ui.authentication.allowUserIdSwitching = false
 {code}
