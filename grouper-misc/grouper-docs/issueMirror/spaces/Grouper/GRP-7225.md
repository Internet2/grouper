# GRP-7225  Grouper OAuth authorize endpoint is an open redirect

The OAuth authorization endpoint reported several request errors by redirecting the browser to the redirect_uri from the request, before that redirect_uri had been checked against the ones the client registered. Anyone could therefore use the endpoint to bounce a browser from a trusted Grouper URL to an address of their choosing, by supplying any client_id and redirect_uri together with a request that fails one of those early checks — for example response_type set to anything other than code, a missing code_challenge, a code_challenge_method other than S256, or an unknown client_id.



The checks are reordered so that everything determining whether the redirect_uri may be redirected to is done first — redirect_uri present, client_id present, client registered, redirect_uri registered for that client, redirect_uri allowed by the configured patterns — and each of those failures shows an error page rather than redirecting. Only after that are the remaining request parameters checked, and those may report the error by redirecting back to the client. A missing or unknown client_id now shows an error page rather than redirecting, per RFC 6749 section 4.1.2.1, which requires an authorization server not to redirect to a redirection URI it has not validated.



No authorization code or token was exposed by this, since every affected path fails before a code exists. The risk is phishing: a link that appears to be a Grouper URL sending a user to an attacker's site.
