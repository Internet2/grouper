# GRP-7376  Allow orgs to hide default GSH templates in favor of org-specific custom templates

See discussion in #incommon-grouper: [https://internet2.slack.com/archives/C7V0UQDJ4/p1788974301281399|https://internet2.slack.com/archives/C7V0UQDJ4/p1788974301281399|smart-link] 

TL;DR: UVA would like to hide the built-in GSH templates to prevent end users from seeing or using them, in favor of its own templates tailored to UVA use cases.

Currently, if an org attempts to hide these templates via the following {{grouper-ui.properties}} overlay:

{noformat}grouper.template.service.logicClass =
grouper.template.policyGroup.logicClass =
grouper.template.tierStructure.logicClass ={noformat}

The Grouper UI will throw a {{NullPointerException}} anytime someone attempts to click the “Run template” button. However, this is trivially fixable with a slight adjustment to {{edu.internet2.middleware.grouper.grouperUi.serviceLogic.UiV2Template}}.

h3. Solution (7.8.0)

Instead of blanking the logicClass (PR #273, not merged), each built-in template has an explicit boolean in grouper-ui.properties, default true:

{noformat}grouper.template.service.enabled = false
grouper.template.policyGroup.enabled = false
grouper.template.tierStructure.enabled = false{noformat}

A disabled template is not offered in the template dropdown, and cannot be run if its key is submitted directly (the UI shows 'This template is not enabled'). A blank logicClass is also treated as disabled, so the overlay in the description no longer throws a NullPointerException.
