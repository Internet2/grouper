# GRP-7031  GSH Java template compilation — compiled report dispatch via ReportConfigType.GSH

* Phase 7 (report). Builds on the GRP-7026 dispatch helper and GRP-7010/7011. Design doc: {{grouper/temp/trash/gshCompileImprovement.html}}.
 * Today a GSH report stores its body as *inline Groovy* in the {{reportConfigScript}} attribute and runs it via {{GrouperGroovysh}} in {{{}ReportConfigType.GSH.retrieveReportDataByConfig{}}}. There is *no* GSH template-config link, so unlike the other types this one needs new report-config surface to reference a compiled template.
 * Add a report config attribute {{reportConfigGshTemplateConfigId}} (in {{GrouperReportConfigAttributeNames}} + {{GrouperReportConfigurationBean}} + {{{}GrouperReportConfigService{}}}) so a report can point at a {{{}templateType=report{}}}, {{templateMode=compiled}} GSH template. (Discriminator: treat a non-blank {{gshTemplateConfigId}} as "compiled", mirroring how the change-log/daemon dispatchers branch — no separate mode flag needed unless we want it explicit.)
 * Branch in {{{}ReportConfigType.GSH.retrieveReportDataByConfig{}}}: when a {{gshTemplateConfigId}} is configured, resolve {{GrouperTemplateReport}} via {{{}GshTemplateCompiledDispatch.instantiate(configId, config, GrouperTemplateReport.class){}}}, assign the {{GshReportRuntime}} ThreadLocal (so helper code's {{retrieveGshReportRuntime()}} still works), and call {{{}runReport(gshReportRuntime){}}}; otherwise keep the existing inline-Groovy path.
 * Reuse the existing {{GshReportRuntime}} context — owning group/stem, subject, and {{{}getGrouperReportData().setFile(...){}}}. Map failures to {{reportInstance}} status {{ERROR}} exactly as the Groovy path does today.
 * UI: add a field on the report-config edit screen for the GSH template config id (shown for GSH reports); externalized label/description in {{grouper.textNg.en.us.base.properties}} only (no French).
 * Tests: a compiled report template produces report data end-to-end; wrong base → clear {{{}ClassCastException{}}}-backed error.
