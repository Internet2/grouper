# GRP-7038  Deprovisioning config save can create duplicate metadata attribute assignments under concurrent saves

* {{GrouperDeprovisioningConfiguration.storeConfiguration()}} → {{updateAttribute()}} → {{assignValue()}} (find-or-create) gated by stale {{{}originalConfig{}}}.
 * Concurrent saves (double-click, two tabs, two UI/WS nodes) both load stale state, both see "changed," both insert → value-identical duplicate assignment-on-assignment rows on a single-assign def.
 * Fix: serialize the save per owner — one transaction, pessimistic lock keyed to the owner (owner row or base attribute-assign row), re-read {{originalConfig}} after the lock, then apply writes and commit. Second save then sees committed value and no-ops.
 * Belt-and-suspenders: in {{{}updateAttribute{}}}, before insert, look up the existing assign-on-assign for that name and update rather than add.
 * Optional UI: disable save button on submit / one-time POST token.
