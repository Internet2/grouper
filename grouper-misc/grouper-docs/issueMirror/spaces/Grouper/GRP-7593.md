# GRP-7593  Web service external system: dynamic authentication from a compiled externalSystem GSH template

Some web services have no static API key or OAuth client credentials. For example LibreChat's admin API only accepts a short-lived (15 minute) JWT that comes from an SSO login, and the site may sit behind a load balancer with its own login cookie. The web service external system (WsBearerTokenExternalSystem) cannot authenticate to those today.

Add a "dynamic" authentication type to the web service external system, backed by a new compiled GSH template type.

New GSH template type: externalSystem (templateMode=compiled only). The compiled class extends the new base class GrouperTemplateExternalSystem and overrides decorateHttpClient(GrouperHttpClient httpClient, String externalSystemConfigId) to add whatever headers or cookies the target needs. The base class is generic so other external system types can call other hook methods on it later.

Web service external system:
- grouper.wsBearerToken.<id>.httpAuthnType = dynamic
- grouper.wsBearerToken.<id>.dynamicGshTemplateConfigId = dropdown of enabled compiled GSH templates with templateType=externalSystem (new GshTemplateExternalSystemConfigIds option driver)
- The template is called from attachAuthenticationToHttpClient, which runs before every attempt including retries, so the template can refresh an expired token. One template instance is kept per external system config id (replaced when the template source changes) so a template can cache tokens in memory.
- Endpoint, proxy, additional headers, 429 handling, delay between calls and the external system Test button all work as before.

The template keeps its own configuration (target host, credentials) and is responsible for marking secret headers as do-not-log.

Use case: PennGroups provisioning to PennChat (LibreChat) where the token comes from a Playwright SSO login.
