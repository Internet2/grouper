# GRP-7277  Container: bump Tomcat to 9.0.121 for CVE-2026-68763 and CVE-2026-68569

The container pinned TOMCAT_VERSION=9.0.120. Tomcat 9.0.121 was released 2026-08-25 as a security release and every CVE in it lists an affected range ending at 9.0.120.

Two are rated Important. CVE-2026-68763 is a denial of service via an allocation leak in HTTP/2 backlog tracking when a stream is reset, affecting 9.0.39 through 9.0.120. That one applies to the container as shipped, because HTTP/2 is enabled in container_files/tomcat/conf/server.xml.grouper via the Http2Protocol UpgradeProtocol element. CVE-2026-68569 is a fail-open principal lookup, where CLIENT-CERT or SPNEGO authentication succeeds for a user that does not exist in DataSourceRealm or JDBCRealm, affecting 9.0.0.M1 through 9.0.120. The shipped server.xml uses LockOutRealm with UserDatabaseRealm, so the default configuration is not affected, but any deployer who substituted a JDBC or DataSource realm with certificate or SPNEGO authentication is, and that is worth a release note.

Two further issues are rated Low: CVE-2026-73180, an authenticated WebSocket session outliving the HTTP session that authenticated it, and CVE-2026-66422, security-role-ref definitions bypassing declarative role constraints.

This is a one line change to the ARG in the Dockerfile. No configuration work is needed. The entire conf directory is byte identical between 9.0.120 and 9.0.121, server.xml.original still matches the stock 9.0.121 server.xml exactly, server.xml.grouper.patch applies cleanly to the stock 9.0.121 server.xml with no fuzz or offset, and no web.xml is patched at all. That is expected for a security-only release.

The apache-tomcat-9.0.121.tar.gz tarball has been staged on software.internet2.edu under grouper/downloads/tools, which is where containerDockerfileInstallGrouper.sh fetches it from, so the build will find it.

Applied to the 7 branch only.
