# GRP-7259  grouper-release skill: stability timing, upgrade task vs instruction cells, security-first highlights

Cutting the 7.4.0 release surfaced gaps and ambiguities in the grouper-release skill (grouper-misc/grouper-docs/skills/grouper-release/SKILL.md).  Fix them so the next release does not repeat the same mistakes.

Changes:

* Stability timing: a release ships as RELEASED and is promoted to LATEST STABLE only after about a week with no issues reported.  The skill did not say this, so a new release could be marked stable on release day.
* Upgrade instructions vs Upgrade tasks: the skill described both cells with one example, and they mean different things.  Upgrade instructions is None unless a shipped Jira needs operators to be aware of something (a count when non-empty); Upgrade tasks is the upgrade task number(s), with (DDL) only when GrouperDdl.java actually changed.
* Highlight list ordering: security items go first (vulnerability fixes, then third-party jar upgrades) so a site deciding whether to upgrade sees them without reading the whole cell.
* Resolving issues: use the bare Resolved transition with no resolution value, which is the project convention; ask before transitioning since an issue may be deliberately left open; an unresolved issue still carries the fixVersion but drops out of the release-notes count.
* Counting Jiras: GET /rest/api/3/search/jql no longer returns a total.  Use POST /rest/api/3/search/approximate-count and sanity-check it against the previous release's published number.
