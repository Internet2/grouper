# GRP-7559  LDAP provisioner: stale member DN (NO_SUCH_OBJECT) fails the whole group and the incremental never refreshes it

Environment: v7, LDAP provisioner to Active Directory, groupAttributes membership (member attribute on the group), entity attribute value cache 0 = ldap_dn, insertEntities=false, about 6,600 provisioned groups and 1.3M memberships, some groups with 10k+ members.

Problem: users get moved between OUs in AD (department changes), which changes their DN. The provisioner keeps the old DN in the entity attribute value cache (ldap_dn) until the next full sync re-reads users. The incremental then writes the old DN into a group member attribute and AD rejects the modify with resultCode=NO_SUCH_OBJECT (00000525 NameErr ... best match of ''). The group object exists. Example: the cache held CN=x,OU=Staff,OU=4651,... while the user was actually at CN=x,OU=Staff,OU=4630,...

Because membership is a group attribute, one bad member value fails the whole group modify (LdapProvisioningTargetDao.updateGroup), and the whole group gets an error. addErrorsToQueue then re-queues that group on every incremental run with a recalc of all memberships, and hits the same stale DN again. The loop only ends when the full sync refreshes the DN cache. The full sync waits for the incremental (waitForRelatedJobsToFinishThenRun), so in our case it sat pending for up to 5h42m, and group changes were delayed for hours. Normally the incremental finishes in 1-2 seconds.

Requested fix:

# When a group member modify returns NO_SUCH_OBJECT, re-retrieve the affected entities from the target by their search attributes (employeeID / cn), update the ldap_dn cache and entity link, and retry the modify.
# If it still fails, fall back to per-value modifies so only the bad membership gets an error, not the whole group.
