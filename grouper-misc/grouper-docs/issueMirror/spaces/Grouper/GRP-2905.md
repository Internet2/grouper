### Chad Redman  (unc.edu) - 2020-08-05T06:45:31.287+0000

The fault is with MS docs:

[https://docs.microsoft.com/en-us/graph/api/resources/group?view=graph-rest-1.0#group-visibility-options] ("Hiddenmembership")

[https://github.com/microsoftgraph/microsoft-graph-docs/blob/master/api-reference/v1.0/api/group-post-groups.md] ("HiddenMembership")

_(Note that the github doc only [added HiddenMembership on 4/3/2020|https://github.com/microsoftgraph/microsoft-graph-docs/commit/2ea43b4afa2bf5e1f40d32238356339042dd7c8e], while the Grouper commit adding the visibility feature was added 4/16/2020. So not a lot of lead time to stay current with the docs!)_

 

While the group creation endpoint in Graph api seems to accept either value, the one coming back is HiddenMembership. Grouper's retrofit2 POJO needs the visibility enum to match the actual value.

The canonical value to put into the changeLog.consumer.<...>.visibility is now officially HiddenMembership to match the updated enum. But the older Hiddenmembership value will be remapped internally, and thus will continue to work.
