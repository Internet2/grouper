# GRP-6857  Jexl scripted group daemons should handle HookVeto exceptions with simple count and message instead of full stack trace

When a membership insert or delete is vetoed by a hook (e.g., MembershipVetoIfDeprovisionedHook), the jexl scripted group daemons (full sync and incremental) currently treat it as a regular error with a full stack trace in the job message. Vetoes are expected behavior and should be logged more cleanly.

Changes:

Catch HookVeto separately from RuntimeException in both GrouperLoaderJexlScriptFullSync and GrouperLoaderJexlScriptIncremental
Track veto counts separately in the debug map (vetoesAddMember, vetoesDeleteMember) so they don't inflate error counts
Log up to 20 veto examples (vetoInsert_N, vetoDelete_N) with just group name, subject ID, and veto message — no stack trace
Use LOG.warn instead of LOG.error for vetoes
