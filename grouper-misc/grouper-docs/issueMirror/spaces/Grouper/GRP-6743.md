# GRP-6743  restrict grouper mcp by folders, groups, entities

*Move readwrite scope enforcement into tool classes and add "restricted empty = denied" behavior*

When an OAuth user consents to readwrite access with data-scope restrictions (specific folders, groups, or subjects), those restrictions are now enforced inside each individual tool rather than centrally in the servlet. This makes the security checks easier to test and maintain.

Additionally, if a user only selects restrictions for some categories (e.g., they specify subjects but leave folders and groups blank), the blank categories are now fully restricted rather than wide open. Previously, leaving a category blank meant no restriction, which could allow unintended modifications. For example, a user who only authorized access to specific subjects could still create or modify any group. Now, blank categories are treated as "nothing allowed" when scope restrictions are active.

*Changes:*
 * Scope checks moved from the servlet into each of the five readwrite tools (add member, remove member, group save, privilege assign, attribute assignment save)
 * Added a flag to distinguish between "no restrictions configured" (all allowed) and "restrictions active but category left blank" (nothing allowed)
 * Updated wiki documentation (user guide, admin guide, technical guide) to clarify that blank categories are fully restricted
 * Added unit tests for the scope restriction logic and integration tests for each readwrite tool verifying that out-of-scope requests are denied and in-scope requests succeed
