# GRP-7195  Provisioning full sync deletes target memberships when a matching id maps to multiple grouper memberships

h2. Summary

When two (or more) Grouper memberships translate to the same membership matching id, the provisioning framework does not merely reject the ambiguous/extra membership — it refuses to match the target row to any of them, leaving the existing target row unmatched. With {{deleteMembershipsIfNotExistInGrouper=true}} the unmatched row is then *deleted*, even though two or more Grouper memberships legitimately want it to exist. On the next full sync the row is missing, both memberships look "not in target," and it is re-inserted (one insert succeeds, the other collides). The result is a per-run add/remove flap plus MAT and "already exists" errors on a membership that should simply be left in place.
