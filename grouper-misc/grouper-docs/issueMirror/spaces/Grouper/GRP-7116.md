# GRP-7116  finish provisioner read from sync-back cache fan-out

The proven recipe (so we don't rediscover it):

*Per provisioner:*
 # *Capability* — declare {{canFullSyncEntitiesFromSyncBack}} (+ {{{}Groups{}}}/{{{}Memberships{}}} if the model supports it). Scope to the *group-centric* membership model ({{{}isScimRetrieveMembershipsByGroup{}}} / {{{}canRetrieveMembershipsAllByGroup{}}}). Entity-centric (byUser) needs the mirror-image {{users ⟹ memberships}} coupling, which is not built.
 # *Managed-attribute capture* — the #1 footgun. Default capture list must include every attribute Grouper manages ({{{}update=true{}}}), under the grouper name, with JSON paths for nested fields. The guardrail warns on any missing.
 # *Per-axis provisioners* (SCIM/Azure/LDAP) need no retrieval-code change (adapter skips the pull). Add {{<name>RetrieveAll\{Users,Groups}ApiCall}} debug keys so tests can assert the skip.
 # *Tests* — mirror the Okta/Google from-cache set: users warm cache, missing-from-cache re-read, and (where the coupling is verified) groups warm cache. In-process mock where available (Google/SCIM/Azure use DB-backed mocks, no Tomcat).
 # Validations - if memberships read from cache requires group or users, then validate that (like okta?)

*Key gotchas learned:*
 * Managed attrs missing from the shadow -> spurious update -> cascade (Google 4-vs-2). Always capture them.
 * Group-centric membership selection is driven by capability, not the {{selectMemberships}} config flag (fixed in {{{}isSelectMembershipsInGeneral{}}}).
 * SCIM memberships ride the group pull (members array in GET /Groups); groups-from-cache depends on memberships-from-cache via the coupling.
 * Azure entity translation skips {{{}subjectId.startsWith('test'){}}}, so tests need {{RegistrySubject}} UPN subjects, not {{{}SubjectTestHelper.SUBJ*{}}}; configs use {{{}assignUdelUseCase{}}}/{{{}assignDisplayNameMapping{}}}.
