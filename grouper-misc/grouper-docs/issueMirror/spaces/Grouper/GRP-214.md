# GRP-214  group disappears temporarily from list

This isnt critical, but when I do these steps, a group drops from the list of groups in a folder.  Then after a little while, it re-appears:

0. Act as admin
1. See a folder in "explore" which a bunch of groups
2. Click on a group (mine is a 
3. Click on manage members
4. Click on add members
5. Search for some members
6. Decide you dont want to add any, and click on the parent folder of the group (under "current location is")
7. See the group not in the list
8. Click on "Explore", and the group pops up again

### Gary Brown - 2009-01-29T09:04:08.646+0000

I think the issue here may be that the UI still thinks you are browsing to find members - and since you can't add a group as a member of itself...

There used to be a button which said something to the effect of 'Cancel add members', but now says 'Return to Group Summary', which doesn't convey the same meaning. However, there is still an inconsistency in how the UI is behaving. When you first click 'Add members', the current group is selected and the list of members shown. At first sight this is nonsensical - no point adding members who are already members, however, if the group had custom list attributes the UI lets you select a list and choose members from there. It is inconsistent to not let someone browse back to the group in this case.

I'll have a look at trying to make the behaviour more intelligent i.e. only default to the current group and show it when browsing if there are custom lists, but we need to look at the label again  - or find a more 'in your face' way of making it obvious when you are searching for members and how to cancel - may be Jen can come up with something?
