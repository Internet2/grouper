# GRP-1732  Get Travis CI working again

Travis is set up already, but has been failing for a while for various reasons. In some cases, it's because the Maven builds don't finish. Other times, it's something like Oracle JDK 7 no longer being available.

## Comments

### cer28 - 2018-04-17T19:07:27.898+0000

Was able to build successfully in the master branch for OpenJDK 7 and 8, but v6 failed. The Oracle JDK 8 Maven build worked, and the coveralls worked, but the last step to deploy gh-pages failed as it timed out after 10 minutes with no output.

 

The gh-pages step clones the entire repository, switches to branch "gh-pages" and updates everything with the current Javadocs. Except for the occasional case of a public method changing, 99.999+ percent of the commits in this branch are changing the timestamp on 3000+ files. You can't even see the useful changes, because Github doesn't show the diff with so many files modified. I recommend skipping this step in Travis, primarily because it takes more than 10 minutes to clone the grouper repo so it will time out and fail, but also it doesn't seem useful to put the javadocs in Git, which could easily be regenerated on demand.
