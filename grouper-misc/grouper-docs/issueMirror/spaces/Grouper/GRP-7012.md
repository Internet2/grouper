# GRP-7012  Provisioner failsafe should not depend on loader.failsafe.use=true

h2. Upgrade instruction

Note that other failsafe issues were resolved (GRP-7014, GRP-7015), so if failsafes were configured on provisioners they might be performing correctly and you might see more failsafes.

You might be affected if you have any provisioner failsafe configured. After upgrade, a provisioner enforces failsafe only when both {{showFailsafe=true}} AND {{failsafeUse=true}} are set on that provisioner (directly or via a provisioner default config). {{loader.failsafe.use}} no longer affects provisioners.

To check, first note whether {{loader.failsafe.use=true}} is set in {{grouper-loader.properties}} — you need it to interpret each provisioner. Then in {{grouper-loader.properties}} find every provisioner with {{showFailsafe=true}} (and check provisioner-default configs like {{provisioner.default.{*}{*}}} */ {{provisioner.<type>.default.}}* for the same):
 * If {{failsafeUse=true}} on the provisioner → no change.
 * If {{failsafeUse=false}} on the provisioner → no change (still off).
 * If {{failsafeUse}} is blank:
 ** and {{loader.failsafe.use=true}} → {*}was enforcing, will stop{*}. Set {{failsafeUse=true}} (on the provisioner or a default) to keep enforcement.
 ** and {{loader.failsafe.use=false}} → no behavior change (was already off).

Also, if {{loader.failsafe.use=true}} today and some provisioners have no {{showFailsafe}} at all, those were enforcing with global defaults and will stop. Set {{showFailsafe=true}} and {{failsafeUse=true}} on those (or on a provisioner default) to keep enforcement.

Loader jobs (SQL/LDAP) are unaffected — {{loader.failsafe.use}} still governs those.
h2. Jira notes:

Problem: provisioner failsafe enforcement currently piggybacks on {{{}loader.failsafe.use{}}}, a SQL/LDAP loader-job flag. An admin can check "Show failsafe options", fill in aggressive thresholds, and the provisioner will silently ignore them unless {{loader.failsafe.use=true}} is set globally or {{failsafeUse=true}} is explicit on the provisioner. Reported on the Internet2 list against 7.0.3.

Fix: in {{{}GrouperProvisioningFailsafe.processFailsafesSetupBean{}}}, stop consulting {{{}loader.failsafe.use{}}}. Provisioner failsafe is enabled only when {{showFailsafe=true}} AND {{failsafeUse=true}} on the provisioner (directly or via a provisioner default config). Loader jobs unchanged — {{loader.failsafe.use}} still governs those.
