# GRP-6958  Raise default hibernate.jdbc.batch_size from 200 to 1000

Background

{{hibernate.jdbc.batch_size}} in {{grouper.hibernate.base.properties}} controls how many INSERT/UPDATE/DELETE statements Hibernate batches per JDBC round trip when flushing the session. It has been set to 200 since the Hibernate 3.x era and has not been revisited since.

For high-volume insert paths — most notably the {{changeLogTempToChangeLog}} daemon (see GRP-6956) processing large ABAC backlogs, but also bulk loader runs, large privilege/group-set fan-out, and any other code path that calls {{saveBatch}} over thousands of entities — the per-page work is dominated by JDBC round trips and 200 leaves measurable throughput on the table.

Change

{{{}hibernate.jdbc.batch_size{}}}: *200 → 1000* in {{grouper/conf/grouper.hibernate.base.properties}}.

Rationale
 * 5x fewer JDBC round trips on bulk insert paths.
 * Well inside Oracle / Postgres / MySQL safety margins: at ~30 columns per row (e.g. {{{}grouper_change_log_entry{}}}), batch 1000 = ~30,000 bind variables per statement, an order of magnitude below Oracle's 65K limit and well within all three drivers' batched-statement memory budgets.
 * Throughput curve is flat in this region — 1000 is the largest value with materially diminishing returns above it, but small enough that small-transaction memory/latency is unaffected.
 * No expected regression on small operations: Hibernate flushes when the session reaches the batch size or when a {{flush()}} / {{commit()}} is called, whichever comes first. Operations that touch fewer than 1000 entities behave identically to before.
 * Override remains available in {{grouper.hibernate.properties}} per deployment.

Companion to GRP-6956

GRP-6956 raised the change-log temp-to-entity page size from 1000 to 5000. That bump increases the number of entities flushed per Hibernate session per page. Raising {{hibernate.jdbc.batch_size}} to 1000 lets that larger per-page batch actually translate into fewer JDBC round trips rather than being capped at 5 round trips of 200 each.

Safety
 * Global Hibernate setting — affects every persistence path in Grouper, not just the change-log daemon. The widened blast radius is the reason this is a separate ticket from GRP-6956.
 * Behavior is equivalent for sessions that flush fewer than 1000 entities (the common case in the UI).
 * No DDL change, no API change, no schema change. Deployments can revert via {{grouper.hibernate.properties}} override.
