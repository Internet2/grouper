# GRP-6862  revert data provider full sync member batching in preparation for subject ID range batching

Revert the member batching introduced in GRP-6798 which batched the processing/writing of changes in calculateAndStoreChanges(). This batching added complexity without addressing the root memory issue — all source and Grouper data was still loaded into memory upfront. A new approach will batch at the data retrieval level using subject ID ranges, which bounds memory usage more effectively. Post-GRP-6798 improvements are retained: readonly mode, debug map change examples, improved duplicate key logging, count fixes, and SubjectSourceCache threshold.
