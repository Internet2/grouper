# GRP-7435  AssetSonar provisioner: assetSonarExcludeEmails so non-person accounts are never managed

An LDAP-fed AssetSonar tenant has many members that are not people: equipment logins, per-lab shared accounts and service accounts, some with institutional addresses (e.g. biochem@example.com, labaccount@example.com). The provisioner matches on email, so a provisioned person whose address equals one of those would adopt and rename the account, and deleteEntitiesIfNotExistInGrouper would deactivate all of them. The AssetSonar docs recommended targetEntityAttribute.N.ignoreIfMatchesValue, but that is parsed and never used anywhere.

Add provisioner config assetSonarExcludeEmails (comma or newline separated, case-insensitive). Excluded members are dropped from every select and from sync-back capture, an insert/update/delete for an excluded email is refused (insert is an error, so a person colliding with an excluded account is visible), and the docs drop the ignoreIfMatchesValue recommendation.
