# GRP-7289  grouper-release and cherry-pick skills: mirror first, push before tagging, quickstart smoke test, fixVersion reconciliation, and expiring old release-notes rows

Updates to grouper-misc/grouper-docs/skills from cutting 4.25.0, 6.4.0 and 7.5.0. Each item comes from something that actually went wrong or was ambiguous during those releases.

grouper-release skill:

* Refresh the grouper-docs mirrors FIRST, before tagging, so the refresh is part of the release rather than a commit landing after the tag.
* Push everything, THEN tag, and verify the tag is an ancestor of the pushed branch. git push --tags does not push the branch: 6.4.0 shipped with origin/GROUPER_6_BRANCH one commit behind its own tag.
* Smoke-test the published image with a local quickstart. Includes the v4 port difference (v4 fronts Tomcat with Apache on 443 and has nothing on 8443, unlike v6/v7), the bs4 venv dependency, and that GROUPER_AUTO_DDL_UPTOVERSION should not be set because prep_quickstart sets it.
* Reconcile the tagged fixVersion set against the commit range and against the container Versions cell before writing the release-notes row. 7.5.0 shipped with GRP-7197 carrying no fixVersion at all, and with the Tomcat 9.0.120 to 9.0.121 bump missing from the security highlight because GRP-7277 was tagged only 6.4.0 and 4.25.0.
* Expire release-notes rows older than three months before the LATEST STABLE anchor, on both release and promotion, and strip the data-highlight-colour attribute that promotions had been leaving behind on every page.
* Correct the sha256 guidance: the digest is split 10/18/18/18 across four spans separated by br, which is what every row on every page uses. The previous text said the opposite. Also use the multi-arch manifest-list digest resolved from the registry, since docker image inspect prints both it and a per-arch digest in an unstable order.

cherry-pick skill: describe a batch and then wait for an informed confirmation rather than picking in the same turn; skip or revert picks that are both difficult and unnecessary; run unit tests after merging; composite-in-place is v7 only.
