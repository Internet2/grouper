# GRP-7190  Folder tree hangs (folderTree.set is not a function) on object view when uiV2.refresh.menu.on.view is true

Symptom: with uiV2.refresh.menu.on.view=true, viewing a folder, group, attributeDef, or attributeDefName page throws a browser console error TypeError: folderTree.set is not a function (in openFolderTreePathToObject in grouperUi.js) and the view page hangs and never finishes loading. GSH lookups and the subject view page are unaffected, and the left-nav folder tree renders on its own, but it can no longer focus or open the path to the object being viewed. Reported by another institution testing v6/v7 (tried 6.1.0, 6.3.0, and 7.3.2).

Root cause: GRP-6521 refactored the Dojo/dijit folder tree into a jsTree and removed Dojo altogether, including the global folderTree object. It left the legacy JS stub openFolderTreePathToObject(pathArray), emitted by the server on object view (UiV2Stem, UiV2Group, UiV2AttributeDef, UiV2AttributeDefName, UiV2Visualization when isMenuRefreshOnView is true), still calling folderTree.set with path and pathArray -- the removed dijit Tree API. With Dojo gone, the name folderTree now resolves to the folderTree div element (browsers auto-expose an element id as a global), and a div has no set method, so the call throws.

Impact: the property defaults to false, so most sites do not see it; any site that enables uiV2.refresh.menu.on.view hits it on every object view. This is a regression introduced by the Dojo removal.

Fix: redirect the global openFolderTreePathToObject stub to dojoInitMenu(true), the maintained jsTree refresh-and-focus path already used by the Browse-folders refresh button and the on-view JSPs. It re-derives the current object from the browser URL (which guiV2link has already updated via History.pushState by the time the script runs), so the server-provided pathArray is no longer needed. Also bumped the grouperUi.js cache-buster to ver=7.3.3. Verified locally: after the fix, navigating to an object no longer throws and the tree auto-expands and selects the viewed object.

## Comments

### Chris Hyzer - 2026-07-28T10:52:07.584-0400

Workaround for sites on an affected release until the fix ships: set uiV2.refresh.menu.on.view=false in grouper-ui.properties and restart. That property defaults to false, so only sites that have enabled it are affected. With it off, the server no longer emits the openFolderTreePathToObject call that throws folderTree.set is not a function, and the folder/group/attributeDef view pages load normally. Trade-off: the left-nav tree will not auto-expand and highlight the object you are viewing. The fix in this issue restores that behavior with the property on.
