# GRP-2296  IncrementalLoading: Disabled Loader Jobs

We had disabled a broken loader job in UI in order to keep the existing memberships safe from the loader-job's problems. Unfortunately, it looks like the Incremental Loader continued to process events for that broken Job and removed members.

Expected behavior:
 * Do not touch the groups managed by a disabled loader job
 * If at all possible, leave the events in the queue until the job is enabled. If not possible, log that the event is being completed without processing because the loader job is disabled.

## Comments

### Shilen Patel - 2019-08-26T15:06:18.060+0000

Since the full sync would fix it anyways, I'll just delete the events from the queue (with a warning message) to avoid a performance issue of having to keep checking those events when trying to process other/valid changes especially if the loader job is disabled for a while.  And that would also avoid processes any "bad" events that may have been queued up for the same reason that the full sync was disabled.
