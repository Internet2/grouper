### Chris Hyzer - 2026-06-30T01:29:46.959+0000

Root cause: in the quickstart container setup script {{container_files/usr-local-bin/librarySetupFilesForComponent.sh}} (function {{{}setupFilesForComponent_quickstart{}}}), the trailing-newline guard was pointed at the wrong file. The {{echo ''}} that's supposed to guarantee a trailing newline was appended to {{{}grouper.hibernate.base.properties{}}}, but the password override property itself is appended to {{grouper.hibernate.properties}} -- a different file. So the guard did nothing for the file actually receiving the override. When {{grouper.hibernate.properties}} didn't already end in a newline, the override concatenated onto the last existing line, producing the reported {{{}hibernate.c3p0.max_size = 100grouperPasswordConfigOverride_WS_GrouperSystem_pass.elConfig = ...{}}}.

This affected both the UI block and the WS block, and was present in the v4, v6, and v7 containers. The INFO log lines also incorrectly said "edit grouper.hibernate.base.properties" when the real edit was to grouper.hibernate.properties.

Fix: point the {{echo ''}} newline guard at the same file the override is appended to ({{{}grouper.hibernate.properties{}}}, dropping {{{}.base.{}}}), and corrected the log messages to match. Applied to all of v4/v6/v7, both UI and WS blocks.
