## **Current Work**

**Vivek**

- Doing provisioner related work
- Allowing JSON pointers
- SCIM based loading entities into Grouper is now supported
- The tables loaded are raw data from the target
- From those you can make a loader based on certain attributes
- Custom attributes can be read from the target, you don’t need to load them
- Can map custom attributes as read only
- They will be pulled in at a full sync
- Design decision, should attribute name be JSON pointer? They are loosely coupled
- Make a friendly name helps
- Bert: is this SCIM specific? Should it be a generic provisioner capability?
- JSON rest provisioners?
- PSP NG was wrapped around target specific subject class that was beneficial to let the provisioner framework carry that around as opaque blob
- You can hold onto the data, cache, etc. But don’t have to mess around w schemas
- Chris: since those APIs don’t have extensions like SCIM does, this seemed to be SCIM specific
- Request to add some things to the interID ? That object model is huge
- Goal of provisioner is not to handle JSON blobs
- In Service Now example, Some attributes are references to other things
- Need data loaded in tables to have entity resolved in provisioner
- If we load name and value, we can have view on the table
- We will see how well it works for Service Now
- Add custom attributes
