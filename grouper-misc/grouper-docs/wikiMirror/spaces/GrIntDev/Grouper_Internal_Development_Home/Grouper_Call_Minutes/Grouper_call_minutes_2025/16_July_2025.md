**From Zoom AI******

**System Upgrade Strategy Discussion**

The team discussed strategies for upgrading users from version 4 to 5 of their system.   
Chris Hyzer and Shilen considered using SQL-based priming to avoid rewriting existing code, while Carey suggested creating version-specific releases that lockstep upgrade from 4 to 5.   
The group agreed that a standalone SQL daemon in version 4 could handle the migration, potentially running once and allowing users to upgrade to version 5 without downing jobs.   
Ben emphasized the importance of building the primer before the upgrade is needed, and Shilen noted that the process might require deleting and reinserting data to ensure accuracy.

**V5 Upgrade Planning Strategy**

Shilen discussed running a task a week before upgrading to V5 to ensure data accuracy in cache tables.   
Chris Hyzer suggested that running the task a week in advance would be sufficient, as the upgrade process would take about 2 hours in V5. Carey proposed using GSH templates in V4 to create a load job for data staging, which could provide insights for upgrade planning.   
Chris Hyzer expressed concerns about the slowness of GSH templates but acknowledged the need for a strategy similar to Carey's suggestion for future upgrades.   
Bert suggested running the V5 container against the V4 system to manipulate the database, allowing the task to be executed while V4 is still running.

**Database Version Compatibility and Performance**

The team discussed challenges with running version 5 of a database against version 4, where compatibility issues prevent the system from starting properly.   
Bert proposed creating a separate Docker image containing a Java class for cache priming, which would avoid the need for full deployment and be more manageable than the existing installer jar. The group also addressed performance issues with the SQL Cache flow sync job, where Shilen's instance was taking 7-12 hours compared to Chris's 2-hour run time, with Chris suggesting that reducing the number of groups through archiving could improve performance.

**Database Optimization and System Updates**

The team discussed several database and system optimization topics, including a full sync mechanism for version 5 and strategies to reduce recalculation requirements.   
They reviewed ongoing work including an AI-generated web service sample converter, a rewritten installer using bash scripts, and plans to upgrade Bootstrap from version 2 to version 5.   
The team also discussed adding a group summary screen and improving provisioning transparency, with Bert suggesting a provisioning log that shows real-time activity and historical audit data.
