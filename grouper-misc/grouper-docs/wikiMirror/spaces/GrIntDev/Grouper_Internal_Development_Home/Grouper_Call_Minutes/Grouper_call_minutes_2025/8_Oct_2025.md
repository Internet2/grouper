**Group Summary Screen**

- Group Summary Screen was released in Grouper v5.21.2 Release
- [Group summary screen](https://grouper.atlassian.net/wiki/spaces/Grouper/pages/28544847/Group+summary+screen)
- You click on a group and you see the group summary screen, you can click **show more info** to see more. Can optionally see privileges, recent memberships, recent audits and more. There is a default view and more info view.
- Reduced use of bullets
- We now cache the membership size of a group and that is displayed
- If you hit more info, Grouper does the count, thus user could see small discrepancy
- Some SQL issues are being handled, wish we could write things in a way that works everywhere, issue of semi colon is challenging
- We should list standards for queries, and look at cross platform queries
- Tested Oracle
- Person who created the group is listed
- Group fields display are now tooltips
- “Ad hoc” was changed to “manual”
- Some **tabs** were disappearing when they shouldn’t
- We decided not to tackle changes in **privileges** yet in the Group Summary Screen.
- To see privileges you must be an admin of a group.
- Did not want to slow down the release.
- Can tackle that in the future.
- Michael G had suggestions about defaults.
- Shilen: Want to keep things as easy as possible for users who just want to manage members of their group.
- Chris: interested in performance issues
- Perhaps do display thru AJAX

**Grouper Banner Customization Discussion (from Zoom AI)**

The team discussed implementing banner functionality in Grouper, with Kellen sharing his experience of customizing templates at UVA to display maintenance messages and environment information. Chris agreed to add banner customization to his list of features to implement, and the team discussed the possibility of including blank includes for customer customization. Shilen suggested adding customizable content below the group summary header in the summary screen, which Chris agreed to consider further with more specific requirements.

**Docker File Permission Best Practices (from Zoom AI)**

Chris and Chad discussed Docker file permissions and multi-stage builds. They clarified that file permissions should be set in the stage build, not the final image, to avoid creating unnecessary layers. Chris agreed to revise the Dockerfile to remove permission changes in the final image and will test if the container works without them. They also discussed the need for an empty /root directory in the final image for mounting purposes.

**Custom UI and Group Summary Updates (from Zoom AI)**

Shilen demonstrated a custom UI for Grouper and discussed the possibility of inserting custom content into the group summary, such as attributes and descriptions. Chris Hyzer and Shilen debated the feasibility of implementing this feature, considering performance implications and the need for Java classes or JSPs. They agreed that a Java class interface could be a viable solution. Shilen also mentioned updates to JIRAs, including adjustments to fail-safes in data providers and the ability to approve them in the UI.

**Data Provider Sync Issues Resolved (from Zoom AI)**

Shilen and Chris discussed issues with data providers, focusing on a bug where new members weren't being created for subject sources and Gail's problem with only half of data changes being processed. Shilen agreed to work with Gail to investigate and fix the changelog issue. They also reviewed a new web service for triggering data provider syncs, discussing its functionality and the need for better error handling and response codes. Chris suggested making the service accessible to a built-in group with appropriate privileges.

**UI Cleanup and Jira Issues (from Zoom AI)**

The team discussed two main topics: UI config cleanup and Jira/Confluence issues. Chad requested approval to remove unused UI configs, which was granted with the condition of tracking and documenting removed items for future reference. Chris Hubing reported on Jira and Confluence upgrade issues, including problems with user creation and browsing, and mentioned that TSG is investigating the problems. They also discussed managing issue creation permissions, with Chris Hyzer suggesting using the co-manage UI to add appropriate team members to the issue creation group.
