**Call Summary from Zoom AI**

The team discussed various technical updates and improvements to the Grouper system, including modifications to file uploads, authorization integration, and changes to group membership updates. Several performance and scalability issues were addressed, particularly regarding group privileges and SQL synchronization, with the team exploring potential solutions and trade-offs. The conversation ended with discussions about managing special subjects in Grouper and potential improvements to access control, though no final decisions were made on these proposals.

**Next Steps from Zoom AI**

1. Vivek to review and potentially commit changes for the reject pattern option in the "add created groups to another group" rule.
2. Chris Hyzer to look into the issue with entity attributes and incremental provisioning failing without retrying, as mentioned by Chad.
3. Chad to continue working on implementing SQL provisioner support for membership objects with ancillary attributes.
4. Chris Hyzer to consider adding a log message for invalid stem queries in the get groups web service.
5. Chris Hyzer and team to discuss and potentially implement a solution for the privilege scaling issue, possibly involving the creation of special "every entity"-like subjects.
6. Chad to update the Wiki page on renaming subject sources to include a warning about potential impacts on web service clients and API calls.
7. Chris Hyzer to consider adding more detailed output to the incremental Jexel script daemon, similar to the provisioner output.
8. Team to review and potentially implement threading for the incremental Jexel script daemon, similar to the full sync process.

- Can delete old groups

- Use more ABAC helps
- ABAC priv model, the attribute does not have privileges, it’s the security realm
- Loose coupling.
- To see who can read or update an attribute, must go there
- And don’t change security

- Everyone can read everything
- It’s not a big deal to read other groups
- Use every entity for community groups and for central IT
