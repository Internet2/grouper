Privacy-Driven Subject Source System (from Zoom AI)

Chris presented a detailed explanation of a new subject source system that uses data fields and privacy realms. The system allows for different levels of access to subject attributes based on user permissions, with attributes like names having multiple privacy levels. Chris explains that the system will be efficient, using aggressive caching and fast queries. He expresses hope that this feature will be ready for version 5, with potential for further iterations in version 7, and encourages migration to this new data field subject source.

Data Provider Implementation Discussion (from Zoom AI)

Shilen and Chris discuss the implementation of data providers for subject sources. They agree that a single data provider can have multiple queries, all based on subject ID. Chris clarifies that each subject source should have only one data provider marked as a subject source data provider, while other data providers can add attributes to subjects. They address potential race conditions and discuss the importance of handling unresolvable subjects. Shilen raises questions about transaction handling and the use of GCDB Access instead of Hibernate for creating member rows, with Chris suggesting a move towards GCDB Access in preparation for V7.

AI Integration for Grouper Systems (from Zoom AI)

Chris provides an update on AI-related projects for Grouper. An intern is working on scripts to convert wiki content and Slack messages into training data for AI agents. The team is developing a Grouper agent to answer general questions, a GSH writer agent for shell commands, and a web service agent. Chris has published these agents on the ChatGPT store for free use. He is also exploring ways to integrate AI with Grouper's authentication and authorization systems, potentially allowing AI to access and interpret job logs. Gail suggests enhancing the AI's ability to reference specific Slack discussions, which Chris agrees is a valuable idea to implement.

AI Versioning for Grouper Project (from Zoom AI)

Chris discusses the need to address version-specific challenges in AI answers for the grouper project. He proposes keeping training instructions and files in git, tagging them with releases, and creating a feature registry to help AI provide version-appropriate responses. The group discusses various AI implementations at their institutions, including in-house solutions and on-premise deployments. Carey mentions using ChatGPT with caution to avoid data leaks. The team agrees on the potential value of exploring AI integration with Grouper to improve user support and learn about different AI model requirements.

AI Integration in Institutional Systems (from Zoom AI)

Chris discusses various options for integrating AI with institutional systems, including using public or institution-specific GPT models, uploading training files, and potentially developing a Grouper-specific container for AI. Carey expresses interest in hosting a Grouper-specific AI remote answer service, which Chris supports. They also discuss the possibility of enhancing Grouper's built-in help tool with AI capabilities. The conversation touches on documentation tools and the potential move towards markdown-based systems, though Chris notes the challenges of changing from Confluence. The group agrees to continue discussing AI integration in the upcoming documentation call.
