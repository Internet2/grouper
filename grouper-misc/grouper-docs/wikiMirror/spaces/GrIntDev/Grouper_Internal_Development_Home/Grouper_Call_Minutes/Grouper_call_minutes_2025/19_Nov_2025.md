**From Zoom AI**

**V5 to V6 UI Update Review**

The team reviewed the user interface for V5 and V6, with Chris explaining that they are working on the final major update before releasing V6 and moving to V7. Chris described the user lifecycle events feature, which allows configuration of actions based on data changes, such as leaving an institution or changing group memberships. Bert and Chris discussed how the system can be triggered by group changes or attribute modifications, with Chris mentioning that Vivek had joined the meeting.

**User Lifecycle Event Management**

Chris explained the process of managing user lifecycle events through policies, which involves identifying lifecycle events, defining actions for different severity levels, and configuring policies to handle specific scenarios. He described the use of in-flight and historical markers to track membership changes and manage grace periods, with actions such as emailing managers or removing users from groups. Chris also mentioned the need to identify managers through ABAC groups and outlined the functionality of a policy part, which combines lifecycle events and actions. Bert clarified the relationship between policies and policy parts, and Chris explained how multiple lifecycle events could be managed simultaneously, with precedence given to shorter grace periods.

**User Lifecycle Management System Development**

The team discussed the development of a user lifecycle management system, focusing on the need to complete the daemon and implement an approval mechanism. They identified the requirement for a new view in the group screen that would display users with lifecycle events, allowing for overrides or immediate removals. Chris emphasized the importance of a minimal viable product, highlighting features like filtering, attestation, and deprovisioning, while noting that additional functionalities could be developed later.

**ABAC Data Consolidation Benefits**

Bert and Chris discussed the advantages of ABAC, highlighting its ability to consolidate data from various sources into a single view, which is particularly useful for tracking institutional lifecycle events. Bert expressed enthusiasm about the potential for summarizing data in a user-friendly manner, allowing for easier audits and issue identification. Dusty inquired about the timeline for implementing these features, asking if they would be included in version 5 or 6 of the MVP.

**User Lifecycle Management Process Review**

The team discussed user lifecycle management and attestation processes. Bert proposed using end dates and meta end dates for reviewing and approving user lifecycle events, which Chris and Carey supported.

They explored the possibility of implementing a global user lifecycle for attestation, with periodic reviews to ensure compliance.

Chris emphasized the importance of scheduling attestation around group owners and lifecycle events.

**The team agreed to review screenshots of the admin screens and continue working on the proposed ideas.**

Bert noted that the system would be attribute-based, allowing for flexible policy establishment without radio buttons.
