**From Zoom AI:**

**AI Interface and Data Privacy**

Jim presented his work on an AI interface for Grouper, which allows AI agents to interact with the system through web services. He demonstrated the functionality using Claude, a local desktop app, and discussed the potential for future AI workflows. Carey raised concerns about data leakage with cloud-based AI systems, and Chad suggested using local LLMs like Olama for more control over data privacy. The group discussed the evolving landscape of AI technology and the importance of user control over data processing.

**MCP Service Setup and Authentication**

Jim reported spending 3-4 hours initially to set up the MCP service and approximately 15 hours total for development, using Clog Code and Swagger documentation to build tools. Chris Hyzer shared two alternative approaches: a basic auth method for GPT web service calls without requiring an MCP, and an OIDC authentication method that allows AI to call web services as the user. Both discussed the challenge of determining the best architecture for institutions, considering whether to use MCP with local running or shared cloud solutions, with Jim suggesting the decision might depend on users' tools and supported options.

**AI Security and Access Controls**

The group discussed security concerns around AI systems and user access controls. Chris Hyzer expressed worry about AI systems potentially accessing sensitive data through web service calls, while Carey highlighted the importance of proper security measures, including avoiding the use of service accounts. Jim suggested that future AI workflows might rely more on service accounts with limited permissions, and Chris proposed using OIDC and Grouper's permission model to ensure that AI systems only perform actions authorized for the specific user. The discussion concluded with Carey emphasizing the need for local MCP installations and secure handling of credentials.

**AI Integration and Protocol Discussion**

The team discussed the implementation of Model Context Protocol (MCP) for integrating AI with web services, where Jim explained that MCP serves as an interface layer between AI agents and services, allowing for tool definitions and standard I/O communication. Chris Hyzer explored different approaches to leveraging AI with Grouper, including both MCP and action-based implementations, and proposed discussing the pros and cons of both methods.

**Data Provider Performance Optimization (from Zoom AI)**

Shilen discussed changes to the data provider, including handling null values and key fields, and addressed performance issues with scripted groups containing many parameters. He explored potential solutions, such as using rows instead of data fields and adding a unique flag for subject rows. Chris suggested considering a smaller search space for the ABAC subject source to improve performance, particularly for large datasets. They agreed to continue iterating on these solutions and testing different approaches.
