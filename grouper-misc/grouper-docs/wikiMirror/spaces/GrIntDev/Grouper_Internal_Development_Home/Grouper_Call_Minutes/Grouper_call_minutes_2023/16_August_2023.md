- **Document within the Grouper Product**

- A panel of people helping can help us see the overall architecture of the wiki, discover what’s out there, and identify outdated things, and we can prune
- We have not wanted to have a snapshot of the wiki with each released version
- If we prune old and someone is using an ancient version of Grouper, this can cause harm
- Grouper Deployment Guide: standards agreed upon by community take more time, maybe updates to the wiki doc would not be as hard
- Info in the Grouper wiki can be hard to find
- Provisioning info is mixed with developers notes, so doing a search results in more than you want
- Search gets pages for older versions
- So you need to follow many links before you find the page that applies to you
- Version related documentation is hard to manage
- Shibboleth project forks for each version, but Shib only has one version at a time, while Grouper has two valid versions at a time
- Problem with forking: when you clarify something, you may need to go to many old version pages
- Use a working group to figure out the right approach
- Need to get Unicon perspective
- See about forming a working group
- Maybe every other Wednesday, could do a Doodle poll
