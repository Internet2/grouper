**GA Tech Use Case around ABAC**

- Bert interested in group ABAC attributes
- Groups as members of a group
- You can have a script based on that
- Picture ABAC scripts as “I want this attribute but not that attribute”
- “Take out people in lock out group”
- It becomes a list of people
- Having only groups as members, constrains
- Bert’s use case: about course relationships, course groups, instructors and TAs too.
- Course Groups Have:
- Used to build aggregate reference groups
- Went to populating the physical sections as reference groups
- Rolled up based on attributes such as start date
- If move to subject based attributes for this info, then what courses students enrolled in has supporting info,
- Can group groups by having ancillary attributes on the group subject
- Use JEXL to assemble courses currently happening
- Can’t remove people
- If you want groups to be members, you need 2 groups
- Can we have hierarchical attributes on subjects?
- Student data, have a row of info
- Each row is a user
- How to roll it up for each student?
- How to represent a student’s courses?
- Separate campus, start dates, end dates,
- Course is what has the attributes…

- About 8 columns, dept start date, end date
- Each person has a grid of data
- Write an ABAC script based on that
