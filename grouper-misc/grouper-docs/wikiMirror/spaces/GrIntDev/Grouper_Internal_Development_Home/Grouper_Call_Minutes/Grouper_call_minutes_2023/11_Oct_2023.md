 With this fix, we released Grouper 4.7.1

**Password Table issue**

- Not sure we deprovision the password table
- Nothing really cleans that up
- If local entity is deleted it may not get cleaned up in the password table
- Delete local entity should check the password table?
- Chad: people who log in should have subject linked to subject table
- Chris: it’s not a security issue. It’s about having a “clean house”
- Shilen: have a daemon that cleans up after something has been deleted for a certain period
- Could be a daemon where if a subject is unresolvable or deleted
- Member entry should be listed as deleted
- If this is fixed there will be a bunch of updates 1st time
- Question: do we want a loader daemon job, looks in pwd table, sees what is not resolvable and removes it from the pwd table?
- How often do local entities come and go?
- A daemon should be OK
- Add that to the list of TODOs for v5?
