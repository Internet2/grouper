**Overview** Starting with Grouper 7.0.0, Grouper includes a built-in **Model Context Protocol (MCP)** server. MCP is an open standard that allows AI assistants and other tools (referred to as "MCP clients") to interact with external systems through a well-defined protocol. The Grouper MCP server enables AI tools such as Claude, Cursor, VS Code Copilot, and others to query and interact with Grouper programmatically using natural-language-driven workflows.

**Additional Notes from Zoom AI**

**Provisioning Framework Performance Improvements**

The team discussed performance and efficiency improvements for the provisioning framework, focusing on addressing performance issues with large datasets and inefficient data retrieval from target systems like Okta. Chris proposed a non-blocking full data load that could send recalcs to the incremental loader, while Bert suggested using templated parent classes and custom classes to store target system information in the database, reducing the need for frequent re-reading. Carey highlighted the need for flexibility in the provisioner model to handle objects not known to Grouper, such as different group types in Azure, and suggested using folder structures to model permissions in target systems like Tableau. The team agreed to implement a generic framework for provisioning users, groups, and memberships, while maintaining provisioner-specific implementations for niche cases.

**Versioning Strategy and Data Storage**

The team discussed subclassing provisioning and the need to break up data storage from JSON to a more queryable format. Chris proposed a new versioning strategy with V7 as an enhancement branch that doesn't change the database structure, while V9/10 will include database rewrite. The team agreed to allow V7 features to be cherry-picked back to V6 if they prove stable after release, while V4 users will need to wait for V6 or V7 depending on their needs.

**AI Code Review and Updates**

The team discussed the benefits and limitations of using AI tools like Cloud Code for writing and reviewing code, with Chris and Carey agreeing on the importance of implementing review processes to catch potential errors. Shilen provided updates on three Jiras, including improvements to point-in-time code handling, the implementation of the "member of any" ABAC option for better performance, and changes to handle authorization request errors from OIDC more effectively.

**AI Guardrails in Grouper Implementation**

Carey and Chris discussed the implementation of AI guardrails in Grouper, focusing on the balance between security and functionality. They explored the idea of allowing local admins to configure what AI can modify, as well as the use of read-only database connections for API calls. Jim expressed support for the built-in guardrails and suggested considering the different use cases for web services and MCP tools. Chris mentioned plans to add new web service operations while keeping some features exclusive to MCP.

**AI Integration with Machine Protocols**

The team discussed implementing MCP (Machine Communication Protocol) with AI agents, focusing on how to integrate external LLMs with Grouper containers. Carey emphasized the need for AI to be deployable within the network, while Chris explained that MCP tools are defined as Java classes with both definition and execute methods. The team agreed to explore using Olama as a proof of concept for AI integration, with Chad suggesting a containerized approach that would allow institutions to use Olama without local installation. The conversation ended with discussions about TechX proposals and community contributions, with Chris encouraging team members to share their Grouper experiences and consider making contributions to the project.
