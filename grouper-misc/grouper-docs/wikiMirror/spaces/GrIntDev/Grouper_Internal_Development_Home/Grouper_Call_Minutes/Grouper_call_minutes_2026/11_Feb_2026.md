## Grouper Release Announcement Feb. 10, 2026

We are proud to announce the release of *Grouper v6.0.1*. There are four upgrade instructions from v5.22.5.

Thanks to early adopters who kick the tires and report issues which we will fix asap.

Special thanks to Chad, Shilen, and Vivek for all the hard work over the last couple of months to make this happen.

This is a significant announcement since:

1. 1. 1. 1. v4 will be unsupported in 12 months. Time to start the upgrade planning.
      2. v4 will receive security fixes, and important bug fixes which are low risk with non-conflicting merges (which as you have seen is more and more difficult as time passes)
      3. v5 will have no more releases. v6 is the new v5. The upgrade from the latest v5 to v6 is not difficult.
      4. If you upgrade from v5 to v6 and have an issue you should be able to revert back to v5 temporarily/quickly if needed.
      5. v6 will receive security fixes and important low risk bug fixes, especially regarding: ABAC, user lifecycle events, provisioning, and other relatively new modules
      6. v7 development will begin. This is a significant rewrite which will not be usable for while

Upgrade notes:

1. 1. 1. 1. You can upgrade from v4 to v6 ([follow the instructions](https://grouper.atlassian.net/wiki/spaces/Grouper/pages/28547828/v6+Upgrade+Instructions+from+v4))

**Logging and Library Cleanup Discussion (from Zoom AI)**

The team discussed logging improvements, with Chris suggesting using diagnostics URLs and noting that relying solely on logs might only catch half the cases. Chad reported progress on removing unused libraries and properties, particularly those with security issues or outdated versions, though some cross-pollination between UI versions made complete removal challenging. The team agreed to continue cleaning up old libraries and properties, particularly targeting them for removal in odd-numbered version releases.

The conversation ended with Ben raising questions about ABAC data provider queries and group loaders, which Chris indicated should be discussed further.

**Database Performance and Migration Planning (from Zoom AI)**

The team discussed performance issues with ABAC queries and membership tables, particularly for large datasets. Chris suggested simplifying queries and potentially using SQL syncs to create simpler tables. They also discussed future database changes, including converting large tables to use UUIDs and other efficient data types. Chris proposed starting with smaller, less complex tables like audits or changelogs before tackling larger ones like memberships. The team considered changing the fundamental way memberships are represented, but decided to punt on that for now. They agreed to focus on V6 upgrades and backlog items in the near term, while starting to think about long-term database changes.
