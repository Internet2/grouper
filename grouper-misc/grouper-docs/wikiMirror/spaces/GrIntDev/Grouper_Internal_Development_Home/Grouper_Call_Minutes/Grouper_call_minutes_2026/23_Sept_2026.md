## **Summary (from Zoom AI)**

Chris Hyzer reviewed action items and updates, including a new redirect system for the Grouper documentation site to improve search indexing.   
Shilen detailed several JIRA fixes, such as addressing circular memberships and improving configuration handling.   
Chris Hyzer discussed performance improvements to the configuration UI and ongoing work to optimize memory usage.   
Chad reported on the messaging provisioner, security scan findings, and the need to document certain features. Vivek Sachdeva demonstrated a new feature to email group export links for large groups and fixed several security vulnerabilities.   
The team also discussed issues with the SCIM provisioner, user lifecycle events, and a security issue requiring the restriction of rule editor access. Various other bug reports and feature requests were mentioned, including a need for a JExel method to access attribute history.

## **Discussion (From Zoom AI)**

**Action Items and System Updates**

The team reviewed ongoing action items, including Shilen's work on investigating MCPR handling of abbreviated stack traces and Chad's creation of a JIRA regarding hyperlinks in the UI. Chris Hyzer discussed a new redirect system implemented for Grouper pages, which maps on-premises pages to their cloud counterparts, addressing issues with outdated content and Google indexing. The team also noted that Chad is working on enhancing the messaging provisioner to allow for customizable message formats based on customer requirements

**JIRA Updates and Circular Membership**

Shilen presented updates on JIRAs completed over the past two weeks, including fixes for Oracle deep check false positives, circular memberships, and membership finder query issues. Gail raised concerns about how the circular membership fix might affect loader jobs that rely on group loops, which Shilen acknowledged as a potential issue for more complex loop scenarios beyond direct A-to-A relationships. Chris Hyzer indicated that the circular membership fix would be included in the next minor version release, not the current dot release.

**Web Service Refactoring and Performance**

Shilen discussed plans to refactor web service code into Grouper Core and requested Chris's review before committing the changes. Chris approved the approach and confirmed that Shilen could proceed with the work, even before an upcoming release. Chris then shared his progress on addressing performance issues in the database configuration, including improvements to cache management and memory usage, which should significantly reduce the impact on UI performance during imports and edits.

**Grouper System Updates and Security**

Chad presented updates on several Grouper system issues. He discussed a messaging provisioner enhancement where he created a JExcel script to allow custom mapping of user fields, though Chris suggested considering JSON attributes as an alternative approach. Chad also reported on security findings from customer scans, including unescaped HTML, content security policy requirements, and stack traces that could leak information. The team agreed to remove the Grouper external feature from UI screens while keeping Grouper entities, and discussed securing the status page and logged out cookie functionality**.**

**Grouper Functionality Updates Discussion**

The team discussed several updates and issues related to Grouper functionality. Vivek presented fixes for entity actions, including the addition of "Fixed Entities Groups in Target" functionality, which allows re-evaluation of group memberships handled by specific provisioners. The team also addressed a security vulnerability where non-admin users could access stem information, which has been fixed. A significant discussion centered on improving the group export process for large groups, with Liam proposing an email-based download system similar to Splunk's background reporting feature to handle timeout issues with large exports. The conversation ended with an announcement about a security issue requiring users to disable rule editors for normal users until a point release is available, and Chris Hyzer requested that users send their user lifecycle event configurations for investigation as some users were experiencing issues with the second daemon not triggering properly.
