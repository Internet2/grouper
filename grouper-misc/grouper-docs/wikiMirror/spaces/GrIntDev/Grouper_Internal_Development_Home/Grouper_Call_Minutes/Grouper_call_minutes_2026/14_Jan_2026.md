**Discussion Summary (from Zoom AI)**

**Task Updates and Security Review**

The team discussed several completed and ongoing tasks, including updates to the wiki, user lifecycle configuration, and HTML email support. They agreed to further discuss a potential security issue raised by Shilen after the call. Chris mentioned that overall, they were looking good with their testing of Grouper v6 and asked if there was anything specific to discuss about them.

**UI and Database Upgrade Planning**

The team discussed ongoing changes to the UI and database structures.

Chris suggested a phased approach to upgrades rather than a single V7 release.

Chad reported that unused config removal work was ready for merging.

Chris noted that some light UI components might no longer be compatible with recent UI changes. The team agreed to proceed with config cleanup while being mindful of potential compatibility issues/ Shilen confirmed that user lifecycle issues had been resolved.

**Project Simplification and Deprecation Updates**

Chris and Chad discussed the progress and next steps for the project, focusing on externalizing text, removing unused libraries, and upgrading dependencies. Chad estimated he could complete these tasks within the week, simplifying where possible. They agreed to address deprecated methods in the codebase as they encounter them, with Chris noting the importance of future-proofing against potential deprecations.   
Shilen volunteered to update the wiki to reflect the changes in examples from Lang to Lang 3.

**Library Merge and Deprecation Plan**

Chad plans to merge three changes this week, including updates to stringutil and the removal of deprecated libraries, while ensuring unit tests remain unchanged before and after the merge. Chris and Chad discussed the removal of some libraries, confirming that they are no longer in use and have been replaced by alternatives like Gripper SFTP and Commons VFS2. They acknowledged the challenge of upgrading libraries without breaking scripts, and Chris suggested a potential approach for database upgrades.

**Grouper V6 Release Planning and Testing**

The team discussed version V6 release plans and agreed to run unit tests and conduct provisioning tests.

They reviewed potential changes to consolidate utility classes and deprecate old ones, though Chris expressed concerns about code comparison difficulties. Chad shared plans to upgrade JavaScript libraries and remove obsolete code.

Vivek confirmed fixes for lifecycle events and failsafe email functionality. The team agreed to review and delete obsolete code components, with Chad planning to share details via Slack for review.

**Component Removal and Rewrite Planning**

The team discussed removing unused or outdated components, including Group or ActiveMQ, which hasn't been updated since 2006 and hasn't been built since 2023. Chris and Chad agreed these could likely be removed, with Chad suggesting they check the wiki page for more information. The group also considered removing the AWS changelog and Legacy UI folder, though Chris wanted to move one specific item to another location.

**Grouper Project Cleanup Initiative**

The team discussed cleaning up the Grouper project by removing unused or outdated components, including the grouper-scim project, which Shilen will merge into the web service while checking for dependencies and potential API requirements. They also decided to remove the network graph applet and secure user data test plugin, as these were deemed unnecessary. Chris expressed hope that the cleanup would benefit users by reducing database and server requirements, setting the stage for future upgrades to V7 and beyond.

**Grouper Provisioning Challenges**

The team discussed several issues related to Grouper and provisioning. Gail explained problems with ingesting user groups from a database and the challenges of using the SQL group list incremental loader. Shilen suggested changes to the incremental loader to handle new groups and memberships more efficiently. Chris and Gail discussed performance issues with large provisioning operations, with Gail noting that a full sync takes about 9 hours. Chris agreed to look into potential solutions and get back to Gail.
