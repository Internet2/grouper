**Grouper BOF Planning and Updates**  
Emily announced that the Grouper BOF has been scheduled for lunchtime Tuesday during TechX. The team reviewed action items including progress on debug log printing, which Chad confirmed was already completed and implemented. Chris assigned Carrie Matt Black to write up an idea about moving code out of the operational image, with the option to submit it via Slack, wiki, or Jira, and asked Chad to create a JIRA regarding hyperlinks with side effects in the UI.

**Grouper Website Accessibility Improvements**  
Reed presented his accessibility improvements for the Grouper website, including making tooltips tabable and voice-readable, enhancing privilege checkmarks, and converting A tags to buttons for better screen reader compatibility. Chris explained the technical reasoning behind using buttons versus A tags for different types of interactive elements and approved Reed's work on accessibility improvements. Shilen discussed his work on MCP features, including adding Wikidocs to Lucene search, though he noted the need for retesting with new releases and mentioned a potential delay on startup while indexing Wikidocs.

**Grouper MCP Updates Discussion**  
Shilen discussed updates to Grouper MCP to support the latest MCP specification that was released three weeks ago. He identified and fixed several issues, including origin header validation, OAuth-related problems, and an open redirect vulnerability in the authorized endpoint. Chris expressed interest in making Grouper a more generic OAuth2 approval engine rather than being specific to MCP, and suggested removing client secret functionality due to potential security concerns and implementation issues where secrets are temporarily stored in plain text.

**Grouper Security Updates Discussion**  
Shilen and Chris discussed security updates for Grouper, focusing on URL configuration and encryption requirements. They agreed to make Grouper WS URL and UI URL required when MCP is enabled, and to implement an upgrade task to encrypt private keys in the database. They also noted that dynamic client registration is being deprecated in OAuth/OIDC, though this was marked as a future enhancement rather than an immediate priority.

**SQL Tool Security Implementation**  
The team discussed security concerns with the SQL Select tool in Cloud Code, particularly regarding database access permissions. Shilen identified that using a super user account could allow malicious queries and file system access, while Chris initially assumed only trusted admins would have access. The team agreed to implement a read-only transaction setting as a temporary solution and to remove the default Grouper connection, requiring explicit configuration for external systems. Shilen also noted that using both Codex and Claude AI models helped identify security issues that one model might have missed.

**API Security Proxy Implementation**  
Bert explained that Georgia Tech wants to allow student applications access to services like Canvas while maintaining control and disclaiming responsibility for potential issues. He described implementing an API security proxy that would hold API keys and act as a middleman, checking user attestation and managing authentication tokens to ensure proper access control. Chris discussed a different approach using OAuth2 with Grouper for group-based permissions, but Bert's solution focused on a central proxy system rather than direct token handling by applications.

**Authentication and Authorization Implementation**  
Bert and Chris discussed implementing authentication and authorization using Canvas web services, where Bert explained they are working on a standard authentication approach using proxy tokens without decoding operations. They explored the potential for generic implementation in Grouper, with Chris suggesting using GSH templates as a web service for specific use cases rather than a generic solution. The conversation then shifted to Bert's existing Zero Trust VPN implementation using Grouper groups to assign different IP addresses across seven network ranges, with firewalls configured to control access based on group memberships and IP addresses. Chris requested Bert to contribute to community documentation and offered to help set up access to the new Confluence system in the cloud.

**Azure and LDAP Updates Meeting**  
Vivek provided updates on several completed tickets, including validating multi-valued Azure Owners in provisioning, converting email box to text area, implementing config ID validation with warnings for prohibited terms, and fixing various UI and functionality issues. Chad highlighted two critical issues that need attention: ticket 7204 involving LDAP connection pooling problems with paging that affects version 6 upgrades, and ticket 7205 fixing a regression in LDAP groups loader functionality. The team discussed ongoing Grouper training efforts using Claude for automated UI interactions, with plans to implement Playwright testing scripts for future upgrades.
