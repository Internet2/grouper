**Summary**  
The Grouper team held a call to review recent work, discuss action items, and share updates. Shilin demonstrated a new AI assistant feature in the Grouper UI, which integrates with LLM providers and logs usage and calls. Chad reported on XSS vulnerability fixes and various JIRA improvements. Vivek detailed several bug fixes and a new configuration review screen. Chris discussed release strategies, including a new approach to cherry-picking fixes for different versions, and the need to reduce the size of releases to Maven Central. The team also discussed the potential for upgrading Hibernate and moving to Tomcat 10. At the end, Chris spoke with Ayman, a student interested in contributing to the project, about getting him set up with access and tasks.

**Data Collection and Query Discussion**  
The team discussed several topics including data collection issues where Gail sought Chad's help regarding logs and data retention, which Chad confirmed could be extended beyond the default one-week period. Chris welcomed Ayman to the Grouper project call and agreed to follow up via email to discuss Ayman's involvement. The team reviewed action items including investigating data providers in external systems, which was already completed, and a discussion about using "not exists" versus "not in" in queries, where the team agreed that "not exists" is generally better for performance unless dealing with a small list of hard-coded values.

**Javadoc Documentation Publishing Discussion**  
The team discussed publishing Javadoc documentation, where Chris expressed concern about storing Javadoc jars in Maven Central and proposed alternative solutions like linking to source code or creating a dedicated documentation site. Chad and Julian agreed with this approach, noting that current Javadoc generation is limited to twice monthly builds and only covers version 4, not versions 6 and 7. The team also briefly discussed Chad's work on a Jexel script enhancement for the messaging provisioner, which has been implemented in Grouper and demonstrated to a customer.

**Security and Configuration Management Updates**  
The team discussed several security and configuration topics. Chris asked Chad to write a wiki page for central or content security policy filter in the container, which Chad confirmed was on his list. The group discussed a security issue that was published, with Chad noting that customers typically just create a group and add sysadmins without running additional scripts. Julian reported progress on user lifecycle events, confirming that previous issues were due to his own configuration errors rather than bugs. The team also discussed configuration management approaches, with Julian sharing UVA's hybrid method of using both file configs in Git repos and database changes between deployment windows, and Liam mentioning their practice of wiping the Grouper config table during upgrades. Chris suggested using a GSH script to delete configs instead of truncating the table, which would copy them to the history table for audit purposes.

**ABAC Group Formation Tool Discussion**  
Gail proposed creating a tool to help users form the right ABAC group by asking relevant questions and providing samples based on available data. Shilen demonstrated the current tool's functionality, including doc searches and database changes, and noted that Claude provided a better experience than GPT during testing. The team discussed potential improvements, such as including version information for Grouper and enhancing logging capabilities, but decided to focus on getting the current version deployed. Shilen needs to complete additional testing and review the code for safety before pushing the updates.

**Vulnerability and Release Strategy**  
Chad reported working on vulnerability fixes over the past two weeks, with most issues addressed in version 7 and some additional proactive fixes still pending. Chris explained the team's new release strategy for handling security fixes, including creating sub-branches for emergency releases when needed, and outlined plans to reduce the size of releases sent to Sonatype due to storage limitations. The team discussed maintaining consistent code across versions 4, 6, and 7, with V7 being the most current and receiving the latest fixes, while older versions would receive fixes from approximately the last month.

**Bug Fixes and System Improvements**  
The team discussed several bug fixes and improvements. They resolved issues with veto rules patterns, group provisioning views, and report actions. The team also fixed problems with the group picker excluding composite groups and improved the handling of user requests to join groups. Additionally, they addressed a critical issue with deleting group members when the target entity changes in Okta, creating unit tests to ensure no existing functionality was broken.

**Configuration Review Feature Discussion**  
The team discussed a new configuration review feature that identifies potential issues and provides recommended actions. Chris suggested adding more gotchas that the team has learned from experience, while Chad noted challenges with custom CRUD options. The team also addressed recent fixes for security permissions and Okta provisioning issues, with Liam and Gail agreeing to test cherry-picked Okta fixes in production to avoid authorization problems.

**Grouper Platform Updates and Enhancements**  
Chris presented updates on Grouper, including fixes for Javadoc requirements, Maven Central source inclusion, and resolved issues with Jackson conflict jars and outdated URLs. Key improvements discussed included updates to the Grouper file table to support binary files (blobs) and larger text limits, new download capabilities for reports, and enhancements to the Duo Provisioner with extended device information. Julian raised questions about upgrading Hibernate and migrating to Java 17/Jakarta, which Chris acknowledged as important but expressed caution about due to past experience with Hibernate upgrades. The conversation ended with Chris discussing onboarding a new student volunteer, Ayman, who expressed interest in contributing 15 hours per week and will be set up with access to the Grouper V7 branch.
