Carey proposed moving code out of the operational image and making it deployable from Git repositories with signature verification, but Chris expressed concerns about the complexity and potential compatibility issues. The conversation ended with a need to coordinate with Shillin regarding task assignment, though the specific details were not fully discussed in the provided transcript segment.

  - Chris outlined a plan to migrate the wiki with a week's notice, removing editing privileges from the on-premises version and implementing URL translation automation to handle broken links.
  - The team agreed to this approach, with Drew confirming they could lock down the on-premises wiki to read-only access.
  - Chris will create a document outlining the migration plan and issues before proceeding with the migration.

**AI-Assisted Documentation Updates Discussion**

- - The team discussed ongoing documentation updates, with Reed reporting completion of approximately 50 wiki page edits using Claude, focusing on fact-checking against Grouper source code and style guides while minimizing links and managing images.
  - Chris and Chad discussed the potential for improved search functionality in the cloud environment and the implementation of MCP (Machine Cloud Protocol) for page editing.
  - Chris explained the current limitations of MCP in Atlassian and the need for consistent runbook procedures.
  - The team agreed that AI-assisted documentation updates represent a practical solution given the Grouper team's limited time for manual documentation reviews.

**Documentation and Accessibility Improvements**

The team discussed documentation improvements, focusing on how to handle screenshots and text content. They agreed that for end-user documentation, screenshots should be combined with text that can be copied and pasted, while behind-the-scenes content could be provided as text only. Reed was tasked with noting that very tall screenshots should be made expandable, and the team identified accessibility improvements as a potential intern project, particularly given upcoming compliance deadlines for government institutions.

**Accessibility Issues and Solutions**

Chris discussed accessibility issues with tooltips, form elements, and HTML tags, explaining that many components need to be converted from A tags to button tags to improve accessibility. He outlined a testing process using Wave accessibility tool and screen readers to verify fixes. Carey raised concerns about maintaining visual consistency while making these changes and suggested implementing automated testing for accessibility and visual changes.

**ABAC Configuration Updates Discussion**

Shilen presented updates on three Jiras related to ABAC configuration. The first Jira [GRP-6866](https://todos.internet2.edu/browse/GRP-6866) added ABAC configuration groups for maximum membership size limits to prevent users from creating scripts with excessive memberships.   
The second Jira [GRP-6931](https://todos.internet2.edu/browse/GRP-6931) introduced a new syntax option for rows to check if data fields are not in a list of values.   
The third Jira [GRP-7054](https://todos.internet2.edu/browse/GRP-7054) fixed a race condition during group recalcs with the incremental loader. Chris requested updates to the ABAC wiki to document these new features, which Shilen agreed to do. The discussion concluded with Chris asking about implementing functions in ABAC to handle term-based logic, specifically for students who want to skip summer terms.

**ABAC Term Logic Challenges**

The team discussed challenges with handling term-based logic in ABAC (Attribute-Based Access Control) systems, particularly around handling special cases where the definition of "current term" differs from standard conventions. Chris explained the current system uses numerical values (0 for current term, 1 for next term, etc.) but encountered issues with specific use cases that require different logic, such as ignoring summer terms. The group explored potential solutions including using Java VSH templates, global ABAC attributes, or reference groups, with Carey suggesting existing approaches like using group folders or property files. The discussion concluded with agreement that they need to build out functionality for data providers to populate global ABAC attributes, which was already on their roadmap.

**SCIM2 Diagnostics Enhancements Presentation**

Vivek presented enhancements for diagnostics that include a new provisioner configuration section for SCIM2, allowing testing of different patching strategies (non-qualified, qualified, and nested) for name and email changes. The diagnostics feature aims to help administrators configure provisioners correctly by simulating various scenarios and providing feedback on which strategies work with their specific SCIM servers. While the functionality is implemented and includes unit tests, Vivek noted that the actual testing against external systems still needs to be verified.

**SQL Cache Performance Optimization**

Chad discussed performance issues with SQL cache in version 4, particularly when handling large nested memberships, and shared findings about new configuration settings that can improve performance. The team agreed to lower the default log batch progress interval from 100,000 to 1,000 to provide better visibility during long-running jobs. They concluded that institutions should avoid using large roll-up groups due to performance issues, and discussed potential future work on migrating composite groups to Jexel expressions, though concerns were raised about the impact on existing systems.
